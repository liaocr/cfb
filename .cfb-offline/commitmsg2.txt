feat(ruler): gen-ruler/4 —— 硬门只装布尔不变量，压缩转软标准

本地零成本重跑 v9 的 89 条 dev，做门级消融，翻掉上一轮的结论。

一、G7 出硬门，改软标准（COMPRESSION_TARGET = 0.5）
   四条实测证据：
   1. 24 条教师稿只挂 G7 一件事，其余七门全过。它们的软分均值 0.6993，
      教师整体 0.703 —— 尺子扔掉的和留下的一样好。
   2. 这 24 条 token 比从 0.5834 起跳，0.55 落在分布内部，没有自然断点。
   3. 压缩本来就在软分里（S4，权重 0.13）。G7 是同一件事数两遍。
   4. 阈值从 0.55 放宽到不设限：教师 42.5% -> 75.3%，学生 27.4% -> 34.2%。
      差距不是缩小而是扩大（15.1 点 -> 41.1 点）。G7 一直在掩盖学生的缺口。
   立下的规矩：硬门只装布尔不变量，程度放软分。
   以后再训到 0.5 时，把 COMPRESSION_HARD_MAX 设成 0.5 就重新装上。

二、G0 提升成顶层布尔 gaugeable，不再靠解析失败串
   实测 dev 89 条：G0 命中在教师和学生上是同一批 16 条，不一致数 = 0
   （它只读 raw/ctx）。拿它进分母是把两边同时压低。eval-sft 现在用 gaugeable
   当分母并做交叉校验，不一致直接 FATAL。

三、新增 tools/g1-guard.mjs —— G1 的确定性后处理门
   dev 里学生只挂 G1 的有 21 条，是最大的一块可回收分数。
   实测（73 条有受力点）：
     off      25/73 = 34.3%，软分 0.5740，孤儿小句 0
     strip    45/73 = 61.6%，软分 0.5836，孤儿小句 0
     drop     46/73 = 63.0%，软分 0.5925，孤儿小句 60（16 条稿）
     sentence 32/73 = 43.8%，软分 0.5126，14 条稿被删空
   drop 多挣 1 条，代价是 60 处「是 ，」这种残骸 —— 硬门全过、软分还升高。
   所以默认 strip，并加了两个东西：
     · 安全阀：修复后正文不足原 40% 就原样退回（sentence 删空 14 条）
     · orphanCount 诊断量。不做成门：教师自然稿自己也有孤儿（722 条最大 8），
       卡在 3 会误杀教师。它没有判别力，只有诊断力。
   全量 722 教师稿上：467 -> 517 过门。

四、学习曲线（deploy/kaggle）
   上一轮只有 40 步一个终点，「欠训」和「目标函数不对」在数据上不可分离。
   新增 --ckpt-steps / --ckpt-gen-n，到点跑 dev loss + 生成同 n 条稿子。
   顺带修两个真 bug：
   · DDP 步数不对齐：412 条 / 批 4 = 103 微批，2 卡切成 52 和 51，
     各自 //4 得 13 和 12 步 —— 步数不等，先跑完的卡会永久等待，
     表现为整轮静默挂死。v9 的 256 条恰好 32/32 把它盖住了。
   · 缓存自检拿冷启动数字比快慢（v9 的 6.7s 里大都是 Triton 首次编译）。
     改成先热身再比，并加「确实更慢就关掉」。

五、教师 prompt v5（transfer/prompts/teacher3-zh.txt）—— 负结果，不采纳
   往 v4 里追加 G1/G3/G4 的门定义，n=30 配对：
     v4 21/23 过门，软分 0.7031；v5 18/23，软分 0.6799；只 v4 过 3 条，只 v5 过 0 条。
   McNemar chi2 = 1.33，不显著，但方向是更差。说明教师的剩余失败不是没被交代，
   把门的定义写进 prompt 不是杠杆。v4 仍是生产提示词。
