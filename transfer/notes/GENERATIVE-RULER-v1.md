# 生成式压缩稿的尺子 v1（gen-ruler/1）

> 这份文档只讲一件事：**怎么判断一份压缩稿是好是坏，而且这个判断要能被机械复算。**
> 它不负责生成稿子。生成是另一件事，而且绝不能由这把尺子的执行者来当老师。

## 0. 为什么必须换掉原来那把尺子

仓库原来也有一套「尺子」（`tools/gold-check.mjs` 那一族）。它检查的是：
引用是否逐字、反引号是否配对、长度是否超线。**全是形式。**

后果在 `tools/gold-forge2.mjs` 上暴露得很干净 —— 那是真正生产「金标稿」的程序，第 48 行：

```js
const target = uniq((raw.match(/[\w./-]+\.(?:mjs|js|ts|json|log)/g) || [])
  .filter((x) => ev.includes(x)))
  .sort((a, b) => b.length - a.length)[0] || null
```

**它按「谁的名字最长」选落点。** 于是 `transfer/gold` 里出现了这样的真金标：

```
落点：/home/u/.dsh/storages/cot-form-b/trace.log（只动这一处；……）
```

那是报错里那个 root 所有、只读的日志文件 —— 是**症状**，不是要改的地方。
而 C1–C6 全过，`qualityAudit.status = "clean"`，`trainingEligible = true`。

**形式尺子量不出语义错误。** 这不是"再补一条规则"能修的，是尺子的定义错了。

同样的病在本仓有三处同源发作，值得放在一起看：

| 位置 | 表现 |
| --- | --- |
| `tools/gold-forge2.mjs` 第 48 行 | 按长度选落点，产出症状路径当改点 |
| `tools/train-v5-micro.mjs` 36–60 行 | 手写正则给单元打标签，实测让准确率**下降 2.95pp** |
| `tools/micro-generator/teach-shape.mjs` | 教师机械抽句，`corpus-report.json` 里 `axesAllPass = 6001/6001`（零负例） |

三处都是「抽取式正则假装自己是生成式判断」。

## 1. 尺子是什么、不是什么（架构铁律）

* 尺子是**判别器**：给定 `(raw, ctx, draft)`，回答「这份稿能不能用」。
* 尺子**不是生成器**，也绝不能被拿来当教师。`tools/micro-generator/teach-shape.mjs`
  第 447 行自己写着：

  > the teacher executes the same rulers it is scored with ⇒ later student numbers are same-source measurements

  **同源测量等于没测量。** 教师必须是另一个东西（真模型，或另一套完全独立的机制）。
* 硬门是布尔，任一不过 ⇒ 拒稿 ⇒ **100% 无损回退 raw**。
  「不劣于原稿」不是证明出来的命题，是这个兜底机制保证的性质。
  用户口径：「没有证明吗？没有，但他就是平均不弱」—— 对，所以它是一条**回归集**，
  不是一条公理。回归集只增不减：跑批 → 找到更差的稿 → 归因 → 修 → 这个 case 永久留下。
* 软分只给**已过硬门**的稿子排序，绝不用来救活一份不过门的稿。

## 2. 七道硬门

| 门 | 判什么 | 为什么 |
| --- | --- | --- |
| G1 quote-grounded | 引用片段里不得出现 `raw ∪ ctx` 里没有的内容锚点 | 「凭空」是三条必拒负类之一 |
| G2 locus-grounded | 稿子**自己声明**落点时，该路径必须出现在 raw 的**动作语境**里 | 直接打死上面那个症状路径缺陷 |
| G3 anchors-kept | 题面失败陈述里的承重锚点必须活下来（路径全保，标识符 ≥ ANCHOR_FLOOR） | `sse-truncated` 真回归的机理 |
| G4 actionable | 稿里至少有一个接地的落点或验证命令；**写出来的命令必须是 raw∪ctx 里真有的那条** | 编一条不存在的验收命令是最常见的"流畅但改事实" |
| G5 no-cause-inversion | 不得把 raw 的因果方向反过来 | 窄检测，只抓带反转标记的对调 |
| G6 not-copy | 剔除合法引用后的 16-gram 覆盖率 < 0.5 | 照抄稿 |
| G7 compressed | `raw ≥ 800` 时稿长 ≤ 0.55·raw（**只有上限，没有下限**） | 不压缩就不叫压缩稿 |

几个刻意的设计选择：

* **G1 只抓「凭空」，不抓「引用保真」。** 第一版用「整句必须是 raw 子串」，
  61 条真手稿里 48 条被判凭空。逐条看过：那些句子不是编的，是轻轻改写了再放进「」。
  保真度是另一件事，它进软分 S6。否则尺子会奖励一种很坏的行为：
  **只要不写引号就永远不违规。**
* **G2 只在稿子自己声明落点时才判。** 通用压缩稿不必声明落点；缺声明由 G4 管。
  「没写落点」和「写错落点」不能混成一类。
* **G6 先剔除引用区间再算覆盖率。** 引用本来就该逐字，
  不剔的话「引了原文」会被算成「抄了原文」。
* **G7 不设下限。** 压得太狠会先撞 G2/G3/G4（没落点、丢锚点、不动手）——
  那是语义判据。再放一个比例下限只是拍脑袋的截断。

## 3. 软分（只在过门稿之间排序）

| 维度 | 权重 | 含义 |
| --- | --- | --- |
| S1 anchorsKept | .28 | raw 锚点整体保留率 |
| S2 groundingDensity | .18 | 稿中锚点能在 raw∪ctx 里找到的比例 |
| S3 decisionCoverage | .18 | raw 里「动作句」被稿覆盖的平均程度 |
| S4 compressionGain | .13 | 压缩收益（软，不是越短越好） |
| S5 tailRetention | .13 | **只出现在 raw 后半段的锚点保留率** |
| S6 quoteFidelity | .10 | 引用逐字比例 |

**S5 是反抽取的那一刀。** 抽取器只会捞开头；凡是尾部锚点整片丢失的稿子，
它的语义覆盖就是假的。这一维让「删掉探索过程」第一次有了代价 ——
而探索过程正是抽取式永远不敢删的东西。

## 4. 六条机械负例轴（`tools/gen-negatives.mjs`，$0、零 API）

正样本要花钱生成，**负样本不用**。把一份已过硬门的好稿沿一条明确的劣化轴做一次
最小机械改动，坏在哪儿构造时就知道 —— 标签是确定的，不是标注出来的。
而且只改一处 ⇒ 长度、语域、题材、术语全部**配对**，模型没法靠「谁更长」混分。

| 轴 | 做法 | 期望门 |
| --- | --- | --- |
| N1-copy | `draft := raw` | G6 |
| N2-drop-anchor | 删掉一个承重锚点 | G3 |
| N3-invent | 在引用里塞一个不存在的锚点 | G1 |
| N4-invert | 把 raw 的真实因果对对调并加反转标记 | G5 |
| N5-over-compress | 只留最长引用句 | G2/G3/G4 |
| N6-wrong-locus | 落点换成 raw 里最长的另一个非动作路径 | G2 |

**N6 不是假想敌**，它就是 `gold-forge2.mjs` 第 48 行那个 bug 的固化。

配套的 `auditRuler()`：造负例 → 拿尺子打 → **报告尺子的洞**。
一条负例整条过了尺子，就是尺子缺一道门。这是让回归集只增不减的机制 ——
把一个飞轮里的「稿子」换成「尺子」而已。

## 5. 实测读数（全部可复算）

| 测什么 | 命令 | 结果 |
| --- | --- | --- |
| v5 机械语料（6001 行里抽 400） | `node tools/gen-ruler.mjs --in .cfb-offline/ruler/pairs-v5.jsonl` | **396/400 被拒（1.0% 过门）**，其中 394 条挂在 G6 照抄 |
| 61 条真手稿 | `--in .cfb-offline/ruler/pairs-hand.jsonl` | 25 过门 / 36 拒（41.0%），挂在 G1×16、G2×15、G3×12、G4×5、G7×1 |
| 六轴负例自审 | `node tools/gen-negatives.mjs` | **110 条派生，108 条被拒，103 条命中预期门，2 个洞** |
| 对 L2 真读数精确对齐 | `node tools/gen-ruler-vs-l2.mjs` | **n=3，3/3 一致** |

第一行是这套东西最硬的证据：**v5 那 6001 条「数据」是规则执行器的输出，不是生成式数据。**
尺子独立地把它们判成照抄稿。

第三行剩下的那两个洞都是同一类：`N5-over-compress`（只留最长引用句）整条过门。
**没有修。** 修不修要看它在真机 L2 上是不是真的更差，不能靠"看起来该拦"就加门 ——
这正是"回归集只增不减"该有的样子：洞先记账，下一批真机读数来了再决定。

顺带一个说明「阈值不是调出来的」的读数：G3 的承重标识符保留率在 61 条上是**双峰**的
（`[min,q25,med,q75,max] = [0,1,1,1,1]`，55/61 满分、6 条为 0），中间没有样本。
所以 `ANCHOR_FLOOR` 取 0.34 / 0.5 / 0.75 / 1.0 影响的都是同样那 6 条 ——
它落在两个峰之间的空谷里，这个事实比"我选了 0.5"重要得多。

第四行必须如实说：**n=3。** 精确对齐是
`hand-samples.jsonl` 的 `(task, sample, round)` ↔ `results.jsonl` 的
`(task, sample, rounds)`。全仓 208 行 L2 读数里，只有 3 条既有一份 hand 稿、
又有 hand 臂结局（多数是 `fixed: null`，即该臂没跑出结局）。
**3/3 不是"尺子准"，是"尺子还没被证伪"。** 回归集的下一批 case 才是它真正的考试。

## 6. 开发过程中真正抓到的四个 bug（都属于"不报错但算错"）

这四个都值得留档，因为它们全都是**静默失真**：不会有异常、不会有红测试，
只会让结论变成噪声。

1. **`/g` 正则配 `.test()` 的 lastIndex 状态。** `ACTION_RX` 带 `/g` 却用 `.test()`，
   同一个输入隔次返回不同结论。已加确定性自测钉住。
2. **分句正则在 ASCII 句点上无条件切。** `"test/hedge.selftest.mjs 报 FAIL…"`
   被从文件名中间切成两半，承重锚点里那个**文件**凭空消失。
   于是一条链上的三样东西同时坏掉：G3 看不见它、负例基座退化、
   N3 变成「把 X 换成 X」的空操作。
3. **`anchorsOf` 返回的是按类型分组的数组，没有位置。** 于是「取边界前最近的锚点」
   取到的是「某类型里的最后一个」—— N4 反因果 24 条一条都抓不住（0/24）。
   修法是 `anchorsWithPos()`。
4. **`base()` 可能返回空串。** `TECH_RX` 写松了会吐出 `"a/b/"`，于是
   `base() === ''`，`indexOf('')` 恒等于当前位置、游标不前进 ⇒ **整个 CLI 挂死**；
   更阴的是 `includes('')` 恒真，会让**所有**锚点都被判成"还在"。
   一个字符类写松了，同时买到一次死循环和一次静默失真。

## 7. raw 矿筛选（`tools/screen-raw-mine.mjs`）

尺子的主入口 `judge()` 需要一份 draft，而 draft 要花钱。raw 矿有 10558 行 / 3500 万字，
全喂教师模型是 \$5–15 甚至更多。所以在花钱之前需要一道门。

**这道门叫 `preflight()`，它是尺子里唯一不需要稿子的那部分。**
它只说「值不值得为这个输入花钱」，不说「稿子好不好」—— 后者是 `judge()` 的事。
这个分工在 selftest §14 里被钉死：**照抄稿必须在预检里过，只在 judge 里被 G6 打死。**
两层判据一旦混用，就会出现「拿预检分数当质量结论」这种事。

### 实测（6 秒，\$0）

| 阶段 | 结果 |
| --- | --- |
| 读入 | 10558 行 / 5 个 census 文件 |
| 按内容去重 `(raw,ctx)` | **7673**（丢 2885 条重复） |
| 每个 trajectory 留 1 个单元 | **4741** |
| 预检通过 | **4687**（拒 54） |
| 仓库覆盖 | **1075 / 1075** |
| 许可 | MIT 2490 / Apache-2.0 1272 / BSD-3-Clause 791 / BSD-2-Clause 134 —— 全部宽松 |

体量：1000 条 ≈ 2.79 MB ≈ 96 万 tok；3000 条 ≈ 8.23 MB ≈ 283 万 tok；
全部 4687 条 ≈ 12.28 MB ≈ 423 万 tok（raw + 估算输出）。

### 两个刻意的设计决定，都是踩过坑才有的

**一、按内容去重，不按 `unitId`。**
实测同一个 `unitId` 会出现多行，且其中 **266 组的 `raw` 各不相同**。
第一版按 `unitId` 去重，于是**静默丢掉 266 份不同的原文** ——
去重是最不该出错的地方，因为它出错时数据看起来依然完整。

**二、默认全部保留，不按 `teachScore` 砍。**
`teachScore` 的权重**没有经过任何真实压缩结果校准**，它只是把
「有具体标识符 / 有决断句 / 是散文而非日志」排序。
拿一个没根据的排序器丢掉 1600 条样本，换不来任何东西。
所以清单按**仓库轮转**排序：想截断到任意 N，多样性都还在（N=500 时覆盖 500 个仓库）。

### 预检几乎不拦人 —— 这是实测出来的，不是阈值太松

| 拒绝原因 | 条数 |
| --- | --- |
| P2 too-long-for-window（>12000 字） | 30 |
| P4 mostly-code | 12 |
| P5 no-load-bearing-anchors | 12 |
| P1 too-short / P3 ctx-missing | **0** |

原因是这个语料的分布本来就整段落在带内：
`rawChars` = {min **1500**, q25 1913, med 2383, q75 3024, max 24026}，
`identifiersInRaw` = {min 0, q25 13, med 19, max 40}。

**所以预检在这个语料上的价值是护栏（防止未来的新语料把不合格输入混进来），不是判别器。**
真正的判别发生在付费之后：draft 出来再走 `judge()` 那七道门。
这一点必须说清楚，否则 `preflight 4687/4741 通过` 会被误读成「4687 条都是好数据」。

### 语料结构（关于泛化的一个警告）

全部 10558 行来自**同一个数据集**（`nvidia/Open-SWE-Traces` v1.1 / `openhands`）、
**同一个教师模型**（`DeepSeek-V4-Flash` / `reasoningEffort=max`）。

好处：这正是目标模型的分布，压缩它等于压缩目标模型自己的思维链。
风险：**没有第二种分布。** 泛化到别的思维链形态（数学推理、长链规划、中文思维）
上完全没有测过。用户要的是「面对任何思维链都可以」，而这批数据只覆盖一种。

## 8. 没验证的部分（诚实清单）

* **阈值只在 n=3 的真机读数上校准过。** `ANCHOR_FLOOR = 0.5`、G6 的 0.5、
  G7 的 0.55 都是从 61 条手稿的分布里挑的保守值，不是拟合出来的最优值。
  （2026-10 补：现有 121 条教师真稿做第二组证据，见 §11。但那是**教师**的稿子，
  不是真机 L2 读数 —— L2 仍然只有 n=3。）
* **G5 只能抓机械制造的反转。** 真正语义级的因果篡改（换掉"因为"的主语、
  把必要条件说成充分条件）它抓不到。别把它当成因果核验器。
* **尺子没在"任意思维链"上测过。** 目前所有测例都是修 bug 型 CoT
  （含文件路径、断言、验收命令）。纯数学/纯推理型 CoT 上 G2/G4 会退化成
  场景门不激活 —— 那种输入上只剩 G1/G3/G5/G6/G7 五道门在工作，未测。
* **G3 对路径要求"一个都不许丢"仍偏严。** 61 条里有 13 条丢路径，其中一部分
  可能确实是好稿。路径保留率是否也该像标识符一样改成下限，要等回归集变大再定。
* **`raw` 的中位长度 2501、p90 5728、max 35378**（`transfer/models/micro-generator-v4flash-scenarios/`
  下 5 个 census 文件，10558 行）。尺子按"整段 CoT 一次压缩"设计；
  超长 raw 要不要分段压缩，未定。
* **`teachScore` 完全未校准**（见 §7）。它现在只用来排序，不用来砍样本。
  第一批付费压缩做完后，必须拿真实结果回头检验它 —— 否则它就是本仓第四个
  「机械排序器假装自己是判断」。
* **预检阈值（800 / 12000 字、anchor ≥ 3）只在这一个语料上量过。**
  它们在这个语料上几乎不拦人（见 §7 的表），所以**没有被真正检验过**。
  换语料时必须重新量分布。

## 9. 怎么用

```bash
# 给一批 (raw, ctx, draft) 打分；JSONL 每行 { id, raw, ctx, draft }
node tools/gen-ruler.mjs --in pairs.jsonl --out report.json

# 从好稿机械派生负例，并报告尺子自己的洞
node tools/gen-negatives.mjs --in pairs.jsonl --out negative-audit.json

# 拿 L2 真读数校准
node tools/gen-ruler-vs-l2.mjs

# 回归测试（已并入 node verify.mjs 的自动发现）
node test/gen-ruler.selftest.mjs
```

## 10. 与训练的关系

尺子和负例生成器都是 **$0 侧**的东西，不依赖任何模型、任何 API、任何训练。
它们的作用是在花钱之前把数据的形状定死：

* **正样本**：仓库里已经付过钱的约 190 对真 pair
  （`.cfb-offline/train/pairs.jsonl` 93 条 + `.cfb-runtime/traj/*/hand-samples.jsonl`
  75 条其中 61 条 `trainingEligible`）。不够再花钱生成，必须**批量**
  （一个 prompt 出 N 份压缩），不许一条一次调用。
* **负样本**：上面六条轴机械派生，零成本、标签确定、长度配对。
* **拒绝采样**：训练出来的学生跑一遍 raw 矿 → 过不了尺子的直接丢 →
  剩下的当新正样本。这一步是自举降本的关键路径。

红线：**绝不把整座 35 MB 的 raw 矿喂给教师模型。**
10558 个单元、3500 万字，按实测单价约 $7–14，而且大部分是重复的探索。

## 11. 教师真稿：第一批付费样本（2026-10）

§7 解决的是「给谁花钱」，这一节是「钱花出去之后拿回来的是什么」。

### 生产

`node tools/gen-ruler.mjs` 要 draft，draft 只能花钱买。生产脚本 `.cfb-offline/teacher/batch.py`：
多线程、断点续传、5 次退避重试、每条把原始 usage 一起落盘。

```
100 单元 / 4 线程 / 338 秒 / 0 失败（3.4 秒每条）
产出 .cfb-offline/teacher/drafts.jsonl（每行含 raw、ctx、draft、usage、license）
```

### 一个纯生产事故，但值得写下来

第一次用 `max_tokens=1600` 跑 10 条，**4 条稿子是空的**。原因不是模型不行：
这是个**推理模型**，它先花掉约 1300 token 思考，`finish_reason` 变成 `length`，正文 0 字。
放宽到 8000 之后 20/20 全成。

**教训**：接一个没接过的模型时，「返回 200 但内容是空的」是一个真实且沉默的失败模式。
`batch.py` 里把 `usage` 和 `finish_reason` 一起落盘，就是为了让这种事故第二次发生时看得见。

### 待定的系统性模式：模块名 → 文件路径

8 条 G1 拒稿是**同一个模式**：题面写 `aiomisc.service.grpc_server`（Python 点号模块名），
稿子写成 `aiomisc/service/grpc_server.py`（文件路径）。原样核查：

```
aiokitchen_aiomisc_pr199#b13     aiomisc.service.grpc_server  -> aiomisc/service/grpc_server.py
astropy_sphinx-automodapi#b11    sphinx_automodapi.smart_resolver -> sphinx_automodapi/smart_resolver.py
brandon-rhodes_python-skyfield   skyfield.units               -> skyfield/units.py
```

这些转换在 Python 里**是对的**。但按我们的规则（「不许编造原文里没有的文件名」）它算凭空，
而且模型**没看过仓库树**，它是在按约定推。

**这是一个必须由人来定的口径，不是能靠调参解决的**，两条路：

* **收紧**（现状）：坚持「只写有出处的」。代价是白白丢掉约 8% 的样本，
  好处是训练出来的学生绝不越界 —— 而我们整套安全性正是建立在「不越界」上。
* **放开**（允许点号→路径规范化）：多拿约 8% 样本，但学生学会了「补全没看到的东西」，
  这个习惯一旦泛化，就会在别的地方编造。

在有人定这个口径之前，**尺子保持收紧**：宁可少要数据，不可污染「不越界」这条性质。
这批 8 条单独留档，定为「口径待定」，不当作尺子 bug。
