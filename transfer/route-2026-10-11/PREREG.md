# 预注册：金标生成 → 尺子提炼（路线 2026-10-11，花费上限 $5）

本文件在任何真机请求发出之前冻结。冻结后的修改必须另立版本号，并在报告中说明。

## 1. 问题
1. 手写压缩稿（hand，金标候选）能否在真机上带来与原文（raw）同等或更好的结局，且效率不劣于 raw？
2. 手写稿相对生产压缩器（auto = `policy:base`）是否更好？（两个计划分开跑，互不混臂。）
3. 能否从这些轨迹中提炼一把"固定规则"的尺子？它要求事先定义的特征，只在 dev 上选阈值。

## 2. 设计
- 场景（5 个 traj-fixtures 家族）：eacces-config、flaky-timeout、perf-regression、wrong-model、sse-truncated。
- 每个场景 2 个样本。最多 6 轮（PLAN-SIMPLE 定义是 10 轮；因预算削减到 6，**这是已披露偏差**）。
- 计划 A：`raw vs hand`。计划 B：`raw vs policy:base`（生产 auto）。计划 B 只在计划 A 的实际花费 ≤ $2.0 时才运行。
- 手写稿（hand）由助手（我）写，只看 raw+ctx（D5）。traj-run 的生产闸链（G1/G2/birthAccept）会拒绝不合格的稿，被拒的稿要重写。
- 冻结：所有手写稿写入 `drafts/`，计算并记录 sha256 清单（`DRAFTS.sha256`）。手写稿不得在看到结局后修改。
- 数据划分（事先定，不因结果调整）：
  - dev = eacces-config、sse-truncated、flaky-timeout（用于提炼尺子）。
  - holdout = perf-regression、wrong-model（只报告，不用于选择）。
  - 注意：holdout 的 Clopper–Pearson 认证（D2，需约 59 条通过稿，约 $7）超出本次预算，**本次不做**。

## 3. 金标判定（事先定义，报告时逐条列出）
一条 hand 轨迹"好"（候选金标），需同时满足：
- 硬门：在 6 轮内修好（fixed）；修好后验收通过（verifiedAfterFix）；falseClaim = false（程序检查）。
- 效率（用户选定的更严口径）：修好轮数 ≤ 同场景 raw 的轮数，且总 token ≤ 同场景 raw 的 token。同场景 raw 取该场景 raw 样本的**中位数**（2 个样本时为均值）。
- 验证适度：修好后的验证调用 ≤ 2。
- 无幻觉：只用程序的 falseClaim 标志；本次**不做**逐句的人工主张审计（已披露限制）。

## 4. 尺子（候选，固定规则，事先列出的特征）
- R1 动作依据保留：raw 末 300 字符中的代码式标识符（不在 ctx 中），在 draft 中原样出现的比例 ≥ 0.8（固定，见 `transfer/ruler-v2/`）。
- G2 凭空主张：draft 反引号标识符必须在 raw∪ctx 中。
- G3 压缩率：len(draft)/len(raw) ≤ 0.5。
- F4 稿长（字符数）。F5 死路/排除标记数（"不要 / 已排除 / 别再 / 死路 / 不再"等，事先列出）。
- 阈值只在 dev 上选：以"金标候选好 vs 差"的区分度为目标。淘汰规则：匹配稿的通过率 < 0.5 ⇒ 淘汰。**这次仍然是探索性的**：dev 样本极少，不能视为已验证。
