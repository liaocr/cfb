# PREREG-v6（已冻结，2026-10-11）

**冻结 ≠ 授权花费。** 本文件只定义闸门与判定规则。任何真机运行仍需用户单独批准预算（PREREG 规则：计划 digest + 上限）。

## 0. 为什么需要 v6
v5（t132）存在两处闸门缺陷（RESULTS §10.9）：
1. 只查带空白的反引号片段，无空白的非逐字片段被放行（wrong-model-s1-r4：`observe(options)`）。
2. 「」引文完全不查。

另外 t132 暴露了结构问题：稿子中的「待查 / 未解」条目会变成下一步动作（sse-s1：模型第 6 轮去查 verify.mjs 的环境异常，raw 臂直接修复）。

## 1. 闸门（v5 全部规则保留，新增 G-v6-1/2/3）
- **G-v6-1 逐字引用**：所有反引号片段与「」引文必须逐字出现在该轮输入（raw、ctx、calls、程序部件）中。违规 `ungrounded-command` / `ungrounded-quote`。
  - 豁免：「改成 / 改为 / 改回 / 替换为」之后的片段是拟议的新代码，不可能在原文中；其依据由 `invented-triple`（锚点须在原文/台账中）与 `invented-decision`（原文须有改法意图）承担。局限：豁免之后写入的无依据片段，若不构成三元组，闸门不拦。
- **G-v6-2 待查不得成为动作**：「所以下一步工具调用 / 验收 / 回放过了之后」行中出现「待查 / 未解 / 未核实 / 尚未核实 / 待定 / 未确认」即违规 `open-as-action`。「未解：」行本身不受限，但不得含可执行指令。
- **G-v6-3 ctx 断言需 raw 佐证**：凡句子把内容归于 ctx（「ctx 写 / ctx 的 / ctx 还 / ctx 里 / ctx 中」），其中的锚点（标识符、路径等）必须在 raw 中出现，否则违规 `ctx-only-claim`。局限：纯中文断言（如「目前是绿的」）无锚点，不在此检查；弱锚点（如 `trace`）可能触发，属于规则的敏感性，不做例外。
- 写稿协议：每份稿写完后，必须通过上述全部闸门才能保存为 `drafts/<id>.md`；稿子被使用之后不得修改。

## 2. 判定与主指标
- **主指标（取代 v5 的修好率为主指标）**：对每个分叉轮 r，比较手写臂与 raw 臂在第 r+1 轮的 reasoning 与 action。
  - 一致性判定：action 类别（bash / edit / read / other）相同，且首个命令的意图相同。
  - 同时记录第 r+1 轮 reasoning 中是否出现稿子里的非原生内容（用 G-v6-1 的命中结果核对）。
- 修好率作为次指标报告，不作为判定依据。
- 任何结论需报告 n 与配对不一致数；n 太小时报告「未区分」，不报告显著性。
