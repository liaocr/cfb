# 预注册 v2（修正案）：扩容 $10，计划 B + hand v2

本文件是 `PREREG.md`（v1）的修正案，v1 不改。开跑前冻结，哈希见 `PREREG-v2.sha256`。

## 1. 为什么修正
- 用户于 2026-10-11 将总花费上限从 $5 扩到 **$10**，并要求"全面推进"。
- v1 第 5 节的门槛"计划 A 实际花费 ≤ $2.0 才跑计划 B"，由用户的批准取代。
- 计划 A 的真实花费约 $2.1（按请求费核算，harness 估 $0.99）。v1 结果里 hand 臂对金标闸的不通过，原因是缺 C2/C3（见 RESULTS §3）。
- 本修正案的目的：(a) 完成计划 B（raw vs 生产 auto），回答"手写稿是否胜过生产压缩器"；(b) 按金标闸的标准重写手写稿（hand v2），检验 v1 的失败是不是由 C2/C3 缺失造成。

## 2. 花费
- 总上限 **$10**（用户批准）。截至本修正案，累计真实花费约 $2.1（计划 A）。
- 真实花费口径（以后统一用这个，不用 harness 估算）：每次请求 $0.02 + 输入 token × $1/M + 输出 token × $4/M（`.cfb-runtime/pricing.a6api.json`）。每次主调用约 $0.025，每次压缩调用约 $0.028。harness 估算低估约 2 倍。
- 计划 B（raw,policy:base；2 样本 × 5 家族；≤ 6 轮）：期望 ≈ $3.0，最坏（110 次主调用 + 60 次压缩）≈ $4.5。
- hand v2（raw,hand；同设计）：期望 ≈ $2.0，最坏 ≈ $2.8。
- 两者合计最坏 ≈ $9.4，加上已花的 $2.1 ≈ $11.5，超过 $10。因此执行时必须逐计划核对真实花费：
  - 计划 B 结束后，若累计真实花费 > $6.5，hand v2 **不开跑**，改为报告。
  - 任一时刻若累计真实花费 ≥ $9.0，立即停止发请求，并在报告中写明被截断的条目。
- 不做步骤 3（holdout 认证，约 $7）：超出 $10 的剩余额度，不在本修正案授权范围内。

## 3. 计划 B（修正：批准跑）
- 设计同 v1：5 家族 × 2 样本，raw 与 policy:base，≤ 6 轮。
- 计划 B 的结果只作为"生产压缩器对照"，不用于金标选择。

## 4. hand v2：写稿标准（写稿者必须遵守，写稿前读本节）
- 与 v1 相同：只看 raw 与 ctx；G1（反引号标识符必须在 raw 或 ctx 中出现）；G2（不改决定，三元组只能来自原文）；引文用「…」且必须逐字出现在本样本的 raw 或 ctx 中。
- **新增**（与金标闸 `three-mode.mjs goldCeiling` 一致）：
  - C1：draft/raw ≤ 闸门上限（见 `CEILING_RATIO_MAX`），即压缩力度要足够。
  - C2：稿中必须有一条闭合判读，形如「如果…就…」或「X ⇒ 说明/就是/即/意味着/不能/得换/要 Y」，且结论必须能从 raw 中的读数推出，不得凭空添加。
  - C3：在「验收 / 读数 / 看到」附近 400 字内，必须有一条反引号包着的可执行命令（node、npm、cat、grep、sed、ls、verify、analyze-trace 等之一），并说明"看到什么读数即算完"。读数必须来自 raw 中已有的工具回显或原文；命令不得是新的环境禁令。
- 写稿前，我（写稿者）已看过 v1 的结果（修好率、被拒项）。因此 hand v2 **不是盲的**，这是已披露的偏离。
- 旧稿（v1 drafts）保留在原处，不复用、不修改。新稿写入新的 drafts 目录。
