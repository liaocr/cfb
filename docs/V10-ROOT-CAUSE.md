# v10 全面归因：为什么 410 条 / 24 轮比 256 条 / 5 轮更差

> 内核 `liaocr/cfb-rwkv7-compressor` v10 · Kaggle T4 ×2 · 2026-10-10
> 全部数字来自真机产物（`report.json` / `learning-curve.json` / `dev-generations*.jsonl`）
> 与本地重算（`tools/gen-ruler.mjs` + `tools/g1-guard.mjs`）。没有一条是推演。

---

## 零、一句话

**根因是训练目标本身是"一次随机采样"，而不是"一个函数"。**

拿同一个输入问教师两次，尺子给出的分数相关系数只有 **r = 0.574**，
过门结论**翻转 24%**。目标既然只有 57% 可重现，用交叉熵去拟合它的学生
必然收敛到**条件均值** —— 而 440 token 稿子的"均值"是一篇 225 token 的模糊文本。
这不是调参问题，是**目标定义问题**。

---

## 一、先把"v10 全面劣于 v9"这件事本身拆开

| | v9 | v10 | 教师 |
|---|---|---|---|
| 训练行数 | 254 | 410 | — |
| 总优化步数 | **40** | **288** | — |
| 轮数 | 5 | 24 | — |
| 最终 train loss | ~1.04 | **0.0003** | — |
| dev loss | 未记录 | **2.84 → 3.59（升）** | — |
| 学生过门（73 条） | **45/73 = 61.6%** | 42/73 = 57.5% | 55/73 = 75.3% |
| 学生软分 | **0.5453** | 0.4874 | 0.7069 |
| S3 决策覆盖 | **0.606** | 0.387 | 0.866 |
| 稿长 p50（token） | 350 | **225** | 440 |

### 1.1 v10 是**跑坏了**，不是数据坏了 —— run 内对照

v10 在三个快照点采样，**数据一个字没变，只有步数在涨**：

| step | 轮 | 软分 | S3 决策覆盖 |
|---|---|---|---|
| 72 | 6.0 | 0.5328 | **0.648** |
| 144 | 12.0 | 0.5103 | 0.568 |
| 216 | 18.0 | 0.4996 | 0.516 |
| 288 | 24.0 | **0.4874** | **0.387** |

**单调下降。数据恒定。** 这一条就排除了"数据变差"的解释。

> 诚实标注：同一张表上的过门率是 63% → 42% → 54%，**不单调**。
> n=30 太吵，读不出趋势。连续量读得出，通过率读不出。

### 1.2 train loss 0.0003 是**背诵**，不是学习

困惑度 1.0003 —— 模型能逐 token 复现训练目标。
而 dev loss 同时从 2.84 单调升到 3.59。**训练降、验证升，是过拟合的定义式**，
不需要任何阈值判断。

## 二、根因：目标是采样，不是函数

### 2.1 直接测量：同一输入问两次

对 85 个**逐 id 相同**的单元，教师（temperature 0.2）各采两次样：

| 量 | 值 |
|---|---|
| 软分 A 均值 / B 均值 | 0.7135 / 0.7109 |
| **两次软分的相关系数 r** | **0.574** |
| \|Δ软分\| p50 / p90 | 0.046 / 0.144 |
| 过门：都过 / **翻转** / 都不过 | 55 / **20 (24%)** / 10 |
| 10-gram Jaccard（同输入两次） | **0.086** |
| 10-gram Jaccard（**不同**输入，基线） | **0.000** |

**基线是 0.000** —— 所以 0.086 是真实的"同一件事的两次不同说法"，
而 24% 的过门翻转率就是**标签噪声**：同一个输入问两次，有 1/4 的概率得到相反答案。

### 2.2 学生产出的就是那个"均值"

| 指标 | 教师 | v9 学生 | v10 学生 | 学生/教师 |
|---|---|---|---|---|
| 稿长 p50（token） | 440 | 350 | **225** | **0.51** |
| raw 锚点保留率 | **56.8%** | 35.8% | **31.2%** | **0.55** |
| 与教师稿 10-gram Jaccard | — | 0.038 | **0.031** | — |
| 与 raw 的 10-gram Jaccard | 0.0626 | 0.0327 | 0.0309 | 0.49 |

**学生的保真度是教师的一半，均匀地一半。**

### 2.3 最关键的一条：学生的分数**对输入复杂度是平的**

按输入里的锚点数分桶：

| 输入锚点数 | n | 学生软分 | 教师软分 |
|---|---|---|---|
| <15 | 6 | 0.499 | 0.674 |
| 15-25 | 29 | 0.507 | 0.706 |
| 25-35 | 25 | 0.498 | 0.739 |
| ≥35 | 13 | 0.382 | 0.662 |

**教师随输入变丰富而升到 0.739；学生是平的 0.50。**
一个在容易和困难输入上得分相同的模型，学到的是一个**近乎恒定的行为**，
不是"按输入做压缩"。这就是条件均值的指纹。

### 2.4 但学生的**行为结构完全正确** —— 所以不是设计错了

四条独立对照，学生与教师的**形状**全部一致，只有**水平**差一半：

| 对照 | 教师 | v10 学生 | 判读 |
|---|---|---|---|
| raw/ctx 锚点保留比 | 2.470 | 2.555 | 一致 → **不是在复述题面** |
| 位置保留曲线（前25% → 后25%） | −23.5 点 | −21.6 点 | 一致 → **不是 RNN 位置遗忘** |
| 跨输入套话率 p50 | 1.3% | 1.8% | 接近 → **不是在套模板** |
| 重复 8-gram 占比 p50 | 1.3% | 4.4% | 都低 → **不是复读退化** |

**结论：学生做的事情是对的，只是做得差。** 这是一个保真度缺口，
不是行为错误、不是格式错误、不是设计错误。

### 2.5 为什么"加数据"没用

254 行（v9）→ 410 行（v10@72）**没有带来任何提升**（0.5453 → 0.5328）。

在噪声目标上做 MLE，**更多的采样点不会降低条件熵** ——
学生照样收敛到同一个均值。这条解释了为什么"再补 1000 条"大概率也没用。

## 三、第二层：训练配方有 5 个**确定**的缺陷（都便宜）

这一层解释"v10 为什么比 v9 差"，但**不解释**"两者为什么都远低于教师"。

| # | 缺陷 | 证据 | 代价 |
|---|---|---|---|
| 1 | **测了 dev loss 却不选 checkpoint** | v10 在 72/144/216 三个点都算了 dev loss，然后**发了最差的最后一个**（3.59）。发 step 72 就是 0.5328 而不是 0.4874 | 免费 |
| 2 | **全程无 shuffle** | `train_rwkv7.py` 里 grep 不到任何 shuffle/random；`batch_rows` 按长度排序后，同样 12 个批次原样重复 24 遍 | 免费 |
| 3 | **`--gen-max-new 768` 在截断输出** | 学生 token max **恰好 768**：v9 10/89、v10 4/89 撞顶。而教师 p90 是 607、**max 750**；训练目标 **max 1927** | 免费 |
| 4 | **LR 日程与总步数耦合** | `lr_at` 用 `total_steps` 做余弦，于是 `--epochs` 同时改变"过几遍数据"和"日程多长"两个变量，任何对比都不干净 | 免费 |
| 5 | **eos 定义与上游矛盾** | tokenizer_config 说 `eos_token = "\n\n"`（id **65530**），generation_config 说 `eos_token_id = 0`。训练器用了 65530（自洽），但与底座先验冲突 | 免费 |

## 四、被**实测否掉**的假设（不要再往这些方向查）

| 假设 | 否证 |
|---|---|
| 学生复读/退化 | 重复 8-gram p50 **4.4%**（教师 1.3%），且随训练**下降** |
| RWKV 定长状态导致位置遗忘 | 位置曲线形状与教师一致（−21.6 vs −23.5 点） |
| 学生在复述题面而不是压缩思维链 | raw/ctx 比 **2.555 vs 教师 2.470**，几乎一样 |
| 学生在套一个模板 | 跨输入套话率 **1.8%** vs 教师 1.3% |
| 「落点原文未定」是塌缩产物 | 它在**教师训练集里占 55.6%**，是正规风格；学生只用 29.2%，比教师还少 |
| 数据量是瓶颈 | 254→410 **零变化** |
| 尺子坏了 | gen-ruler/5 已修两处缺陷；三个"尺子坏了"假设全部被实测否掉 |
| 本地几秒能跑一个模型 | 无 GPU；全部打分在本地纯 CPU 字符串处理完成 |

## 五、修法（按性价比排序）

### 1. best-of-k 教师稿 —— 最高性价比，**$8.86**

同一批 85 个单元，教师采两次，取尺子分高的那个当训练目标：

| | 软分 | 过门率 |
|---|---|---|
| 单次采样 | 0.7135 | 75.3% |
| **best-of-2** | **0.7487 (+0.035)** | **88.2% (+12.9 点)** |

**花 $8.86 把训练目标的过门率从 75% 抬到 88%+。**
这是唯一一条能**直接抬高学生天花板**的杠杆 —— 学生模仿的是目标，
目标质量 +12.9 点，学生的上限就 +12.9 点。

### 2. dev loss 选 checkpoint —— 免费

训练器**已经**在每个快照点算了 dev loss，只是发模型时把它扔了。
加一步"按 dev loss 挑最好的快照"即可。v10 立即从 0.4874 回到 0.5328。

### 3. `--gen-max-new 768 → 2048` —— 免费

教师 token max 750、训练目标 max 1927，而生成上限 768。窗口 6144 有大量余量。

### 4. 加 shuffle + 按 dev 早停 —— 免费

### 5. 数据 1461 → 4687

**优先级最低。** §2.5 已证明 254→410 零变化。在目标噪声没降下来之前，
加数据大概率买不到东西。**先做 1，再做 5。**

## 六、下一步：一个能分辨"均值 vs 容量"的实验

§2 的结论"学生收敛到条件均值"与"191M 容量不够"**在当前证据下不可分离** ——
两者都预测"输出更短、锚点更少、对复杂度不敏感"。

**分辨实验**：对同一批单元做 best-of-4 教师稿，重训一版。

- 若学生显著提升 → **根因是目标噪声**，继续买 best-of-k
- 若学生纹丝不动 → **根因是容量**，191M 到顶了，要换底座

成本：教师增量 $8.86（无 GPU） + 一次训练 ~60 分钟。
**这是唯一能把根因钉死的实验，而且它本身也是修法。**
