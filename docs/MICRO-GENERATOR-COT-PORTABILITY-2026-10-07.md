# Is chain-of-thought transferable across models and versions? — 2026-10-07

This answers the question raised about the six curated seeds and the 21,208-row DeepSeek auxiliary corpus: *given that the CFB target is DeepSeek-V4.1-Flash, does another model's — or an older version's — chain of thought still work?*

Short answer: **no, not as a substitute for the target model's own reasoning.** Measured on one pinned public corpus, with harness and task sources held fixed, changing only the model changes the thinking channel completely. Every number below was computed read-only from public artifacts; no model API was called and no license condition was accepted.

## 1. The 21,208-row DeepSeek corpus is real — and it is the predecessor model

Verified directly against the pinned parquet files (`nvidia/Open-SWE-Traces@f8fb5b3d2c787f85f8a00f5fe04fe3f1a11088ef`, config `v1.1`, split `openhands`, path prefix `data/openhands/deepseek_v4_flash/`):

- The pinned dataset card's release note states v1.1 added trajectories "generated by [DeepSeek-V4-Flash] and [Qwen3.6-27B] across OpenHands, SWE-agent, and mini-swe-agent harnesses"; the config listing shows `data/openhands/deepseek_v4_flash/*/*.parquet` alongside `data/openhands/qwen36_27b/*/*.parquet`.
- Row-level metadata over that path: `teacher_model.name = DeepSeek-V4-Flash`, `enable_thinking = true`, `reasoning_effort = "max"`, **21,208 rows**, 9 parquet shards, ≈ 2.52 GB.
- Every row carries `resolved = -1` (no success label). `sum(resolved)` returns `-21208`, i.e. there is not a single resolved/unresolved verdict in the subset.
- Reasoning is real and full-length: sampling 240 trajectories returned 10.6 M characters of `reasoning_content`, ≈ 44,268 characters (≈ 11–14 k tokens) per trajectory, ≈ 946 characters per assistant turn.

So "21k DeepSeek traces with full CoT" is confirmed — with the crucial qualifier that they were produced by **DeepSeek-V4-Flash**, the previous generation, not by DeepSeek-V4.1-Flash.

## 2. Measured: with harness and tasks fixed, CoT changes completely when the model or version changes

Protocol: pin the dataset revision; sample 80 consecutive rows from each of 12 evenly spaced shards per config (960 trajectories per cell); measure assistant turns and characters in the `reasoning_content` versus the visible `content` channel; measure marker frequencies inside each model's generated text. Each shard is read in its own process (multi-hundred-MB parquet shards exhaust a 2 GB sandbox otherwise). Two axes are held fixed in each comparison, so the differences cannot be explained by the harness or the issue distribution:

- **Same harness (mini-swe-agent), same task sources, same dataset family — different release:** Qwen3.6-27B emits essentially **no** reasoning channel, while Qwen3.8-27B in the identical harness emits **≈ 100 k characters of CoT per trajectory**. A one-release version change moved the thinking volume from zero to the largest in the whole corpus.
- **Same harness (OpenHands), same version (v1.1), different model:** DeepSeek-V4-Flash puts essentially all of its text into the reasoning channel (44 k chars, ~12 chars visible), while Qwen3.6-27B in the same config uses no reasoning channel at all and writes 8 k chars of visible content. They are not the same behaviour with different words — they are different output channels.

## 3. How different are V4 and V4.1 as models?

Documented, not inferred:

- **DeepSeek-V4.1-Flash was trained from scratch** on a 45 T-token multimodal corpus with a new **Causal Encoder-Decoder** architecture (20 encoder + 20 decoder layers), CSA2 attention, FP4 KV cache, a 196 B Engram memory and native vision — as opposed to V4-Flash, whose 0731 release kept the preview architecture and only re-ran post-training. Sources: the [V4.1-Flash model card](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash) and [technical report](https://arxiv.org/html/2609.19969v1).
- **Post-training differs in data, not algorithm:** V4.1 uses the same SFT → RL → on-policy-distillation skeleton but "all substantive changes lie instead in the data pipeline: large-scale automated synthesis of agent tasks and environments with progressive scaling of data, tasks, and rollouts". CoT behaviour is exactly what such agentic data pipelines reshape.
- **The reasoning control changed shape:** V4 exposes three prompt-level modes (Non-think / Think High / Think Max, where Max prepends a special system prompt), and the community found the effort levels are implemented as template prompts (`encoding_dsv4.py`). V4.1 replaces them with a **continuous integer `reasoning_effort` 1–100**, and the report notes that effort control "learned on single-response reasoning transfers faithfully to long-horizon agentic trajectories".
- **Behaviour moved a lot on agentic benchmarks:** DeepSWE v1.1 54.4 → 74.2, Terminal-Bench 2.1 82.7 → 90.6, Codeforces 3289 → 3471 (self-reported, same card family); HLE moved slightly down (37.8 → 36.8).
- **Third-party observations are mixed but consistent with a changed thinking style:** Artificial Analysis measures V4.1-Flash (max) at ≈ 250 M output tokens on its index ("very verbose", median 140 M), and practitioners report both "more concise thinking than V4" and "it overthinks as much as V4" — with the added wrinkle that legacy effort names now map to maximum effort.

Observable trace-level comparison, with the caveat that the harnesses and task sets differ:

| Quantity | DeepSeek-V4-Flash (OpenHands, this corpus) | DeepSeek-V4.1-Flash (TianxiCode run, SWE-bench-Live lite) |
|---|---|---|
| Reasoning words/tokens per instance | ≈ 44.3 k characters (≈ 11–14 k tokens) | **4,903 reasoning tokens** |
| Assistant turns / steps | 46.8 assistant turns | 29.2 steps |
| Tool calls per instance | not measured in the same unit | 48.5 |
| Resolved | unlabelled (`resolved=-1`) | 204 / 300 |

The V4.1 archive cannot settle the question textually: its `reasoning` events carry `"text": ""` plus `reasoningEncryptedContent`, so only the token accounting above is observable. Taken together: the two generations differ in model, training data, effort control, and measured deliberation volume — the CoT is **not** interchangeable in any strong sense.

## 4. What this implies for CFB

1. **A reasoning trace is model-specific supervision.** Teacher-specific style signatures are documented in the distillation literature, and mismatch between teacher and student weakens transfer. With CFB's target being a specific model, another model's CoT is off-distribution supervision for that model's own thinking channel.
2. **Therefore the six Open-SWE seeds and the V4-Flash corpus cannot stand in for V4.1-Flash reasoning.** Their `finalSplit=null` / `trainingEligible=false` status is the correct disposition, and it stays that way until target-model traces exist.
3. **What *is* portable is the task-side structure**, not the CoT: repository state, tool commands and their outputs, failing/passing test evidence, and the notion of "what is done / what failed / what is next". That is model-agnostic input material, and it is precisely what CFB's `raw + ctx` side encodes. A draft format defined as *evidence-grounded progress state* (facts + next action + confidence, with omissions flagged) is learnable from any model's traces; a draft that must *imitate V4.1-Flash's phrasing or deliberation* is not.
4. **Options, in order of evidential strength for the target-model question:**
   - **A. Generate target traces**: run DeepSeek-V4.1-Flash (MIT weights, API `deepseek-flash`) on non-benchmark repositories under a fixed harness with `reasoning_effort` pinned, then build `raw + ctx -> draft` samples. Requires user-provided API or endpoint access; nothing in this workspace can call a model API.
   - **B. Model-agnostic framing**: keep target-model trace data out of training, use other-model traces only as raw material with explicit `off-target` labelling, and state in the card that target-model transfer is untested.
   - **C. Predecessor auxiliary + transfer test**: use the 21,208 V4-Flash rows for annotation-pipeline work and run a migration check (train on V4-Flash-derived drafts, evaluate on held-out V4.1 traces) — but the second half still requires A.

## 5. Limits of this analysis

- Sampling, not exhaustive counts: 960 trajectories per cell from 12 evenly spaced shards; totals are sample-derived. The full V4-Flash subset count (21,208) *is* exact, from a metadata aggregate over its 9 shards.
- Character counts are a proxy for deliberation; tokenisation differs per model, so cross-model comparisons are order-of-magnitude statements, not exact equivalences.
- The v1.1/openhands split mixes DeepSeek and Qwen rows; they are separated here by `metadata.teacher_model.name`.
- The v1.1/v1.2 DeepSeek and Qwen subsets carry `resolved = -1`, so no success-conditioned comparison is possible.
- Third-party Reddit/AA observations are user-reported impressions, not controlled measurements, and are labelled as such.
- Everything here is AI single-reviewer analysis (`arena-agent-mode`), no human or independent second review; no model was queried; no repository was cloned.
