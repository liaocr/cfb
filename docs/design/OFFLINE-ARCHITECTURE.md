# 离线层架构（v13.8，2026-10-02）

> 目标（用户指令）：**把离线层做成一台「接上 API 就能高速开练」的机器。**
> 判据：离线能做的全部离线；只有「候选是否真的更好」才需要通道；通道一好，按一下按钮就能开跑。

## 1. 为什么重做

改造前，离线层是一个**互不相连的工具箱**：`effect-mr`（判据）、`effect-eval`（通道）、
`draft-lint`、`analyze-trace`、`cf-eval` 各自为政，没有共享的语料、没有判据回归、
没有候选搜索、没有成本模型。后果是**每一轮迭代都要从零开始，且要花真钱才知道对不对**。

对照理论（`docs/theory/CFB-THEORY-COMPLETE.md`）暴露的三个具体缺口：

| 理论要求 | 改造前 | 改造后 |
|---|---|---|
| 卷五 S10.5 七个效果指标 | 只有 2 个（falseDone / repeat 类） | 6 个离线可判 + 4 个显式标注「需评委」 |
| 卷四 A2 v(i) 的代理量 | 未验证、未实现 | 离线打分器（`scoreDraft`，权重可逐项归因） |
| 卷六 H4 宿主能力等级 | 未问、未实现 | 如实记录为缺口（见 §6） |

以及一个更根本的：**判据本身从未被当作可优化的组件**。`claimOf` 系列是手写正则，
v13.5 才发现 5 例伪阳性——**判据错了，后面所有实验都在优化错误目标**。

## 2. 新的分层

```
                   ┌──────────────── 离线（零 API，永远可跑）────────────────┐
生产 trace ──┐     │                                                        │
历史实跑   ──┼──►  cfb-corpus ──► corpus.json ──┬──► cfb-criteria（判据回归）│
              │     （语料编译）                 ├──► cfb-lab（候选/打分/出价）│
              │                                 ├──► cfb-labels（人工标注/功效）│
              │                                 └──► cfb-train（门禁与规划）   │
              └────────────────────────────────────────────────────────────┘
                                        │ 四门全绿
                                        ▼
                        effect-ready run --live（唯一花钱的一步）
```

内核是 `tools/helpers/offline-core.mjs`：trace 解析 → 轨迹重建 → 漏斗 → 判据内核 →
静态打分 → 秩相关 → 编辑距离 → 确定性 PRNG。**全部确定性、无网络。**

## 3. 四个新工具

### `tools/cfb-corpus.mjs` —— 语料编译
把「生产 trace + 历史实跑记录」编译成自包含语料（含**全文与 ctx**，下游不必回头读 `transfer/`）。
产出 `.cfb-offline/{corpus.json,split.json,report.md}`；切分按任务 60/20/20，**题不跨集**（防偷看）。

**它第一次给出了生产的真实漏斗**（本机 18.4 MB trace / 13426 事件 / 200 块）：

| 块 | 值 |
|---|---|
| 起火 | 200 |
| 蒸馏成功 | 130 |
| 蒸馏失败 | 70 |
| 完成态拼接 | 76 |
| 直通 | 118 |
| **达成率** | **38.0%** |
| **平均压缩比** | **31.3%** |

这组数字此前从未有过。它说明：压缩器在真实生产里**只有 38% 的块真正接上**，
而接上的那些压到了 31.3%。

### `tools/cfb-criteria.mjs` —— 判据工作台
内建黄金集（n=20：v7 报告 §3 的 5 例伪阳性逐字 + 真阳性/真阴性 + 5 条新边界），
对 4 个判据版本报 P/R/F1，并检查**内核与运行时判据是否漂移**。

**首次运行就抓出 2 个此前未知的真伪阳性**：
- 「修复**没有**落地」——修复词后的后置否定，`NEG_RE` 够不到（它只往前看且要求否定词收尾）；
- 「**已修复的**路径有两条」——修复词当定语，描述名词而非宣称问题解决。

两条守卫已落地到 `effect-mr.mjs` 与内核：

| 判据 | 通过 | 精确率 | 召回率 | F1 |
|---|---|---|---|---|
| `claimOf` | 10/20 | 33.3% | 100% | 50.0% |
| `claimOfV2` | 12/20 | 38.5% | 100% | 55.6% |
| **`claimOfV3`（改造后）** | **17/20** | **100%** | **100%** | **100%** |

伪阳性 **8 → 0**，伪阴性保持 0。剩余 3 条是 `none↔hedged` 边界（均非 `fixed`），
对 `falseDone` 无影响；门禁只要求**精确率与召回率都 100% 且内核不漂移**，逐字差异照常打印。

同时**诚实列出七个理论指标的覆盖缺口**：`falseDone`/`overHedge`/`repeat`/`bump`/`reEdit`/`greenAsProof` 离线可判；
`contradiction`/`oscillation`/`wrongEdit`/`correct` **需要评委**，不假装可判。

### `tools/cfb-lab.mjs` —— 实验设计器
候选不是「改提示词」，而是**改渲染器的决策表**（依据卷五 S1：副模型只输出结构化标注，
取舍/顺序/措辞/人称/否定形式全部由代码决定）。7 个旋钮，共 3×3×3×2×2×3×2 = **648 种组合**：

| 旋钮 | 取值 | 理论依据 |
|---|---|---|
| `order` | state-first / conclusion-first / exclusion-first | 卷一 T1、卷三原则7（价值靠尾） |
| `length` | tight / normal / roomy | 卷一 T2（长度是输出不是输入） |
| `exclusionForm` | paired / list / none | 卷五 P2（替代先行） |
| `person` | first / neutral | 卷五 D4（第一人称双刃剑） |
| `freshness` | on / off | S10.14 K1 |
| `kItems` | all / core / off | S10.14 六条 |
| `notation` | prose / symbol | 卷三原则6（双编码） |

候选枚举**确定性可复现**（同 seed 同候选组）；`scoreDraft` 的分数**等于各权重项之和**，
可逐项归因（`gate` +40 / `invention` −50 / `kCore` ×8 / `shortness` ≤10 …）。
`quote` 子命令按 profile 价表算出「验 top-k」的预留上限。

### `tools/cfb-labels.mjs` —— 人工标注 + 功效分析
从语料抽待标注句（按代理判据分层，**代理说 fixed 的最优先复核**，因为伪阳性成本最高），
校验人工标注文件，并把「n 太小」从感觉变成数：

| n | 可分辨绝对差 |
|---|---|
| 20 | 43.8 个百分点 |
| 40 | 31.0 |
| 80 | 21.9 |
| 160 | 15.5 |

**这就是「n=2 判不了任何事」的定量版本**：想分辨 10 个百分点需要 n≈384。

### `tools/cfb-train.mjs` —— 统一驱动
一条命令跑完离线全流程，每阶段有**门禁**，不绿就停：

```
node tools/cfb-train.mjs          # 全流程 + plan.json / plan.md
node tools/cfb-train.mjs --check  # 只跑门禁，0/1 退出码（可进 CI）
```

当前状态：**四门全绿** —— 通道一好即可进入阶段 4。

## 4. 修复的真实缺陷

**`offline-core.mjs` 的 trace 解析器把损坏静默吞掉。** 原正则是
`/^\[时间\] \[tag\] (\{.*\})$/ `——JSON 体写进了同一条模式，于是
「锚定前缀正确但 JSON 体坏掉」的行**匹配失败**，被记成 `ignored` 而不是 `malformed`。
在生产 trace 上这意味着**真实的损坏会被无声忽略**。已改为两段式（先认锚定前缀，再单独解析 JSON 体），
并增加「解析结果必须是对象」的检查。

## 6. 这份改造**没有**解决什么（诚实清单）

1. **`contradiction`/`oscillation`/`wrongEdit`/`correct` 四个指标仍需评委**，离线只能给规则代理。
2. **`greenAsProof` 的规则代理从未与评委对齐过**——它有实现、有测试，但**没有效度证据**。
3. **`scoreDraft` 的权重是人工设定**，未经数据拟合；它的排序有效性尚未在真实结果上验证
   （结构已就位：`rankCandidates` 会给出与真实值的秩相关，但目前没有足够的带标签样本）。
4. **黄金集只有 20 条**，分辨力约 44 个百分点；`cfb-labels` 能扩，但需要人工裁决。
5. **卷四 D 的 1 号未解问题（v(i) 代理量在 agent 轨迹上的误差）依然未解**——
   本次只是把「可计算」这件事从零变成有，**不是**证明了那组代理量与反事实重要性相关。
6. **卷六 H 协议（宿主能力等级 C0–C3）仍未实现**，我们依然不知道 DSH 宿主是 C0 还是 C1。
7. 生产漏斗的 38% 达成率**尚未归因**：是通道慢、窗口短，还是稿本身的问题，未知。
