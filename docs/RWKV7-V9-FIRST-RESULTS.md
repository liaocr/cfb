# RWKV7 压缩微模型 · v9 第一轮真训结果

> 内核 `liaocr/cfb-rwkv7-compressor` v9 · Kaggle T4 ×2 · 2026-10-10
> 训练 40 步 / 30.1 分钟（含生成）· 评测用 `tools/eval-sft.mjs` · 尺子 `gen-ruler/3`
> 全部数字来自真机产物：`dev-generations.jsonl`（89 条）+ `report.json`

## 一、主结果

| | 教师 DeepSeek-V4-Flash | 学生 RWKV7-0.1B |
|---|---|---|
| 硬门通过（89 条） | **31 / 89 = 34.8%** | **20 / 89 = 22.5%** |
| 有受力子集（73 条） | **31 / 73 = 42.5%** | **20 / 73 = 27.4%** |
| 软分均值 | **0.6957** | **0.5638** |
| 软分 p50 | 0.6984 | 0.5723 |
| 真 token 数 p50 | 440 | **350** |
| 压缩比 p50（token 比） | 0.5009 | **0.3537** |
| 字数 p50 | 905 | 697 |

配对四格：**都过 10 · 只学生过 10 · 只教师过 21 · 都不过 48**
软分逐条：**学生赢 14 · 输 75 · 平 0**

### 这个差算不算"真的差"

两个数要分开看，别拿一个没有显著性的数当结论：

| 判据 | 统计量 | p | 读法 |
|---|---|---|---|
| 硬门（McNemar，10 vs 21 不一致对） | χ²=3.226 | **0.0725** | **没到 0.05**，只能说"倾向于更差" |
| 软分（符号检验，14 赢 vs 75 输） | z=−6.47 | **1.0e−10** | **决定性的** |

硬门是阶跃的、89 条样本又小，单看它会误判；软分连续、用满 89 条，**这一轮的结论依据是软分**。

### 它是真在生成，不是照抄

**89 条里学生稿与教师稿逐字相同的有 0 条。** dev 是按仓库切的（FNV-1a），不存在同仓库泄漏 —— 所以逐字相同只可能来自"学会了照抄"，而 0 条说明它确实在生成。

## 二、学生的失败画像：用**保真**换**更短**

失败分布（一条稿可同时踩几个闸）：

| 闸 | 学生 | 教师 | 变化 |
|---|---|---|---|
| **G1 quote-grounded** | **39** | 9 | **+30 ← 头号病灶** |
| G7 compressed | 20 | 38 | −18（学生压得更狠，这条它赢） |
| G3 anchors-kept | 16 | 7 | +9 |
| G4 actionable | 14 | 4 | +10 |
| G0 no-leverage | 16 | 16 | 持平（与稿子无关） |
| G6 not-copy | 1 | 1 | 持平 |

一句话：**学生把 token 比从 0.501 压到 0.354，代价是引文不再落在原文上。** 教师过 G1 而学生挂 G1 的有 **36 条**，这是全部差距的主来源。

## 三、三条具体的病（都有实例）

### 1. 语言翻转 —— 52%（46/89）的稿子语言跟教师不一致

提示词写的是【语言】用【原文】本来的语言写。教师稿以中文为主的有 67/89，学生只有 43/89。

实例 `adamtheturtle_sybil-extras_pr297#b11`（教师全过，学生挂 G1+G3）：

> **教师**：ShellCommandEvaluator 的 `_run_command` 里用了 `sys.stdout.buffer`/`sys.stderr.buffer`，但 capsys 和 click.testing.CliRunner 会把 `sys.stdout` 换成 `StringIO`……
>
> **学生**：The `ShellCommandEvaluator` fixture in `src/sybil_extras/evaluators/shell_evaluator.py` exports `result` from `sys.stdout`/`sys.stderr`……

换了语言就没法逐字引用原文 —— **这很可能就是 G1 涨 30 的直接原因之一。**

### 2. 退化 / 复读 —— 77/89 条出现明显重复片段

重复片段峰值 p50：教师 4.0 · 学生 5.0（≥3 视为明显复读）。

更要命的是**学生"赢"的那 10 条里，有几条是靠说得更少更虚赢的**：

> `bastibe_python-soundfile_pr58#b21`（学生过、教师只挂 G7）
> 学生稿：info 的返回实现是 FileObject._name **再对象**，所以用它来存字典名就够……

"再对象"不成句。这是**负向约束型尺子的老毛病**：G1–G7 全是否定式（不许编、不许抄、不许超长），没有一条要求稿子**必须说清什么**，于是含糊、短、不落把柄的文字反而容易过门。G0 补了"必须存在承重锚点"，但补不到"必须说清"。

### 3. 模式混淆 —— 该压缩的时候在写计划

最惨的一条 `fox-it_dissect.util_pr70#b15`（学生软分 0.350 vs 教师 0.928）：

> **教师**（695 字）：仓库状态干净，27b44fe HEAD。题面说测试文件已由用户处理，所以只动非测试源文件与 pyproject.toml。计划落点：pyproject.toml 的 ruff select 加 N、S……
>
> **学生**（96 字）：We need to clean up the repo as described, re-read the issue, and confirm the test file changes.

学生写的是**任务的复述**，不是**思维过程的压缩**。它学到了 system 提示词的口吻和格式，没学到"把这一段推理压成结论"这件事本身。

## 四、这轮到底证明了什么

**证明了的：**
1. 端到端链路真的通了 —— 数据 → 双卡 DDP 训练 → 存档 → 生成 → 本地配对评测，全自动，一条命令。
2. 191M 的底座**能学**：0/89 照抄、token 比自主压到 0.354（比教师还狠）、14 条软分赢过教师、10 条硬门教师没过它过了。
3. 30.1 分钟一轮，**迭代成本可接受**。

**没证明的：**
1. 它现在**不如教师**（软分 0.5638 vs 0.6957）。这是一个**起点基线**，不是能交的东西。
2. 40 步 / 256 条**远远不够**。train loss 到 1.0 就停了，这个量级还远没到收敛。

## 五、下一步的杠杆

> ⚠ **本节初版把「加数据」排在第 1 位，那是错的。** 下面是查过数据之后重排的。

### 5.1 先想清楚天花板在哪

训练目标 = 教师稿，评测 = 尺子，而**教师自己的 dev 成绩是 31/89 = 34.8%**。
所以"一个完美模仿教师的学生"大约就是这个位置 —— 加数据是**逼近**它，不是突破它。

一个必须说清的反向可能：训练集是**过滤过的**（只留过尺子的教师稿），
学生学的分布比教师在 dev 上的实际表现更干净，**理论上可以超过 34.8%**。
所以 34.8% 是参照点，不是硬顶。但它是最现实的近期目标。

**如果 34.8% 这个水平本身不可接受，那问题不在学生身上，在教师和尺子上。**

### 5.2 现在还不能判断是「缺数据」还是「缺步数」

- 40 步、loss 停在 1.0，太早。
- **train loss 1.0 vs dev loss 2.35 这个差不能用来判过拟合** —— 训练集是过滤过的、
  dev 没过，两个分布本来就不同，这个差值里混着"dev 的目标本来就难"。
- 学生的 G1 挂率：中文稿 33% / 英文稿 54%；教师 7% / 18%。**两种语言都是教师的 2~4 倍**，
  且失败长这样：`flake9`（= flake8）、`py476`、`init__`（= `__init__.py`）。
  这是**退化**，不是"没见过这个例子"。

**最便宜的判别实验：同样的数据，把步数从 40 提到 150~200（epochs 5 → 20）。**
30 分钟一轮。能收敛 → 是欠训练；还是不行 → 才轮到数据。

### 5.3 数据里有个自相矛盾，这个比"数量"重要

| | |
|---|---|
| 提示词第 3 行 | 「用【原文】本来的语言写，不要在语言之间翻译」 |
| 原文 raw / ctx | **100% 英文**（train 256/256、dev 89/89） |
| 教师稿 | **76% 中文**（train 194/256、dev 67/89） |

**76% 的训练目标违反提示词自己那条语言规则。** 学生被同时要求服从两个互斥的东西，
只学了一半（与教师的语言一致率 48%）。**这跟数量无关 —— 再加 6 倍，是同一个矛盾放大 6 倍。**

### 5.4 排序

| # | 杠杆 | 依据 | 成本 |
|---|---|---|---|
| 1 | **加步数**：epochs 5 → 20 | 40 步 loss 还在 1.0；先分清欠训练还是缺数据 | 30 分钟 |
| 2 | **定语言口径**，按口径重产教师稿 | 76% 的目标与提示词冲突 | 一个决定 + 可能的 $2.9 |
| 3 | **加数据**：256 → 722+ | 逼近 34.8% 那个参照点 | 教师稿已有 722 |
| 4 | **批处理生成** | 现在 29.8 token/s、一条一批 | 让每轮迭代变快 |
| 5 | 缓存判定加"更慢就关" | 自检报开缓存 0.2× | 顺手 |

### 5.5 一个更正：中文稿**不是**教师 G7 挂掉的原因

初版我按 RWKV 分词器算出"中文稿 token 比 0.645 vs 英文 0.522"，据此说中文稿拖垮了 G7。
**查了尺子自己的判据后不成立**：尺子口径下中文稿 G7 过 38/67 = 57%、英文稿 13/22 = 59%，
几乎一样。原因是尺子的 `estimateTokens` 用的是 **DeepSeek 系数**，不是 RWKV 分词器。

语言那件事确实值钱，但它走的是**引用保真（G1/G3）**那条路，不是 G7。

## 六、两个实测更正

1. **生成吞吐实测 29.8 token/s**（34687 token / 1164 s），不是我上一轮按 64-token 自检外推的 2.1 token/s —— **差 14 倍**。那个自检含 Triton JIT 冷启动，不能用来外推吞吐。以后只认真机全程读数。
2. **存档修复生效**：`_tied_weights_keys 归一 1 个模块 · lm_head 与输入嵌入共享存储=False` → `存档校验 399 块 · max|Δ|=0.00e+00` → 权重 764 MB 完整落盘。v8 丢的那一轮，这次保住了。
