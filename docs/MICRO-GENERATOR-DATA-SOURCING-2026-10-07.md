# Micro-generator data sourcing and admission decision — 2026-10-07

## Scope

Target remains `raw + ctx -> draft`: a short, evidence-grounded progress draft from coding-agent/user/tool history. No training or inference API was called. Public-data checks below were read-only. No external source is treated as CFB-specific gold merely because it has summaries or trajectories.

## QMSum screening

- **Source:** Yale-LILY/QMSum, data files fetched at commit `b675bb3f00e4703ad83b663ed2679b3bf4574330`, only `Academic`, `Committee`, and `Product` `train`/`val` JSONL. The downloaded copy was in `/tmp/qmsum/domains/` and was used only for screening; it was not imported into the workspace corpus.
- **Screening counts:** 197 meetings total (162 train, 35 validation) and 1,332 `specific_query_list` queries (1,095 train, 237 validation). Counts by domain: Academic 41/9 meetings and 218/45 queries; Committee 24/6 and 284/67; Product 97/20 and 593/125. These are QMSum counts, not CFB data.
- **Span handling:** the repository's `data_process.ipynb` extracts each relevant span with `range(start, end + 1)`, so the start and end turn indices are inclusive. The examples were inspected as query plus the cited transcript turns; no QMSum test rows were used in screening.
- **Admission decision:** **not admitted**. QMSum is a query-based multi-domain meeting summarization benchmark, not coding-agent progress-state compression. In sampled candidates, the answer/span support is not consistently safe to accept without claim-level review. Example: Committee validation meeting 1, query 4 asks about Morneau and debt; the provided relevant crop says the government remains committed to supporting Canadians, while the answer additionally asserts a strong pre-pandemic fiscal position and support for small businesses. Those additional claims are not present in that supplied crop. This makes QMSum a possible auxiliary research source only after a separate full audit; it is not an appropriate certified CFB train set now.
- **License status:** the public repository is listed as MIT-licensed by the repository search result, but a direct request for `LICENSE` at the pinned data commit returned HTTP 404. Therefore the license for the exact pinned snapshot was not resolved here; no QMSum data was redistributed or used for training.
- A previously downloaded `main` test file had a label inspected in an earlier session; that material is not blind gold and is excluded from this project’s confirmatory evaluation.

## Evidence-annotated QMSum variant

- **Source:** `etri/QMSum_SummaryEvidence`, pinned to commit `5847d36a12a8b48a69ac7cae4c5c34358cc0e1d3`. Its README says the set manually annotates supporting evidence for each summary sentence with central/peripheral evidence labels; files are organized into train/val/test. The pinned `LICENSE` was fetched and is MIT (SHA-256 `c96997c040d5d3b192f70935cb0c8697b2bbb908c17e070448be7a024c634ccd`). The repository's source description is not a substitute for our own CFB validation.
- **Sample review:** train `Bdb001.json` has a five-sentence XML-format summary with five aligned evidence groups; train `Bmr003.json` has three aligned sentences/groups. In val `Bmr005.json`, query 0 says the group agreed that speaker mn005 would mark overlap regions only, while its first cited evidence talks about fan/impulsive noise; this is not a safe gold sentence without additional evidence. That sample was rejected.
- **Admission decision:** **not admitted to the CFB corpus.** This is a better-grounded auxiliary summarization candidate than vanilla QMSum, but its JSON stores the annotated evidence snippets and summary targets, not the full transcript (`ami`/`icsi` fields are null in the checked sample). Using those target-conditioned snippets as `raw` would train compression from preselected evidence, not retrieval/compression from full raw history. Rejoining the original QMSum transcript would reintroduce the unresolved pinned-snapshot license and span-alignment issues described above. No data from this repository was copied into the workspace corpus or used for training.

## Coding-agent dataset candidates

- **nebius/SWE-agent-trajectories:** the Hugging Face card describes 80,036 coding-agent trajectories and a CC BY 4.0 dataset license, while also requiring respect for each underlying repository’s license. It has issue-solving traces, final patches, and evaluation logs, but not ready-made `raw + ctx -> draft` progress summaries. Target creation would itself be AI-authored and need full fact review; no rows were downloaded or admitted.
- **SALT-NLP/SWE-chat:** the dataset describes real coding-agent sessions, but accessing files requires agreeing to share contact information. No account/condition was accepted; no data were accessed or used.
- DialogSum and Tweetsumm were not adopted: the former is generic daily dialogue and the latter’s task fit/licensing were not verified to the standard needed for this corpus.

The `cx-cmu/agent_trajectories` release was also found: its card describes complete interaction traces across six benchmarks, including SWE-bench, but no reference progress summaries were found, and its usage license was not established in this screening. It is therefore not admitted.

Other earlier search-only leads remain unadmitted: the ASE 2025 RepairAgent/AutoCodeRover/OpenHands release (120 trajectories) and the CLI trajectory-analysis corpus (1,794 trajectories) are raw/annotated action traces, not ready-made `raw + ctx -> progress summary` targets; for the latter, underlying-source licensing was not audited. SWE-Intervene is action-level decision/feedback annotation rather than progress-summary supervision. Together/CoderForge and other long-horizon coding-agent corpora likewise were not shown to include this target format in the initial search. These search snippets are discovery leads only, not verified admissions.

## What is usable now

The local source queue contains 17 original raw/context/reference records across three **already-known development families**, representing 16 unique raw+ctx inputs. The original targets remain excluded. A new output contains one conservative AI-authored/AI-single-reviewed rewrite per unique input; see `transfer/models/micro-generator-ai-reviewed-dev-candidates.jsonl` and the 17-row disposition file. All 16 are explicitly `finalSplit=dev`, `sourceCoverage=partial`, and `trainingEligible=false`; they are not certified gold or training examples. The identical-input `perf-regression` conflict maps both original drafts to one proposed rewrite without selecting either old target. The exporter was checked to retain 0 train / 0 dev rows and mark all 16 candidates excluded.

Six additional Open-SWE rows were source-pinned and curated into `transfer/models/micro-generator-open-swe-seed/`. All six are Qwen3.8-27B/mini-swe-agent trajectories, not DeepSeek-V4.1-Flash traces. The AI-single-reviewed drafts are retained only as exploratory annotation examples; every `finalSplit` is null, all `trainingEligible` flags are false, and no target-model transfer has been shown. The bounded benchmark-overlap screen is recorded in the seed audit; it does not cure the model-distribution mismatch.

**Current decision:** no DeepSeek-V4.1-Flash-compatible, full-source-coverage, fully fact-reviewed training set is certified. Keep QMSum and the evidence-only QMSum variant out of the CFB corpus; do not fine-tune until traces from the designated target model and intended harness are sourced, fully annotated under the explicit AI single-reviewer policy, split by family, and tested on a held-out target-model set. The AutoCompact release remains a future lead but is not currently available under published dataset terms.
