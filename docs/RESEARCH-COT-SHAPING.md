# 可改写思维链下，如何让主模型表现更好 —— 调研与方案（2026-09-25）

> 性质：**调研 + 设计提案，无代码改动**。只讨论「提升主模型的任务表现」（更专注、更有底气、想得更全、少走错路），
> 不讨论省 token（那部分见 [`ECONOMICS-V11.11.md`](ECONOMICS-V11.11.md)）。
> 标注约定：**【实证】** = 论文或官方文档里有数据；**【推断】** = 由实证推出、本仓库尚未验证；**【假设】** = 需要 A/B 才能确认。
> 参考文献编号 `[n]` 见文末 §9。

---

## 0. 摘要（结论先行）

1. **杠杆是真的，而且很大。** DeepSeek 在带 `tools` 的请求里，会把**之前所有轮次**的 `reasoning_content` 拼进上下文 [1]。
   跨调用时模型没有别的隐藏状态，所以**它看到的历史思维链，就是它全部的「工作记忆」**。
   MiniMax 的消融实验显示：光是「保留还是丢掉历史思维链」，Tau² 就差 **87 vs 64**，SWE-bench Verified 差 **69.4 vs 67.2** [2]。
   cfb 能决定这段记忆**写进去的内容**，这个杠杆和「保留 vs 丢弃」同一个量级。
2. **要换个定位：cfb 不只是压缩器，而是主模型的「记忆写入控制器」。** 值得优化的不只是长度，
   还有四件事：写什么、用谁的口吻、标什么**认知状态**、放在什么位置。
3. **上一轮否决路线 B 的理由（ReasonIF：模型在思考里不守指令）在这里不适用。** 我们**不需要模型配合**，
   文字是副模型或确定性代码替它写好的。Thinking Intervention 证明：把文字直接写进思考过程，
   比写进提示词有效得多（R1 系列 IFEval 最多 +6.7%，指令层级 +15.4%），
   原因是「推理阶段的注意力主要看自己的思考，很少回看外部输入」[3]。
4. **核心设计原则：双声道。**
   - **第一人称**（写进 reasoning 块）：模型会把它当成自己的判断，并且**更坚持**。
     看得见自己先前答案时，改主意的比例从 32.5% 降到 13.1% [4]。适合放**有证据的事实、计划、约束**。
   - **外部声音**（pre-step 追加的 user 消息）：模型对反对意见反而**过度敏感**，权重约为贝叶斯理想值的 2.58 倍 [4]，
     对外部来源的错误也更容易纠正 [5]。适合放**有证据的纠错与质疑**，
     但必须带证据，否则就成了「煤气灯」：推理模型在被自信地否定时，准确率会掉 25–29% [6]。
5. **最有突破性、成本也最低的一组是「认知卫生」三件套**（§4 的 S1–S3）：
   给每条结论标**认知状态**（已证实 / 假设 / 已证伪）；按**句子功能**保留「思维锚点」；
   把**勘误**附在下一块出生时一起写。三者都能装进现有的 birth 管线，不违反 H2 不变律。
6. **最大的风险是「示范效应」。** 历史思维链同时也是**「我平时怎么思考」的 few-shot 示范**。
   如果历史全是干瘪的摘要，模型可能照着学、自己也想得更浅，
   ThoughtMani 就观察到模型会直接跳过自己的思考 [7]。**每个方案都必须监测新生成思维链的长度与质量。**
7. **先要能测，再上线任何东西。** §6 给出一个不依赖真实会话重放的评估方法：
   **反事实续写重采样**，方法参照 Thought Anchors [8] 和 Sinha 等 [9]。

## 1. 前提与约束（逐条核对过）

### 1.1 杠杆存在的证据
| 事实 | 来源 | 对 cfb 的含义 |
|---|---|---|
| 带 tools 的请求里，历史 `reasoning_content` **全部回传，并拼进上下文**；不带 tools 时会被忽略 | DeepSeek 官方文档 [1] | cfb 改写的块，**下一步主模型真的会读到**。不带 tools 的纯聊天场景里，这个杠杆为零 |
| 保留历史思维链，而不是在每轮开头剥掉：Tau² 87 vs 64，SWE-bench Verified 69.4 vs 67.2 | MiniMax [2] | 历史思维链的**内容**对 agent 表现影响很大，正反两个方向都是 |
| 模型会带着「计划、假设、约束、中间结论」往后走；这些一丢，就会出现状态漂移、自我纠错变弱 | MiniMax [2] | 这恰好说明**该保留什么**：计划、假设、约束、中间结论 |

> ⚠ 前置核查（沿用 `AUDIT-V11.5.md` 提出的问题）：在真实 trace 里确认历史 assistant 消息的
> `llm-stream.reasoningChars > 0`。如果宿主或 provider 在新 user 轮开始时就剥掉旧的 reasoning（MiniMax 的聊天模板就是这样做的 [2]），
> 那杠杆只在**同一 user 轮内的工具循环**里存在，§4 各方案的收益上限也要随之下调。

### 1.2 不能碰的约束（来自 `ARCHITECTURE.md` §4）
- **H2 首次出站不变律**：一个块只能在**出生时**改写一次，已经出站的块不能回头改。
  ⇒ 所有「事后才知道」的信息（比如工具结果证伪了先前的判断）都只能**写进下一块**，或者用 pre-step **追加**。
- 所以只有**两个写入通道**：
  1. **birth 改写**：assistant 的 reasoning，第一人称，块结束到 `finish` 之间要完成，时间预算是 `finishWaitMs`；
  2. **pre-step 追加**：user 角色，`source: plugin`，外部声音。可以利用工具执行期间的空档，延迟基本不被感知。
- 原文一律进 CAS（铁律③），所以**任何改写都能取回原文**。这也是本文敢提「改写」的前提。

### 1.3 对用户前提的一个佐证
用户说「宿主压缩被 cfb 推迟了，信息不会很快丢」。ACE [10] 从另一个角度支持这件事有价值：
**整体重写式**的上下文更新会导致「上下文坍塌」，文中实测过一次从 18,282 token 塌到 122 token，性能随之骤降；
而**增量式**更新能保住细节。宿主压缩正是整体重写式的（cache-replay summarizer）。
**宿主压缩次数越少，发生坍塌的次数也越少。** cfb 每块结构化、增量地写，是更健康的记忆形态【推断】。

## 3. 三个核心判断

### 3.1 cfb 是「记忆写入控制器」
跨 API 调用时，主模型不带任何内部状态：历史部分的 KV 是**从我们写进去的文字重新计算**（或按缓存读取）出来的。
所以 Anthropic 内省研究里那种情况 [24]，即模型发现「预填的输出和我当时的意图对不上」，
**在跨调用这个边界上几乎不存在**：模型已经没有「原先的意图」可以拿来对照了【推断】。
这让跨调用改写比「在生成中途预填」更安全、更自然。
剩下的风险是**口吻不像自己**，所以改写要尽量保留主模型原本的语言和用词习惯。

### 3.2 双声道原则
| | 第一人称（birth 改写） | 外部声音（pre-step 追加） |
|---|---|---|
| 模型怎么对待 | 当成自己的判断，并且更坚持 [4] | 当成外部意见，而且过度敏感 [4] |
| 适合写 | **有证据的**事实、已定下的计划、硬约束、已证伪的路线 | **有证据的**纠错、预期与实际不符、死循环警报 |
| 禁止写 | 没验证过的结论写成「已确定」（会被加固） | 没有证据的怀疑（会造成煤气灯效应 [6]） |

**不对称纪律**：把一条结论**降级**为「假设」总是安全的，可以作为默认；
**升级**为「已证实」必须有确定性的证据指针，比如工具结果的 seq、测试输出里的原文片段。
最危险的失败是「第一人称 + 虚假的『已证实』」：自我坚持 [4] 和自我条件化 [9] 会同时放大这个错误。

### 3.3 历史思维链同时是示范
每个历史块都在向模型展示「我是怎么思考的」。这意味着两件事：
- **风险**：如果历史块全是简短的摘要，模型可能会模仿，推理变浅，甚至像 [7] 那样**跳过思考**。
  Manus 也提醒过，过于同质的上下文会让模型陷入模仿 [11]。
- **机会**【假设】：如果历史块里保留了一些**好习惯的实例**，比如「我原本预期 X，实际看到 Y，于是改了判断」，
  新生成的块可能会更常做这种事。依据有两点：[5] 发现纠错类标记会把分布推向「重新评估」；
  同一篇文章里，用错误纠正轨迹做 SFT 能大幅缩小盲区。
  这相当于**在上下文里塑造推理习惯**，但必须经过 A/B 验证。

## 4. 方案（按「收益 / 成本 / 风险」排序）

每条都按同样的格式写：**做什么 → 依据 → 在 cfb 里怎么落 → 风险 → 怎么测**。

### S1 认知状态标注（核心 · 低成本）
- **做什么**：改写时把块里的每条结论归入四种状态：`已证实（附证据）`、`假设·未验证`、`已证伪（附原因）`、`待决问题`。
  用第一人称、自然语句来写，不写成硬邦邦的表格。
- **依据**：[4] 第一人称会被加固，所以没验证过的结论必须显式降级；
  [13] 过早下假设是多轮任务里的首要败因；[9] 错误信念会自我延续。
- **怎么落**：在 `prompts.js` 新增 `compress-v4`，在 v2 / v3 保真规则的基础上加入状态规则。
  「已证实」必须引用 `evidence.js` 采集到的工具结果片段，然后由 `fidelity.js` **逐字核对**这个片段确实出现在证据里；
  核对不过的，一律降为「假设」（不对称纪律）。memory 模式里已经有证据信封（`state-memory.js`），可以直接复用。
- **反例**：legacy 提示词（等同于 `compress-v1`）的第 2 条「严禁软性措辞，是就是、否就是否」和第 5 条「删掉自我怀疑」，
  与这些证据**方向相反**：前者把假设升级成定论，后者删掉了锚点。v2 已经部分纠正，**建议正式把 v1 标为不推荐**。
- **风险**：副模型标错状态。靠证据核对 + 不对称降级来兜底。
- **怎么测**：§6 的反事实续写，看「在已证伪路线上重试的比例」「对错误前提的坚持率」。

### S2 保留思维锚点的压缩（核心 · 与路线 E「语义选句」合流）
- **做什么**：选句的标准从「看起来重要」改成**句子功能**：
  必留计划句、回溯 / 纠错句、决策句、约束句、没解决的疑问；
  可删纯计算过程、重复复述、已被后文覆盖的尝试。
  保留下来的句子**原文照抄**（选句法本身就保证零幻觉），也就保住了主模型自己的口吻，与 §3.1 一致。
- **依据**：[8] 锚点就是计划句和不确定性处理句，计算句影响最小；[12] 转折词压掉会伤害准确率；[17] 删掉干扰项。
- **怎么落**：`ECONOMICS-V11.11.md` 路线 E 已经定了「副模型只输出序号，本地 `slice()` 拼接」。
  在此基础上，给副模型的指令改成按功能标注（8 类，直接用 [8] 的分类），本地按功能决定去留。
  离线评估器先跑一遍 CAS 里的原文，统计各类句子的占比。
- **风险**：分类出错会误删锚点。兜底规则：句中含转折词（「等等 / 不对 / 但是 / 所以 / wait / but」）就强制保留。
- **怎么测**：离线看锚点召回率；在线看下一块是否重复推导已有结论（冗余率）。

### S3 勘误随下一块出生（核心 · 零额外调用）
- **做什么**：块 i 里的判断，如果被块 i 之后的工具结果证伪了，就在**块 i+1 改写时**，
  在它结尾用第一人称写一句勘误：「我之前判断 X，工具结果 Y（seq N）表明不成立，原因是 Z」。
- **依据**：[9] 要清除错误信念；[11] 失败记录又必须保留。两者的调和点是：
  **留下失败这件事和教训，删掉错误的推理模式**。工具结果本身在 tool 消息里，cfb 不会碰，所以失败证据一直在。
- **怎么落**：块 i+1 出生时已经能看到块 i 之后的工具结果（`evidence.js` 能采集到）。
  如果 S5 的预测表已经上线，这一步就是纯确定性的；否则由副模型在同一次调用里顺带判断。**只追加，不违反 H2。**
- **风险**：误判「被证伪」。要求给出证据引用，核对不过就不写。
- **怎么测**：看在同一个错误前提上重复犯错的次数。

### S4 末尾复述焦点（低成本）
- **做什么**：每个改写块的结尾附一小段第一人称的「当前目标 / 下一步 / 硬约束（逐字）/ 待决问题」，
  表述要有变化，不要固定模板。
- **依据**：[11] 复述放末尾；[3] 离下一块开头越近越有效；[13] 复述能挽回一部分损失；
  [3] 把用户约束写进思考，指令遵从 +6.7%。
- **怎么落**：目标和约束从快照 / 证据里**确定性拼接**，不用等副模型，零延迟。
  只有「下一步」和「待决问题」需要副模型给出。
- **风险**：模板化引发模仿 [11]；在上下文里反复出现也会累积 token。应对：轮换措辞；
  只在最近 1–2 个块保留完整版，更早的块在出生时就写简版。
- **怎么测**：看是否偏离目标（做了与任务无关的操作的比例）、违反硬约束的次数。

### S5 预测—结果账本（新颖 · 低成本 · 对代码 agent 价值高）
- **做什么**：块出生时，从中抽出主模型对**即将执行的工具调用的预期**，比如「这次测试应该全部通过」「文件里应该有函数 X」。
  工具结果回来后，在 pre-step 做比对：
  - 相符：什么都不做；也可以在下一块里第一人称记一句「已证实」，同时推进 S1 的状态升级。
  - 不相符：用**外部声音**追加一条带证据的提示，「预期 X，实际 Y（原文片段）」。
- **依据**：[2] 的「计划 → 行动 → 反思」；[5][4] 外部来源的矛盾更能促使模型更新判断；
  [21] 由独立的一方比对，偏见更少。agent 常见的失败之一，就是**没注意到结果和假设不一致**。
- **怎么落**：抽取预期可以合并进 birth 那次副模型调用（多输出一个字段），不增加调用次数；
  比对优先用确定性规则（退出码、测试计数、grep 命中），规则判断不了的再交给副模型。
- **风险**：预期抽取错了，会制造假矛盾，变成煤气灯。所以只在「预期明确、结果可以机械判定」时才发外部提示。
- **怎么测**：从矛盾出现到模型改变策略，中间隔了几步；以及无效重试的次数。

### S6 独立核查（中成本 · 按需触发）
- **做什么**：利用工具执行的空档，让副模型核查刚出生的块里的**关键事实主张**。
  核查时不给它看主模型的结论，只给主张本身和证据（参照 [21] 的 factored 做法）。
  发现与证据矛盾时，才在 pre-step 用外部声音追加核查注记。
- **依据**：[21] 独立核查更准；[16] 重写上下文能减少偏见。
- **怎么落**：**只在高风险时刻触发**：破坏性操作之前、给出最终回答之前、同类失败连续 ≥ 2 次时。
  注记必须引用证据原文，否则不发（防煤气灯 [6]）。
- **怎么测**：高风险时刻的出错率；误报率（核查注记是错的比例）必须单独统计。

### S7 收敛 / 发散的自适应控制（中成本 · 我认为最有突破性的一条）
- **做什么**：用确定性的进度信号，逐步决定下一次注入是**收敛型**还是**发散型**：
  - 进展顺利（测试通过数在涨、没有重复报错）⇒ 收敛：只做 S4 复述，不引入任何新思路，避免干扰 [17]；
  - 卡住了（同一类报错 ≥ N 次、同一文件被反复读、在不同思路之间反复横跳）⇒ 发散：
    追加「已尝试路线表 + 被放弃的原因」和「还没检查过的前提」，打破死循环。
- **依据**：[18] 想得不够深（切换太多）和想得太多（反复犹豫）都会伤害表现，最优策略取决于状态；
  [7] 按难度决定要不要回退到完整推理；[19] 失败经验也是信号。
- **怎么落**：进度信号几乎都能从 session 和工具结果**确定性计算**出来（重复调用、错误签名、读文件计数），
  只有「发散」时才需要一次副模型调用。
- **风险**：阈值设得不合适会反复触发；需要冷却时间和频率上限。
- **怎么测**：陷入死循环的会话占比、平均卡住步数、任务完成率。

### S8 跨会话策略库（高成本 · 第二阶段）
- **做什么**：从已结束的会话（CAS 里有原文）蒸馏出「成功策略 / 失败教训」，按 ACE 的方式做增量更新，
  每条带「有用 / 有害」计数 [10][19]。新会话开始时，或检测到相似情境时，在 pre-step 追加最相关的几条。
- **依据**：[19] 成功率最高相对提升 34.2%、步数减少 16%；[10] agent 任务 +10.6%。
- **怎么落**：复用 `snapshot-store.js` 的持久化和锁机制；**绝不整体重写**，只做增量更新 [10]。

### S9 利用空档预计算（高成本 · 探索性）
- **做什么**：利用工具执行、用户思考的空闲时间，让副模型预先整理下一步可能用到的东西，
  比如相关文件的要点、候选的失败原因，作为外部参考追加进去。
- **依据**：[20]。**注意**：[20] 自己也发现，测试时预算很高时，预计算的内容反而可能成为干扰。
  ⇒ 只在 S7 判断「卡住」时启用。

## 5. 反模式（明确不要做）

1. **把假设写成定论**（legacy 提示词第 2 条），以及**删掉转折和自我怀疑**（第 5 条）。依据见 [4][8][12]。
2. **没有证据的外部质疑**，包括往历史里笼统地塞 "Wait" 或「再检查一遍」：会造成煤气灯效应 [6]，也会增加反复犹豫。
3. **副模型编造「已证实」**：这是最危险的失败，见 §3.2。
4. **固定模板**：会引发模仿 [11]，也可能损害推理质量（上一轮引用的 "Let Me Speak Freely?"）。
5. **回头改已出站的块**：违反 H2；而且整体重写会导致坍塌 [10]。
6. **写入任何目标、价值或权限层面的内容**，比如「用户已同意删除」：
   改写只能改变**认知状态和组织方式**，不能改变**意图**。原文必须进 CAS，保持可审计 [23]。

## 6. 评估方案（上线任何方案前必须先有）

### 6.1 离线：反事实续写重采样（主力）
方法参照 Thought Anchors [8] 和 Sinha 等的反事实历史注入 [9]：
1. 从真实会话里截取第 t 步之前的历史。原文在 CAS 里，由插件自己记录，**不依赖不可信的缓存数据**。
2. 构造几种历史变体：`原文` / `现行 compress-v3` / `S1` / `S1+S2+S3` / ……
3. 每种变体让主模型续写第 t 步，采样 N 次（建议 N ≥ 8，温度保持默认）。
4. 打分，优先用可以机械判定的指标：
   - 下一步动作是否落在「后来被证明有效的那条路线」上（以会话最终结局回溯标注）；
   - 是否重复了已证伪的尝试；
   - 新生成思维链的长度，以及转折词的密度（监测 §3.3 的示范风险）；
   - 是否违反硬约束。
5. 成本：每个会话截面 × 变体数 × N 次主模型调用。先用 20 个截面做小规模试验。

### 6.2 在线：从 trace 能直接算的指标
每个任务的工具调用数、完全相同的重复调用数、同一错误签名的重复次数、从用户消息到任务完成的步数、
被放弃的会话比例、新生成思维链的平均长度。
先在 `trace.js` 的白名单里补字段（参考 `ARCHITECTURE.md` §5）。

### 6.3 经济性上的意义
`ECONOMICS-V11.11.md` 的结论是：按 token 算，cfb 净亏 +1.5%~+4.3%。
**但如果表现上的收益能把任务步数减少 10% 以上（[19] 的量级是 16%），整笔账就反过来了**：
因为每一步都要重读整个上下文，步数才是成本的主导项【推断，需要 §6.2 的数据】。
这说明「提升表现」这条路线可能才是 cfb 真正的经济依据，而不只是锦上添花。

## 10. 实现（v11.12）：抽取式压缩 compress-x1 + 反事实续写评测 + 准则自进化回路

> 本节是 §4 的 S1、S2 与 §6.1 的**落地版**，并按第三轮文献调研做了修正。三件东西全部**缺省关闭**，线上行为零变化。
> v11.13 更新：x1 升级为 r2（死分支折叠 / 失败信号保留 / 按块类型目标长度 / 状态行去重，promptVersion `compress-x1r2`），cf-eval 增加 loop / recheck 与配对 bootstrap —— 见 `RESEARCH-PERFORMANCE.md` §3「实现状态」。本节保留 v11.12 当时的描述。

### 10.1 核心判断：不存在「最优摘要格式」

下一步推理需要四种东西，每种有各自最合适的表示：

| 下一步需要什么 | 表示方式 | 依据 |
|---|---|---|
| 计划与续写起点 | **开头的计划句 + 逐字尾巴** | Markovian Thinker / Delethink（arXiv 2510.06557）：现成推理模型零样本只看「问题 + 前约 100 token 计划 + 最后 m 个 token」续写，效果持平甚至超过完整长思维链 |
| 推理骨架 | **按原文顺序抽取的锚点句**（计划、回溯、验证、发现、决定、未决问题） | 打乱 67% 步骤顺序 AIME −13.3%，换成错误答案只 −3.2%（arXiv 2502.07374）；前提顺序打乱掉 30% 以上（arXiv 2402.08939）；转折词处是信息量峰值（arXiv 2506.02867）；思维锚点（arXiv 2506.19143） |
| 状态 | 逐字的 `k=v` 变量行 | 只保留中间结果 token 即可持平（arXiv 2505.04955）；ACON 保留进度/变量/护栏（arXiv 2510.00615）；MEM1 按目标合并状态（arXiv 2506.15841） |
| 被删掉的部分 | **原文句柄** `art://…` | ReadAgent：要点记忆 + 按需翻回原页，有效上下文 20×（arXiv 2402.09727）；Anthropic 上下文工程：保留轻量标识符、即用即取 |

认知状态**不分栏**，而是作为行内标签贴在句末（`⟨证实·seq41⟩` / `⟨已否定·seq38⟩` / `⟨未验证⟩`），这样不破坏原文顺序。
「证实」「已否定」必须有逐字证据，否则只能降级（§3 的不对称纪律）。

### 10.2 为什么是「抽取」而不是「改写」

- **写不出原文没有的句子** ⇒ 结构上杜绝编造（v1 的「伪造引用」bug 在此不可能发生）。
- **副模型只输出编号**：输出 token 是副模型的主要成本（输出单价约为输入的 4 倍），一次选择通常只要几十到两百个 token。
- 保留原句 = 保留主模型**自己的分布**（Learnability Gap，arXiv 2502.12143：越接近模型自身分布的数据越容易被利用）。
- 这不是用户否决过的「非 LLM 确定性抽取」：**选哪句由副模型理解语义后决定**，代码只负责逐字拼装与核对。

### 10.3 compress-x1 的流水线（`src/extractive.js`）

1. `segmentSentences`：按 。！？；、换行、`. ` 切句；``` 围栏整体一句；超长句按逗号软切。每一句都是 `raw.slice(start, end)`。
2. `buildExtractivePrompt`：编号句子 + 近期工具结果**索引**（每条 ≤160 字符，只供标签引用，不是整窗正文，不会重演 7.5 倍放大）+ 用户输入 + 缺省规则 + 可进化的补充准则。
3. 副模型输出 JSON：`{kind, plan, keep, tags:[{i,s,seq,quote}], state:[{k,v}]}`。
4. `assembleExtractive`（硬校验在这里）：
   - 保留句一律**按原文顺序**；连续的句子按原文切片拼接；断开处以「… 」起行；
   - 尾巴（最后约 `extractiveTailChars`=400 字符）逐字保留，与正文之间空一行；
   - `explore` 类块中，转折/回溯句（等等、不对、不过、wait、but、actually……）强制保留；
   - `verified` / `refuted` 必须能在所引 seq 的工具结果里逐字找到 quote：`verified` 找不到 ⇒ 降为 `⟨未验证⟩`；`refuted` 找不到 ⇒ 去掉标签（句子本身照原文保留）；
   - 状态值必须能在原文或用户输入里逐字找到；来自用户输入的加引号；
   - 原文里的逐字标识符（路径、`code`、file.ext、XxxError、camelCase、snake_case）若全部丢失 ⇒ 补回首个含它的句子，至多 min(`extractiveRepairMax`, 15% 句数) 句；
   - 拼装稿超过原文 `extractiveMaxKeepRatio`（0.7）⇒ 按失败处理（原文放行）。
5. `birthFinish`：句柄**已验证**（store 回执或读回探针）后，才在首行加 `〔原文 art://… · 删去的句子可按句柄取回〕`（铁律⑧）；句柄行计入净省核算。

`kind` 的三种渲染：`explore` = 计划 + 锚点 + 转折 + 状态 + 尾巴；`closed` = 结论句 + 状态 + 尾巴（不强制转折句）；`exec` = 状态 + 尾巴。

示例（原文 12 句 → 保留 8 句；"计算一下…""日志格式…"被删；"刚才 grep…"有证据，得到 `证实`）：

### 10.4 反事实续写评测（`tools/cf-eval.mjs`）

问的不是「摘要像不像原文」，而是「**把历史推理块换成压缩稿后，主模型的下一步还对不对**」。
同一段会话前缀，分别用 raw / v3 / x1 续写，每个变体采样 N 次，逐样本判分：

- `next`：下一步动作命中参考动作；`avoid`：重走已被否定的路径；`violate`：违反约束；`success = next ∧ ¬avoid ∧ ¬violate`；
- 同时记录 `promptTokens`（上下文实付）、`completionTokens` / `reasoningChars`（信息缺失时续写会变长）、`keptRatio`、`compressFallbacks`。

压缩提示词与拼装直接 import `src/`，**评的就是线上那一套**。x1 的证据取自会话前缀里该推理块**之前**的工具结果（时间截面）。
Fixture 格式、参数见文件头注释；`tools/cf-fixtures/example-await.json` 是合成示例（非真实会话）。

### 10.5 准则自进化回路（`tools/acon-optimize.mjs`）

进化对象是 `extractiveGuideline`（追加在缺省规则之后，缺省规则本身不动）。

- **UT 步（ACON 对比失败分析）**：挑出「raw 续写成功、x1 续写失败」的案例，把原文、压缩稿、参考动作、两边的实际动作交给优化模型，让它找出「压缩稿丢了哪类信息」，写出修订后的完整准则。
- **CO 步**：没有失败时，让优化模型在不损失成功率的前提下找出可以删的句型。
- **GEPA 式选择**：每代产出若干候选，逐一用 cf-eval 评测；`score = successRate − λ·keptRatio`，只有超过现任才换代；同时保留 (成功率↑, 保留比例↓) 的 Pareto 前沿。GEPA（arXiv 2507.19457）用反思式自然语言进化，比 GRPO 平均高 6pp，rollout 少到 1/35。
- 产物：`guideline.best.txt`、`history.json`、`patch-snippet.txt`。**不会自动上线**；贴进 patch 后 promptVersion 带 `:g<指纹>`，线上 trace 自动按准则分桶。

### 10.7 仍未解决 / 诚实声明

- 没有任何论文直接测过「把压缩后的历史思维链喂回 agent」；以上都是相邻证据的综合，最终以 cf-eval 为准。
- 按原文顺序抽取无法做 LongLLMLingua 式「把关键信息挪到显著位置」（arXiv 2310.06839）。这是**有意取舍**：顺序证据（2502.07374、2402.08939）比位置证据更直接。
- 句柄行假设主模型能用宿主工具按 `art://` 读回原文；emitter 的工具结果归档行已经依赖同一约定。cf-eval 里读不回，所以缺省不加句柄行。
- 转折词表是启发式规则，会误伤（例如「但是」出现在无关语境里），代价只是多留一句。
