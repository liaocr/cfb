## 1. 这个仓库的"宪法"（用户明示，违反即返工）
- 每阶段一个 commit；全部做完后重算 manifest 再 `git push origin main`。
- 数据审核必须**逐条全读**，不许为省 token 抽样；**允许双向改判**（可把可训练判成 NOISE、可下调 yVal）；可训练数下降、分数变难看都可接受。
- **手写稿不得参与打标**：新家族的标签只能从**可执行 fixture 的运行时事实**派生。
- 训练权重一律不碰（`transfer/models/v5-micro-weights.json` 是生产件）；`--push-back` 未经要求不加。
- 已划掉的：P2 真机补洞/渠道；Mode1 补稿。别再回到话题里。
- 闸门不许放宽：`NEAR`、`margin≥0.05`、`distinctScorePairs≤2`、`<100M` 参数、三折 CV 的 +20pp。想"过线"只能靠加数据/修数据。

## 3. 流程经验（做过才知道的）
**A. 标签盲审（M0）**
1. 孪生工具的 digest 必须与构建器 `reviewDigestOf` **逐字一致**（`sha256(JSON.stringify({sourceId,unitIdx,text}))`），否则回灌时被静默丢弃。
2. **继承闸绝对不能用"数据集 sha 相同"** —— 回灌本身就会改变数据集 ⇒ 一次 apply 把已完成的 245 条判定全判废（我真栽了，靠 `.cfb-offline/review/v*.jsonl` 批次文件重建）。正确判据：**该单元 digest 是否仍存活**；改过正文的单元自动丢弃。这条已钉进 `test/micro-label-review.selftest.mjs`。
3. 先抽样再决定要不要全审：`sha256(seed+id)` 确定性抽 15，误标率 >10% 才升级为整批复核（这次 2/15 = 13.3% ⇒ 全审了 120 条负例）。**两遍审核已经做完，别再重复。**
4. 排查脚本必须排除**已审 id**（`dump-suspect.mjs` 初版没排除 ⇒ 打印的 34 条全是自己刚判过的，白跑一轮）。
5. 判读口径：工作表里被截断的半句 ⇒ NOISE/低分；同结论重复句只给首句高分；纯复述任务、格式约束、"让我们验证"类 ⇒ NOISE；工具参数 schema 核对也算 NOISE。
6. `labelRule` 字段是**旧规则名**，`slot` 才是我的结论 —— 别把两者当矛盾去"修数据"。

**B. 一次性新家族盲测（M1）**
1. **一个文件只能一个家族**：`tools/eval-micro-js-pairs.mjs:484`（`final-test-must-have-exactly-one-family`）与 `tools/kaggle-train-micro.py:1638`（`blocked-final-dataset-must-contain-one-family`）两处硬要求 ⇒ 两个家族 = 两次独立的一次性测量。
2. 标签从 `require.cache` 读"测试真正加载了哪些文件"派生。**模块文件名不许随任务变体改** —— 改了 doc 里引用的名字与运行时事实就脱钩（我中途这样改过，回滚了）。
3. mojibake 样本必须 **latin1 落盘**：否则 `'Ã'` 被再 UTF-8 编一次 ⇒ "双重编码"变"三重损坏"，锚点失真。由 `bugReproduced` 断言守住。
4. 长度对齐：`tok` 对 `本步无新增事实。` 这类填充一次跳 ~5 token，NEAR=3 时经常 overshoot ⇒ 用**标点级**填充（`。`）+ 在 `win×lose` 全组合里搜最小差。搜索时**对照组必须取未填充那一侧的 tok**（取错就选不出最近对；`pair-drift` 会抓你，这闸是有用的）。
5. 三条硬闸留着别拆：`blind-units-not-unique`（防复制体冒充样本量）、`pair-not-matched`（防 `near` 冒充 `matched`）、`endpoint-cap-exceeded`。
6. **只能评一次分。** 构造阶段只跑 `--validate-dataset-only`（结构/血缘/审核，不出分数）。谁先手跑评分，谁就把这道一次性测量烧掉了。
7. 别为指标做假特征：`cueExcluded` 只在 `isNeg` 成立时非零（`src/compile-v5-local.js:303`）⇒ 往 EXCLUDED 句子里塞"无需/不用"不会让它变 1.0，只会污染文本。当前 `cueExcluded=0` 是**如实记录**的局限。
8. 已知局限（已写进 `stats.limitations`，别当新发现）：不测线索驱动的排除判定；matched 层靠标点填充对齐 ⇒ 读作"同长度判别力"。

**C. 飞轮分数（v14.24.5）**
- 量纲：`structuralScore`（`tools/helpers/experiment.mjs:75-77`）是**±1 旗标计数和**，不是 0–1 判分。解法选的是"带单位"：`scoreKind: 'structural-tally' | 'judge-01'`，构建器按单位分派最小差值（0.05 / ≥2），**缺字段按 `judge-01`** ⇒ 既有数据零变化。
- 被否决的方案：把 tally 名次化到 0–1 —— 会编造裁判从未断言的强度差，且名次值只有几个 ⇒ 再踩 `distinctScorePairs≤2`。
- 读数的坑：修前基线"可训练 draft pair 59"里含 13 行被计数尺度平凡放行的垃圾行；修后 17 是保护生效的真数。**别把 17 当倒退**，也别回滚 promote 侧的越界丢弃。

**D. gold（金标）洞**
- `tools/gold-forge2.mjs` 是 $0 锻造器，铁律：引用逐字取自该条 `raw/ctx`、抽不到就标 `needs-manual`、只允许一处反引号、长度 ≤ min(C1, C6)。
- **`--ids` 模式是"预锻、不含真机读数" ⇒ `--write` 不落盘**（我撞过：19 条里 16 条达线，`transfer/gold` 仍 5、`devGoldItems` 仍 4）。要真入库得走 pending → 真机读数 → `gold-place-drafts` → `gold-check` → `gold-attest`。
- 后果链要知道：gold 不达标会被自动降 `use:'train'` ⇒ `plan-bench` 报 `no-gold:dev`、`train-v5-micro` 报 `no-ruler-for-eval`、`export-train` 剔出 SFT。
