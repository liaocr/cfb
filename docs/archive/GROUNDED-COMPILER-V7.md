# v7：恢复判断所需的证据，验证认领到消费，而非只验证生成

日期：2026-09-22。基于最终 v6，一次性完成本批代码修改。未部署、未推送，未修改宿主 profile。

## 先讲不能作出的保证

**没有真实完整会话和同模型配对运行，就不能证明任务质量、编译成功率、实际压缩率或费用绝不退步。** 本批不把回归通过、正文范围、固定响应或模拟宿主替代这些产品指标。

本次明确撤回 v6 的“工具正文默认全部退出副编译输入”。恢复独立核对材料会增加相对于 v6 的输入；不能同时继续声称“旧正文跨轮零重发”。这是保真优先的主动取舍，不是隐瞒回退。

## 已修改的整体流程

1. 采集并固定当前证据截面，记录与副模型成功仍解耦。
2. 默认编译请求带工具正文，包含正常返回，不再让 reasoning 自证。
3. 两栏只是输出组织形式，不能删掉 reasoning 独有的目标、条件、否决理由、备选解释及已有计划。
4. 正常启用迟到认领时继续 ready-only；已就绪仍可当场压缩。没有可用迟到通路的已知情形则保留原配置等待上限。
5. 区分输入准备、成功生成、归档、暂存、后续机会、命中、发射、确认消费及后续请求中的呈现。
6. 新证据目录有容量上限；达到上限退化为当轮内存证据编译，而不是停掉压缩器或删除仍被引用的证据。
7. 四个旧开关退出生产配置入口；不再增加新开关。

## 一、证据输入：不仅修补错误结果

新增 `evidence-input.js`，默认生产路径已接入。

| 当前窗口中的材料 | v7 输入行为 |
|---|---|
| 普通正常返回 | 每条保留至多前1200字符，即不因“已记录”删掉原来可见的前缀 |
| 最近一条已返回结果 | 前4096字符；超出时再提供末尾1200字符 |
| isError、非零数值 exitCode、failed、cancelled | 前8192字符；超出时再提供末尾1200字符 |
| 空的显式返回 | 明确提供空结果，不改判为 pending |
| 显式结果缺少事件序号 | 保留正文，不因为没有 seq 假装没有返回 |
| pending/running、无显式结果 | 不补造执行结果 |
| 完全相同的正文与可见区间 | 同一请求内只展示一份，但保留所有独立事件关联 |

**长错误正文不保证全文进入模型。** 未提供的中间区间明确标记，输出真实范围回执；不把片段宣称成完整结果，也不把传输了某个范围当作理解正确。

原始采集正文仍保存，未主动改写工具消息。源码里的1200字符“模型输入截断”与上游显式截断信号现在分开：不能仅因为旧提示词只留1200字符，就把已经采集的完整正文误标成源头已截断。

工具正文是独立核对材料，不是绝对真相。正常结果里的版本、空集合、失败统计和反证同样可见。判断涉及工具观察时，提示词要求注明可见 callSeq/resultSeq，缺失序号不得编造。输出仍是未经逐条语义核验的 inferred。

**没有按落盘进度删除旧正文。** 因为保存、提供给模型、形成正确结论不是同一件事。本轮保留保守前缀，而非声称已经做成无损的跨轮语义去重。固定工具材料放在动态状态和 reasoning 前面，便于前缀稳定；未为缓存另发请求，也未验证商户缓存收益。

### reasoning 独有信息

保留两栏，但明确要求两栏内承载：目标与验收、约束、项目语义状态、否决原因、备选解释、既有条件计划。计划注明尚未执行，不得新增行动。不能因为没有专门栏位就删除这些内容。

这属于编译要求，不是机器已经证明每个模型回答都满足它。没有新增第二次模型审核调用，也没有把词法检查伪称为语义保真证明。

## 二、等待与压缩机会

正常生产配置仍不主动等副模型，完整迟到结果走已有认领通路。已完整就绪的结果仍通过原净省和归档门禁当场采用。

增加已知无消费通路的保护：

- 显式关闭 `birthDeferredClaim`；
- 缺少 sessionId；
- reasoning UTF-8 大于192KiB，预留既有256KiB迟到缓存单项预算中的输出空间；

这些情形不强行 ready-only，而使用原 `birthFinishWaitMs`。当前用户配置仍是1500ms，没有提高等待上限。它不是“任何情况都取消1500ms”，而是避免明知不能认领还把所有结果抛到后台。

后台模型8000ms、输出1200、生产 prewarm:false、distillStream:true、模型和 provider 不变。没有串行模型调用链、没有新 surface 或 tool-call 协议。

不再把“配置里的1500没动”说成“行为没变”：正常路径确实改了等待行为。所引用历史样本支持在当时负载中移除无收益等待，但 p10 本身不能证明全体样本零命中，也不证明未来所有模型永远慢于1500ms。

## 三、认领链路：这次验证到后续请求

新增 `grounding.selftest.mjs`，实际调用 `apply()` 注册的 hook、实际本地 HTTP/SSE 传输、可控制延迟的模型响应及模拟宿主的 surface/append：

1. reasoning 流结束时副模型响应仍被阻塞，原文先走。
2. 在响应到达前发生下一轮 pre-step，没有半成品替换。
3. 响应完整返回，原 reasoning CAS 成功，产物进入迟到缓存。
4. 原 reasoning 仍为活跃尾部时不碰它；保留 keepTail=1。
5. 出现更晚 assistant 后形成可认领机会。
6. 第一次 append 故意失败，结果不被消费。
7. 再次 pre-step 发射成功，精确 receipt 才被确认消费。
8. 后续 llm options 实际包含生成后的记忆文本；再次 pre-step 不重复发射。

相同流程又在**证据目录达到全局配额**时执行一遍：默认生产准备函数回退为当轮内存证据，仍成功生成、认领、消费。

两份本地记录：

- `docs/archive/optimization-evidence-v7/local-consumption.json`
- `docs/archive/optimization-evidence-v7/quota-fallback-consumption.json`

每份都有1个生成且归档成功、1个发射、1个确认消费、1个后续 options 呈现。这证明本地接线不是“生成了但根本用不到”。**不证明真实宿主中772次机会的认领率，不证明真实宿主投影实现，也不证明模型任务正确率。**

下一轮 pre-step 不保证必然发生。keepTail=1 还意味着有下一轮用户输入也不必然能立即认领；可能需要更晚 assistant 才能脱离活跃尾部。结束日志没有消费机会不能直接记成认领失败。

### 生命周期统计

新增：

```bash
node analyze-consumption.mjs trace.log consumption.json
```

按 taskId 关联生成、归档、暂存、机会、命中、实际 append、确认和后续呈现。不会用 `claim-hit / 所有起飞` 冒充认领成功率，也不会把 inline 候选输出当作已验证的宿主替换。

`compiler-input-prepared` 记录准备提供的正文 hash/区间；不是网络已送达证明，更不是模型理解正确证明。成功响应和应用状态另行关联。

`memory-presented-in-options` 只证明 hook 看到的后续消息中含有该文本，计量器为有界进程内状态；不证明最终 provider 收到的请求完全相同。完全相同的多个输出不随意归属某个任务。

传输保留上游实际提供的 usage（若有），标为 providerReportedUsage。没有则未知；不按字符估算账单，不把商户缓存声明当经核实费用。

### 不安全的恢复没有自动开启

迟到缓存仍为有界进程内状态。**没有把持久化判断恢复成可自动替换原消息的授权。** 目前仍缺可靠的生成块—宿主消息身份闭环；只凭 raw、seq 候选和存盘状态跨重启认领，会重新引入错误绑定风险。

因此本批没有承诺跨重启保持所有压缩机会；也没有虚构主模型后续一定继续运行。这里仍是清楚标出的能力边界，不以“所有优化都完成”掩盖它。

## 四、存储与本地开销

新增 `evidence-storage.js`，是默认资源边界，不是一个新开关：

- evidence-v1 全局：256MiB 受管文件内容，100000文件；
- 单 session/branch：64MiB，20000文件；
- 预留原子替换临时峰值，写入前先记额度；崩溃可保守多计，不靠少计放大空间；
- 每个观察批次统一预留、统一结算，避免为每条正文和元数据反复更新额度表；
- 原有 v6 数据第一次通过清点接管；若已有数据超限，不删除旧材料来伪装已满足限制；
- 超限、锁冲突、损坏或停用持久化时，以明确标注的当轮内存证据继续编译，没有虚构索引地址；
- 停止默认向宿主共享 CAS 再复制一份工具证据。reasoning 归档和既有发射归档仍不变；已存在的 CAS 对象不删除。

限制针对**新增证据树的受管文件内容与数量**，不是物理磁盘块精确上限，也不是宿主全部存储、原有 trace 和快照的总配额。额度元数据、目录结构等有额外成本。同步 I/O 仍存在，`evidence-prepare-cost.ms` 单独记录它，不能把准备成本藏到模型计时之外。

### 安全生命周期管理

没有对仍可被历史消息引用的 view/body 按时间强删。提供离线审计及只删除无引用对象的清理：

```bash
# 先停止宿主，ROOT 为 .../storages/cot-form-b/evidence-v1
node replay.mjs storage-audit ROOT storage-audit.json
node replay.mjs storage-gc ROOT storage-gc.json
```

GC 保留所有已提交索引与所有 view 的引用，仅删除识别出的无引用正文/记录/引用文件；异常结构拒绝猜测。清理后重算额度。活动或遗留锁需要检查，不靠锁龄强抢。

长期所有材料都被引用且达到上限时，默认退化为临时输入，不自动破坏历史。持续完整记录与有限空间不能两者无限满足；这个边界明确保留。

## 五、清理旧配置，而不是再添开关

以下四项已从 DEFAULTS、公开类型、生产初始化与 BOOT 活跃选项中移除：

- stateEvidenceViews
- stateEvidenceBodyBudget
- stateSnapshotMirror
- stateCompileQueue

旧 profile 若仍传这些键，规范化时删除并在 BOOT 的 retiredOptions 中报告，不会暗中启动另一套路径。不修改用户磁盘上的 profile。

旧快照镜像／恢复的生产 hook 初始化及准备回调已移除。历史导出函数的直接调用与回归仍保留兼容，不把它们描述为当前生产默认能力。曾启用 mirror 的安装应注意：新版本不再自动创建或恢复那些镜像，旧 CAS 数据未删除。

`stateSnapshot:false` 仍可停止持久化，但不再像 v6 一样因此把整个副编译器停掉：当前采集证据可在内存中参与编译，输出不附不存在的索引。

## 本批没有冒险扩大范围的内容

- 没有遮蔽主模型工具正文、删除 runtime context 或改 tool-call。
- 没有为提高压缩率接纳半成品，放宽未知身份认领，或增加等待和输出预算。
- 没有新增串行模型校验调用。
- 没有把单次成功生成、内存暂存、后续 options 呈现转换成 token/账单节省百分比。
- 没有宣称两栏提示词已经证明语义无损。

**本批完成的是可验证的代码修正与消费链路，不是缺少真实数据时仍能给出的“绝不降性能、绝不掉压缩率”保证。**
