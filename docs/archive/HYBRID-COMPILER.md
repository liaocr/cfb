# v6：确定性证据记录＋两栏判断编译

日期：2026-09-22。基于已交付 v5；未部署、未推送、未修改宿主 profile。

## 结论先行

这次改的是正在使用的 **`birth + stateMemory:true` 默认生产流程**，不是增加一个默认关闭的实验开关：

- 已采集的证据先记录，记录进度不再等待副模型成功。
- 副模型不再每轮接收工具结果正文；输入改成原始 reasoning、确定性事件状态视图、变化事件及真实引用。
- 副模型只写“关键判断与依据”“未决差距”，不负责重建全部六栏事实。
- finish 不再主动陪副模型等 1500ms。只采用已经完整就绪的结果，否则原文先走，完整迟到结果沿用下一轮认领。

**实现与本地数据流验证已完成；真实产品指标尚未验收。** 没有完整 27568 行会话、配对主模型执行、探索轮标注和独立错误状态审核，不能宣称 timeout＋empty 已下降、重复探索已下降或已证明零错误状态走错路。

## 对建议的取舍

| 建议 | 实际选择 |
|---|---|
| 四栏完全确定性生成 | 不接受“语义四栏都能无误推导”。代码记录用户原话、调用／返回、显式运行字段；不自动提取所有目标、禁止与验收条件，不把工具终局当任务成功。 |
| 模型只补判断与差距 | 采纳。默认请求改成两栏；未经完整模型成功的 reasoning 仍然原文保留。 |
| 完整状态＋增量 | 采纳“完整已观察记录＋变化版本”，不冒称掌握整个未采集会话。模型看到有限状态视图，完整记录通过真实索引取回。 |
| 按 sourceCutSeq 过滤旧内容 | 不采纳。按来源事件身份、元数据与内容 hash 识别版本；迟到低 seq、旧事件内容变化仍进入新记录。 |
| 工具正文改按需取回 | 采纳到副编译输入。正文保存为实际文件，CAS 写入成功后才发布其返回的句柄；不凭算法推算一个未写入的句柄。 |
| 为等压缩成功继续阻塞主流程 | 默认不再等待。已完成才替换，否则原文先走。没有新增模型链。 |

2.9 次平均重发、94% 产物不可达等推论没有作为独立事实或收益估算使用。

## 默认路径现在怎么走

### 1. 先记录，而不是成功以后才“算处理过”

新增 `evidence-ledger.js`，在生产 `birthStart` 构造编译输入之前接线：

1. 仍由现有宿主事件适配器采集、固定截面、判定来源。
2. 在 session＋branch 独立目录保存采集到的完整正文、不可变事件版本与原子索引。
3. 用户原话只标记为未自动分类的用户原话。来源未确认的消息另外记录，不能当用户授权。运行上下文保留；补齐了原适配器使用 `SOURCE.runtime` 却未定义该别名的问题。
4. 新旧版本共存。`completed` 表示调用生命周期，不是任务完成；非零 exitCode 与调用失败分别记录。
5. 准备失败不退回旧的全量六栏请求：不调用副模型，保留 reasoning 原文，留下失败记录。

没有可用事件身份时不按相同文本猜同一事件。代价是匿名观察可能重复记录；不以节省为由合并身份不明的材料。

记录发生在原有合格 birth 触发点；不是全会话无遗漏采集器。短于既有门槛、关闭模式、dry-run 等原有门禁不被绕过。首次安装只有实际采集到的窗口，不能凭空恢复窗口之外的用户要求。

### 2. 副模型不再收到旧工具正文

生产准备函数无条件接入既有已启用的状态编译模式。新信封中工具正文列表为空，`buildJudgmentPrompt` 使用确定性 frame：

- 当前 reasoning 保留全文；用户原话和运行字段不让模型背诵生成。
- 最近的工具生命周期元信息、有限变化事件索引、参数或明确标记的参数片段。
- 采集边界、未确认来源材料数量、真实文件／已确认 CAS 引用。
- 模型只输出判断与差距；解析失败仍是失败，不把记录表当成功摘要。

正文保存在索引引用的文件中，不在每次失败后重新装入下一次副编译请求。上游标记的截断状态保留；“本次采集全文”不等于证明源工具从未截断。

**不是无损等价的模型输入。** 副模型本次没有读取工具，提示词明确禁止声称看过未提供的正文；必要疑点保留待核验。原始 reasoning 可能含错误推断，模型两栏也仍是 inferred，不因此变成事实。减少证据正文可能损失模型核验能力，这个取舍必须由真实主模型重放验收，不能用输入缩短证明合理。

旧导出 API 的无 frame 调用保留兼容，旧回归仍运行；正在使用的生产 birth 路径不再依赖 `stateEvidenceViews`、旧覆盖过滤或编译队列开关。`stateSnapshot:false` 在新生产路径中停止持久化并保留原文，不悄悄切回全量六栏请求。

### 3. 前台不再等副模型，但不伪造完成

新默认为 ready-only：

- finish 时模型与 reasoning CAS 已完整成功：再走既有可接受输出、净省等门禁。
- 尚未就绪：原文立即先走，原因记为 `background-judgment-pending`，不是把前台未等待伪记为上游超时。
- 后台真实 `timeout 8000ms`／`empty distillate` 仍按原错误记录，不能从统计中抹掉。
- 完整迟到产物继续走 v5 的 session／branch／任务认领、逐字覆盖及发射前复检。

配置值 **1500 / 8000 / 1200 不变**；1500 仍是旧兼容路径预算，新路径不主动消耗它。生产 `prewarm:false`、`distillStream:true`、模型、provider 与 profile 未修改。裸库原有启用默认也未改，不替用户开启插件或修改配置。

这里消除的是主动等待，不是承诺端到端零延迟：事件扫描、同步本地 I/O、宿主流处理仍有开销。没有真实环境的端到端延迟分位数。

### 4. 按需取回是真实引用，不是虚构工具能力

目录：`$DSH_HOME/storages/cot-form-b/evidence-v1/<session+branch hash>/`，未设置时使用 `~/.dsh`。

- `*.txt`：正文按内容 hash 保存。
- 事件 JSON：调用参数、返回状态、来源、正文位置等不可变记录。
- `index.json`：已观察事件版本索引，追加记录而非用“最新终局”覆盖任务语义。
- `view-*.json`：当前冻结 frame、当前记录及历史读取边界。
- `*.cas.json`：实际 `cmbStore.putText` 成功后保存的引用。

后台 CAS 归档不进入 finish 等待，最多两个本地 store 工作任务、64 个待处理项；未排入或失败的项仍有真实本地文件，再次看到时可重试。没有增加模型调用。

为避免每轮复制整个越来越大的历史表，view 不重复保存全历史索引。历史按 **首次观察 revision** 截取，不按来源 seq 截取；`readEvidenceHistory` 可还原旧 frame 的已知记录，不纳入后来观察到的事件版本：

```bash
node replay.mjs inspect /实际路径/view-….json history-records.json
```

成功的 reasoning 产物和迟到认领文本附带该证据索引位置。模型失败时不插入假摘要或仅有句柄的 reasoning 替代品。原始工具消息不删除、不遮蔽、不改写，runtime context 也不删。

现有宿主文件读取或 CAS 读取工具允许访问这些位置时，主模型可按需读取。**没有新增 read 工具，也没有证明每种宿主都具备相同权限**；实际宿主的引用可读性仍待验证。现有原始工具消息继续保留，避免把未经验证的检索权限当成唯一信息通道。

## 已经验证了什么

本地 HTTP/SSE 固定响应测试实际经过 `apply → agent/pre-step → llm/stream → birthStart → finish`：

1. 第一次故意不返回响应，触发真实传输层的 **8000ms timeout**。
2. 第二次返回空文本，触发 **empty distillate**。
3. 第三次返回完整两栏响应。

这三个请求里，相同工具正文没有进入副模型请求；第一次记录的事件在两次失败后仍已提交，后续不依赖模型成功再记录。finish 保留原文；完整两栏返回之后才进入成功流程。记录能够导出，再由真实编译入口重放。

**这里 timeout＋empty 仍是 1＋1：它们是故意制造的故障，不是“已经减少”的生产指标。** 固定响应也不能测试语义正确率、主模型行为、费用或真实上游性能。

其他检查包括迟到低 seq、旧正文变化、匿名身份、分支隔离、运行上下文、真实引用就绪、旧 frame 历史读取、准备失败不退回全量输入。5 项反证分别拆掉默认接线、切回旧提示词、阻止确定性提交、误用 cut 过滤、拆掉 ready-only 入口，均被检出；修改均已恢复。

全量回归：1101 通过／0 失败／1 宿主跳过，14 套件。它只说明已执行回归结果，不是产品变好的验收。

## 录制、重放、产品验收分开

新增 `replay.mjs`，不要求更改生产开关。现有 trace 开启时新增 `evidence-ledger-committed.indexPath` 与确认 reasoning 归档的 taskId、handle、hash，供导出关联；不把原始正文写进 trace。

### 导出编译录制

提供一个本机适配模块，默认导出实际 CMB store（或返回 store 的工厂），具有既有 `readRangeByHandle(handle, sessionId, startLine, lineCount)` 方法。这里不臆造宿主初始化契约。

```bash
node replay.mjs capture trace.log ./actual-cmb-store-adapter.mjs capture.json
```

工具逐段读到明确 EOF，并核对正文 hash；句柄缺失、正文变化、换行还原不一致、未到 EOF 都拒绝标记完整。录制只覆盖有完整材料的合格 birth，不冒称完整会话。导出包含用户与工具原文，应按私有会话资料管理。

### 重放副编译器

`compile-config.json` 提供实际模型、provider／端点、credentialRef、credentialsPath／settingsPath 等原配置，不在报告中复制密钥。使用空的独立数据目录，不能对生产存储直接重放：

```bash
# 候选 v6
node replay.mjs run capture.json compile-config.json /path/to/v6 /empty/v6-home candidate-compiler.json
# 基线 v5：使用真实 v5 模块目录，而不是给 v6 挂开关伪装
node replay.mjs run capture.json compile-config.json /path/to/v5 /empty/v5-home baseline-compiler.json baseline
```

会调用真实配置的副模型 API，可能收费；本批只执行了本地固定响应测试。工具锁定既定 1500／8000／1200、prewarm:false、流式响应，不部署、不改 profile。

报告明确为 `compiler-only-replay`：没有主模型、没有真实源时序调度、没有重复探索／错误走向标注，**不能用于通过产品验收**。由于两侧编译提示词不同，固定返回同一句话也不是比较真实成功率的方法。

### 产品验收

```bash
node replay.mjs evaluate baseline-full.json candidate-full.json independent-audit.json acceptance.json
# 没有资料时也可直接运行，结果必须为“未验收”并退出 2
node replay.mjs evaluate
```

完整宿主重放报告必须包含：

- `kind: full-session-replay`、完整性与真实模型运行声明、配对源 SHA256、相同 profileFingerprint。
- 所有编译终局 `compiles`，以及是否真正应用；不能以零调用／零应用通过。
- 每个主模型探索轮的 id、goalId、redundant 标注。
- 同一任务集合的 outcomes，防止少做任务换指标。
- 独立审核者、绑定两份报告具体 JSON 内容的 SHA256、所有成功编译和探索轮的审核 ID，以及错误状态导致错误行动的因果案例。

验收条件：timeout＋empty 严格下降、同目标重复探索轮严格下降、候选错误状态走错路为零；同时总编译失败不增加、任务结局不退步。资料不全是“未验收”，不是通过；有齐全资料但条件不满足是“未通过”。评估器不能自行认证外部记录或人工标签的真实性，仍依赖真实宿主材料与独立审查。

当前没有完整宿主重放驱动和生产访问凭据，不能把这个编译录制工具说成已完成真实主模型端到端重放。费用下降也未验收：需要实际输入／输出／缓存使用和结算，不能按字符数或测试数推出。
