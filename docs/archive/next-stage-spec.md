# 下一阶段实施规格（可逆上下文分层 v8）

> 面向实施模型的唯一说明。只写已定事实、硬约束、机制、禁止项、待查项。
> 不含实现代码、不含调参建议、不含任何"可以按数据拟合"的余地。

---

## 0. 目标（一句话）

在**不比宿主多制造一次前缀断裂**的前提下，把宿主强制压缩造成的信息销毁，替换为**可逆换址 + 有界索引 + 可检索归档**。

---

## 1. 基线事实（代码级已证，不要重新验证）

| 事实 | 值 |
|---|---|
| 宿主压缩默认在场 | `compaction` service 已注册 |
| 触发点 | `thresholdRatio = 0.8` |
| 保留 | `retainRatio = 0.16` |
| 动作 | 有损摘要 `<compacted-summary>` 分节 checkpoint |
| 多轮行为 | 指令明文 `Do not copy it forward`——旧 checkpoint 被主动丢弃，损失随压缩次数累积 |
| 断裂次数 | 由宿主决定，我们无权增加 |

**因此：任何"主动折叠"都是净损失。** 断裂是我们要消灭的成本，不是可以频繁使用的工具。

---

## 2. 五条硬约束（违反任何一条即为错误实现）

**H1｜不主动折叠**
折叠次数不得超过宿主本来的压缩次数。断裂零新增。

**H2｜两次压缩之间只追加，不改写**
任何对"已发送字节"的修改都造成前缀断裂。已发送内容一律不动。
推论：去重、取代只能在**内容产生时**执行（此刻 KV 尚未建立），加入后再删即违规。

**H3｜禁止任何价值预测**
禁止：打分权重、内容形状规则（结构标记/类型表）、"哪类信息重要"的启发式。
理由：这些只能从单一使用者的分布拟合，在大众分布上必然失效。
**唯一允许的排序信号**：年龄、最后触碰时间——可观测事实，零参数。

**H4｜索引必须有字节预算**
索引条目会线性增长，是新的无界历史。必须分层 + 固定预算。

**H5｜删除索引条目前，必须先有归档检索**
有检索：删条目 = 收回提醒位，内容仍可 search 到。
无检索：删条目 = 内容事实上不可达 = 等同于销毁。
**顺序不可颠倒。**

---

## 3. 四层模型

| 层 | 内容 | 位置 | 有界性 |
|---|---|---|---|
| **T0** | 最近窗（全细节） | 上下文 | 宿主 `retainRatio` 决定 |
| **T1** | 细索引：近期外置项，逐条可定位 | 上下文 | 固定预算 B1 |
| **T2** | 粗索引：较旧，按块聚合 | 上下文 | 固定预算 B2 |
| **T3** | 归档：原文 + **按内容检索** | 磁盘 | 字节级保真，受磁盘限制 |

**降级**：仅按年龄/最后触碰时间推进 T1→T2→出上下文（出上下文 ≠ 出 T3）。
**删除**：仅当 T3 可被按内容检索后才允许。

---

## 4. 机制

### 4.1 产生时外置（当前唯一可持续的优化点）

在 `tools/post-execute` 阶段（内容尚未发送）对超阈值结果外置。

**为什么它是主机制**：
```
到达 0.8 所需步数 = (0.8 × 窗口 − 固定部分) / 每步新增字节
→ 每步新增越小 → 触发越晚 → 压缩次数越少 → 断裂真的下降
```
这是唯一不制造断裂、且不需要任何预测的收益来源。

**限制（诚实）**：净收益取决于回读率。若模型频繁回读，每步字节可能不降反升。回读率真实值待真实数据。

### 4.2 索引条目格式

只描述"是什么 + 怎么取回"，**不是内容摘要**。
允许：范围列表、结构统计（`{user:5, tool:4, assistant:2}`）。
禁止：内容样本、语义概括——那会重新引入价值判断。

### 4.3 Pin（模型声明）

- 模型可显式 pin："这个后面还要用"
- **Pin 有固定上限（建议 ≤3）**，超出时最老的 pin 自动降级为普通条目
- 理由：无上限的 pin 会让索引再次无界

### 4.4 取回失败语义

`recover` 失败 → 相关结论标记为"缺证据"，**不得前进为 resolved / 无问题**。
（与既有 `K=U 不可冒充` 同原则。）

## 5. 禁止项（明确清单）

- ❌ 会话内主动折叠（违反 H1）
- ❌ 修改已发送消息（违反 H2）
- ❌ 打分 / 权重 / 内容形状分类（违反 H3）
- ❌ 无预算的索引（违反 H4）
- ❌ 在归档检索建成前删除索引条目（违反 H5）
- ❌ 用 mock 量化"摘要失真率"（那是模型能力，mock 测出的是自欺）
- ❌ 为触发压缩而补 mock 专用假路径（等于造仿真）

## 6. 待查项（实施前必须先回答，我给不出答案）

| # | 问题 | 影响 |
|---|---|---|
| Q1 | 宿主 `compaction` service 能否被覆盖/接管？ | 能 → 我们提供同触发下的更好表示；不能 → 压缩侧无事可做，价值全在 4.1 |

| Q4 | `contextWindow` 实际值、`restrict` 后 toolsBytes 实测值？ | 所有字节预算的分母 |
| Q5 | 真实回读率 | 4.1 的净收益方向；**只能来自真实数据** |

## 7. 验收（仅列离线可判定的，不含能力层）

1. **断裂次数 ≤ 宿主基线**（不得更多）
2. 所有已外置内容：T3 有原文 + 有取回路径（可枚举断言）
3. `recover` 失败时，相关结论保持"缺证据"，不变成 resolved
4. 同输入两次运行，索引状态完全一致（确定性；无拟合参数）
5. 每步新增字节相比基线不升高（代码级可测）

**不可验收（明确排除，不要假装能测）**：
- 模型是否会主动取回（需真实模型）
- 宿主压缩的失真率数字（需真实摘要，mock 无意义）
- 端到端成本/延迟（需真实网关）

---

## 8. 一句话定位（对外表述，不得夸大）

> 不是"无损系统"，是**记忆分层系统**：
> 上下文有界，归档字节级保真，中间层在预算内无损、超预算按年龄确定性地变粗。
> 与宿主原生的差别不是"我们不丢"，而是**我们只丢指针精度，且原文永远在并可被检索**。
