# 第二批优化：记忆可信度、身份隔离与安全停用

日期：2026-09-22。
基于第一批本地修改版继续工作，未推送 GitHub、未调用外部模型、未部署到用户网关。

## 这轮为什么先做这些

第一批处理“已有产物丢失、覆盖过滤不可靠、重复读取事件”。第二批优先防止**记忆本身给主模型错误的确定性或错误关联**。

结构化记忆不能因为存盘了就变成观察事实；两个编译批次都叫 m1，不代表说的是同一个对象。同样，A 会话已经取得的流不能在稍后执行时突然读取 B 会话的配置。

这些是减少错误坚持与返工的必要基础，但本地回归不能证明真实任务正确率已经提高多少。

## 已完成

### 1. 编译输出不再自动升级成 observed

`generateStateMemory()` 原来把六栏文本解析后的每一条标成 `evidence:'observed'`，即使它只是模型判断、用户报告或未确认假设。

现在：

- 生产编译条目默认 `origin:'model', evidence:'inferred'`；
- 并行块的 `mergeOrdered()` 默认同样是 inferred；
- 条目时间使用输入冻结时点 `env.at`，不再用网络完成时间冒充形成顺序；
- birth 和 checkpoint 输出加入一条简短的来源说明；
- 显式、可信调用路径提供的工具观察仍可保留 observed，不把所有事实一律降级。

这里的 inferred 表示“模型编译产物尚未逐条独立核验”，不是断言内容为假。原始工具证据仍完整归档。

**尚未实现**：模型输出可机器验证的 evidenceIds／修正关系协议。没有假装仅凭这次改动就完成了逐条事实核验。

### 2. 编译提示词不再制造确定性

修正状态编译提示词中的三处冲突：

- “已保存快照＝权威基线、非推测”改成“完整保存的模型编译记录，不提升原证据权限”；
- “新材料自动优先”改成“比较来源、适用范围和证据，拿不准保留分歧”；
- 删除禁止不确定措辞的笼统要求，保留材料里的“可能／未确认”；
- “禁止再动代码 ⇒ 代码修改阶段已结束”改成如实转述用户禁止，不新增阶段完成事实；
- 不再要求将一切内容写成过去时／完成时。

六栏格式、maxOutputTokens、模型、timeout 和 finishWaitMs 不变。旧的非 stateMemory 蒸馏提示词本轮未改。

### 3. 条目身份不再冒充对象身份

- 生产每次状态编译创建独立 UUID 命名空间，条目形如 `compile-…:m1`；
- `createMemoryProjection({namespace})` 支持显式命名空间，其内部修正链接保持一致；
- 投影保留调用方明确提供的 objectId、problemId、propositionKind，不自行推导；
- 无 objectId/scope 的条目不再靠 id 或 Math.random() 建立比较槽，而是独立保留；
- 已有旧快照中同名 m1 的不同条目，也不会仅因名字相同在后续归并中被比较。

默认纯函数调用仍可使用 m1，保持原接口兼容；关键是生产编译使用唯一前缀，归并不再以裸条目 ID 推断对象。

不能逆推出已经在旧版归并中丢掉的文本；这部分仍需原始证据重新编译。

### 4. 相同文字也必须先检查范围

原去重发生在 scope 检查之前。因此，同一个对象在配置 A 和配置 B 下都写“测试通过”，其中一份可能被丢掉。

现在先检查命题种类与适用范围，再检查字面重复；证据等级、有效性不同的记录也不直接合并。相同范围与状态的重复 evidenceIds 用 Set 合并，防止引用列表重复膨胀。

本轮没有重写全部归并算法。例如存在显式 scope/objectId 时，强弱证据与修正关系的更细裁决仍需后续结构化引用协议支持。

### 5. 旧快照兼容：保留正文，撤销不可靠覆盖权限

新增独立字段 `memoryPolicyVersion:2`。文本编译格式仍是 state-v1，快照文件结构版本仍为 1；因此可以显式读取并归一化旧文件，而不是因整体版本不匹配直接失忆。

对没有 policy 字段的旧快照：

1. 保留全部现存条目正文；
2. 对模型来源的 blanket observed 降为 inferred，保留 legacyEvidence 标记；
3. 可见文本显示“旧版模型编译记录，未独立核验”；
4. 清除旧 coverage 的省略权限和不可靠 applied 标记；
5. 读取过程不改原文件；下一次成功提交时写入 policy 2，并只重新覆盖本次实际编译的证据；
6. 记录 migratedFromPolicy，归一化重复执行不继续改变状态。

为什么撤销整个旧覆盖集合：旧版可能已经把不同编译里的同名 m1 错误合并，不能仅凭现存条目推断哪些证据仍被完整承载。

**明确代价**：迁移初期可能重新发送更多工具证据，甚至重新遇到大输入超时。这是保真回退，不是本轮性能收益。旧快照正文仍作为带来源限制的 prior state 提供；冷启动／增量批次编译仍是后续工作。

未来未知 policy 或损坏快照拒绝读取；本轮进一步禁止 commit 直接覆盖这种现存文件。原文件保留，提交返回 invalid-existing-snapshot，等待明确恢复处理。

### 6. 停用与 dry-run 真正作用于 birth 流

- enabled=false 或 mode=off 时，llm/stream 返回宿主原流，不启动后台编译或归档；
- birth dryRun 保留现有观测，直接返回原流；不执行 birth 转换、不调用提纯模型、不写 reasoning 归档；
- 直接调用 birthStart 的 dry-run／disabled 也有门禁。

这是可见行为变化：birth dry-run 不再是付费“影子编译”，而是观测与透传。如将来需要付费 shadow 模式，应另加明确开关，不能复用 dryRun 隐含开启。

### 7. 同模型换 provider 与流执行身份冻结

原 provider 更新位于“模型名变化”分支内，同模型换端点时不会更新。

现在模型或 provider 变化都能触发跟随；每条 birth 流在取得时捕获：

- session 对象与 sessionId；
- branchId；
- 模型／provider 及本次配置；
- 证据采集使用的 session。

之后 B 的 pre-step 或 provider 更新不会改变已经取得的 A 流使用的这些值。

本地端到端测试使用两个真实 loopback HTTP 路径与两个测试凭据，验证 A/B 请求的 URL、model、Authorization、用户证据、归档 sessionId 和快照分支均不串用。

**边界**：这解决的是“流已取得之后被共享变量污染”。若宿主在 llm/stream 回调之前已经交错 pre-step，而且没有提供请求所属 session 标识，本插件仍不能凭空辨认归属。因此不是宣称所有宿主并发时序已解决。

迟到结果依然主要以 sessionId + reasoning 原文关联，消息级／分支级精确认领身份仍待宿主接线。

跳过项仍为需要宿主兄弟包的集成断言，不能宣称真实 DSH 验收已完成。没有网络商户请求，没有真实模型效果评估。

3. 恢复以条目 ID 作为对象身份；
4. 将去重移到 scope 检查之前；
5. 保留旧快照覆盖权限；
6. 取消旧模型证据降级；

## 预期效果与不能承诺的效果

可由本地代码验证的效果：

- 不再因编译／存盘就授予观察事实等级；
- 不再仅因 m1 同名让无关联条目互相覆盖／冲突；
- 不会因文字相同丢掉不同配置下的状态记录；
- 停用和 dry-run 不再意外消耗提纯调用；
- 已取得的流不随后续请求改变模型、端点或证据会话。

这批不是“大幅缩短 token”的补丁。来源说明增加少量可见字符，保留原本被错误去重的记录可能增加长度，旧快照迁移可能暂时恢复全量证据。其目标是降低错误记忆驱动返工的风险。

不能据此宣布：任务正确率提升某个百分比、成本下降某个百分比、已经达到最佳上下文。

## 下一步最值得做

1. **会话级编译批次队列**：固定本批截面，在飞期间累计下一批，不重复编译同一批工具历史。需同时设计块级产物与消息身份关联，不能仅串行化 Promise 就声称完成。
2. **可验证的状态增量协议**：条目引用证据 ID、保留命题／范围／关系，由宿主确认来源等级；避免让模型每轮重写整份六栏。
3. **覆盖依赖感知的工作集投影**：减少旧状态渲染量，但只有完整承载的证据才允许省略；不靠截断和字符预算删除不确定性。
4. **真正的 CAS 镜像恢复接线**：当前仍是本地文件快照优先；此前报告中的未接通问题未在本轮冒充修复。

上述路线全部完成后的目标形态是：主模型优先看到当前目标、有效约束、关键证据和未决差距；后台只处理新到证据与必要修正；历史正文可按来源恢复，不必每轮全量重发，也不会因为投影变短就静默撤掉约束。预期减少重复探索和重复输入，但总成本与任务正确率仍需同任务、同验收条件的实测，不能从字数直接换算收益。

## 使用

- 已用第一批源码：应用 `cfb-phase2-incremental.patch`。
- 仍是 GitHub 原提交：使用包含两批改动的 `cfb-optimized-v2.zip` 或累计补丁。
- 不要把累计补丁再次应用到第一批修改树上。

```sh
node verify.mjs
node manifest.mjs --check
```

部署继续采用原 file: 依赖副本刷新流程，先备份插件和本地 snapshots 目录，再删除安装副本、pnpm install --ignore-scripts、体检、重启。未改 profile 中任何预算／模型配置。
