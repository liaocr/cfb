# v8：共享重复证据展示，不减少核对材料

日期：2026-09-22。基于最终 v7；未部署、未推送、未修改宿主 profile。

## 本轮重点

不再改变证据保留策略，而是减少两类确定性重复工作：

1. 同一请求中，同一份工具正文因为“普通／失败／最近结果”的视图不同，被反复展示重叠片段。
2. 同一批观察中，相同正文被重复计算 hash、重复读取磁盘校验。

同时修正生产与编译重放的准备逻辑差异。没有新增开关、模型调用或等待预算，没有恢复 v6 的正文移除。

## 1. 同一请求内合并区间，保留所有事件

v7 按“正文 hash＋截取区间”去重。如果同一份20000字符正文分别出现为普通结果、错误结果和最近结果，就会产生三份视图：

- 普通：`[0,1200)`；
- 错误：`[0,8192)`、`[18800,20000)`；
- 最近：`[0,4096)`、`[18800,20000)`。

v8 根据**完整采集文本精确相等**分组，对该组要求提供的区间求并集，只显示一次：

`[0,8192)`、`[18800,20000)`。

不是按相同前缀猜全文相同，不按相同工具名、任务目标或事件 ID 合并。普通结果、失败结果、取消、空返回及无序号结果继续沿用 v7 的选取规则。

### 不合并的东西

每条调用仍有自己的 id、callSeq、resultSeq、参数、status、exitCode、isError 和上游截断标记。共享正文不是“这些调用发生过同一件事”，更不是“多个调用只发生一次”。

正文在首次引用处展示，事件行保持原顺序，没有把所有正文搬到最前面、所有事件搬到最后面。每条回执包含：

- `bodyLabel`：明确引用哪一份展示；
- `requestedRanges`：v7规则要求的原区间；
- `ranges`：实际展示的并集区间；
- `sourceTruncated`、`providedComplete`：逐事件判定，不能让一条完整来源替另一条截断来源背书。

区间使用 JavaScript UTF-16 半开区间，不是 token 或 UTF-8 字节偏移。相邻区间直接连接，不再插入实际上并不存在的“中间未提供”提示。

### 能证明与不能证明

本地样本验证：三条事件的正文展示量由15888字符变为9392字符，原有每个选取区间都能从新展示中逐字恢复。该数字只是**合成样本中的重复正文删除量**，不是生产 token、账单、吞吐或正确率提升。

100组确定性混合工作负载逐事件核对了旧区间覆盖与正文一致性，包括正常／失败／取消、不同长度、中文和 emoji。另测了同前缀不同后缀、源截断标记顺序反转、空结果、缺序号和 pending。

没有重复正文时，不存在这类新增去重收益。提示词表示方式改变也不等于已经证明模型理解无损；真实任务质量与压缩率仍须重放验收。

## 2. 减少单批本地重复 I/O 与 hash

证据账本新增**只在本次同步准备批次内**有效的检查缓存：

- 相同正文的来源 hash 计算一次；
- 同一不可变文件在同一批次只读取校验一次；
- 正文校验复用刚计算的来源 hash；
- 跨批次不沿用旧文件校验结果。

测试中，三条相同正文观察第二次进入准备时，正文来源 hash 计算一次，命中两次批内文件校验缓存。随后在批次之间修改文件，下次准备仍检测到损坏并转入既有内存证据回退。

这减少的是重复操作，不是宣称端到端耗时下降了某个百分比。生产 `evidence-prepare-cost` 现在同时记录该批 I/O 计数；实际磁盘和模型耗时仍需真实环境观测。

## 3. 生产与重放共用准备逻辑

新增共享入口 `prepareCompilerEvidence`，生产 hook 与 v8 编译重放直接使用它，统一：

- 正常持久化准备；
- `stateSnapshot:false` 的内存证据路径；
- 配额、锁冲突和文件错误后的回退。

v7 重放器之前直接调用持久化函数，并不完全等同于生产的回退行为。本批修正这一差异，HTTP 测试确认停用持久化时仍把错误正文交给副模型、没有伪造索引，也没有意外建立证据目录。

录制器还会报告已知发生、但缺少持久化 frame 的临时输入编译，不能静默漏掉它们再宣称录制完整。这里没有凭 trace 中的 hash 反造原文。归档回执关联改为一次索引，避免对每个 frame 反复扫描整份日志。

旧版本候选模块的重放兼容仍保留；基线比较应使用真实旧版本模块目录。编译器重放仍不是完整主模型重放。

## 4. 本轮没有改变的边界

- reasoning 全文、用户原话、运行材料、正常／错误工具证据的 v7选取规则不减。
- 不做跨请求“已记录所以可省略”的语义去重。
- 1500／8000／1200、ready-only 的适用条件、迟到认领和原文兜底门禁不变。
- 不修改主模型工具消息、surface 协议或 profile，不增加模型链。
- 不自动跨重启认领来源身份不足的旧结果。
- 新增存储配额、满额回退和无引用对象清理继续沿用 v7。

## 5. 验证与交付

新增10项检查；5项源码反证均检出并恢复：错误合并相同前缀、丢掉后续要求区间、提升截断来源、跳过跨批文件校验、重放绕过生产准备。

全量：1124通过／0失败／1宿主跳过，16套件。v7 的完整迟到认领、append失败重试、满额后继续消费等回归仍通过。

记录目录：`docs/optimization-evidence-v8/`：

- `range-preservation.json`：合成区间保留样本；
- `mutations.json`：反证结果；
- `verification.txt`：全量回归；
- `product-acceptance.json`：真实产品验收仍为**未验收**。

完整交付包：`cfb-v8-delivery.zip`。包含完整插件、最终v7到v8的增量补丁、原始基线到v8的累计补丁。

常用命令仍为：

```bash
node verify.mjs
node manifest.mjs --check
node analyze-consumption.mjs trace.log consumption.json

```

录制／编译重放的参数见 `HYBRID-COMPILER.md` 的工具使用部分，消费与存储维护见 `GROUNDED-COMPILER-V7.md`。

**本批证明的是选取证据未减少、重复展示和重复操作被去掉，不是已经证明真实任务性能、压缩率或账单收益。**
