# CFB 统一优化交付：范围回执、输入工作集、快照镜像与故障门禁

2026-09-22。基于原仓库 5a4def6 与此前三次本地优化继续开发。

**本次一次性交付代码、接线、回归、副作用验证和补丁。未推送 GitHub，未部署用户网关。**

## 1. 这次实际完成的闭环

```text
宿主工具事件（不改原文）
    ↓ 完整正文哈希 + 结果身份 + 确切区间
有界编译输入工作集（元信息保留，缺口明确）
    ↓ 同一次六栏编译，不新增模型调用
完整响应 + 原始 reasoning CAS 成功
    ↓
本地原子快照：entries + 整结果覆盖 + 范围输入回执
    ├─ 下轮携带完整可见快照，才允许复用范围
    └─ 独立后台 cot-snapshot 镜像
           ↓ 重启／本地缺失
       分页读到 EOF + 完整哈希 + 会话／分支／版本校验
           ↓
       安全物化本地状态；失败则保留原文、重新编译
```

这是后台**编译输入**工作集，不是裁剪主模型工具消息，也不是已经完成了主对话语义工作集或完整的条目关系验证系统。

用户材料改变了优先级：当前负载更接近串行，第三批并发通道不作为当前主收益依据。材料的核验边界见 `PRODUCTION-EVIDENCE-RECONCILIATION.md`。

## 2. 范围回执：不再把看到片段等同于看过全文

新增 `evidence-views.js`。

回执身份包含：

- 结果事件序号、tool-call ID、工具名和参数；
- 生命周期、退出码、错误标记；
- **完整源正文 SHA-256** 和长度；
- 视图策略版本、区间边界和块大小。

这里的“完整源正文”指适配器收到的结果事件文本，不证明工具自身没有限制 stdout 或文件读取范围。

会话与分支由快照文件及读取校验隔离。区间单位明确是 **JavaScript UTF-16 offset**，不是字节；不切开有效 surrogate pair。

完整正文未变、来源身份相同、区间相同，才可能复用。即使只改了未读后缀而长度不变，旧回执也失效。调用方已经截断的源文本或缺少结果序号，不获得这种复用身份。

回执是“这个范围进入过一次完整成功并可靠保存的编译”的记录，**不是逐条结论正确性证明**。模型没有独立引用验证能力，摘要遗漏风险仍需真实任务语义验收。

### 持久化约束

- 只有成功编译＋reasoning 归档成功＋本地提交成功才持久化回执。
- entries 与 viewReceipts 在同一个原子文件中提交，不拆成先推进水位、后写正文。
- 回执最多 4000 个，淘汰只导致重发，不赋予新覆盖权限。
- 读取旧 policy 时不凭空产生回执；数据结构兼容当前 policy 3。
- 快照无效、超过完整渲染上限、关闭覆盖复用或时间截面不允许：不复用回执。
- 不再凭整体工具 seq 对新视图路径过滤正文，避免绕过正文哈希和范围校验。

## 3. 输入工作集：控制每次工作量，而不是扩大等待

新增开关 `stateEvidenceViews`，默认关闭；配套 `stateEvidenceBodyBudget` 默认 6000。

开启后：

- 工具名称、参数、状态等元信息保留；参数沿用 400 字符上限，但新视图显式显示截断标记，并在已选结果头部呈现参数；用户原话、runtime、原始 reasoning 不由这条路径裁剪。
- 每个工具每次最多选择一个约 600 字符区间。
- 初次先看头部，成功后可推进到尾部，再逐步进入中间。
- 优先错误结果，再按近期顺序分配预算。
- 已覆盖区间由完整快照承载；未选中的正文明确标注“本轮未纳入”，不写成空结果或未执行。
- 提示词要求保留真正影响验收的未知，不为每个未纳入工具机械生成一个新缺口。
- 六栏主要输出本轮新增、修正、分歧和关键约束，避免逐条重复未变化背景；没有换输出协议。

### 这里的 6000 是什么

它只约束工具**正文视图**，不是整个 prompt、不是 token 数，也不是主对话窗口上限。元信息、用户要求、reasoning 和完整快照仍会占用输入。没有为了硬凑总长度而截断约束或快照。

### 代价与范围

这不是无损地把同样多的证据压小，而是**在本轮明确少提供一些片段**，再按成功回执推进。某些重要信息可能位于尚未选择的中间区间；事件可能在完成全部区间前离开采集窗口，不能承诺最终必读全文。

原始工具事件没有被该路径改写，但本轮也没有新增自动跨窗口、按任务需求检索所有旧工具正文的能力。

快照仍须完整可见才允许复用；快照增长超过 12000 字符时会安全退回不复用，而不是把部分状态冒充全量承载。本轮不静默删除旧约束／冲突来解决状态增长。

## 4. CAS 不再只有一个未被调用的恢复函数

新增 `stateSnapshotMirror`，默认关闭。

### 写入

生产代码现在实际调用：

```js
store.putText(snapshotJson, {
  producer: 'cot-snapshot', sessionId, retention: 'session'
})
```

- 成功的本地提交之后，用 setImmediate 独立调度；不把镜像 Promise 挂进 birthFinish 等待。
- pre-step 发现已有合法本地快照时，也能后台补镜像，不必等待一次新的模型成功。
- 相同内容在本进程内复用成功写入回执，避免每轮重复登记。
- 镜像写入按会话／分支有界排队，保留在飞和最新待写；失败不回滚本地成功状态。

这减少重启后的状态丢失风险，但不是同步双写事务：本地成功与镜像成功之间仍有崩溃窗口。不会声称每份最新快照一定已进入 CAS。

### 恢复

pre-step 检测本地缺失后启动后台恢复，不等待它再放行主请求。恢复若没赶上当前编译，当前任务保持既有兜底，不延长 finish。

恢复流程：

1. 按 session 与 producer 查询 catalog；
2. 使用带 sessionId 的 readRangeByHandle；
3. **必须分页读到 atEof**，不把 catalog.lines 当作完成证明；
4. 无进展、格式错误、超过 4 MiB 或 200 页时拒绝不完整结果；
5. 校验完整内容 SHA-256、结构、版本、sessionId 与 branchId；
6. 在最多 100 个近期候选中选最高 revision，而非盲选最新时间戳；同最高 revision 内容冲突则拒绝猜测；
7. 本地锁内物化；不覆盖新版本，也不自动覆盖损坏或未来版本的现存文件。

历史六栏渲染文本不会被用于初始化覆盖集合。旧成功产物如果根本没有结构化镜像，仍不能凭空恢复。

恢复任务有去重、30 秒失败重试间隔与活跃任务容量限制；缺 store 服务不会破坏主 pre-step 决策。真正宿主的所有权拒绝、磁盘故障与网关重启还需在宿主侧验收，本地只验证了给出的 API 形状。

## 5. 一并修复的漏洞与观测问题

### SSE 的坏帧不能被当成“没关系，继续拼”

旧收集器可跳过坏 JSON 帧后接受后面的 stop，存在半成品被接受的风险。现在仍能保留解析诊断，但完整性门禁拒绝含坏帧的结果，JSON 请求收到 SSE 的错配路径也一样。

SSE 接收的 4 MiB 上限从注释变成真实拒绝门禁，避免长残行和事件缓冲无限增长。

### 不把所有 4xx 当成 thinking 参数不兼容

参数降级候选限制到 400/422。401、403、429 等不再因此追加一次同样无效的降级请求。没有声称 400/422 重试必然免费或必然有效；maxAttempts 的显式设置仍保留。

### 倒置替换区间拒绝执行

emitCheckpoint 对非法／倒置目标区间直接拒绝，不 Math.min/Math.max 交换后继续删除。没有改宿主历史日志。

### 观测能关联到实际任务

- 每个 birth 任务新增 taskId，起飞、终结和 finish 路径使用同一 ID；它不注入模型提示词。
- 缺失失败原因明确记 unknown-failure，不编造 timeout。
- 超时阶段区分 await-headers、await-first-event、receive-body；修正了原来统一写 await-response 的断言。
- BOOT 依赖指纹纳入 compile-lane.js 与 evidence-views.js。
- 诊断身份纳入完整快照文本、视图区间、runtime/priorMemory 与覆盖状态，避免同长度内容碰撞。它目前主要用于 trace，不把这项说成已经接通模型缓存。
- 新增 `deploy/analyze-trace.mjs`，严格锚定日志前缀，按 BOOT 分组。

## 6. 验证：包含可观测副作用，不只测纯逻辑

新增 **41 项检查**，总计 **1073 通过、0 失败、1 项宿主相关检查跳过，12 套件**。

关键断言直接检查：

- snapshot 文件是否实际写入 viewReceipts；
- 后一次串行请求发送的范围是否真的从头部变成尾部；
- trace 是否出现 state-evidence-view 和 state-snapshot-committed；
- 生产 llm hook 是否实际调用 producer=cot-snapshot；
- pre-step 是否真的从模拟分页 CAS 物化文件，而且不等待被阻塞的读取；
- 现存合法文件能否在没有新模型成功时补镜像；
- 失败、锁竞争和坏哈希是否没有副作用。

**11 项撤回反证全部检出**，包括禁用回执写入、绕过预算、去掉完整正文哈希、提前认定分页 EOF、删除镜像接线、接受坏 SSE 等。恢复源码后再全量验证。

旧测试只有超时阶段的预期标签从 await-response 调整为 await-headers；没有通过删掉失败用例来增加通过数。

### 串行 SSE 实验——不依赖并发

夹具：28 条不同的 3299 字符工具结果，三个请求逐次完成，无重叠；服务返回固定六栏文本。是长结果压力样例，**不是用户真实分布回放**。

| 指标 | 原输入路径 | 范围工作集 |
|---|---:|---:|
| 模型调用数 | 3 | 3 |
| 每次工具正文字符 | 33,600 / 33,600 / 33,600 | 6,000 / 5,990 / 6,000 |
| 实际发送 prompt 字符 | 39,718 / 39,958 / 39,980 | 12,715 / 13,215 / 13,007 |
| 三次 prompt 合计 | 119,656 | 38,937 |

字符变化约 **67.5%**，包括少提供正文片段的贡献，不能称为相同完整信息的无损压缩。未测真实模型语义质量、主对话后续 token、缓存命中、账单或生产成功率。

证据在 `docs/optimization-evidence-v4/`。

## 8. 交付边界

代码里现在接通了范围输入复用、编译输入工作集、输出重点提示、CAS 写入与后台恢复。但没有把以下事情冒充完成：

- 逐条结论的独立证据引用核验与语义修正 reducer；
- 主对话的完整语义工作集、跨窗口按需取回所有旧正文；
- 主消息／分支／事件身份齐全的迟到结果认领；
- 无限增长状态的可证明安全裁剪；
- 真实商户 API、宿主模块或 TypeScript 编译器验收。

因此可以确认本地失败门禁、输入体量变化与副作用接线；不能确认线上成功率从 2.6% 提升到了多少。没有推送或部署。
