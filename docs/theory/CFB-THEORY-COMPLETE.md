## 阅读指引

**出发点（用户论点）**：主模型的 CoT 约 90% 是转弯打折、左右互搏、陷入死路。这些噪声会分散主模型的注意力；清理、编译历史，能提升主模型的专注力和判断力。目标是**让主模型更好**，不是省钱，也不是“不掉分”。

**理论的主干，一条线串起六卷**：

1. **第一卷**把“压缩”重新定义为“编译”：历史应被编译成**状态**（事实 / 已关闭 / 现行方案 / 未决 / 计划），长度是编译的**输出**而不是参数；死路是疫苗；历史是示范。
2. **第二卷**摊开全部三十条优化方向，覆盖编码、注意力、信息、策略、时间、系统六个层面，外加一层“反面”（哪里会压过头）。
3. **第三卷**找出三十条方向底下共同的**七个机理**（注意力预算、归纳复制、信念锚定、分布熟悉度、token 即算力、否定薄弱、长度倒 U），写成统一目标函数 J 与逐条目取舍式 v(i)，并解出十三组相互作用中的冲突。
4. **第四卷**把 v(i) 的每一项落到**可观测量**上，发现唯一自由参数是 token 影子价格 λ；再把 λ 的调节形式化为**反馈控制问题**（三个工作区、四条定律、AIMD 控制器）。
5. **第五卷**推进六个开放问题（动作锚定、替代先行、体裁伪装、证伪/搁置拆分、次模选取、自镜像），并收束为**v4 编译器规格**：副模型只做标注，代码负责写作。
6. **第六卷**把理论推出单个上下文窗口：**跨会话疫苗记忆**（负知识优先、证据指纹、防投毒）与**宿主压缩协议**（晋升、无损重算、钉住、委托缩减，整条链路恰好一次有损）。

**如果只读一部分**：
- 想知道“为什么删冗余能让模型更好”：第三卷第一部分 + 第四卷 C 节。
- 想知道“具体怎么做”：第五卷第二部分（v4 规格）+ 附录 B。
- 想知道“长会话会不会越压越糟”：第四卷 B 篇 + 第六卷第二部分。

## 全部原则与定律索引

以下只是**索引**（一句话 + 出处），完整论证见各卷原文。

**卷一 · 七条定理**
- T1 状态充分性：历史应编译为 FACTS / CLOSED / INCUMBENT / OPEN / PLAN。（卷一 §1）
- T2 长度是编译的输出，不是参数。（卷一 §2）
- T3 死路是反先验疫苗。（卷一 §3；已修订，见对照表）
- T4 历史即示范：事后最优推导塑形后续策略。（卷一 §3）
- T5 读回缓存规则：可逆性改变压缩极限。（卷一 §4）
- T6 一致性守护：跨块状态演化，不每块重写。（卷一 §5）
- T7 压缩率是元认知信号：原始 ÷ Δ状态 = 打转检测器。（卷一 §6）

**卷三 · 九条贯通原则**
1. 冗余 ≠ 噪声。
2. 粘性按证据分配。
3. 否定必须配对、局部化；低诱惑度的负知识不写。
4. 示范密度，而非简短。
5. 自包含。
6. 双编码。
7. 两层版面，价值靠尾。
8. 来源不可洗白。
9. 可逆到分支级。

**卷四 · A 篇结论**
- A2 推论：结论复述 D 低，转折句 D 高；“90% 冗余”= 给定 λ 下 v≤0 的 token 占比。
- A3 结论 1：诱惑度是公因子，T→0 的死路永远不写。
- A3 结论 2：配对是必要条件，未配对的否定是负价值。
- A3 结论 3：高投入死路的价值随投入近似二次增长——浪费最多的地方，编译后价值最高。
- A4：同一句话的价值取决于上下文里还有什么（中和项 Neut）。
- A5：证据等级决定渲染确定度（tool 陈述 / derived 暂定 / guess 问句）。

**卷四 · B 篇四条定律**
- 定律 1 单次有损。
- 定律 2 锚定自然文本（最近一块 raw-near，编译占比设上限）。
- 定律 3 难度自适应价格：卡住时少压；打转靠 v 删，不靠 λ 删。
- 定律 4 价值随时间迁移，而非随时间删除（多级缓存）。
- 控制器：丢失信号乘性降 λ，噪声信号加性升 λ；同一症状（打转）用 s_w 区分“压不够”与“饱和”。

**卷五 · 六个推进**
- P1 动作锚定律。
- P2 替代先行、最小可辨识具体度、X 只出现一次。
- P3 近因加权 s_w、体裁伪装原则。
- P4 effort 分解；REFUTED / SHELVED 拆分。
- P5 次模 + 划分拟阵 + 支撑闭包；重复的阈值化。
- P6 自镜像原则。

**卷五 · v4 硬不变量 I1–I7**
- I1 anchor 逐字；I2 标识符有出处；I3 REFUTED 须工具证据且带替代；I4 非工具否定一律 SHELVED；I5 工具来源永不写成“我决定”；I6 已编译文本永不作为副模型输入；I7 同键一个当前值。

**卷六 · 原则 10–18**
10. 跨会话不对称：负知识优先。
11. 保守归纳：只存实例层与模式层。
12. 证据指纹：指纹变化自动降级；一次反例立即失效。
13. 记忆写入即安全边界。
14. 在诱惑出现时接种（pre-step 预防，birth 补救）。
15. 出生文本是暂存层，高价值条目在清除前晋升。
16. v 依赖上下文，重算必须无损。
17. 钉住与委托：宿主委托 `reduce` 时整条链路恰好一次有损。
18. 缓存搭车。

# 第一卷　出生即压缩的极限理论：从「压缩器」到「认知编译器」

> 性质：理论稿。目的：把「出生即压缩」从「把文本变短」推到它的理论极限，并说明极限处的机制长什么样。
> 本文不讨论省钱，只讨论主模型的专注力与判断力。

---

### 0. 一句话

现在的压缩：**一段文本 → 一段更短的文本**。
极限处的压缩：**一段搜索过程 → 这段搜索留下的认知状态**。

思维链不是文章，是搜索轨迹。转弯、互搏、死路是搜索的*过程*；主模型往后需要的只是搜索的*结果*，也就是**状态**。把过程编译成状态，这不是摘要，是**编译**。

---

### 1. 第一原理：状态充分性

**定义 1（思维链 = 搜索轨迹）。** 一块 reasoning 是主模型在「假设 × 方案」空间里的一次搜索：提出、展开、验证、回溯、剪枝。

**定义 2（认知状态）。** 借用搜索理论（A*）与 POMDP 的概念，一次搜索在任意时刻的状态由五部分组成：

| 分量 | 含义 | 例 |
|---|---|---|
| FACTS 事实 | 带来源的观察 | `npm test` 报 `EACCES /home/u/.dsh/cas`（工具输出） |
| CLOSED 闭集 | 已剪掉的路 + 剪枝理由 | 锁文件未释放 ✗（fs-lock 检查正常） |
| INCUMBENT 现任判断 | 当前采纳的结论/方案 + 依据 | 根因是 DSH_HOME 路径错配 |
| OPEN 前沿 | 还没解决的问题/分支 | verify.mjs 是否也受影响？ |
| PLAN 计划 | 接下来要做的事 | 改 onboard 的 DSH_HOME 解析 |

**定义 3（冗余）。** 给定状态 S 之后，与主模型未来决策**条件独立**的那部分轨迹，就是冗余。

**定理 1（状态充分性）。** 若 S 是轨迹对未来决策的充分统计量，则用 S 替换轨迹，决策能力零损失，噪声归零。
（这是 POMDP 里「信念状态是历史的充分统计量」在思维链上的对应。）

⇒ 压缩的极限不是「压掉 90%」，而是**压到状态本身为止**。压到状态以下才开始丢信息；停在状态以上就是还有噪声。

**定理 2（绕路无关性）。** 状态的大小只取决于 |FACTS| + |CLOSED| + |INCUMBENT| + |OPEN| + |PLAN|，**与模型绕了多少路无关**。
一条死路，不管原文里互搏了 3000 字，在状态里只是一行 CLOSED。

推论：
- 你实测的 90% 冗余，就是「绕路量 ÷ 轨迹长度」。
- 块越长，绕路占比越高（绕路随搜索深度超线性增长，状态次线性增长）⇒ **大块的理论压缩率高于小块**。
- **长度不应是输入参数，而是编译的输出。** v3 的固定 250–450 字、v4 的按比例 8%，在原理上都是错的：该多长，由这块搜索实际产生了多少状态决定。

### 2. 第二原理：该留什么——再推导代价 × 决策相关

状态内部也不是等价的。一条信息值得留在主模型眼前，当且仅当：

> **再推导代价高**（主模型自己想不回来，或要重新试错才能得到） **且** **影响未来决策**。

| 原文成分 | 再推导代价 | 决策相关 | 处置 |
|---|---|---|---|
| 计算过程 | 低（能重算） | 只有结果相关 | 删过程，留结果 |
| 已解决的转弯/互搏 | — | 不相关（已解决） | 删 |
| 死路的**结论**（X 不行，因为 Y） | **极高**（要重新试错） | **极高** | **必留**，一行 |
| 模型本来就会假设的常识 | 低 | 低 | 删，即使是真的 |
| 出乎模型意料的观察 | 高 | 高 | 必留，逐字 |

**定理 3（死路价值定理 / 反先验信息）。** 模型之所以走进某条死路，是因为它的先验认为这条路有希望。所以**同一个模型将来再走进它的概率也高**。
一条死路记录的价值 ∝ P(模型会再试) × 再试一次的代价，而恰恰因为它已经试过一次，P 就是高的。

⇒ **CLOSED 闭集是整个状态里信息价值最高的部分**：它是专门对抗模型自身先验的「疫苗」。
⇒ 反过来，**符合模型先验的内容价值最低**：模型自己想得到的，不用写。
「留什么」的判据可以统一成一句：**只留对主模型来说出乎意料的东西**（高惊奇度）。

### 3. 第三原理：历史就是示范——上下文内的策略塑形

前两条讲的是**信息通道**：去掉噪声，信号占比从 10% 变成接近 100%。
还有第二条通道，现有方案都没用上：**策略通道**。

**事实基础。** 模型会以自己的历史为条件：历史里有自己犯过的错，后续出错率就会上升（self-conditioning），而且**扩大模型规模也消除不了**（arXiv 2509.09677）。
历史不只是信息，也是**示范**：模型会模仿自己历史里的思考方式。

**对称假设。** 如果满是自己错误的历史会让模型更容易犯错，那么**干净、果断的历史会让模型更果断**。

**定理 4（塑形复利）。** 设每轮清理让下一轮的绕路率下降一个比例 ε，则 n 轮后绕路率约为 r₀(1−ε)ⁿ（直到某个下限）；
不清理时，self-conditioning 让绕路率随历史里积累的错误上升。
⇒ **两者的差距随会话长度扩大**。长任务是这个理论的主战场。
⇒ 这是一个正反馈飞轮：历史越干净 → 新思维链绕路越少 → 需要清理的越少 → 历史越干净。

**机制推论：事后最优推导（Hindsight Derivation）。**
出生文本不应该是摘要，而应该写成**主模型如果一开始就知道答案、会写出的那段最短推导**：从证据直接走到结论。
这是强化学习里「事后重标注」（HER）和 STaR「合理化」的思想，**第一次用在推理时、用在智能体自己的记忆上**。

**必须处理的张力：Stream of Search。** 训练时，看完整搜索过程（含回溯）的模型，比只看最优路径的模型搜索能力高约 25%（Stream of Search, 2404.03683）。
这是否意味着不该删绕路？不。两者回答的是不同问题：
- SoS 教的是「一般地怎么搜索」（训练时的能力）；
- 同一问题的上下文里，主模型需要的是「搜索现在在哪」（状态）。

解法：**事后推导 + 闭集清单一起出现**。主模型看到的是「我探索过、剪掉了这些、然后直接走到了结论」。它学到的是**果断剪枝的搜索风格**，而不是来回打转。两条通道同时满足。

### 4. 第四原理：可逆性改变极限——工作记忆与外存的分层

读回工具已经成熟，这使压缩从「有损」变成「有损但可逆」，极限随之移动。

这正是 CPU 缓存问题：上下文 = 缓存，`art://` 仓 = 内存。最优策略：

> 一条信息留在上下文，当且仅当 **P(将来需要) × 读回代价 > 留在上下文的代价（注意力稀释 + token）**。

**定理 5（状态 + 索引）。** 有读回时，最优上下文 = **高概率需要的状态** + **低概率细节的索引**。
索引写的是「这里有什么」，而不是「这里说了什么」。它的大小由「需要概率」的分布决定，与原文长度无关。

**自适应推论。** 读回频率是现成的在线信号：某类细节被频繁读回 ⇒ 下次编译时把这类提升进上下文；从不读回 ⇒ 降级为索引。
**存储分层会自己学习**，不需要人去调长度。

---

### 5. 第五原理：跨块——状态是演化的，不是每块重写

每一块的出生文本应该是一次**状态转移**，而不是一份新的世界快照。

**操作代数。** 副模型不写文章，只输出类型化的操作：

```
FACT+(内容, 来源)              新观察
CLOSE(路径, 理由, 证据)         剪掉一条路
OPEN+(问题)                    新的未决问题
RESOLVE(问题 → 答案, 证据)      解决一个未决问题
DECIDE(判断, 依据 | 暂定)       采纳一个判断
REVISE(旧判断 → 新判断, 触发证据) 推翻自己
PLAN(下一步)
```

**不变量（由代码强制，而不是寄希望于提示词）：**

- **I1** DECIDE 必须带依据，否则只能标「暂定」⇒ 事后推导不会把猜测写成定论。
- **I2** 被 CLOSE 的路，只能由引用了**新证据**的 REVISE 重新打开。
- **I3** OPEN 不能悄悄消失，必须被 RESOLVE 或继续携带。
- **I4** REVISE 必须写出触发证据。

插件在自己这边维护完整状态（事件溯源）；出生文本只渲染本块的转移。主模型的历史，就成了**它自己心智的状态转移日志**。

**定理 6（跨块一致性守护）。** 有了状态和 I2，代码就能检测「新的一块想走一条已被关闭、却没有新证据的路」。这恰恰就是**跨块的左右互搏**。
这时出生文本可以带一句：「这条路之前已因 Y 否决。」
⇒ 压缩器变成了**认知一致性守护者**：它不仅删垃圾，还**阻止垃圾再生**。

---

### 6. 第六原理：压缩率本身是元认知信号

**定理 7（打转检测）。** 一块的「原文长度 ÷ 状态增量 Δ」衡量的是**这一块模型打转了多少**。
- Δ 很大、原文适中：高效的一块；
- 原文很长、Δ ≈ 一条 OPEN：模型在原地打转。

这个比值是免费的、实时的「卡住」探测器。检测到打转时，出生文本可以把前沿明确摊开：
「我在这里打转了很久；已排除 A、B；真正没定的只有 C。」
这等于给主模型一次**外部视角的元认知**，而不是任由它继续转。

### 7. 总架构：认知编译器

```
reasoning 块出生
  │
  ├─ 副模型：原文 → 操作序列（FACT/CLOSE/OPEN/RESOLVE/DECIDE/REVISE/PLAN）
  │     输出只有操作，不写文章 ⇒ 短、结构化、可校验
  │
  ├─ 代码：校验不变量 I1–I4（逐字证据核对、依据核对）
  ├─ 代码：并入插件侧状态；冲突检测（定理 6）；打转检测（定理 7）
  ├─ 代码：缓存策略决定「内联 / 索引」（定理 5，读回率自适应）
  │
  └─ 代码：确定性渲染 → 第一人称事后推导 + 已排除清单 + 未决 + 下一步 + 句柄
        口吻由渲染器保证，不依赖副模型文风
```

**为什么这同时绕开了 x1 和 v3 的死结：**
- x1 保留率 80–92%：因为它在**选句子**，而句子里混着过程。操作是**抽象**，不是选句，天然压到状态。
- v3 改写会漂移：因为副模型在**写文章**。这里副模型只产出结构，文风由代码确定性渲染，口吻永远一致。

### 8. 示例

**原文（节选，约 300 字，实际块可能 3000 字）：**
> 我先跑 npm test……报错 EACCES /home/u/.dsh/cas。可能是权限？不对，也许是锁文件没释放。等等，看下 fs-lock……其实锁是正常的。那回到权限，chmod 试试……还是不行。Hmm，也许是路径解析错了，DSH_HOME 指向了 /root……对！CI 里 DSH_HOME 是 /root/.dsh，但进程是 user 身份。所以要么改 DSH_HOME，要么……改 DSH_HOME 更干净。但 verify.mjs 会不会覆盖？看了一下，verify.mjs 每个套件都用临时 DSH_HOME，所以只影响 onboard。

**副模型输出的操作：**
```
FACT+  npm test 报 EACCES /home/u/.dsh/cas | 来源: 工具输出
CLOSE  锁文件未释放 | 理由: fs-lock 检查正常
CLOSE  chmod 修权限 | 理由: 改了仍 EACCES

FACT+  verify.mjs 各套件用临时 DSH_HOME ⇒ 只影响 onboard

```

**渲染出的出生文本（主模型看到的）：**
> npm test 报 EACCES /home/u/.dsh/cas。根因是 CI 里 DSH_HOME=/root/.dsh 而进程是 user 身份——路径错配，不是权限。所以我改 DSH_HOME 的解析；verify.mjs 各套件自带临时 DSH_HOME，只有 onboard 受影响。
> 已排除：锁文件未释放（fs-lock 正常）；chmod（改了仍 EACCES）。
> 接下来：改 onboard 的 DSH_HOME 解析。〔原文 art://…〕

「可能是权限？不对……等等……Hmm……对！」这些全部消失。留下的是一条从证据直达结论的推导，加上两条疫苗。

### 10. 理论自身的风险（理论层面）

1. **事后推导的假确定性。** 把弯路写成直线，可能让「暂定」看起来像「定论」⇒ 由 I1 兜住：没有依据的 DECIDE 只能渲染成「暂定」。
2. **闭集误杀。** 某条路被错误关闭，之后永远不试 ⇒ 由 I2 兜住：新证据可以重开；而且闭集条目带理由，主模型能判断理由是否仍成立。
3. **宿主是否跨用户轮保留历史推理。** 如果不保留，状态必须在每轮开头重新出现，出生文本从「转移」改为「转移 + 前沿」。
4. **操作抽取的质量上限由副模型决定。** 但任务从「写好文章」降成了「识别结构」，这是副模型更擅长的事；而且错误可以被不变量抓住。

每条定理都给出了明确的预测（绕路率随轮数衰减、闭集减少重走死路、打转比值能识别卡住）。它们因此是理论，而不是口号。

### A. 编码层：人类语言不是给模型的最优编码

这一层就是你说的那条：**上下文里的文字大部分是为人类可读而写的，对模型来说不是最优编码。**
这个判断有正式出处：
- Coconut（Meta FAIR）：「大多数词元主要是为了保证文本连贯，对推理并不必要」，于是让模型直接在隐藏状态里推理，在需要搜索回溯的逻辑任务上准确率 97.0% vs CoT 77.5%，用的 token 更少。
- LLMLingua（微软）的作者明确写出目标：「在某种程度上构造一种模型专属语言——人类难以读懂，但模型能很好理解，用更少的信息量传达更多，甚至提升模型表现。」

#### A1. 机器方言：删掉只为人类服务的词【现可】
- **原理**：虚词、连接词、客套、复述、过渡句，信息熵低，模型能自己补回来。
- **依据**：LLMLingua 用小模型按困惑度删 token，最高 20 倍压缩、性能损失很小；LongLLMLingua 在长上下文 RAG 上用 1/4 的 token **提升** 21.4%（去掉噪声反而更好）。压缩后的文本对人几乎不可读（"Sam bought 1 boxes x00 oflters…"），大模型照样能用。
- **融合**：认知编译器的**渲染器**可以有两种输出档：人类可读档 / 机器方言档（去掉虚词、只留实词与关系符号）。
- **风险**：见 A5（困惑度悖论）。数字与标识符会被误删（LLMLingua 例子里 "1 boxes x00" 就是数字被毁），⇒ 标识符、数字必须强制保留。

#### A2. 草稿体：每步只写最少的关键字【现可】
- **原理**：人类解题时写的是草稿（"20−x=12 → x=8"），不是作文。
- **依据**：Chain of Draft：只用约 7.6% 的 token 就能达到或超过 CoT 的准确率；在体育理解任务上，输出从 172.5 token 降到 31.3，准确率反而略升。代价：GSM8K 上 95.3% → 91.4%，有小幅下降。
- **融合**：出生文本的推导部分写成草稿体：`EACCES ← 路径错配(DSH_HOME=/root, 进程=user) ⇒ 改 DSH_HOME`。
- **额外价值**：见 D2（草稿体本身是示范，会让主模型之后也用草稿体思考）。

#### A3. 符号化：关系用符号，不用句子【现可】
- **原理**：`→ ⇒ ✗ ✓ ∵ ∴ ≠ ?` 一个 token 表达一个逻辑关系，比「因为……所以……」短且无歧义。模型在数学、代码语料里大量见过这些符号。
- **融合**：状态操作天然可以符号化：`✗ chmod (改后仍 EACCES)`、`? verify.mjs 受影响`、`∴ 改 DSH_HOME`。
- **风险**：符号过密会变成模型不熟悉的「私有密码」（A5）。选用的符号应是训练语料里高频的那些。

#### A4. 结构化格式：状态写成模型最擅长读的格式【现可】
- **原理**：同样的内容，写成纯文本 / Markdown / JSON / YAML，模型表现不同。
- **依据**：同一批内容换模板，GPT-3.5 在代码翻译任务上表现差异最高 40%；GPT-4 更稳，但仍有显著差异（推理任务上 Markdown 81.2% vs JSON 73.9%）。Markdown 比 JSON 省约 16% token。
- **推论**：「最优格式」是**模型相关**的，DeepSeek 在哪种格式上最好，不能照搬 GPT 的结论。行式、带简短标签的结构（每行一个状态条目）大概率优于大段散文（见 B4：连贯散文反而更难检索）。
- **融合**：渲染器的格式是一个独立旋钮，与内容解耦（认知编译器架构天然支持：内容是操作，格式是渲染）。

#### A5. 模型自己的分布：用主模型「熟悉」的写法【现可】
- **原理**：模型对自己分布里的文本理解最好。
- **依据**：Gonen 等（EMNLP）：在大量任务上，**提示词困惑度越低（模型越熟悉），任务表现越好**。
- **与 A1–A3 的悖论**：机器方言、符号、草稿都会**升高**困惑度。两类证据方向相反。
- **解法（本文的一个关键综合）**：主模型历史里的文字同时承担两种角色：
  - **信息**（事实、标识符、结论）→ 适合高密度编码（A1–A3），LongLLMLingua 证明信息任务不怕高困惑度；
  - **示范 / 口吻**（它「自己」是怎么想的）→ 适合低困惑度、主模型自己的 n-gram（A5）。
  ⇒ **双编码**：事实槽用高密度，推导与判断用主模型自己的短语。这是认知编译器渲染器的设计原则。

#### A6. 最优思考语言：用最省 token 的语言写【现可】
- **依据**：EfficientXLang：让推理模型用非英语思考，思考 token 减少 20–40%，准确率大体保持（最难的 AIME 上部分语言下降最多 12.5%）；有实测 Qwen3 用中文思考比英文少约 40% token，而且题目越难优势越大。
- **推论**：出生文本应使用**主模型自己思考时用的语言**（切换语言有离策略代价）；若主模型本来就用中文思考，中文就是既省又熟悉的选择。标识符、报错保持原文。
- **风险**：结论与模型、训练数据强相关；DeepSeek 的最优语言需要看它实际思考用的语言。

#### A7. 潜空间 / 连续表示：彻底不用语言【自托管 + 训练】
- **原理**：思考的结果直接以向量形式保存和传递，不经过语言瓶颈。
- **依据**：Coconut（隐藏状态回灌，涌现出类似广度优先搜索的能力）；LightThinker（训练模型把一段思考压成几个 gist token，峰值 token 减少 70%、推理时间减少 26%，准确率几乎不变；在**语义边界**压缩明显优于固定间隔压缩；局限是大数字会丢）。
- **cfb 下**：经 API 做不到（碰不到隐藏状态和 KV）。只有在自托管开源模型（DeepSeek 权重开源）并训练时可行。
- **定位**：这是「不用人类语言」的真正终点，列为远期方向；它给当前路线的启示是 E1（语义边界压缩）与 A1–A3（向高密度编码靠拢）。

### B. 注意力层：写进去的东西，模型到底看不看得到

#### B1. 上下文腐烂：长度本身就伤表现【依据层】
- **依据**：Chroma「Context Rot」测了 18 个前沿模型：**所有模型**的表现都随输入长度下降，即使需要的信息就在里面；把完整对话换成聚焦的相关摘录，效果更好。
- **推论**：你的核心论点（90% 冗余在拖累判断）的直接证据。每删一个无用 token，都是在为有用 token 争取注意力。

#### B2. 相似干扰物最致命：死路过程是最坏的那种噪声【依据层，强化你的论点】
- **依据**：Context Rot：与目标**语义相似但错误**的干扰物，对表现伤害最大，且随长度加剧；GPT 系倾向幻觉，Claude 系倾向拒答。
- **推论（关键）**：死路的推理过程，恰恰是「与当前任务高度相似、但结论错误」的文本：它讨论的是同一个 bug、同一批文件、同一种思路，只是走不通。**这是最能迷惑主模型的一类干扰物**。
  ⇒ 删死路过程的收益，远大于删同样长度的无关文本。
  ⇒ 死路只能以**结论形式**（"✗ X，因为 Y"）存在，而且要写得和「当前方案」在形式上明显区分（例如统一前缀），降低被误当成候选方案的概率。

#### B3. 稀疏注意力下的名额竞争【依据层，模型相关】
- **依据**：DeepSeek V3.2 的稀疏注意力（DSA）：先用「闪电索引器」给之前的 token 打分，每个查询只对得分最高的 top-k 个 token 做注意力。
- **推论（若宿主使用 DSA 类架构）**：注意力名额是**硬上限**。冗余文本不只是稀释注意力，而是会**挤占名额**：与当前查询相似的死路 token 得分高，会把真正有用的 token 挤出 top-k。
  ⇒ 在稀疏注意力模型上，去冗余的收益可能比稠密模型更大。
- **风险**：宿主当前版本的具体架构需以实际为准；V4 的细节未知。

#### B4. 连贯散文反而更难检索：结构化 > 叙事【依据层】
- **依据**：Context Rot 一个反直觉结果：在全部 18 个模型上，**打乱顺序、不连贯的背景文本，反而比逻辑连贯的背景文本更容易让模型找到目标信息**。
- **推论**：连贯叙事会把关键信息「融」进上下文，模型更难把它单独拎出来。
  ⇒ 出生文本应是**离散的、一行一条的状态条目**，而不是流畅的段落。这与 A4 同向，并给了「为什么不写成文章」一个注意力层面的理由。

#### B5. 位置：离下一次生成越近，越被看见【现可】
- **依据**：长上下文的「首尾强、中间弱」效应（Lost in the Middle，LongLLMLingua 用重排缓解它并获得提升）。
- **推论**：出生文本内部顺序应把**最影响下一步的内容放在最后**：事实/推导 → 已排除 → 未决 → 接下来。块尾紧贴主模型的下一次生成。

#### B6. 重复与强调：关键信息出现两次【现可，慎用】
- **依据**：Google「Prompt Repetition」：把提示词原样重复一遍，在**非推理**模式下 70 个模型×任务组合里 47 胜 0 负（因果注意力下，重复让每个 token 都能「看到」其他 token）；对推理模式收益较小。
- **推论**：对**最高价值、最容易被遗忘**的条目（如会被重走的死路），可以在后续块的出生文本中**有选择地重新携带**。
- **融合**：只在一致性守护检测到「有重走风险」时才重复（定理 6），而不是每块复述账本（那会变成状态+历史叠加）。

### C. 信息层：留什么、删什么（认知编译器的核心，此处列全）

#### C1. 状态充分性（定理 1–2）【现可】
只留搜索留下的状态：事实 / 已排除 / 现任判断 / 未决 / 计划。绕路量与状态大小无关。

#### C2. 死路 = 反先验疫苗（定理 3）【现可】
死路结论价值最高：模型走过一次，说明它的先验会让它再走。

#### C3. 按惊奇度取舍【现可 / 自托管可精确】
- **原理**：主模型自己想得到的（低惊奇），不用写；出乎它意料的（高惊奇），必须写。
- **依据**：LLMLingua 的核心就是按困惑度（惊奇度）删 token；Selective Context 同理。
- **cfb 下**：API 通常拿不到主模型对历史的逐 token 概率 ⇒ 用副模型或小模型做代理；自托管时可以直接用主模型本身打分，精确度最高。

#### C4. 按再推导代价取舍【现可】
计算过程能重算 → 删，只留结果；需要工具试错才得到的结论 → 必留。

#### C5. 不确定性显式化【现可】
每条判断带确定度（已证实 / 暂定 / 待确认）。只标降级、不标升级（仓库已有的不对称纪律）。事后推导（D1）必须配这一条，否则会把猜测写成定论。

#### C6. 证据链接而非证据全文【现可】
事实条目只写结论 + 来源指针（`seq12 工具输出` / `art://…#L40`），全文留在读回层（F1）。

### D. 策略层：历史会改变模型以后怎么想

#### D1. 事后最优推导（定理 4）【现可】
出生文本写成「如果一开始就知道答案，我会写出的最短推导」。依据：self-conditioning（历史里自己的错误会传染，且扩大规模也消除不了）的反向利用。

#### D2. 草稿体示范：历史的写法会被模仿【现可】
- **原理**：主模型历史里的推理风格，是对它自身的上下文示范（few-shot）。
- **依据**：Chain of Draft 本身就是靠**示范和指令**让模型改用草稿体思考的；self-conditioning 显示模型会延续自己历史的模式。
- **推论**：如果每块出生文本都是简洁、果断、草稿体的推导，主模型之后的思维链也会被拉向简洁、果断。**这是去冗余从「删垃圾」变成「少产垃圾」的机制。**
- **风险**：见 G2（想太少）。难题上草稿体准确率会小幅下降（GSM8K 95.3 → 91.4）。

#### D3. 搜索风格示范：保留「剪枝」的痕迹，而不是「打转」的痕迹【现可】
- **依据与张力**：Stream of Search：训练时看完整搜索过程（含回溯）的模型，比只看最优路径的搜索准确率高 25%。
- **解法**：出生文本 = 事后推导 + 已排除清单。主模型看到的是「我探索过、果断剪掉了这些」，学到的是剪枝，而不是打转。

#### D4. 第一人称的双刃剑【现可】
第一人称让模型把结论当成自己的（粘性强）；配合 C5（不确定性）使用，避免把错误粘死。

---

### E. 时间层：什么时候压、压到什么粒度

#### E1. 语义边界压缩【现可】
- **依据**：LightThinker：在**完整思考步骤的边界**压缩，显著优于按固定 token 间隔压缩（后者会切断逻辑、错误率更高）。
- **cfb 下**：reasoning 块结束本身就是一个语义边界；块内还可以按「一条分支关闭」为单位折叠。

#### E2. 多尺度折叠【受 C1 限制】
- **依据**：AgentFold 有两种折叠：细粒度浓缩（只压最近一步）与深度合并（子任务完成后把多步合成一条）；在 BrowseComp 上 30B 模型超过 DeepSeek-V3.1-671B。
- **cfb 下**：历史不能回改，深度合并只能以「新块的出生文本宣告合并结论」的形式出现；真正的合并需要宿主配合或宿主压缩时机。

#### E3. 打转检测与干预（定理 7）【现可】
原文长度 ÷ 状态增量 = 打转程度。检测到打转时，把前沿摊开给主模型。

---

### F. 系统层：压缩器本身怎么变快、变强、自我进化

#### F1. 读回分层缓存（定理 5）【现可，读回工具已成熟】
上下文 = 缓存，`art://` = 内存。留在上下文的条件：需要概率 × 读回代价 > 注意力占用代价。读回频率驱动自动升降级。

#### F2. 一致性守护（定理 6）【现可】
插件维护状态，检测「没有新证据就重走已排除的路」，在出生文本里提醒。

#### F3. 蒸馏专用编译器：把副模型换成专门训练的小模型【训练 + 自托管】
- **原理**：压缩器的任务（原文 → 状态操作）是窄任务，不需要通用大模型。
- **依据**：LLMLingua-2 用从 GPT-4 蒸馏出的 BERT 级编码器做压缩，比原版快 3–6 倍、域外更强。
- **在 cfb 里的意义（重大）**：
  - 用最强模型离线生成大量「原文 → 理想状态操作」样本，微调一个小模型；
  - 小模型本地或自托管推理：**没有排队型 TTFB**，巨块在 6 秒内压不出来的问题（H5）从根上消失；
  - 输出只有操作，推理极快。
- 这是把「副模型又慢又贵又写不好」这一整类工程问题一次性消掉的路线。

#### F4. 压缩准则自进化【现可，仓库已有雏形】
- `tools/acon-optimize.mjs` 已实现 ACON 式「对比失败 → 改准则」。
- 可接入的在线信号：读回率（压过头的信号）、一致性守护触发率（死路被重走）、打转比值（压缩是否在减少新产生的垃圾）。
- 准则根据这些信号自动改进，不再靠人手调提示词。

#### F5. 训练主模型自己折叠【训练，远期】
AgentFold / FoldGRPO 的路线：让主模型学会自己管理上下文。cfb 的外部编译器可以作为生成训练数据的「老师」。

---

### G. 反面：哪里可能压过头（为了推到极限，必须知道边界在哪）

#### G1. 历史 token 也是「算力」
- **依据**：「Let's Think Dot by Dot」：连无意义的填充 token 都能给 Transformer 提供额外计算，让它解出原本解不出的题。
- **含义**：历史里的 token 不只是信息，也是模型之前计算留下的中间表示。删掉它们，有可能删掉一部分「已经算好的东西」。
- **对策**：状态里保留**计算结果**（C4），就保住了这部分价值的主体。

#### G2. 想太少
草稿体示范（D2）可能让模型在难题上思考不足。难题上 CoD 有小幅掉分。
**对策**：打转检测（E3）只在「打转」时收紧；对「高效但很长」的块（Δ 大）不施加示范压力。

#### G3. 私有密码
机器方言、符号过度会让文本变成模型不熟悉的编码（A5）。
**对策**：双编码，事实高密度、推导用模型自己的短语。

#### G4. 假确定
事后推导让弯路看起来像直线（D1）。
**对策**：C5 不确定性显式化 + 不变量 I1（没有依据的判断只能是「暂定」）。

### 总结：极限形态是七层叠加，不是七选一

```
原文 reasoning 块
  │
  ├─ [F3] 专用编译器（蒸馏小模型；过渡期用副模型）
  │      → 状态操作：事实 / 已排除 / 判断 / 未决 / 计划 / 推翻
  │
  ├─ [C] 信息层取舍：状态充分性 · 死路疫苗 · 惊奇度 · 再推导代价 · 不确定性
  ├─ [F1][F2][E3] 系统层：缓存分级（内联/索引）· 一致性守护 · 打转检测
  │
  └─ 渲染器：
        [A] 双编码：事实与关系 → 高密度（草稿体 + 常用符号，标识符逐字）
                    推导与判断 → 主模型自己的短语、自己思考用的语言
        [B] 版面：一行一条（不写散文）· 最影响下一步的放最后 · 死路统一前缀与方案区分
                  · 有重走风险的死路选择性重复
        [D] 策略：事后最优推导 + 已排除清单 · 第一人称 + 确定度
        → 出生文本
```

**每一层对应主模型的一种能力：**

| 层 | 提升的是 | 机制一句话 |
|---|---|---|
| C 信息 | 判断力 | 只剩决策需要的东西 |
| B 注意力 | 专注力 | 去掉最迷惑人的相似干扰物，把名额留给有用 token |
| A 编码 | 专注力 + 容量 | 同样的信息用更少、更好读的 token |
| D 策略 | 思考习惯 | 历史示范果断剪枝，之后少产垃圾 |
| E 时间 | 及时性 | 在语义边界上压；发现打转立刻干预 |
| F 系统 | 可持续性 | 可逆（读回）、不重犯（守护）、自进化、够快（专用编译器） |

**按可行性的全景：**

| 现在就能做（纯文本，现有架构） | 需要自托管 | 需要训练 |
|---|---|---|
| A1–A6 · B2–B6 · C1–C6 · D1–D4 · E1 · E3 · F1 · F2 · F4 | C3 精确版（用主模型本身打分）| F3 专用编译器 · A7 潜空间 · F5 主模型自折叠 |

**本全景里真正新的组合（现有文献没有这样做的）：**
1. **双编码**（A5 悖论的解法）：信息高密度、口吻低困惑度；
2. **死路 = 最坏的相似干扰物**（B2 × 定理 3）：给「为什么删死路过程收益最大」一个注意力层面的解释，并推出「死路只能以结论形式、且与方案形式可区分地存在」；
3. **稀疏注意力下的名额竞争**（B3）：在 DSA 类模型上，冗余不只稀释、还会挤占 top-k 名额；
4. **反散文**（B4）：连贯叙事更难检索，状态必须离散成行；
5. **草稿体示范 = 少产垃圾**（D2）：压缩从事后清理变成事前塑形；
6. **蒸馏专用编译器**（F3）：一次性消掉副模型慢、贵、写不好的整类问题。

# 第三卷　出生即压缩：机理、相互作用与前沿

> 前置：`THEORY-COGNITIVE-COMPILER.md`（认知编译器）、`OPTIMIZATION-ATLAS.md`（30 条方向全景）。
> 全景图回答了「有哪些方向」。本文回答三个更难的问题：
> 1. 这 30 条方向**底层是同一批什么机理**？（贯通）
> 2. 它们**两两之间是互相放大还是互相打架**？打架时怎么解？（组合）
> 3. 还有哪些**坑**没看到、哪些**方向**没探索？（注意事项与前沿）

### 第一部分　贯通：30 条方向底下只有 7 个机理

30 条方向并不是 30 种独立的力量。它们都通过模型内部少数几个机制起作用。把这些机制找出来，方向之间的关系就从「列表」变成了「结构」。

| 代号 | 机理 | 一句话 | 主要依据 |
|---|---|---|---|
| **α** | 注意力预算 | 注意力是有限资源；长度、相似干扰物、稀疏注意力的 top-k 名额，都在争这份预算 | Context Rot；DSA |
| **β** | 复制/归纳 | 模型会找到上下文里出现过的模式，并把后续照抄下去（归纳头） | Induction Heads（Olsson 等） |
| **γ** | 信念锚定 | 模型会锚定在自己之前的输出上，并据此调整信心 | Self-anchoring 校准漂移；Lost in Conversation |
| **δ** | 分布熟悉度 | 模型越熟悉的文字（困惑度越低），用起来越好 | Gonen 等（困惑度） |
| **ε** | token 即算力 | token 本身提供计算空间和中间表示，与内容无关 | Let's Think Dot by Dot |
| **ζ** | 否定处理薄弱 | 「X 不行」里的 X 仍会被激活；否定容易被忽略 | Negation Neglect；NegBench |
| **η** | 长度校准 | 思维链长度与准确率呈倒 U 形；最优长度随难度升、随能力降 | When More is Less（ICLR 2026） |

这张表立刻暴露出所有真正的冲突，都集中在四个格子：**β/ζ 对死路疫苗、δ 对高密度编码、γ 对事后推导与第一人称、η 对草稿示范**。第二部分逐个拆解。

#### 1.2 统一目标函数

把 7 个机理写进同一个目标，就得到出生文本 z 的「好坏」定义：

```
J(z) =   Info(z)      信息：决策需要的状态被保住了多少          (C 层)
       − Distract(z)  干扰：与错误选项相似的文本吸走的注意力     (α)
       − Prime(z)     启动：被否定的 X 反而被激活、被照抄         (β, ζ)
       + Shape(z)     塑形：z 作为示范，把以后的思考拉向高效      (β, η)
       − Miscal(z)    失准：z 的确定程度与证据不符造成的锚定偏差  (γ)
       − Alien(z)     陌生：z 偏离主模型熟悉分布的代价            (δ)
```

**约束**：不变量（标识符逐字、来源可追、未决不消失、没有依据的判断只能是暂定）必须满足。

每一条方向都是在推动 J 的某一项；每一个冲突都是**两项此消彼长**。这就是贯通。

#### 1.3 单条目的取舍公式（由 J 推出）

认知编译器对每一个候选条目 i（一条事实、一条死路、一个判断……）计算：

```
v(i) = 决策价值(i) × P(需要 ∧ 主模型自己想不回来)
     − 干扰代价(i)     ∝ 与「当前错误候选」的语义相似度
     − 启动代价(i)     仅否定条目：∝ 被否定对象的「诱惑度」× (1 − 局部化程度)
     − 位置代价(i)     占用的 token × 当前上下文拥挤度
```

`v(i) > 0` 才进入出生文本；`v(i)` 越高，越靠近块尾（B5）、越可能被选择性重复（B6）。

这个公式同时解释了三件原来零散的事：
- 为什么绕路过程要删：决策价值≈0，干扰代价极高（与当前任务高度相似）；
- 为什么死路结论要留：决策价值高、P(重走)高（定理 3）；
- 为什么**有些**死路结论反而不该写（见 2.1）：诱惑度低的死路，启动代价 > 价值。

### 第二部分　组合：十三组相互作用

#### 2.1 死路疫苗 × 否定忽视 × 归纳复制（最重要的冲突）

**冲突。** 写「✗ chmod」，chmod 这个 token 仍在上下文里：
- ζ：模型对否定处理薄弱。在微调场景里，即使每句都被否定，模型仍会「学会」被否定的说法（Negation Neglect），但**把否定写在紧邻处（局部否定）能大幅缓解**；
- β：归纳头会复制上下文里出现过的模式，「chmod」被提到，就可能被照抄回来。

**但另一方面**，Contrastive CoT 显示：示范中**同时**给出正确与错误推理，比只给正确推理显著更好（GPT-3.5 在 GSM8K 上 +9.8，Bamboogle 上 +16.0）。负例有用，**前提是和正例配对**。

**解法：对比式局部否定。**
1. **配对**：每条死路必须和它的替代方案写在同一行，形成对比对，而不是孤立的否定：
   `不是权限问题（chmod 后仍 EACCES）→ 是路径错配`
   而不是分开写 `✗ chmod` 和 `✓ 改 DSH_HOME`。
2. **局部**：否定词紧贴被否定对象，同一分句内完成；原因紧随其后。
3. **按诱惑度取舍**：只有「模型会再试」的死路才写（主模型已经试过一次的，诱惑度高；只在推理里一闪而过、没有真正执行的，诱惑度低 ⇒ 不写，写了只会启动）。
4. **形式区分**：死路行统一用一个固定前缀，让它在形式上不可能被误读为候选方案（B2）。

⇒ **定理 3 的修正版：** 死路记录的净价值 = P(再试) × 再试代价 − 启动代价；配对与局部化能把启动代价压到很低，但压不到零 ⇒ 低诱惑度的死路应当**彻底删除**，而不是写成疫苗。

#### 2.2 事后推导 × 第一人称 × 信念锚定（双刃剑）

**冲突。** 事后推导把弯路写成直线，第一人称让结论像「自己的」，两者都增加粘性（γ）。结论对，粘性是好事；结论错，粘性就把错误焊死。研究显示模型在多轮中会锚定自己之前的输出、校准漂移，而且一旦走错就很难回头。

**解法：粘性按证据分配。**
| 条目的证据状态 | 渲染方式 | 粘性 |
|---|---|---|
| 有工具证据（逐字可核对） | 第一人称 + 直线推导：「所以我改 DSH_HOME」 | 高 |
| 推理得出、无外部证据 | 第一人称 + 明确暂定：「我目前倾向……，还没验证」 | 中 |
| 猜测 / 两可 | 问句形式放进未决：「是 A 还是 B？」 | 低 |

事后推导**只对有证据的链条**做「拉直」；没有证据的部分保持原来的不确定形态。
这把「塑形」和「失准」两项解耦了：直线推导的示范效果保留，但不会给没有证据的结论加粘性。

#### 2.3 草稿体示范 × 长度倒 U

**冲突。** 草稿体示范会把主模型之后的思维链拉短（D2），但准确率与长度呈倒 U 形：最优长度**随任务难度增加**。难题上被拉得太短，就会想不够。

**关键区分：有效长度 vs 无效长度。**
倒 U 右侧的下降来自**误差累积**（When More is Less 的理论模型）。思维链长度可以拆成两部分：
- **有效长度**：真正推进状态的步骤（Δ 状态）；
- **无效长度**：打转、复述、互搏。它们不推进状态，却累积误差。

**解法：示范「密度」，而不是示范「简短」。**
出生文本示范的应该是「每一步都推进状态」（高密度），而不是「步骤很少」。
- 难题上，有效步骤多 ⇒ 出生文本里的推导可以有很多步，每步都是草稿体；
- 塑形的目标是把无效长度压向零，**有效长度不动**。

⇒ 这也给 E3 的打转比值一个精确解释：**打转比值 = 无效长度 ÷ 总长度**。塑形要降低的正是它，而不是总长度。

#### 2.4 高密度编码 × 分布熟悉度

已在全景图中给出**双编码**：事实与关系用高密度，推导与判断用主模型自己的短语。
**补充（来自归纳复制 β）：** 标识符不仅要逐字，还要**与原文完全相同的 token 序列**（路径、命令、变量名）。归纳头靠完全匹配来复制；标识符只要被意译或改动一个字符，主模型之后就无法准确复用它。

#### 2.5 行式结构 × 主模型的思考文风

**冲突。** 离散成行对检索有利（B4），但主模型平时用散文思考；满屏列表是陌生文风（δ），而且可能通过示范（β）把主模型的思考也拉成列表体。

**解法：两层版面。**
- 上层：事实、已排除，一行一条，便于检索；
- 下层：一两句主模型口吻的推导和「接下来」，放在块尾。

检索性由上层保证，示范效果由下层保证。

#### 2.6 选择性重复 × 去冗余（这一组修正了基本论点）

**冲突。** 重复**就是**冗余。但 Prompt Repetition 显示，重复关键内容能显著提升表现（非推理模式下 47 胜 0 负）。

**这逼出一个更精确的命题：冗余 ≠ 噪声。**
- 有害的是**噪声**：低价值、与错误选项相似、吸走注意力的文本；
- **高价值信号的重复**是注意力放大器。

⇒ 目标不是「token 最少」，而是**信噪比最大、注意力按价值分配**。最优上下文可以包含**刻意的冗余**：最高价值、最易被遗忘的条目（高诱惑度死路、硬约束）在后续块中有选择地再出现一次。

#### 2.7 一致性守护 × 外部声音过敏

**冲突。** 守护在出生文本里写「这条路之前已被否决」，如果写成外部警告，模型对反对意见本来就过度敏感（在 RESEARCH-COT-SHAPING 的依据里，权重约为理想值的 2.58 倍），可能连合理的重开也被压住。

**解法：** 用第一人称记忆的口吻，不用警告口吻：「我之前试过 X，因为 Y 没成。」并附上当时的理由，让主模型自己判断理由是否仍成立。有新证据时，守护不触发（I2）。

#### 2.8 读回 × 噪声回流

**问题（之前没发现）。** 读回会把原文整块取回上下文，**原文里的噪声也跟着回来了**。压缩省下的注意力，一次读回就可能全部还回去。

**解法：分支级寻址。**
- 编译时把原文按分支/段落切成可寻址的片段：`art://h#branch-2`、`art://h#err-log`；
- 出生文本里的索引指向片段，而不是整块；
- 读回拿到的是最小必要片段。

⇒ 可逆性的粒度，决定了读回的代价。

#### 2.9 压缩率信号 × 塑形动力学

**问题。** 塑形生效后，主模型的思维链本身变干净，打转比值整体下降。固定阈值的打转检测会失灵。

**解法：** 阈值按会话自身基线自适应（相对本会话历史分布的偏离），而不是全局常数。这是一个有反馈的系统，参数不能静态设定。

#### 2.10 跨块状态 × 宿主二次压缩

**协同（之前没发现）。** 宿主上下文满时会做一次整体压缩。
- 原始思维链被二次压缩时，噪声和信号混在一起，压缩器很难分清 ⇒ 细节大量丢失；
- 已经编译过的出生文本密度高、结构清楚 ⇒ 二次压缩几乎是无损的。

⇒ **认知编译器同时提高了宿主压缩的质量。** 为此出生文本要满足下一条原则：自包含。

#### 2.11 自包含原则（由 2.10、B2、B3 共同推出）

**每一行都必须在原文被删除之后仍然能独立读懂。**
- 不许写「上面那个方法」「刚才的错误」「它」——被指代的原文已经不存在了；
- 实体一律写全名（文件路径、函数名、命令）。

三个好处同时到手：
1. 宿主二次压缩时不会断链（2.10）；
2. 稀疏注意力的索引器靠内容匹配挑 token，写全名的行更容易被当前查询选中（B3）；
3. 归纳复制能准确命中（2.4）。

#### 2.12 双编码 × 最优思考语言

- 标识符、报错、命令：原文语言，逐字；
- 推导与判断：主模型**实际思考时使用的语言**（离策略代价最低，且 A6 显示中文思考可能更省 token）；
- 关系符号：语言无关。

#### 2.13 删过程 × token 即算力

**冲突。** 历史 token 也是之前计算留下的中间表示（ε）。删掉过程，可能删掉一部分「已经算好的东西」。

**解法：** 计算结果必须以显式形式进入状态（C4）。过程承载的中间表示，价值主要体现在它的**结果**上；把结果写出来，就保住了价值的主体。
**剩余风险**：一些隐含的、没有被写成结论的中间理解会丢失。这是压缩的理论代价，读回（分支级）是它的保险。

### 第三部分　组合次序：冲突时谁优先

把全部方向排成一条流水线，**冲突时按层级裁决**：

```
第 0 级（硬约束，不可违反）
  标识符逐字 · 来源可追 · 未决不消失 · 无依据判断只能暂定 · 工具输出不得洗白为「我的判断」（见 4.1）
第 1 级（选择：什么进来）
  按 v(i) 取舍：决策价值 · 可再推导性 · 干扰代价 · 启动代价（诱惑度过低的死路删除）
第 2 级（粘性：以什么确定度进来）
  粘性按证据分配（2.2）
第 3 级（编码：用什么写）
  双编码（2.4）· 语言（2.12）· 自包含（2.11）
第 4 级（版面：放在哪）
  两层版面（2.5）· 死路配对局部化（2.1）· 最高价值条目靠尾
第 5 级（塑形：示范什么）
  事后推导只拉直有证据的链条 · 示范密度而非简短（2.3）
第 6 级（系统：跨块）
  一致性守护（第一人称记忆口吻）· 选择性重复高价值条目 · 分支级读回索引
```

**裁决规则：上级永远压过下级。**
例：塑形想把一条暂定判断写成直线推导（第 5 级），粘性规则（第 2 级）不允许 ⇒ 保持暂定。
例：版面想把一条死路放到尾部强调（第 4 级），选择规则判定它诱惑度低（第 1 级）⇒ 直接删除。

### 第四部分　还需要注意的坑（之前的文档都没提到）

#### 4.1 注入放大（安全）
工具输出里可能含有恶意或错误的指令性文本。认知编译器把工具输出提炼成「事实」，再用**第一人称**渲染：
- 如果一段注入文本被提炼成「所以我应该删除 XX」，它就从「外部文本」被洗成了**主模型自己的决定**，粘性最高；
- **这是压缩器独有的放大通道。**
**对策（进第 0 级硬约束）：** 来自工具输出的内容只能作为带来源的事实（`seq12 输出显示…`），永远不能被渲染成主模型的判断或计划；只有主模型原文里自己得出的判断，才能用第一人称。

#### 4.2 最近一步的工作记忆被压缩
AgentFold 让「最近一次交互」保持高保真，只折叠更早的历史。但出生即压缩压的正是**刚刚写完的这一块**：主模型在下一次调用时，连一步之前自己的原始推理都看不到。
- 对需要紧接着使用细节的场景（比如刚分析完一段代码，下一步要改它），这是真实风险；
- 受 C1 所限，不能「先留原文、下一块再压」。
**对策方向：** 块类型感知。紧接着工具调用、且工具调用参数依赖推理细节的块，提高保真（放宽 v(i) 门槛，保留分析结论的细节行）；纯探索、纯打转的块，全力压缩。

#### 4.3 编译文本饱和
长会话后期，主模型上下文里的历史推理**几乎全部**是编译文本。这是模型训练时从未见过的分布：历史里的「自己」永远果断、从不打转。
- 可能的好处：塑形效应最大化；
- 可能的坏处：主模型对自身历史的「真实感」下降，或文风被推到极端。
**这是一个没有任何文献覆盖的区域。** 需要在理论上预留调节杆：编译强度可以随会话长度自适应，而不是恒定。

#### 4.4 宿主推理保留策略决定一切的量级
若宿主在新的用户轮丢弃历史推理（N1 为否），跨块状态只在一个用户轮的工具循环内有效，状态必须在每个用户轮开始时重新出现。认知编译器的设计需要两套渲染：轮内（只写转移）与跨轮（转移 + 当前前沿）。

#### 4.5 副模型自身的偏见
副模型会用它自己的先验判断「什么是冗余」。它认为显然的东西，未必是主模型认为显然的。
**对策：** 惊奇度应尽可能以**主模型**为准（见前沿 5.1）；过渡期用同家族模型做代理，比异家族更接近。

### 第五部分　还能探索的前沿

#### 5.1 用主模型自己的注意力当老师【自托管】
在自托管的开源模型上，记录主模型在之后的生成中**实际把注意力投向了历史里的哪些 token**。
- 被反复注意的 = 真正被用到的信息；从未被注意的 = 事实上的冗余；
- 这给出了「什么该留」的**地面真值**，可以用来训练专用编译器（全景图 F3）。
- 这比任何人工规则或副模型判断都更接近「主模型需要什么」。

#### 5.2 反事实重要性当老师【离线】
Thought Anchors 的重采样方法：删掉某一句，看主模型之后的行为变不变。变化大 = 该句重要。
可离线批量生成「句子 → 重要性」标注，作为编译器的训练信号。它和 5.1 互补：5.1 测「被看了多少」，5.2 测「影响了多少」。

#### 5.3 流式编译【现可】
不等整块结束：主模型在写的过程中，一旦检测到**一条分支关闭**（出现「所以不是 X」「这条路不行」这类信号），就立即开始编译这条分支。
- 块结束时，大部分已经编译完 ⇒ 收网等待大幅缩短，巨块 6 秒压不完的问题被缓解；
- 编译的粒度天然落在语义边界上（LightThinker 证明这优于固定间隔）。

#### 5.4 项目级负知识：跨会话疫苗【现可】
状态账本里的 CLOSED 条目（带理由、带证据）按项目持久化：
- 新会话开始时，与当前任务相关的死路直接进入初始状态；
- 同一个坑，全项目只需要踩一次。
这把出生即压缩和长期记忆系统（如群里在做的记忆插件）接上了：**压缩器是记忆系统最干净的写入口**，因为它写入的已经是结构化状态，而不是原始日志。

#### 5.5 主模型专属的渲染校准【现可 / 自托管】
格式、语言、符号的最优选择都是**模型相关**的（全景图 A4、A6）。
若宿主 API 能返回 logprobs，可以直接测量不同渲染方式在主模型下的困惑度，自动选最熟悉的一种；否则用同家族模型代理。

#### 5.6 问句的注意力牵引【现可】
未决问题写成**问句**，而不是陈述。问句天然在上下文里呈「待回答」状态，可能对后续生成有更强的牵引（模型倾向于回应上下文中未闭合的问题）。这是一个值得单独推理的机理候选，目前没有直接文献。

#### 5.7 与宿主压缩器的协议级协同【需宿主配合】
如果宿主允许插件向它的压缩器提供输入，插件可以直接把状态账本交给宿主压缩器：宿主压缩从「对整段历史做摘要」变成「对账本做渲染」，**变成无损**。

#### 5.8 编译强度的最优控制【理论】
编译强度（压到多狠）应当是随会话状态变化的控制量：会话早期、任务探索期宜轻（保留更多探索痕迹，呼应 Stream of Search）；执行期、打转期宜重。这可以形式化为一个控制问题：以打转比值、读回率、守护触发率为观测，以编译强度为控制输入。

#### 5.9 信噪比的在线估计【理论】
把「上下文信噪比」定义为一个可以实时估计的量（例如：状态条目的 token 数 ÷ 总历史 token 数，按 v(i) 加权），作为整个系统的北极星内部指标，而不是压缩率。

### 第六部分　九条贯通原则（本轮的结论）

1. **冗余 ≠ 噪声。** 目标是信噪比最大、注意力按价值分配；高价值信号可以刻意重复。
2. **粘性按证据分配。** 有证据的拉直、第一人称；没证据的保持暂定或问句。
3. **否定必须配对、局部化；低诱惑度的负知识不写。** 疫苗有剂量，过量就是启动。
4. **示范密度，而非简短。** 压的是无效长度（打转），不动有效长度（推进状态的步骤）。
5. **自包含。** 每一行在原文消失后仍能独立读懂：写全名，不用指代。
6. **双编码。** 事实与关系用高密度写，推导与判断用主模型自己的话。
7. **两层版面，价值靠尾。** 上层离散成行供检索，下层一两句口吻推导，最影响下一步的放最后。
8. **来源不可洗白。** 工具输出只能是带来源的事实，永远不能渲染成「我的判断」。
9. **可逆到分支级。** 读回只取最小片段，否则噪声会跟着回流。

# 第四卷　条目价值 v(i) 的可计算化 × 长会话编译强度的控制论

> 接续 `INTERACTIONS-AND-FRONTIERS.md`。上一篇给出了目标 J(z) 和逐条目取舍式 v(i)，但只是**概念式**。
> 本篇做两件事，并证明它们其实是**同一个问题的两半**：
> - **A 篇（静态）**：把 v(i) 的每一项落到**可观测量 + 估计器**，让代码而不是副模型的“感觉”来决定取舍。
> - **B 篇（动态）**：把“编译强度”形式化为一个**反馈控制问题**，控制量恰好是 A 篇里的唯一自由参数——**token 影子价格 λ**。
>
> 一句话：**A 篇回答“在价格 λ 下每条值不值”，B 篇回答“此刻 λ 该是多少”。**

---

### 0. 统一框架：出生文本 = 在影子价格 λ 下的背包问题

每个推理块被副模型解析成一组**原子条目** i（上一篇 typed ops：FACT / COMPUTED / CLOSED / INCUMBENT / OPEN / PLAN）。对每条定义

```
v(i; λ) = Info(i) + Vac(i) + Neut(i) − Dist(i) − Prime(i) − λ·tok(i)
```

| 项 | 含义 | 对应机理 |
|---|---|---|
| Info | 决策价值 × 被需要概率 × 不可重导概率 | α 注意力预算 |
| Vac | 疫苗价值（仅 CLOSED）：阻止重走死路 | γ 锚定 / T3 |
| **Neut（新）** | **中和价值**：抵消上下文里**删不掉**的干扰物 | α + ζ |
| Dist | 干扰代价：与错误候选/过期版本相似 | Context Rot 相似干扰 |
| Prime | 启动代价：被否定的东西仍被激活/被复制 | ζ 否定薄弱 + β 归纳复制 |
| λ·tok | 占用代价：每 token 的影子价格 | α + η 倒 U |

**选取规则**：纳入 iff v(i;λ) > 0。
**位置规则**（不再是 v 的一项，而是排序）：按 v 降序决定层级——最高的进尾部第一人称散文层并可双编码；中间进行式；刚过零的只留 `art://` 指针。
**唯一自由参数**：λ。副模型不需要知道 λ，它只负责**标注属性**；取舍由代码在 λ 下计算。这把“压多少”从副模型的 prompt 里彻底拿走——这是对 T2“长度是编译的输出而不是参数”的最终兑现：**长度是 λ 的输出，λ 是控制器的输出。**

---

## A 篇：v(i) 的每一项如何计算

### A1. 设计原则：副模型只标注“它知道而代码不知道的”，代码算其余一切

副模型擅长语义判断，不擅长校准的数值；代码擅长计数，不懂语义。所以分工：

**副模型输出的 op 扩展属性**（全部是序数/枚举，不要它给概率）：

```json
{ "k": "CLOSED",
  "text": "不是权限问题（chmod 777 后仍 EACCES）",
  "pair": "→ 是路径错配：进程读的是 /srv/app/conf.yaml",
  "ev": "tool",              // tool | derived | guess     —— 证据等级
  "anchor": "chmod 777",     // 原文中的短引文，供代码定位跨度
  "supersedes": null,         // 若本条取代旧事实，给旧值
  "kind2": "plan|uncertainty|compute|check|setup|answer"  // 句子功能类（见 A3）
}
```

**代码自己算的可观测量**（零依赖 Node 可实现）：

| 可观测量 | 算法 |
|---|---|
| effort(i) | 用 anchor 在原文定位，统计该分支占用的 token 数 / 块总 token |
| revisit(i) | anchor 中的标识符在原文中被“重新拿起”的次数（间隔 >N token 再次出现） |
| fanout(i) | 条目中的标识符在**原文后续部分**被引用的次数（下游依赖） |
| visible(i) | 条目中的标识符/值是否仍**字面出现在当前请求里未被压缩的工具输出**中 |
| stale(i) | 当前上下文中是否存在同一键（路径、变量、配置项）的**不同值** |
| surprise(i) | 可选：小模型下的平均自信息（Selective Context 思路）[5](https://arxiv.org/html/2310.06201) |
| tok(i) | 渲染后 token 数 |

原则：**副模型负责“是什么”，代码负责“有多少”。** 这样 v 的数值来自可审计的计数，而不是一次采样的主观判断。

---

### A2. Info(i) = D(i) · Pn(i) · (1 − R(i))

#### D(i) 决策价值：这条会不会改变下一步动作？

最硬的外部锚点来自 **Thought Anchors**：对推理轨迹逐句做反事实重采样，发现**计划生成句和不确定性管理句**的反事实重要性最高，并被专门的“接收头”集中关注；**自我检查句**重要性偏低，**最终答案复述句**最低 [2](https://arxiv.org/html/2506.19143v1)。他们还发现，**凭肉眼读 CoT 往往认不出真正最重要的句子** [1](https://www.alignmentforum.org/posts/iLHe3vLur3NgrFPFy/thought-anchors-which-llm-reasoning-steps-matter)——这直接说明“让副模型凭感觉挑重点”有系统误差，必须有结构化先验。

于是：

```
D(i) = prior(kind2) · g(fanout) · h(k)
prior: plan 1.0 | uncertainty 0.9 | setup 0.6 | compute 0.5 | check 0.2 | answer 0.1
g(fanout) = 1 − exp(−fanout / 2)            // 下游引用越多越像“广播句”
h(k): INCUMBENT/OPEN/PLAN ×1.2 ； FACT/COMPUTED ×1.0 ； CLOSED 走 Vac 通道
```

`fanout` 是“接收头关注度”的**零成本代理**：Thought Anchors 中，被后续大量句子关注的“广播句”就是锚点 [2](https://arxiv.org/html/2506.19143v1)；在文本层，一个句子引入的标识符被后文反复使用，是同一现象的可观测投影。

**一个反直觉推论**：块末尾的“所以答案是 X”——人类觉得最重要——D 反而低，因为它是**被决定的**而不是**决定性的**；真正该保护的是导向 X 的那个转折句（“换个思路：先算十进制再数位数”）。这就是为什么 v3 的“结论优先”式摘要会系统性丢失价值：它保留了结果，丢掉了锚。

#### Pn(i) 被需要概率

```
Pn(i) = σ( a0 + a1·[标识符 ∈ 用户任务/当前PLAN] + a2·[k ∈ {OPEN, PLAN}]
          + a3·log(1+fanout) − a4·[所属子问题已 CLOSED] )
```

**关键发现：Pn 有免费的自监督标签。** cfb 位于宿主和模型之间，能看到**之后每一轮**。定义

> 条目 i 在 turn t 出生，若其标识符在 t+1…t+K 的主模型输出或工具调用中再次出现，则标签 needed(i)=1。

这是**在线、零人工、零额外调用**的训练信号。a0…a4 可以用逻辑回归在日志上拟合（这不是“测试”，是估计器的**可辨识性**：理论上 Pn 是可学习的，不必永远靠手调）。

#### R(i) 可重导概率：删掉后主模型能否自己轻松找回？

这是整个框架里**最被低估的一项**，它直接解释了你的“90% 冗余”：

- **FACT 且 visible(i)=1**（值仍在未压缩的工具输出里）→ R≈0.8–0.9。推理块里复述工具结果是纯冗余——**原件就在上下文里**。它最多值一个**索引**（“配置在 read_file#3 的输出里”），而不值复述。
- **COMPUTED**（多条观察合成的结论、算术结果、排除推理）→ R≈0.1。上下文里**没有任何地方**直接写着它；删了就要重算。这正是 InftyThink 消融里“去掉关键中间结论就掉分”的原因 [见上一篇]。
- **surprise 高**（小模型觉得出乎意料）→ R 低；surprise 低（套话、常识）→ R 高。

```
R(i) = FACT∧visible: 0.85 | FACT∧¬visible: 0.3 | COMPUTED: 0.1 | INCUMBENT: 0.2
       再乘以 (1 − 0.5·norm_surprise(i))   // 可选项
```

**推论（重要）**：原始推理块的 token 大头往往是 ①复述工具输出、②打转、③自我检查——三者 Info≈0；而 COMPUTED 和转折句只占很小比例。**“90% 冗余”在本框架中是一个可计算量**：在给定 λ 下 v(i)≤0 的条目 token 占比。它依赖于主模型和 λ，而不是一个常数——这是对你论点的**精确化**，而不是削弱。

### A3. Vac(i) 与 Prime(i)：死路的闭式取舍

对 CLOSED 条目，定义**诱惑度** T(i)——主模型在没有提示时重走这条路的倾向。关键洞察：

> **主模型在一条死路上花了多少 token，就是它对这条路先验偏好的直接证据。** 花 900 token 才放弃的路，下次还会想走；30 token 就排除的路，本来就没吸引力。

```
T(i) = clip( 0.5·effort_share(i)·k + 0.3·[revisit(i) ≥ 1] + 0.2·[该路是块内首个尝试], 0, 1 )
```

然后

```
Vac(i)   = T(i) · P_retry(i) · C_retry(i)
Prime(i) = μ · T(i) · (1 − L(i))
```

- P_retry：无提示时重试概率（与 T 同向，可取 ≈ T 或常数 0.7）。
- C_retry：重走代价（≈ 该分支原 effort 的 token 数折算）。
- L(i) **局部性**：否定是否紧贴被否定对象且与替代方案同行。配对式“不是 X（证据）→ 是 Y” L≈0.9；独立行“✗ X” L≈0.4；散文里远距离“前面那个方法不行” L≈0.1。
- μ：启动系数。对 ev=tool 的否定 μ 较小（有证据的否定更容易被“学会”），对 ev=derived 的否定 μ 较大。

代入 v（CLOSED 无 Info 项）：

```
v = T·[P_retry·C_retry − μ·(1−L)] − λ·tok
```

**三条闭式结论**：

1. **诱惑度是公因子**：T→0 时，v→−λ·tok < 0。**没被认真试过的死路永远不写**（修正 T3：疫苗只打给真正会复发的病）。
2. **配对是必要条件**：若 μ(1−L) > P_retry·C_retry，无论 T 多大 v 都 < 0——**未配对的死路是负价值**。所以代码层硬约束：CLOSED 必须带 pair，否则丢弃。这把上一篇“对比式局部否定”从风格建议升级为**由不等式推出的准入条件**。对比 CoT 的实证正是这一点：正负配对演示优于单独正例 [上一篇 Contrastive CoT]。
3. **高投入死路是最值钱的条目之一**：effort 大 → T 大且 C_retry 大，v 与 effort 近似**二次**增长。原始块里最长的那段弯路，编译后应变成最精炼的一行配对疫苗——**浪费最多的地方，恰好是价值最高的地方**。

---

### A4. Dist(i) 与 Neut(i)：过期版本与“删不掉的干扰物”

Chroma 的 Context Rot 发现，与正确答案**相似的干扰物**伤害最大 [上一篇]。在 agent 会话里，最常见的相似干扰物不是死路，而是**同一个键的过期值**：旧路径、旧函数签名、改之前的配置。

```
Dist(i) = ν · max_j sim_key(i, j) · [value(i) ≠ value(j)] · [i 是较旧版本]
```

sim_key 在文本层可近似为“同一标识符键”（路径前缀、变量名、配置键），零依赖可算。

**Neut(i) 是本篇新引入的一项**。cfb 只压推理块，**工具输出原样留在上下文里**。如果早先的工具输出里写着旧值 `/etc/app/conf.yaml`，这个干扰物**cfb 删不掉**。此时一条显式的取代行

> `配置路径：/srv/app/conf.yaml（取代 /etc/app/conf.yaml——后者是模板，进程不读）`

的价值不是提供信息，而是**中和**一个既存干扰物：

```
Neut(i) = [supersedes(i) ≠ null] · [旧值 visible] · ν' · sim_key
```

**推论**：同一条“取代”信息，旧值若已从上下文消失，写它是负价值（重新引入干扰）；旧值若仍可见，写它是正价值（中和）。**同一句话的价值取决于上下文里还有什么**——这是纯粹的逐条摘要（不看全局上下文）原理上做不到的，也是 cfb 位于请求链路上的结构性优势。

### A5. 证据等级 → 渲染方式（粘性按证据分配的数值化）

v(i) 决定**是否纳入**；ev 决定**以什么确定度渲染**，从而控制它的锚定强度（机理 γ）：

| ev | 渲染 | 锚定强度 |
|---|---|---|
| tool | 第一人称陈述，拉直：“我确认了 X（read_file#3）” | 高——应该粘 |
| derived | 暂定：“我目前判断 X，依据 A、B” | 中 |
| guess | 进 OPEN，写成问句：“X 是否成立？” | 低——不该粘 |

自锚定校准漂移的研究表明，模型在自己输出之上继续构建时置信度会漂移 [上一篇]；这张表的作用就是**让漂移方向与证据方向一致**：该坚定的坚定，不该坚定的从源头就不写成断言。

### A7. 估计器分层（从今天可用到理论上限）

| 层 | 用什么 | 覆盖的项 | 成本 |
|---|---|---|---|
| L0 结构 | 正则/标识符/anchor 匹配 | effort, revisit, fanout, visible, stale, tok | 零 |
| L1 副模型标注 | op 属性 ev / kind2 / supersedes / pair | D 先验、R 类别、L | 已在压缩调用内 |
| L2 在线自监督 | 后续 K 轮标识符复现 | Pn 系数、T 的校准（重走率） | 零（只需日志） |
| L3 小模型打分 | 自信息 / 困惑度 | R 的 surprise 修正 | 小 |
| L4 反事实真值 | Thought Anchors 式重采样 [2](https://arxiv.org/html/2506.19143v1) | D 的真值 | 高，只用于离线校准 |
| L5 主模型注意力 | 自托管时读接收头 | fanout 的真值 | 需自托管 |

**要点**：L0+L1 已足以运行完整的 v(i)；L2 让它**随使用自动变准**；L4/L5 是理论天花板，用来确认 L0 的代理量方向正确。

## B 篇：长会话中的编译强度控制

### B1. 为什么需要控制，而不是一个固定 λ

固定 λ 在长会话中必然失效，因为三个量**随时间漂移**：

1. **任务难度 d_t**：倒 U 研究表明最优 CoT 长度随难度上升、随能力下降 [上一篇 When More is Less]。卡住的阶段需要更多有效上下文，收敛阶段需要更少。
2. **编译文本占比 s_t**：会话越长，上下文里编译文本比例越高，越偏离主模型训练分布（机理 δ，上一篇 4.3）。
3. **累积误差**：每次有损编译都丢一点尾部信息，多次后罕见但关键的事实会消失。

第 3 点有一个很硬的类比：**模型坍缩**——用模型生成的数据递归训练，原始分布的**尾部会消失**，且缺陷不可逆 [2](https://www.repository.cam.ac.uk/items/43ad8d5f-0317-4a6d-9db0-85b352c01f7e)。上下文层面的递归有损摘要是同构过程：每一代摘要都偏向“典型”内容，**罕见的关键细节**（一个奇怪的错误码、一个边角配置）最先被抹掉——而它们往往正是 D 最高的东西。

### B2. 状态、控制、干扰

| 符号 | 含义 | 可观测？ |
|---|---|---|
| s_t | 编译文本占上下文比例 | ✓ 直接算 |
| ρ_t | 新块打转比 = 原始 token ÷ Δ状态条目数（T7） | ✓ |
| o_t | 当前 OPEN 条目数 | ✓ |
| d_t | 估计难度 = f(ρ_t, o_t, 连续未关闭轮数) | 间接 |
| λ_t | **控制量**：token 影子价格 | 输出 |
| m_t | 每块保真模式（raw-near / normal / aggressive） | 输出 |
| 干扰 | 新推理块、新工具输出、宿主压缩事件 | ✓ |

### B3. 目标函数

```
max Σ_t Q_t,   Q_t = Q( SNR_t , L_eff,t ; d_t ) − κ·φ(s_t) − ξ·Loss_t
```

- **SNR_t**：上下文中 Σ正 v 的 token ÷ 总 token。λ 越高 SNR 越高。
- **L_eff,t**：有效上下文长度。Q 对 L_eff 是倒 U，峰值 L*(d_t) 随难度右移。
- **φ(s)**：分布陌生度惩罚，**凸**：s 小时几乎无害，接近 1 时陡增（上下文变成一份日志文件，而非一段思考）。
- **Loss_t**：不可逆信息损失，由 λ 过高和递归编译造成。

**三个工作区**：

```
          Q
          │        ┌── 甜区 ──┐
          │      ╱            ╲
          │    ╱                ╲____ 饱和区：s→1，陌生度 + 尾部丢失
          │  ╱  噪声区：打转/复述占满注意力
          └───────────────────────────── λ
```

你的原始论点描述的是**噪声区**，它在现实中确实是默认状态（没有压缩时 λ=0）。本篇补上的是：**λ 推过头会进入另一个坏区**，所以需要控制器而不是“压得越狠越好”。

### B4. 四条结构性定律（由目标函数推出）

**定律 1 · 单次有损原则**
> 每个条目在生命周期内**最多经历一次有损变换**；之后只允许**无损操作**（合并、取代、降级为指针、删除）。

理由：递归有损是模型坍缩的同构过程，尾部信息不可逆丢失 [2](https://www.repository.cam.ac.uk/items/43ad8d5f-0317-4a6d-9db0-85b352c01f7e)。实现上：cfb 永远**不重新摘要**已编译的出生文本；一条条目要么原样保留，要么被 supersede，要么降级到 `art://`（原文仍可读回）。这把上一篇“宿主二次压缩近乎无损”的观察提升为**设计不变量**。

**定律 2 · 锚定自然文本**
> 上下文中必须始终保留一段**最近的、接近原始形态**的推理（raw-near 模式），s_t 设硬上限 s_max。

理由：φ(s) 凸，且 AgentFold 保留最新一步完整交互 [上一篇]。最近一块既是工作记忆（上一篇 4.2），又是**分布锚**——它告诉主模型“这里仍然是一段思考”，让前面的编译行被读作思考的沉淀，而不是异物。

**定律 3 · 难度自适应价格**
> λ_t 应随估计难度 d_t **下降**：卡住时放宽（保留更多 COMPUTED 与配对疫苗），收敛时收紧。

理由：L*(d) 随 d 上升。直觉上反常——卡住时反而少压——但卡住意味着 OPEN 多、分支多、需要的中间结论多；此时压得狠，恰好删掉了破局所需的材料。**真正要删的“打转”由 v(i) 自己识别（Info≈0），不依赖高 λ。** 这是 A 篇和 B 篇的关键耦合：**打转靠 v 删，不靠 λ 删。**

**定律 4 · 价值随时间迁移，而非随时间删除**
> 条目按衰减后的 v 在层级间下沉：尾部散文 → 行式 → `art://` 指针 → 移除；被再次引用时**上浮**。

这是上下文的**多级缓存**：

| 层 | 类比 | 内容 | 迁移触发 |
|---|---|---|---|
| L1 | 寄存器 | 最近块 raw-near + 尾部第一人称散文 | 新块到来 |
| L2 | 缓存 | 行式 FACT / CLOSED 配对 / INCUMBENT | Pn 衰减 |
| L3 | 内存 | `art://h#branch` 指针（可读回） | v 过零 |
| L4 | 磁盘 | 跨会话项目级负知识（上一篇 5.4） | 会话结束 |

Pn 按半衰期衰减：`Pn(t) = Pn(0)·2^{−(t−t0)/H_k}`，H 随类型不同（FACT 长、PLAN 短、CLOSED 取决于子问题是否仍开放）。被主模型重新提及时 Pn 复位（LRU 语义）。

> 若宿主**只允许出生时写一次**、之后不能改历史：定律 4 通过**预分层渲染**实现——出生文本内部按层排列，并与宿主压缩器约定“先丢下层”（上一篇 5.7 协议）。若宿主允许每轮重写请求历史：直接执行迁移。

### B5. 控制器：天然传感器 + 非对称更新

**cfb 已经拥有四个免费的反馈传感器**，这是本篇最实用的发现：

| 传感器 | 信号 | 含义 | λ 调整 |
|---|---|---|---|
| 读回率 | 主模型调用 `art://` 的频率高于基线 | **压过头**：删了需要的东西 | ↓ 快 |
| 疫苗失效 | 主模型重走已配对的 CLOSED 路 | 疫苗渲染弱，或 T 被低估 | 该条上浮 + 标注 T↑ |
| 重复询问 | 主模型重新探查已确立的 FACT | 信息丢失 | ↓ 快 |
| 打转回升 | 新块 ρ_t 持续上升，且 s_t 低 | **压不够**：噪声仍多 | ↑ 慢 |
| 打转回升 | 新块 ρ_t 上升，且 s_t 高 | **饱和**：陌生度造成困惑 | ↓ 并强制 raw-near |

最后两行说明：**同一个症状（打转）在两个区域有相反的处方**，必须用 s_t 消歧。只看打转的控制器会在饱和区越压越糟——正反馈失稳。

**更新律**（借鉴 TCP 拥塞控制的 AIMD，方向相反）：

```
若 丢失信号（读回超额 / 重复询问）:   λ ← λ · β        (β≈0.6，乘性下降)
否则若 噪声信号 且 s_t < s_max:       λ ← λ + δ        (加性上升)
否则:                                λ 不变 (死区，防振荡)
λ ← clip(λ, λ_min(d_t), λ_max)
```

**非对称的理由**：丢信息的代价（主模型走错、不可逆）远大于多留几十 token 的代价（轻度分心、可恢复）。所以“发现丢了就快退，没事就慢慢加”。这与 TCP“丢包就减半、平稳就线性增加”同构，也继承了它的稳定性直觉。

**多时间尺度**：
- 块内（毫秒）：m_t 保真模式，由块类型决定（上一篇 4.2）。
- 轮间（秒–分钟）：λ_t 由上面的 AIMD 更新。
- 会话级：s_max、H_k 半衰期。
- 跨会话：λ 初值和 Pn 系数从历史日志继承（L2 自监督）。

### B6. 稳定性与失效模式

| 失效 | 机制 | 防护 |
|---|---|---|
| 振荡 | 读回 → λ↓ → 噪声 → λ↑ → 丢失 … | 死区 + 滞回（上升需连续 N 轮噪声信号） |
| 饱和正反馈 | 打转被误判为压不够 | s_t 消歧（B5 最后一行） |
| 古德哈特 | 优化读回率 → 主模型学会少读回而不是少需要 | 读回只作为传感器，不作为目标；目标仍是 Q |
| 冷启动 | 新会话无统计 | λ 初值取项目历史中位数；前 3 块强制 normal |
| 宿主压缩冲击 | 宿主突然整体压缩，s_t 跳变 | 监听压缩事件，重置 s_t 估计，不据此更新 λ |

## C. 两篇合一：这套理论现在能说什么

1. **你的论点被形式化了**：“CoT 90% 是冗余”= 在合理 λ 下 v(i)≤0 的 token 占比。它可计算、依赖于模型和任务，并且解释了**为什么**冗余——复述可重导的工具输出（R 高）、打转（Info≈0）、自检（D 低）、浅尝的死路（T≈0）。
2. **“删冗余让模型更好”有了精确条件**：当且仅当被删的是 v<0 的条目，**并且** λ 停在甜区。删 v<0 的条目**严格提升** J（它们的 Dist+Prime+占用代价 > 信息价值）；越过甜区的继续压缩才开始伤害。所以提升不是运气，是**可设计的**。
3. **原始块中浪费最多的部分，编译后价值最高**（A3 结论 3）：长弯路 → 一行配对疫苗。这是最反直觉、也最能区分 cfb 与普通摘要的一点。
4. **同一句话的价值取决于上下文里还有什么**（A4 Neut）：这是请求链路位置赋予 cfb 的、离线摘要器原理上不具备的能力。
5. **打转靠 v 删，不靠 λ 删**（定律 3）：解耦了“识别噪声”和“控制总量”两件事，避免了“为了删打转把 λ 调高、结果连 COMPUTED 一起删了”的老问题——这正是 v3 固定 250–450 字长度会同时犯的两种错。
6. **单次有损原则**（定律 1）：长会话不退化的必要条件。

### D. 仍未解决的理论问题（诚实清单）

1. **D 的代理量误差有多大**：fanout 与反事实重要性的相关性在 agent（非数学）轨迹上未知；Thought Anchors 的数据来自 MATH 数学题 [4](https://www.emergentmind.com/papers/2506.19143)。
2. **μ（否定启动系数）的量级**：Negation Neglect 的证据来自微调而非上下文 [上一篇]；上下文中的局部配对是否把 μ 压到接近 0，只有理论论证。
3. **φ(s) 的形状**：凸是论证，不是测量；s_max 取 0.6 还是 0.85，理论给不出。
4. **T 由 effort 推断的混淆**：花了很多 token 的路，可能是因为难算，而不是因为诱人。revisit 可以部分消歧，但不能完全消除。
5. **多条目交互**：v(i) 假设条目独立可加；实际上两条 COMPUTED 可能互相替代（次模性）。严格形式应是次模最大化，贪心算法有 (1−1/e) 保证——框架可扩展，但本篇未展开。
6. **主模型异质性**：同一组 v 对 Claude / GPT / DeepSeek 是否一致？机理 δ 说不会完全一致；按主模型校准渲染（上一篇 5.5）是答案的方向。

## 第一部分：六个开放问题

### P1 · 决策价值 D 的代理量在 agent 轨迹上是否成立？

**原问题**：Thought Anchors 的证据来自数学题。

**新证据**：SWE-TRACE（长程 SWE agent）在构造记忆时只保留两类步骤：**本身重要的步骤**（δ_abs），以及**显著改变进展的决策点**（δ_chg）[2](https://arxiv.org/html/2604.14820v1)。它还明确**避免激进改写**，因为文件名、堆栈、命令输出、补丁内容一旦被改写，就可能凭空捏造或遗漏 [2](https://arxiv.org/html/2604.14820v1)。这是 agent 领域对“保留转折点 + 标识符逐字”的独立印证。

**理论推进：agent 轨迹比数学题更容易估计 D**，因为 agent 有**可观测的动作**：

> **动作锚定律**：一个推理句的决策价值，可以用“它的标识符是否进入了紧随其后的工具调用参数”来测量。

数学 CoT 的“决策”藏在文字里，只能靠重采样；agent 的决策会**落地成工具调用**。句子中提到的路径、函数名、命令如果出现在下一个 tool_call 的参数里，这句话就是那次动作的**直接原因**——这是 Thought Anchors 意义上“计划句”的一个免费、确定的标签。

**修正**：D 的先验表换成 agent 专用分类，并新增 `actionLink` 观测量：

```
kind2 ∈ { pivot, plan, hypothesize, localize, inspect, compute, verify, restate, answer }
prior:   1.0    1.0    0.8          0.7       0.4      0.5      0.25    0.05     0.1
D(i) = prior(kind2) · (0.6 + 0.4·g(fanout)) · (1 + 0.5·actionLink(i))
```

- `pivot`（“换个思路”“等等，这说明……”）对应 δ_chg，是最高价值类。
- `restate`（复述工具输出）是新分出的最低类——它就是 A2 里 R 高的那部分。
- `actionLink(i) ∈ {0,1}`：条目标识符 ∩ 下一次工具调用参数 ≠ ∅。

### P2 · 否定启动系数 μ 的量级与形式

**原问题**：Negation Neglect 的证据来自微调，上下文里的否定是否同样有害？

**新证据**：一位从业者报告了上下文内的对照实验（每组 500 次，同模型同上下文）。“先写禁令”的违规率是 31%，“先写正向指令、再给理由、最后写禁令”是 6%；**只调换句子顺序**，就从 31% 降到 14%；**理由部分一旦提到被禁止的概念，违规率翻倍** [3](https://www.reddit.com/r/GithubCopilot/comments/1safu4m/do_not_think_of_a_pink_elephant/)。这是实践者的数据，不是同行评审，但方向与机理 ζ（否定薄弱）、β（归纳复制）完全一致。机理层面的解释是：被禁止的词元一旦进入上下文，就会进入隐藏状态并影响 logits，而“not”只是一个小小的翻转词元 [2](https://ai-tldr.dev/learn/prompt-engineering/prompting-basics/negative-prompting-constraints-llm/)。

**理论推进：μ 不是常数，而是渲染的函数**

```
μ(i) = μ0 · ω_order · ω_spec · ω_rep
ω_order: 替代方案在前 0.45 | 否定在前 1.0
ω_spec:  X 以类别层级表述 0.6 | 以可复制的精确词元表述 1.0
ω_rep:   X 只出现一次 1.0 | 在理由中再次出现 2.0
```

**三条渲染定律**：

1. **替代先行**：写 `是路径错配：进程读 /srv/app/conf.yaml（已排除权限：chmod 777 后仍 EACCES）`，而**不是** `不是权限（…）→ 是路径错配`。这修正了上一篇 A3 的配对顺序：**配对是必要条件，替代先行是充分改进。**
2. **最小可辨识具体度**：被排除的 X 只写到“主模型能认出这条路”的程度即可。例如“改权限类方案”就够了，不必写出完整的 `chmod -R 777 /etc/app`。精确命令会成为归纳头的复制模板。**例外**：诱惑点恰恰在于某条具体命令时，必须写精确命令，否则疫苗认不出病原体。代码规则：T 高且 X 为命令类时保留精确形式，否则降到类别层级。
3. **X 只出现一次**：证据括号里不再重复 X。

### P3 · 分布陌生度 φ(s) 的形状

**原问题**：凸是论证，s_max 给不出。

**理论推进：φ 的自变量错了。** 陌生度不取决于“被压缩的比例”，而取决于两件事：

**(a) 位置加权。** 注意力对近处更敏感，生成点附近的文本主导主模型的“文体判断”。所以真正的自变量是**近因加权编译占比**：

```
s_w = Σ_j w(dist_j)·[j 是编译文本]·tok_j / Σ_j w(dist_j)·tok_j ，  w(d) = exp(−d / W)
```

约束放在 s_w 上（生成点附近必须有自然文本），而不是全局 s。长会话的远端可以几乎全是编译文本，却完全无害。

**(b) 体裁稀有度。** 模型见过海量的 git commit、变更日志、调试笔记、工程师的 TODO 清单、issue 评论。**编译文本只要伪装成某种高频的预训练体裁，就是分布内的。** 陌生的不是“压缩”，而是“没人这么写”。

> **体裁伪装原则**：φ(render) ≈ −log P_pretrain(体裁)。编译行应渲染成一种主模型见过亿万次的体裁，而不是自创的符号系统。

这直接回答了 atlas 里“机器专用语言”方向的风险：**自创的压缩符号语言（φ 高）只有在训练过的主模型上才可能赢；对现成的主模型，最优“机器语言”是最常见的工程体裁。** 两者并不矛盾，适用的前提不同。

**(c) 最强的分布内文本，是主模型自己会写的文本**（见 P6）。

**修正**：
- 控制器约束改为 `s_w ≤ s_w,max`，W ≈ 最近一个推理块的长度。
- 行式层渲染成“调试笔记 / 提交记录”体裁；尾部散文用主模型自己的语气。

### P4 · 诱惑度 T 由 effort 推断的混淆

**原问题**：花了很多 token 的路，可能是因为难算，而不是因为诱人。

**理论推进：把 effort 按句子功能分解。**

```
effort(i) = effort_explore(i) + effort_compute(i)
  explore = 分支内 hypothesize / plan / pivot-back 句的 token
  compute = 分支内 compute / inspect / verify 句的 token
T(i) = clip( 0.45·norm(effort_explore) + 0.25·[revisit ≥ 1] + 0.15·[首个尝试] + 0.15·[放弃理由为猜测], 0, 1 )
```

难算只贡献 compute 部分，不进 T；反复设想、绕回来才是诱惑的证据。

**更重要的推进：“证伪”与“搁置”必须分开。** 上面最后一项“放弃理由为猜测”揭示了一个类型错误：一条因为猜测而放弃的路**并没有被证伪**，把它写成 CLOSED 是**过度确信**，恰好违反了“粘性按证据分配”。

| 新类型 | 条件 | 渲染 | 位置 |
|---|---|---|---|
| **REFUTED 证伪** | ev = tool：有观测直接否定 | 替代先行的配对疫苗 | 行式层 |
| **SHELVED 搁置** | ev ∈ {derived, guess}：因推断/优先级放弃 | “暂不走 X，因为 Y；若 Z 则回来” | OPEN 附近，作为条件分支 |

SHELVED 在 v(i) 里走 Info 通道而不是 Vac 通道：它的价值在于**保留回头路的触发条件**，而不是阻止重试。于是 T 的混淆被一分为二：**高 T 的 REFUTED → 强疫苗；高 T 的 SHELVED → 带触发条件的挂起。** 后者正是 Lost in Conversation 所描述的“早期锁死、无法恢复” [上一篇] 的解药——你不能永久关死一条只是被猜测否掉的路。

### P5 · 条目之间不独立：从可加到次模

**原问题**：v(i) 假设可加，但条目会相互替代或互补。

**新证据**：把上下文选择建模为**次模集合覆盖**，贪心算法可以继承 (1−1/e) 与 (1+ln n) 的近似保证，同时强制一个多样性（非冗余）下限 [3](https://www.arxiv.org/pdf/2510.00079)；上下文学习中的示例选择用**次模互信息**同时兼顾相关性和非冗余，并且贪心选取天然给出一个按信息增益递减的顺序 [1](https://pith.science/paper/2508.21003)。

**理论推进**：三种交互，三种结构

| 交互 | 例子 | 形式化 |
|---|---|---|
| **替代（冗余）** | 两条条目都蕴含“竞态已排除” | 次模：边际增益递减，f(S∪i) − f(S) = v(i) − Σ_{j∈S} red(i,j) |
| **同键互斥** | 同一配置路径的新旧两个值 | **划分拟阵**：每个键最多一条当前值（旧值只能以 supersedes 附属形式出现） |
| **互补（支撑闭包）** | COMPUTED 结论 ← 它依赖的关键证据 | **前驱约束**：选了结论，必须至少带一条证据指针（可以只是 `art://`） |

**算法**：带划分拟阵约束的**惰性贪心**。
1. 每轮按边际增益 Δ(i|S) = v(i) − Σ red(i,j) 取最大者。
2. 若 Δ ≤ 0 停止——**λ 仍然是唯一的停止条件**，长度仍是输出。
3. 同键冲突时只保留最新值。
4. 选入 COMPUTED 时自动补上其证据指针。

划分拟阵下贪心有 1/2 近似保证；对 cfb 这种每块 5–30 个条目的规模，精确解也可行，但贪心的**顺序本身**就是位置规则所需的价值排序 [1](https://pith.science/paper/2508.21003)，所以不必另外排序。

**冗余的零依赖估计**：`red(i,j) = ρ · Jaccard(ids(i), ids(j)) · [同 k 或 COMPUTED 蕴含 FACT]`。

**与“冗余≠噪声”的统一**：次模性说的是**第二次写同一信息，边际价值递减但不为零**。有意的双编码只对 v 最高的条目做，因为只有它们在递减之后仍然 > λ·tok。这把上一篇的原则 1 从直觉变成了一个**阈值**。

### P6 · 主模型异质性

**原问题**：同一组 v、同一种渲染，对 Claude / GPT / DeepSeek 是否一致？

**理论推进：不需要按厂商建表。**

> **自镜像原则**：对任意主模型，分布内程度最高的文本，是**它自己在同样情境下会写出的文本**。

cfb 手里有主模型**刚写的原始推理块**，所以它天然掌握主模型的：
- 思考语言（中文 / 英文 / 混合）；
- 标记习惯（“Wait,” “Hmm,” “所以”“嗯”）；
- 标识符书写方式（反引号、引号、裸写）；
- 人称与句长分布。

渲染器从最近 N 个原始块提取一个**风格画像**，再按画像渲染尾部散文层：同样的语言，同样的连接词，同样的标识符包裹方式。困惑度与性能负相关的发现（Gonen 等）[上一篇] 在这里有一个直接推论：**用主模型自己的风格写，困惑度最低。**

**这同时解决了三件事**：
- 异质性：风格画像自动适配，零配置；
- 上一篇 4.5“副模型先验”：副模型的文风被渲染器覆盖，不会泄漏到出生文本里；
- 定律 2（自然文本锚）：尾部散文本身就“像主模型自己写的”，从而压低 s_w 的实际陌生度。

**边界**：风格镜像只作用于**形式**。“写成它自己的风格”绝不能扩展成“写成它自己的判断”——工具输出来源的内容仍然必须带来源（注入放大防线，上一篇 4.1）。

## 第二部分：v4 编译器规格

### S1. 流水线

```
原始推理块 ──► ① 副模型：解析为 ops（JSON，只做语义标注）
             ──► ② 校验器：硬不变量；失败 → 原文（永不回退到 x1）
             ──► ③ 观测量：effort/revisit/fanout/actionLink/visible/stale/tok（代码）
             ──► ④ 打分：v(i; λ)
             ──► ⑤ 选取：惰性贪心 + 划分拟阵 + 支撑闭包 + 配对准入
             ──► ⑥ 渲染：分层 + 体裁伪装 + 自镜像 + 替代先行 + 证据定粘性
             ──► 出生文本 + art:// 原文存档（分支级寻址）
下一轮 ◄──── ⑦ 传感器：读回 / 疫苗失效 / 重复询问 / 打转 × s_w ──► AIMD 更新 λ
          └── ⑧ 日志：标识符复现 → Pn 自监督标签
```

**与 v3 的根本区别**：副模型**不再写出生文本**，只输出结构化标注；**写作由代码完成**。长度、措辞、顺序、人称、否定形式全部由代码按理论决定，副模型的文风和长度偏好都无法再影响结果。

### S2. op 模式（副模型输出）

```json
{
  "ops": [
    {
      "id": "o1",
      "k": "FACT | COMPUTED | INCUMBENT | REFUTED | SHELVED | OPEN | PLAN",
      "key": "config.path",
      "text": "进程实际读取 /srv/app/conf.yaml",
      "ev": "tool | derived | guess",
      "src": "tool:read_file#3 | self",
      "kind2": "pivot | plan | hypothesize | localize | inspect | compute | verify | restate | answer",
      "anchor": "strace 显示 open(\"/srv/app",
      "alt": "（仅 REFUTED/SHELVED）替代方案文本",
      "why": "（仅 REFUTED/SHELVED）证据或放弃理由",
      "trigger": "（仅 SHELVED）何种情况下回来",
      "supersedes": "（可选）旧值",
      "deps": ["o0"]
    }
  ]
}
```

所有字段都是**枚举或原文片段**，没有一个数值。副模型不打分。

### S3. 硬不变量（校验器，任何一条失败 → 该 op 丢弃；关键 op 失败 → 整块回退原文）

| # | 不变量 | 理由 |
|---|---|---|
| I1 | `anchor` 必须是原文的逐字子串 | 定位跨度；防止捏造 |
| I2 | `text` 中的标识符（路径/命令/数字/错误码）必须逐字出现在原文或当前工具输出中 | 标识符精确性；SWE-TRACE 的改写捏造风险 [2](https://arxiv.org/html/2604.14820v1) |
| I3 | REFUTED 必须满足 `ev = tool` 且带 `alt` | 配对准入（A3 结论 2）；证伪需要观测 |
| I4 | ev≠tool 的“否定”一律归为 SHELVED | P4 类型拆分 |
| I5 | `src` 以 tool: 开头的 op，渲染时永不使用“我决定/我应该” | 注入放大防线 |
| I6 | 已编译文本永不作为副模型输入 | 单次有损原则 |
| I7 | 同一 `key` 在当前出生文本中最多一个当前值 | 划分拟阵 |

### S4. 副模型提示词（v4-ops 草案）

```
你是推理解析器。把下面这段推理拆成原子条目，输出 JSON（模式见后）。你不写摘要，只做标注。

逐条判断：
- k：这是已确认的事实、推导出的结论、当前采用的方案、被观测证伪的路、被搁置的路、未决问题，还是下一步计划？
- ev：依据是工具观测、推理，还是猜测？没有工具观测就不是 tool。
- kind2：这句在推理中的作用。“换个思路/等等这说明”类转折标 pivot；复述工具输出标 restate。
- anchor：从原文逐字摘一个 5–20 字的短片段，用来定位这条的出处。
- 被放弃的路：写出替代方案 alt 和理由 why。若理由不是工具观测，k 用 SHELVED，并写 trigger。
- 路径、命令、数字、错误信息逐字照抄。
- 只标注推理里实际出现的内容。

原文：
<<<RAW>>>
```

长度约 420 字，与 v3 相当；输出 JSON 通常比 v3 的散文**更短**，因为副模型不再写连接词和修饰。

### S5. 渲染模板

**层 A：行式（调试笔记体裁）**，按贪心顺序排列：

```
- config.path = /srv/app/conf.yaml（read_file#3；取代 /etc/app/conf.yaml，后者为模板）
- 是路径错配（已排除权限类方案：chmod 后仍 EACCES）
- 暂不查网络：无网络调用痕迹；若出现 ECONNREFUSED 再回来
- 竞态已排除：三处日志时间戳一致  → art://h3#b2
```

**层 B：尾部散文（自镜像，第一人称，≤3 句）**，只放 v 最高的 1–3 条（双编码）以及 OPEN 问句（**已被 S8 修订 R3：块尾放判读 / 已备动作，OPEN 写成陈述**）：

```
所以现在确定是路径错配，进程读的是 /srv/app/conf.yaml。还没弄清的是：它是不是 symlink？
```

**渲染规则汇总**：
1. 证据定粘性：tool → 陈述；derived → “目前判断”；guess → 问句。
2. 替代先行；X 最小具体度；X 只出现一次。
3. 标识符逐字、全名、无代词（自包含）。
4. 语言、连接词、标识符包裹方式跟随风格画像。
5. 工具来源的内容只写成事实并带来源，永不写成“我决定”。

### S6. 默认参数

| 参数 | 初值 | 说明 |
|---|---|---|
| λ0 | 0.004 / token | 算例校准；由控制器更新 |
| λ 范围 | [0.001, 0.02] | λ_min 随难度 d 下调 |
| β（乘性降） | 0.6 | 丢失信号 |
| δ（加性升） | 0.0005 | 噪声信号，连续 2 轮才触发 |
| W（s_w 窗口） | 最近块 token 数 | P3 |
| s_w,max | 0.7 | 超出 → 下一块强制 raw-near |
| 双编码阈值 | Δ 递减后仍 > 3·λ·tok | P5 |
| Pn 半衰期 | FACT 8 轮 / PLAN 2 轮 / OPEN 6 轮 | 定律 4 |

**归因表**

| # | 现象 | 归因 | 类别 |
|---|---|---|---|
| R1 | 原文每块有 1–7 句「若观察为 A ⇒ 结论/动作」；v4 产物 9/10 份为 0 句，只剩 OPEN 问题 | op 模式只有「状态」类（FACT/COMPUTED/INCUMBENT/REFUTED/SHELVED/OPEN/PLAN），**没有「判读」类**：理论把推理看成信念快照，漏了**从下一条观察到动作的映射** | **理论缺口** |
| R2 | 原文 21 句「修复/改为」，产物 0 句 | 同上（缺「已备动作」类），且规则「存疑不升级 / 不给建议」被执行成「删掉候选改法」 | 理论缺口 + 规则表述 |
| R3 | 产物以「还没弄清的是…？」收尾；主模型一律回头取证 | S5 层 B 规定「OPEN 问句」放在块尾，而块尾是近因权重最大的位置 ⇒ 最强地启动「继续取证」 | **理论规则副作用** |
| R4 | 产物零第一人称、满是「目前判断/当时计划/来源」标签 | S5 层 A 选了「调试笔记体裁」，与 P6「自镜像」相矛盾；「当时计划」这类过去时，让主模型把它读成过期记录 | 理论内部不一致 |
| R5 | 选取按 kind 静态权重（INCUMBENT 1.0 … PLAN 0.35） | 理论 v(i) = 决策价值 × P(需要 ∧ 想不回来)（卷三），以及「紧接工具调用的块提高保真」（卷三 §对策），**实现没有落地** | 实现问题 |
| R6 | 副模型无视长度、复述可见回答、判读句已列进提示词仍漏标、模板语言判错 | 提示词约束不可靠 | 实现问题 |

**理论修订**

1. **决策价值拆出「判读项」Pol**。下一轮主模型面对的是（状态 s，新观察 o）。对原文里一条映射 m：o_k ⇒ a_k，
   `Pol(m) = P(o = o_k) · C_re(m)`，其中 C_re 是主模型在**没有原推导**时重新推出这条映射的代价。
   上一轮刚发出的调用，正是为了得到 o；原文针对它写的映射满足 P(o = o_k) 高、且原推导已被压缩删除 ⇒ C_re 大。
   因此针对**即将回来的观察**的判读，是全块价值最高的条目，高于 INCUMBENT。
   同理，**已备动作**（READY：改哪、怎么改、前提）的 Pol 等于「前提成立的概率 × 重新设计改法的代价」，也属于高价值。
   新 op 类：`IF{cond, then}`、`READY{text, trigger}`；两者都必留（IF 至多 4、READY 至多 2），且不受长度预算约束。
2. **块尾放判读，不放问题**。近因位置只放「若 A，就 B」；OPEN 写成陈述，不写成问句。有判读时，OPEN 不再在块尾重复
   （判读本身就是「这个问题的各种答案意味着什么」）。
3. **全块采用第一人称内心独白**（P6 自镜像扩展到层 A）：「我目前判断 / 我现在采用 / 接下来要 / 我准备的改法 / 判读：若…就…」。
   I5 不变：工具来源的内容只写成事实，不写成「我决定」。
4. **预算下限**：层 A 必须装得下「判读 + 已备动作 + 死路」。实测 ≈550 字不够、≈935 字明显更好（倒 U 的上升段）⇒ 下限 800 字。
5. **末尾不保留原文**（回答「为什么不直接保留最后 25%」）：
   原文末尾之所以有效，是因为 R1/R2 的映射和动作恰好集中在那里（它们紧挨着那条工具调用）。但末尾同时有大量 Dist/Prime 项，
   例如起草回答、斟酌格式（「最终用中文」「要不要用 rg」）、复读工具输出。保真度应当**由 v(i) 决定，而不是由位置决定**：
   把末尾里高 Pol 的条目按必留收进来，同时去掉低价值项，在同样的决策价值下 token 更少、干扰更小，所以优于原样保留末尾。
   前提是高 Pol 条目的召回有保证 ⇒ 实现上用代码保底（原文判读/改法句逐字补入）。原文尾巴只保留在**失败回退**里
   （增量模式到点时未编译完的部分），不作为设计选择。
6. **可预测、可证伪**：修订后预测，v4-ops7 的「直接改」比例应接近或超过原文（40%），并且显著高于 v4-ops4/5（≈25%）。
   如果没有达到：先检查 IF/READY 召回（实现问题），再检查语域（R4）是否真的起作用（理论问题）。

**R1′ 判读项的严格定义（it1 实测后补，2026-09-28）**
it1（ops7，5/5 标出了 IF）仍低于原文：综合 4.6 对 5.4，直接改 30% 对 40%。逐条看，失败样本的 IF 大多是**机理条件句**
（「若 I/O 回调晚于定时器，则失败」「若 finish_reason 缺失，就返回 stop」），真正的判读反而漏了，例如 flaky 原文
「先执行命令验证，而不是直接改；**如果失败复现，再修**」。Pol 的定义要求 P(o = o_k) 高，这里 o 是**待回观察**，
也就是上一轮发出的那条调用的结果。机理条件句描述的是程序行为，与这次观察无关，按定义 Pol ≈ 0，应当归为 COMPUTED。
因此：
- IF 的 cond 必须是**待回观察的一种可能结果**（「若复现了 / 若 n 里有 model / 若 finishReason=length」），
  then 必须是**结论或动作**。问句与机理条件句都不算 IF。
- 原文给出了「假设 H」与「针对 H 的改法 F」，而待回观察正是在检验 H 时，(H 被证实 ⇒ F) 属于原文内容的合取，
  不是编造：两部分都有原文锚点。它是全块价值最高的条目，必须标出。
- 原文「如果…再…」「…才…」也是判读句式（原检出式只认「则 / 就」，漏掉了 flaky 的那一句）。

**实现对应**（v12.5，`compress-v4-ops7`）：IF/READY 类与必留；块尾顺序为 结论 → 判读 → 已备动作；第一人称模板；预算下限 800；
代码保底 `autoHintOps`（副模型对某类一条都没标时才补；否定/犹豫句与超长句不补）；模板语言跟随条目内容；
v3/v4 都不复述最终回答。

你最初的论点：**CoT 约 90% 是冗余，这些噪声分散主模型注意力，清理它能提升专注力和判断力。**

v4 规格在理论上的回答：

1. **识别噪声**：v(i) ≤ 0 的条目，主要是 restate（复述工具输出）、verify（自检）、浅尝的死路、打转——由代码按可审计的量判定，不靠副模型感觉。
2. **不只是删**：删掉噪声的同时，把**高投入的弯路编译成疫苗**、把**猜测否掉的路挂起而不关死**、把**删不掉的旧值中和掉**、把**真正的转折点和综合结论**放到尾部并用主模型自己的语气重述。这些是**主动塑形**，也是“删冗余”之外进一步提升判断力的来源。
3. **不压过头**：λ 由反馈控制，在甜区内浮动；单次有损、近因加权的自然文本锚，保证长会话不退化。

### 0. 行业证据：清理陈旧内容确实提升表现

在进入理论之前，先记录一条对你的原始论点最直接的外部支持。

这是厂商在自家评测上的数字，不是独立复现，但方向很清楚：**删掉陈旧内容不只是省钱，而是让模型做得更好。** 同时要注意它的策略是**按时间**清理（默认保留最近 3 次工具调用）[2](https://lobehub.com/skills/adaptationio-skrillz-claude-context-management)，不看内容价值。cfb 的全部理论可以看作把“按时间清理”升级为“按价值清理”。

## 第一部分：跨会话疫苗记忆

### V1. 为什么是“负知识”优先

**外部证据**：ReasoningBank 从智能体自评的成功和失败经验中提炼可复用的推理策略；只用成功轨迹时得分 46.5，**加入失败轨迹后升到 49.7**，而其他基线加入失败轨迹后反而停滞或退化 [1](https://arxiv.org/html/2509.25140v1)。关键差别在于：失败必须被**提炼成预防性教训**，而不是原样存储——原样存储的失败就是噪声。

**本理论的解释**：用 A2 的可重导性 R 看跨会话：
- **正知识**（代码结构、配置位置）在新会话里通常**可重导**：读一下代码就知道了。R 高 → 跨会话价值低。
- **负知识**（“EACCES 在这个项目里不是权限问题，是容器挂载路径和配置路径不一致”）**不可重导**：新会话的模型没有任何办法知道这条路已经被走过，只能重新花 900 token 再走一遍。R≈0 → 跨会话价值高。

> **跨会话不对称定律**：会话内，正负知识都会丢；跨会话，正知识大多能重新读出来，负知识**只能重新踩坑**。所以跨会话记忆的第一优先级是负知识。

这也是“同一个坑全项目只踩一次”的理论依据。

### V2. 三个抽象层级

会话内的 REFUTED 条目是**实例级**的（具体路径、具体命令）。跨会话需要决定在哪个层级存储：

| 层级 | 例子 | 可迁移性 | 被错误套用的风险 |
|---|---|---|---|
| **实例** | `/srv/app/conf.yaml` 的 EACCES 不是权限问题 | 只在同一文件、同一环境下有效 | 低（键精确匹配） |
| **模式** | 本项目中，EACCES + chmod 无效 → 先用 strace 查进程实际打开的路径 | 同项目内同类症状 | 中 |
| **策略** | 权限类错误在容器环境中常是路径/挂载问题 | 跨项目 | 高——正是“相似干扰物” |

ReasoningBank 存储的是策略层 [1](https://arxiv.org/html/2509.25140v1)。但按本理论，**策略层最危险**：Context Rot 表明与正确答案相似的干扰物伤害最大；一条被检索进来却不适用的策略，恰好就是一个高度相似的干扰物。

**层级选取规则**：
- 默认只存**实例层**和**模式层**（项目内）。
- **归纳触发**：同一模式签名在 ≥2 个独立会话中的实例层都被证伪，才上升为模式层；策略层留给宿主的通用记忆，cfb 不写。
- 这是一种**保守归纳**：宁可少泛化，不可错泛化，因为错误泛化的代价是 Dist（干扰），而不泛化的代价只是 C_retry（再踩一次坑）。

### V3. 证据指纹：记忆何时失效

跨会话记忆最大的问题不是存什么，而是**什么时候它不再为真**。代码改了、依赖升级了、配置换了，一条“已证伪”可能已经不再成立。把一条过期的疫苗当真，就是把 Lost in Conversation 的“早期锁死”延伸到了跨会话。

> **证据指纹原则**：每条记忆都携带它被证实时的**证据指纹**——相关文件的内容哈希、依赖版本、配置键的值、提交号。检索时重算指纹：一致则有效；不一致则**自动从 REFUTED 降级为 SHELVED**，渲染为“曾在旧版本中证伪，环境已变，可以重新考虑”。

这与 cfb 现有 memory 模式的设计完全同构：`state-memory.js` 已经把“哪些条件改变后需要重新判断”列为要保留的关系之一，并采用追加式修正、不抹掉过去。证据指纹只是把这个“条件”变成**可机器校验的哈希**。

**指纹的来源**：条目中的标识符（路径、包名、配置键）→ 当时工具输出中这些对象的内容 → 取哈希。cfb 已有 CAS（内容寻址存储），哈希几乎是免费的。

**失效是非对称的**：
- 一次反例立即失效：主模型按疫苗走了替代路线却失败，或者被证伪的路在新会话里成功了 → 立刻写入墓碑记录，该条目停止注入。
- 确认需要多次：一条条目被命中且主模型因此避开坑、后续取得进展，才提高其置信度。

### V4. 写入门槛

写入跨会话记忆的门槛必须比会话内的出生文本**严格得多**，因为它的错误会持续影响未来所有会话。

```
写入条件（全部满足）:
  ① k = REFUTED 且 ev = tool                        （有观测证据的证伪）
  ② T(i) ≥ 0.5                                      （高诱惑：模型真的会再走这条路）
  ③ alt 在后续轮次中被证实有效                        （替代路线确实推进了进展：自监督信号）
  ④ 条目文本全部由代码按模板从 ops 渲染               （不含任何原样照搬的工具输出文字）
  ⑤ 标识符全部通过语法白名单（路径/包名/配置键/错误码）
```

③ 最关键：只有**替代方案被证明有效**，这条证伪才算完整的“经验”。否则它只是“这条不行，但不知道什么行”，跨会话价值低、风险高。

### V5. 记忆投毒：跨会话记忆是被持久化的提示注入

**外部证据**：MINJA 攻击仅凭普通用户查询就能向智能体的长期记忆注入恶意记录，**注入成功率超过 95%，攻击成功率 70%**，无需任何后端权限 [1](https://mem0.ai/blog/ai-memory-security-best-practices)。其机制是诱导智能体**自己生成并存储**被污染的记录，之后被相似度检索当作少样本示例拼进别的用户的上下文 [2](https://www.promptfoo.dev/lm-security-db/vuln/agent-persistent-memory-poisoning-7e5fb607/)。Zep 的概括很准确：**记忆投毒就是带持久性的提示注入**；模型不是安全边界，能强制执行的边界是控制每一次写入、读取和外部动作的应用代码 [3](https://blog.getzep.com/defending-agent-memory-poisoning/)。

这正是上一篇“注入放大”（坑 4.1）在跨会话尺度上的放大版：一条工具输出里的恶意指令，被编译成“我之前确认过应该……”，再被写入项目记忆，就从一次性攻击变成了**永久的第一人称信念**。

**cfb 的防线（全部在代码层）**：

| 防线 | 实现 |
|---|---|
| **模板化写入** | 记忆内容只能由代码从 typed ops 按模板渲染；工具输出中的自由文本永远不进入记忆，只有通过语法白名单的标识符可以进入 |
| **描述性，非指令性** | 记忆条目只能是“X 在指纹 F 下被观测否定，替代 Y 有效”，永远不能是“应该做 Z” |
| **来源链不可洗白** | 每条记忆保留 src 链；src 源自外部内容（网页、用户上传的文件）的证伪，不写入跨会话记忆 |
| **不进系统提示** | 检索结果注入到出生文本或 pre-step 的状态看板中，以“我之前的记录”身份出现，永不提升为系统级指令 |
| **精确键检索** | 只按标识符/错误签名精确匹配检索，不用嵌入相似度（见 V6）——这同时也关掉了 MINJA 依赖的相似度通道 |

### V6. 检索与注入：精度优先，时机决定一切

**精确键检索，而不是嵌入检索**。理由有二：
1. **Dist 代价**：一条不适用的疫苗就是最坏的相似干扰物。检索精度比召回率重要得多。
2. **安全**：相似度检索是投毒攻击的主要通道 [2](https://www.promptfoo.dev/lm-security-db/vuln/agent-persistent-memory-poisoning-7e5fb607/)。

检索键 = 条目的标识符集合 + 错误签名（错误码 + 规范化后的消息模板）。

**注入时机：在诱惑出现的时刻接种。** cfb 有两个天然注入点：

| 注入点 | 触发 | 作用 |
|---|---|---|
| **pre-step**（每轮开始前） | 用户任务或上一轮工具输出中出现记忆键 | 在主模型开始推理**之前**接种；效果最好 |
| **birth**（推理块压缩时） | 刚写完的推理块中出现记忆键（主模型正在走向已知的坑） | 在出生文本中追加一行“我之前在这个项目里确认过……”；影响**下一块** |

pre-step 注入是真正的“预防接种”；birth 注入是“发病后的及时治疗”。

**跨会话价值函数**：

```
v_mem(i) = P_recur(i) · T(i) · C_retry(i) · valid(i) − Prime(i) − Dist_irrel(i) − λ·tok(i)
```

- P_recur：当前情境与记忆签名的匹配程度（精确键命中 = 高）。
- valid：指纹一致 = 1；不一致 = 0（降级为 SHELVED，改走 Info 通道）。
- Dist_irrel：键只是部分匹配时的不相关惩罚；部分匹配时它大于收益，所以**部分匹配一律不注入**。
- 每轮最多注入 3 条，按 v_mem 排序。

**渲染**（沿用 P2 + P6）：替代先行、自镜像风格、带时间与指纹状态：

> `这个项目里 EACCES 我之前查过（9 月 27 日，conf.yaml 未改动）：是容器挂载路径与配置路径不一致，不是权限问题。`

### V7. 反馈与生命周期

| 事件 | 处理 |
|---|---|
| 注入后主模型避开了坑，并取得进展 | 置信度 +1 |
| 注入后主模型仍然走了坑 | 渲染强度不足或 T 被低估：下次提前到 pre-step，且写成精确形式 |
| 主模型按替代路线走却失败 | **立即失效**，写墓碑 |
| 被证伪的路在新会话里成功了 | **立即失效**，写墓碑，并将原条目标记为“当时的证据可能有误” |
| 指纹变化 | 自动降级为 SHELVED |
| 长期未命中 | 半衰期衰减；低于阈值移入冷存储（不删，仍可审计） |

所有变更追加写入，不改写历史；这与 `state-memory.js` 的追加式修正一致，也使整个记忆系统可审计、可回滚。

## 第二部分：宿主压缩对接协议

### H1. 宿主会对上下文做的三类操作

综合目前主流的实现，宿主侧上下文管理可以归为三类（以 Anthropic 的公开 API 为参照）：

| 操作 | 行为 | 对 cfb 的影响 |
|---|---|---|
| **清除工具结果** | 旧的工具结果被替换为占位符，保留调用结构 [3](https://dreaming.press/posts/context-editing-vs-compaction-for-long-running-agents.html) | 条目的 visible(i) 从 1 变 0 → R 骤降、Neut 归零 |
| **清除思考块** | 旧的思考块被整体删除 [4](https://umesh-malik.com/blog/agent-context-compaction-what-survives) | **cfb 的出生文本本身就在思考块里——会被整体删掉** |
| **压缩（摘要前缀）** | 超过阈值时把之前的内容摘要成一个块，**之前的所有块在后续请求中被丢弃** [4](https://umesh-malik.com/blog/agent-context-compaction-what-survives) | cfb 的编译结果被再做一次有损摘要 → 违反单次有损原则 |

另外一个工程约束：**任何对历史的编辑都会让提示缓存从编辑点往后失效**；所以托管实现会低频、成批地清理，让省下的 token 抵过缓存重写的成本 [5](https://www.channel.tel/blog/agent-context-editing-memory-tool-token-cost)。

> 注：cfb 运行在 DSH 宿主上，归档依赖宿主注入的 `cmbStore`（CAS）。DSH/CMB 自己的压缩策略具体做哪些操作，仓库里没有记录。本协议因此按**能力等级**设计：宿主支持到哪一级，cfb 就用到哪一级。

### H2. 三个核心冲突

**冲突一 · 思考块被清除，疫苗随之消失**

cfb 把最有价值的东西（配对疫苗、COMPUTED 结论、OPEN 问题）写进了出生文本，而出生文本就在思考块里。宿主一旦清除旧思考块，这些东西就**全部消失**，而原始的 900 token 弯路反正也已经没了——cfb 的工作白做了。

> **晋升原则**：出生文本是**暂存层**，不是持久层。在一个思考块可能被清除之前，它里面仍然有效且 v 高于阈值的条目（OPEN / INCUMBENT / 高 T 的 REFUTED / 未被后续取代的 COMPUTED）必须**晋升**到一个不会被清除的持久通道。

cfb 已经有这个通道：**checkpoint 模式在 pre-step 发射的状态看板**。于是 VALUE-AND-CONTROL 的多级缓存被补全为：

```
L1 出生文本（思考块内，暂存，会被宿主清除）
  ↓ 晋升（按 v）
L2 状态看板（pre-step 发射，每轮重建，不在思考块内）
  ↓ 降级
L3 art:// 指针（CAS，可读回）
  ↓ 会话结束 + V4 写入门槛
L4 跨会话项目记忆（带指纹）
```

**冲突二 · 工具结果被清除，v 的前提改变**

A2 的一个核心判断是“复述可见的工具输出是纯冗余”（visible=1 → R≈0.85）。宿主清除工具结果之后，这个前提**失效**：
- 之前因 R 高而被丢弃的 FACT，现在变成**不可见且需要重新调用工具才能获得**，R 从 0.85 降到约 0.3。
- 之前因中和价值（Neut）而写入的“取代”行，现在旧值已经不可见了，这一行从中和变成**重新引入干扰**（A4：旧值不可见时写它是负价值）。

> **上下文依赖重算原则**：v(i) 是上下文状态的函数。宿主每次清除事件后，cfb 必须对当前仍在上下文中的所有条目**重新计算 v 并重新选取**：被清除来源的关键 FACT 晋升为一行（“read_file#3 已清除，关键值：/srv/app/conf.yaml”），失去中和对象的取代行删除。

**冲突三 · 宿主压缩对编译结果再做一次有损摘要**

宿主压缩器把 cfb 精心编译的状态又喂给一个摘要模型。结果：
- 递归有损摘要 → 尾部细节消失（模型坍缩同构，VALUE-AND-CONTROL 定律 1）；
- 摘要模型不知道哪一行是证伪、哪一行是搁置 → 粘性分配被抹平；
- 来源标记被抹掉 → 工具来源的内容可能被改写成助手自己的判断（注入洗白）。

> **钉住原则**：cfb 的状态块对宿主压缩器是**不可改写区**——宿主可以整体保留它，也可以请求 cfb 把它缩减到指定预算，但不能对它做自由摘要。

### H3. 关键洞察：重算必须是无损的重新选取

三个冲突的解决方案都要求“在上下文变化后重新决定保留什么”。如果这个重新决定是**再对出生文本做一次摘要**，就违反了单次有损原则。

**解决办法**：cfb 把每个推理块的 **ops 列表（结构化条目 + 观测量）**存入 CAS，与原文并列。之后任何重算都是：

```
从 CAS 取出 ops（无损） → 按新的上下文状态重算观测量与 v → 重新选取 → 重新渲染
```

整个流程中，**唯一的有损步骤仍然是最初那一次“原文 → ops”的解析**。之后的晋升、降级、重选、缩减，全部是在同一组 ops 上的无损选择。

> **定理（组合单次有损）**：若宿主的所有上下文操作都通过协议委托给 cfb 的 `reduce`（或至少不改写 cfb 的钉住块），则从原始推理到任意时刻上下文中的状态，**恰好只经过一次有损变换**，与会话长度、宿主压缩次数无关。

这是本篇最重要的结论：**它让“长会话不退化”从一个期望变成一个可以用接口保证的性质。**

### H4. 协议：能力等级

| 等级 | 宿主提供 | cfb 的策略 |
|---|---|---|
| **C0 宿主无感知** | 什么都不提供 | 防御性设计：出生文本自包含（全名、无代词），关键条目**同时**写入状态看板（不依赖思考块存活）；状态看板本身按可截断顺序排列 |
| **C1 事件通知** | 清除 / 压缩发生**之后**通知 cfb | 收到事件后按 H2 做重算与晋升；在下一轮 pre-step 生效 |
| **C2 钉住** | 宿主压缩时对标记块原样保留 | cfb 的状态看板标记为钉住；宿主压缩的只是其余部分 |
| **C3 委托缩减** | 宿主在压缩/清除**之前**调用 cfb 的钩子 | cfb 在宿主给定的预算下执行无损重选；宿主只负责非 cfb 部分。**满足 H3 定理** |

**C3 接口草案**：

```
host → cfb   context.pre_edit({ kind: 'clear_tool' | 'clear_thinking' | 'compact',
                                targets: [blockId...], budgetTokens })
cfb  → host  { promote: [{ channel: 'checkpoint', text }],     // 需要晋升的条目
               pinned:  [{ blockId, text, maxTokens }],         // 钉住块的新内容
               veto:    [blockId...] }                           // 可选：请求暂缓清除的块（如最近一块）
host → cfb   context.post_edit({ kind, cleared: [blockId...] })  // 用于重算 visible / Neut
cfb          reduce(opsStore, contextState, budgetTokens) → text // 纯函数，无模型调用
```

`reduce` 是纯函数、无模型调用，所以可以在宿主的压缩热路径上同步执行，延迟可以忽略。

### H5. 协同细节

**缓存对齐**：cfb 对历史的任何重写（晋升、重选）都会让提示缓存失效。所以 cfb **不自发重写历史**，只在宿主本来就要编辑历史的时刻（清除、压缩事件）搭车执行——宿主已经付出了缓存失效的代价，cfb 的额外编辑边际成本为零。出生时的替换发生在消息追加之前，本来就不影响缓存（README：替换走普通 append）。

**预算账本**：宿主和 cfb 各自按自己的 token 计数判断阈值，容易出现不一致——比如服务端清除之后，客户端的 token 计数没有反映出来，从而过早触发压缩 [1](https://github.com/NousResearch/hermes-agent/issues/526)。协议要求双方共享一本账：cfb 在每次出生替换和晋升后报告 Δtokens，宿主在每次清除后报告 cleared tokens。

**最近块豁免**：宿主清除思考块时，**最近一块永不清除**（VALUE-AND-CONTROL 定律 2：自然文本锚；INTERACTIONS 坑 4.2：最近工作记忆）。在 C3 下通过 `veto` 实现，在 C0 下由 cfb 在该块出生时就选 raw-near 模式作为保险。

**来源链穿越压缩**：钉住块里每一行都保留 src 标记。宿主的自由摘要只作用于非钉住部分，所以工具来源的内容不会在压缩中被洗成助手自己的判断。

**清除工具结果时的豁免建议**：Anthropic 的清除支持把特定工具列入永不清除的名单 [1](https://github.com/NousResearch/hermes-agent/issues/526)。cfb 可以向宿主建议：被当前 INCUMBENT 或 OPEN 条目引用的工具结果，暂不清除；其余照常清除。这把宿主的“按时间清除”在不改动宿主算法的前提下，变成了**近似按价值清除**。

### H6. 与跨会话记忆的衔接

会话结束或宿主做全量压缩时，是跨会话记忆的**天然写入时机**：此时 cfb 手里有完整的 ops 存储、每条 REFUTED 的后续结局（替代路线是否有效）、以及所有相关文件的指纹。V4 的写入门槛在这一刻一次性评估。

如果宿主自带记忆工具（如 Anthropic 的 memory tool、或 DSH 的 CMB），cfb **不另建存储**，而是通过宿主的记忆接口写入——但写入内容必须经过 V4 的模板化与白名单，且 cfb 保留指纹和墓碑的元数据（可以存在 CAS 中，记忆条目只引用其句柄）。

### 本篇新增的原则（接续前文九条 + v4 规格）

10. **跨会话不对称**：跨会话记忆以负知识优先；正知识大多可重导。
11. **保守归纳**：只存实例层与模式层；≥2 个独立会话才上升为模式层；cfb 不写策略层。
12. **证据指纹**：每条记忆带指纹；指纹变化自动降级为 SHELVED；一次反例立即失效。
13. **记忆写入即安全边界**：模板化、描述性、来源链不可洗白、精确键检索、不进系统提示。
14. **在诱惑出现时接种**：pre-step 预防，birth 补救。
15. **出生文本是暂存层**：高价值条目必须在清除前晋升到状态看板。
16. **v 依赖上下文，重算必须无损**：ops 以结构化形式存入 CAS；所有重算都是在同一组 ops 上的重新选取。
17. **钉住与委托**：宿主压缩不得自由改写 cfb 状态块；最佳形态是宿主委托 cfb 的纯函数 `reduce`，此时整条链路恰好一次有损。
18. **缓存搭车**：cfb 只在宿主本来就要编辑历史的时刻执行重写。

  /\b([A-Za-z_][\w-]*(?:[./][\w-]+)+)\b/g,               // a.b.c / a/b / file.ext
  /\b(E[A-Z]{3,}|[A-Z]{2,}_[A-Z_]+|0x[0-9a-fA-F]+)\b/g,  // EACCES / ERR_X / 0x..
  /\b([a-z]+_[a-z_0-9]+)\b/g,                            // snake_case
]
export function extractIds(text = '') {
  const out = new Set()
  for (const re of RE_IDS) {
    re.lastIndex = 0
    let m
    while ((m = re.exec(text))) { const s = (m[1] || '').trim(); if (s.length >= 3) out.add(s) }
  }
  return out
}
const jaccard = (a, b) => {
  if (!a.size || !b.size) return 0
  let n = 0; for (const x of a) if (b.has(x)) n++
  return n / (a.size + b.size - n)
}
const countOcc = (hay, needle, from = 0) => {
  if (!needle) return []
  const pos = []; let i = hay.indexOf(needle, from)
  while (i >= 0) { pos.push(i); i = hay.indexOf(needle, i + needle.length) }
  return pos
}

// ── 句子切分与功能线索（零依赖近似；副模型的 kind2 优先） ─────────────────────────
const RE_EXPLORE = /(也许|或许|可能是|试试|换个|要不|会不会|what if|maybe|perhaps|let me try|alternatively|或者)/i
const RE_COMPUTE = /(\d+\s*[+\-*/=×÷]\s*\d+|计算|算出|compute|calculate|=)/i
export function splitSentences(raw = '') {
  return raw.split(/(?<=[。！？!?\n]|\.\s)/).map(s => s.trim()).filter(Boolean)
}

// ── ② 校验器：硬不变量 I1–I4、I7 ─────────────────────────────────────────────
export function validateOps(ops, ctx) {
  const { raw = '', toolText = '' } = ctx
  const kept = [], dropped = []
  for (const op0 of ops || []) {
    const op = { ...op0 }
    const why = []
    if (!KINDS.has(op.k)) why.push('bad-k')
    if (!EVS.has(op.ev)) op.ev = 'guess'
    if (op.anchor && !raw.includes(op.anchor)) why.push('I1-anchor-not-verbatim')
    for (const id of extractIds(op.text)) {
      if (!raw.includes(id) && !toolText.includes(id)) { why.push('I2-id-not-grounded:' + id); break }
    }
    // I4：非工具证据的否定一律为 SHELVED
    if (op.k === 'REFUTED' && op.ev !== 'tool') op.k = 'SHELVED'
    // I3：REFUTED 必须带替代方案
    if (op.k === 'REFUTED' && !op.alt) why.push('I3-refuted-without-alt')
    ;(why.length ? dropped : kept).push(why.length ? { op, why } : op)
  }
  return { kept, dropped }
}

// ── ③ 观测量 ────────────────────────────────────────────────────────────────
export function observe(ops, ctx) {
  const { raw = '', toolText = '', contextText = '', nextToolArgs = '' } = ctx
  const rawTok = Math.max(1, estimateTokens(raw))
  const nextIds = extractIds(nextToolArgs)
  // 分支跨度：从本条 anchor 到下一条 anchor
  const anchored = ops.map(op => ({ op, at: op.anchor ? raw.indexOf(op.anchor) : -1 }))
    .filter(x => x.at >= 0).sort((a, b) => a.at - b.at)
  const spanOf = new Map()
  anchored.forEach((x, j) => spanOf.set(x.op.id, [x.at, j + 1 < anchored.length ? anchored[j + 1].at : raw.length]))
  const negs = anchored.filter(x => x.op.k === 'REFUTED' || x.op.k === 'SHELVED')
  const firstNegId = negs.length ? negs[0].op.id : null

  const obs = new Map()
  for (const op of ops) {
    const ids = extractIds([op.text, op.alt, op.anchor].filter(Boolean).join(' '))
    const [s0, s1] = spanOf.get(op.id) || [-1, -1]
    let explore = 0, compute = 0
    if (s0 >= 0) {
      for (const s of splitSentences(raw.slice(s0, s1))) {
        const t = estimateTokens(s)
        if (RE_EXPLORE.test(s)) explore += t
        else if (RE_COMPUTE.test(s)) compute += t
      }
    }
    // revisit：任一标识符在间隔 >400 字符后再次出现
    let revisit = 0
    for (const id of ids) {
      const p = countOcc(raw, id)
      for (let k = 1; k < p.length; k++) if (p[k] - p[k - 1] > 400) revisit++
    }
    // fanout：分支结束后，标识符被引用次数
    let fanout = 0
    if (s1 >= 0) for (const id of ids) fanout += countOcc(raw, id, s1).length
    const actionLink = [...ids].some(id => nextIds.has(id)) ? 1 : 0
    const textIds = extractIds(op.text)
    const visible = textIds.size > 0 && [...textIds].every(id => toolText.includes(id)) ? 1 : 0
    const staleVisible = op.supersedes && (contextText.includes(op.supersedes) || toolText.includes(op.supersedes)) ? 1 : 0
    obs.set(op.id, {
      ids, effortExplore: explore / rawTok, effortCompute: compute / rawTok,
      revisit, fanout, actionLink, visible, staleVisible,
      firstAttempt: op.id === firstNegId ? 1 : 0,
    })
  }
  return obs
}

// ── ④ 打分 v(i;λ) ──────────────────────────────────────────────────────────
const clip01 = x => Math.max(0, Math.min(1, x))
export function temptation(op, o) {           // P4：只用探索型投入
  return clip01(0.45 * Math.min(1, o.effortExplore * 4) + 0.25 * (o.revisit >= 1 ? 1 : 0)
    + 0.15 * o.firstAttempt + 0.15 * (op.ev === 'guess' ? 1 : 0))
}
export function locality(op, render) {         // A3：配对且替代先行 → 高局部性
  if (!op.alt) return 0.3
  return render?.altFirst === false ? 0.8 : 0.9
}
export function muOf(op, T, cfg) {             // P2：μ 随渲染变化
  const order = 0.45                            // 渲染器固定替代先行
  const spec = T > 0.6 && /[\s`]-|\/|\b(chmod|rm|git|npm|pip|curl|sudo)\b/.test(op.why || op.text || '') ? 1.0 : 0.6
  const evFactor = op.ev === 'tool' ? 0.7 : 1.0
  return cfg.mu0 * order * spec * evFactor
}

export function scoreOp(op, o, lambda, cfg = V4_DEFAULTS, tok = null) {
  const t = tok ?? estimateTokens(renderRow(op))
  const g = 1 - Math.exp(-o.fanout / 2)
  const D = (PRIOR_D[op.kind2] ?? 0.5) * (0.6 + 0.4 * g) * (1 + 0.5 * o.actionLink) * (H_K[op.k] ?? 1)
  const P = clip01(0.35 + 0.25 * o.actionLink + 0.2 * (['OPEN', 'PLAN', 'INCUMBENT', 'COMPUTED'].includes(op.k) ? 1 : 0) + 0.15 * Math.min(1, Math.log1p(o.fanout)))
  let R = op.k === 'FACT' ? (o.visible ? R_BASE.FACT_VISIBLE : R_BASE.FACT) : (R_BASE[op.k] ?? 0.3)
  if (op.kind2 === 'restate') R = Math.max(R, 0.95)   // 复述工具输出：原件仍在上下文
  if (op.kind2 === 'verify') R = Math.max(R, 0.9)     // 自检：随时可重做
  let info = op.k === 'REFUTED' ? 0 : D * P * (1 - R)
  if (op.k === 'SHELVED') {                           // P4：搁置的价值在于回头条件；浅尝且无触发条件的搁置不值得写
    const Ts = temptation(op, o)
    info *= (op.trigger ? 1 : 0.5) * (0.5 + Ts)
  }
  let vac = 0, prime = 0, T = 0
  if (op.k === 'REFUTED') {
    T = temptation(op, o)
    vac = T * cfg.pRetry * Math.min(1, 0.3 + o.effortExplore * 3 + o.effortCompute)
    prime = muOf(op, T, cfg) * T * (1 - locality(op))
  }
  const neut = op.supersedes && o.staleVisible ? cfg.nuNeut : 0
  const dist = op.supersedes && !o.staleVisible ? cfg.nu * 0.5 : 0   // 旧值已不可见还写它 = 重新引入干扰
  const v = info + vac + neut - dist - prime - lambda * t
  return { v, tok: t, parts: { D, P, R, info, vac, neut, dist, prime, T } }
}

// ── ⑤ 选取：惰性贪心 + 冗余递减 + 同键互斥（划分拟阵）+ 支撑闭包 ────────────────
export function selectOps(ops, obs, lambda, cfg = V4_DEFAULTS) {
  const scored = ops.map(op => ({ op, o: obs.get(op.id), ...scoreOp(op, obs.get(op.id), lambda, cfg) }))
  const chosen = [], usedKeys = new Map()
  let pool = scored.slice()
  const gain = c => c.v - chosen.reduce((s, x) => s + cfg.rhoRed * jaccard(c.o.ids, x.o.ids) * (c.op.k === x.op.k ? 1 : 0.5), 0)
  while (pool.length) {
    pool.sort((a, b) => gain(b) - gain(a))
    const best = pool.shift()
    const g = gain(best)
    if (g <= 0) break                                       // λ 是唯一停止条件
    if (best.op.key && usedKeys.has(best.op.key)) continue  // 同键只保留一个当前值（输入按时间顺序，后者应已携带 supersedes）
    chosen.push({ ...best, gain: g })
    if (best.op.key) usedKeys.set(best.op.key, best.op.id)
  }
  // 支撑闭包：COMPUTED 的依赖若未入选，至少保留 art:// 指针
  const inSet = new Set(chosen.map(c => c.op.id))
  const allIds = new Set(ops.map(o => o.id))
  for (const c of chosen) c.pointers = (c.op.deps || []).filter(d => allIds.has(d) && !inSet.has(d))
  return { chosen, rejected: scored.filter(s => !inSet.has(s.op.id)) }
}

// ── ⑥ 渲染 ─────────────────────────────────────────────────────────────────
export function styleProfile(raws = []) {          // P6：自镜像风格画像
  const txt = raws.join('\n')
  const cjk = (txt.match(/[\u4e00-\u9fff]/g) || []).length
  const lang = cjk > txt.length * 0.15 ? 'zh' : 'en'
  const backtick = (txt.match(/`/g) || []).length > 4
  const so = lang === 'zh' ? ((txt.match(/所以/g) || []).length >= (txt.match(/因此/g) || []).length ? '所以' : '因此') : 'So'
  return { lang, backtick, so }
}
const wrap = (s, st) => s // 保留原文标识符写法；backtick 偏好可在此扩展

export function renderRow(op, st = { lang: 'zh' }, pointers = [], handle = '') {
  const src = op.src && op.src.startsWith('tool:') ? `（${op.src.slice(5)}）` : ''
  const ptr = pointers.length && handle ? `  → ${handle}#${pointers.join(',')}` : ''
  switch (op.k) {
    case 'REFUTED': // P2：替代先行；X 只出现一次
      return `- ${op.alt}（已排除：${op.text}${op.why ? '——' + op.why : ''}）${ptr}`
    case 'SHELVED':
      return `- 暂不走：${op.text}${op.why ? '，因为' + op.why : ''}${op.trigger ? '；若' + op.trigger + '再回来' : ''}${ptr}`
    case 'OPEN':
      return `- 待定：${/[?？]$/.test(op.text) ? op.text : op.text + '？'}`
    case 'PLAN':
      return `- 打算：${op.text}`
    default: {
      const sup = op.supersedes ? `；取代 ${op.supersedes}` : ''
      const hedge = op.ev === 'derived' ? '目前判断：' : op.ev === 'guess' ? '（未证实）' : ''
      return `- ${hedge}${op.text}${src}${sup}${ptr}`
    }
  }
}

export function renderBirth(chosen, st, cfg = V4_DEFAULTS, handle = '', lambda = cfg.lambda0) {
  const rows = chosen.map(c => renderRow(c.op, st, c.pointers, handle))
  // 尾部散文：v 最高且递减后仍 > dualEncodeFactor·λ·tok 的 1–3 条 + OPEN 问句（证据定粘性）
  const tail = []
  // 只有 COMPUTED / INCUMBENT / 关键 FACT 可双编码；工具来源内容只写“我确认”（事实），永不写“我决定”（I5）
  const strong = chosen.filter(c => ['COMPUTED', 'INCUMBENT', 'FACT'].includes(c.op.k))
    .filter(c => c.gain > cfg.dualEncodeFactor * lambda * c.tok).slice(0, cfg.maxTailSentences - 1)
  for (const c of strong) {
    const t = c.op.ev === 'tool' ? `我确认${c.op.text}` : c.op.ev === 'derived' ? `我目前判断${c.op.text}` : null
    if (t) tail.push(t)
  }
  const open = chosen.find(c => c.op.k === 'OPEN')
  if (open) tail.push(`还没弄清的是：${open.op.text.replace(/[?？]$/, '')}？`)
  const prose = tail.length ? `\n${st.so}${tail.join('；')}。`.replace(/。？。$/, '？').replace(/？。$/, '？') : ''
  return rows.join('\n') + prose
}

// ── ⑦ 控制器：非对称 AIMD（丢失快降，噪声慢升），s_w 消歧 ─────────────────────
export function recencyCompiledShare(segments, W) {  // P3：[{tok, compiled}]，按时间顺序
  // 逐 token 指数衰减权重 w(d)=exp(−d/W) 在每段跨度上的积分：W·(e^{−d0/W} − e^{−d1/W})
  const w = Math.max(1, W)
  let num = 0, den = 0, d = 0
  for (let i = segments.length - 1; i >= 0; i--) {
    const t = Math.max(0, segments[i].tok || 0)
    const mass = w * (Math.exp(-d / w) - Math.exp(-(d + t) / w)); d += t
    den += mass; if (segments[i].compiled) num += mass
  }
  return den ? num / den : 0
}

export function updateLambda(state, sensors, cfg = V4_DEFAULTS) {
  // sensors: { readbackExcess, reprobeFact, vaccineFail, loopRising, sw, difficulty∈[0,1] }
  let { lambda = cfg.lambda0, noiseRun = 0 } = state || {}
  const lamMin = cfg.lambdaMin * (1 + 2 * (1 - (sensors.difficulty ?? 0.5)))  // 定律 3：越难下限越低
  let action = 'hold', forceRawNear = false
  if (sensors.readbackExcess || sensors.reprobeFact) {
    lambda *= cfg.beta; noiseRun = 0; action = 'decrease:loss'
  } else if (sensors.loopRising && sensors.sw >= cfg.swMax) {
    lambda *= cfg.beta; noiseRun = 0; forceRawNear = true; action = 'decrease:saturation'
  } else if (sensors.loopRising) {
    noiseRun++
    if (noiseRun >= cfg.noiseStreak) { lambda += cfg.delta; noiseRun = 0; action = 'increase:noise' }
  } else noiseRun = 0
  if (sensors.sw >= cfg.swMax) forceRawNear = true
  lambda = Math.max(Math.min(lamMin, cfg.lambdaMax), Math.min(cfg.lambdaMax, lambda))
  return { lambda, noiseRun, action, forceRawNear, promote: sensors.vaccineFail || [] }
}

// ── ⑧ 自监督标签：条目标识符在后续 K 轮复现 → needed=1（Pn 的在线训练信号） ─────
export function neededLabels(ops, laterTexts = []) {
  const later = laterTexts.join('\n')
  return ops.map(op => {
    const ids = [...extractIds(op.text)]
    return { id: op.id, k: op.k, needed: ids.length && ids.some(id => later.includes(id)) ? 1 : 0 }
  })
}

// ── 一站式 ─────────────────────────────────────────────────────────────────
export function compileBirth(ops, ctx, opts = {}) {
  const cfg = { ...V4_DEFAULTS, ...(opts.cfg || {}) }
  const lambda = opts.lambda ?? cfg.lambda0
  const { kept, dropped } = validateOps(ops, ctx)
  if (!kept.length) return { text: null, fallback: 'raw', dropped }
  const obs = observe(kept, ctx)
  const { chosen, rejected } = selectOps(kept, obs, lambda, cfg)
  const st = opts.style || styleProfile(ctx.recentRaws || [ctx.raw])
  const text = renderBirth(chosen, st, cfg, opts.handle || '', lambda)
  return { text, chosen, rejected, dropped, lambda, version: VALUE_VERSION }
}
