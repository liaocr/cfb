# 第 0 章 · 一页纸

**这是什么**：一个跑在 DSH 宿主里的上下文记忆系统。它不改模型、不改宿主工具语义，只做一件事——
**把大块内容搬出上下文，在原地留下一个能读回来的稳定地址**。

**为什么**：一次 25 KB 的工具输出留在上下文里，之后每一轮都按缓存命中情况继续计费；
而宿主压缩（compaction）虽然能把它拿掉，却是**不可逆的**——丢了就没了，模型也不知道自己丢了什么。

**立场（v8）**：不阻止压缩、不减少信息，**只降低指针精度**。原文件永远在磁盘上，代价只是一次回读。

**三个层次**：

| 层 | 名字 | 干什么 |
|---|---|---|
| L0 | 句柄 Handle | `art://…` 稳定地址（约 28 字符），代替原文驻留上下文 |
| L1 | 缓冲 Cushion | 句柄旁的有预算**投影**（不是截断），给模型一个"这里是什么"的线索 |
| L2 | 定点回读 Retrieval | 用句柄精确取回原文（分页/长行续读/检索/预算） |

**v8 加的第二层**：宿主压缩发生时，把**真正消失的那部分**归档成新的句柄，并在**每会话一份的根**里留下一行指针。
于是"宿主丢掉的东西"从不可逆变成可检索。

```
工具输出(大) ──T1──▶ 句柄+缓冲（上下文里只剩几十~几百字符）
宿主压缩     ──v8──▶ 丢失集合（差分 ∪ 宿主账本）──▶ 归档 blob ──▶ 根 art://root ──▶ 需要时读回
```

**一句话结论**：这套系统的价值不在于"我们现在认为什么重要"，而在于**丢了的东西还能不能找回来**。
所以它从不给内容打分，只做两件事：**如实归档**、**保持地址稳定**。

# 第 1 章 · 理论：为什么是这个形状

## 1.1 五条硬约束（H 系列，不可协商）

| 约束 | 内容 | 违反的后果 |
|---|---|---|
| **H1** | 零主动折叠 | 等于我们自己决定"该丢什么" = 猜测重要性；且会打断前缀 |
| **H2** | 两次压缩之间只追加、不改写 | 改写 ⇒ 前缀断裂 ⇒ KV 缓存全断（真金白银） |
| **H3** | 只用年龄/最后触碰 | 给内容打分就是价值预测，只是换个地方拟合 |
| **H4** | 索引必须有字节预算 | 索引是无界历史，会重新长成第二个上下文 |
| **H5** | 删索引前必须先有归档检索 | 没有检索的删除 = 销毁 |

## 1.2 七条设计哲学（全部是被教训逼出来的）

| 条 | 一句话 | 逼出它的教训 |
|---|---|---|
| 2.1 禁止价值预测 | 价值只能从单一分布拟合，在大众分布上必然失效 | 保护集、打分方案全部被 A/B 证伪 |
| 2.2 只追加，不改写 | 历史一旦改写就无法解释 | 前缀断裂与缓存失效 |
| 2.3 断裂是成本，不是工具 | 缓存断裂是真金白银，不能随手支付 | v7 索引在头部 ⇒ 每次折叠都变字节 |
| 2.4 不拟合、不造假、不自我安慰 | 没有数据就说没有数据 | 空数据报 PASS、把手动触发说成阈值触发 |
| 2.5 保真度 ≠ 可取回性 | 内容在磁盘上 ≠ 找得回来 | 有归档无地址 ⇒ 等于丢了 |
| 2.6 读权威源 | 宿主自己记的账 > 我们推导出来的信号 | `shadowedRange` 误差 6 倍；差分对跨 turn 恒盲 |
| 2.7 不拥有别人的工具集 | 别去决定不属于你的东西（否决项 V1） | 硬编码工具白名单 |

## 1.3 观测 vs 拟合（本项目最容易搞混的一条）

| | 性质 | 允许进决策回路？ |
|---|---|---|
| **拟合** | 从**样本**估计**总体**，外推到别的会话/未来 | ❌ 禁止 |
| **实时测量** | 读**当前会话此刻**的仪表（剩余预算、缓存命中、这块内容有多大） | ✅ 允许 |

关键在**有没有外推**，不在"谁执行"：人读指标调参是拟合，系统自适应读指标也是拟合（且更糟——隐式、不可复现）。
**净收益守卫属于实时测量**：它对每一块具体内容现算"外置后是变大还是变小"，不读历史、不猜重要性。

## 1.4 认知等级（写作契约）

- **已实测**：有数字、有出处，可以当事实用。
- **结构性推理**：由机制与代码推出，**不是实验**，必须自己标出来。
- **未验证**：明确写"未验证"，**绝不与已证事实混排**。

# 第 2 章 · CMB 基座（工具输出外置）

## 2.1 定位与它到底解决什么

CMB（Context Memory Bundle）是 DSH 的一个 Cordis 插件。它不改变模型、不改变宿主工具语义，只做一件事：
**把超过阈值的工具输出搬出上下文，换成句柄 + 有预算的缓冲**。

算一笔账（本机实测常数，零 API 成本）：记 `S` = 原文长度；`R` = 替换后驻留 = 句柄(28) + 缓冲 + 框架 `F`；`P` = 单次回读返回字符数；
`r` = 缓存读价/全价之比；`D` = 该工件存活回合数。**框架开销 F 实测 470–484 字符**。
不省钱的误式是"只比 S 与 P"——正确判据要看 `D`（存活多久）与 `r`（缓存有多便宜）。

## 2.2 三层记忆模型

| 层 | 内容 | 关键设计 |
|---|---|---|
| **L0 句柄** | `art://` + base64url(**HMAC-SHA256**(key=sessionId, msg=内容))(约 28 字符) | 会话绑定：换个会话同一内容也取不回 ⇒ 句柄泄露不等于数据泄露 |
| **L1 缓冲 Cushion** | 由 `buildCushion()` 生成 | **是有预算的投影，不是原文截断**（保结构、保头尾、标注省略） |
| **L2 定点回读** | 四种模式共用同一存储接口 | 分页 / 长行续读（`nextByteOffset`）/ 检索 / 响应总预算 |

## 2.3 宿主接缝（唯一的侵入点）

| 接缝 | 内容 |
|---|---|
| **写入接缝** | `ctx.on('tools/post-execute', …)`：返回决策（外置/放行） |
| **生命周期接缝** | dispose / shutdown：排空在途写入、注销写者标记 |

**硬契约**：工具返回值必须是**无损 JSON**。违反的直接后果是宿主**拒绝整次工具调用**（模型收到错误而不是数据）。
⚠️ **未验证**：宿主是否 await 异步 dispose ⇒「热重载」不是被承诺的能力，支持路径是进程级重启。

## 2.4 写入路径（九步）

```
① 触发判定      长度 > threshold(4096)，且不在豁免名单
② 净收益检查    句柄 + 缓冲 + 框架  >=  原文  ->  不外置（零 I/O，连 blob 都不写）
③ 内容寻址      sha256(payload) -> 已存在则直接复用（幂等）
④ 单飞合并      同一 (sessionId, sha) 的并发写入只落一次盘，其余等同一 Promise
⑤ 写临时文件    随机后缀 .tmp，写完 fsync
⑥ 原子发布      rename(tmp, blob) —— 原子替换，读者永远看不到半截文件
⑦ 目录登记      追加 catalog 记录 -> fsync -> 再更新内存活集（顺序不可换）
⑧ 渲染 L0+L1    生成摘要缓冲（有预算）
⑨ 精确复检      渲染后再算一次净收益，仍为负则回滚为原文（统计 spillRejectedNoGain）
```

**为什么②和⑨都要做**：②省掉无谓的磁盘 I/O；⑨覆盖"预测与渲染不一致"的情形（缓冲是内容相关的，预测可能偏乐观）。

**两个守卫**：预检（成本 0，挡掉明显不划算）+ 复检（精确，实测过 缓冲 6695 > 源 6089 被拦下）。

## 2.5 读取路径与响应安全

- 三种模式共用同一信封：`{ mode, handle, ok, message, … }`。
- **长行续读**：单行超过页字节上限时返回该行的**一个字节块** + `nextByteOffset`；落在多字节字符中间会**向前对齐**到下一个字符边界（不返回半个字）。
- **输出安全（两层防线的教训）**：`jsonSafe` 严格规则 + 响应总预算 = JSON 序列化后的完整工具结果（默认 `48000` 字符，`maxResponseChars` 可配）。

## 2.6 存储引擎

**磁盘布局**：`<root>/` 下有 blob 目录、`catalog.jsonl`（快照）、journal、`.writer-pid`、trace 等。

**Blob 格式**：`[ payload ][ trailer JSON ][ 4B LE trailer 长度 ][ 4B LE magic 0x445… ]`——**带尾部魔数，可从两头校验**。

**校验顺序不可交换**：① 身份（文件名 sha == trailer 内 sha）→ ② 长度/魔数 → ③ 内容哈希 → ④ 类型/租约。

**Journal 与 Snapshot（写前日志 + 快照）**：追加写入，latest-wins；残行处理必须**先修复再追加**，
否则下一条追加会与残行粘连成一行、连带吞掉新记录。正常 journal 永不被触碰。

**压实（Compaction）状态机**：写快照临时文件 → fsync → rename 发布 → 轮转日志 → 重建空日志 → 删除旧日志，
**全程持有与追加共用的一把锁**（本轮改对的地方）。

**停写状态机（Journal 故障）**：append 或 sync 失败 / 短写未完成 / 修复失败 / 压实失败 ⇒ 进入停写态，**大声报告**而不是假装成功。

**租约、GC 与配额**：把「引用计数」与「实际占用」分开陈述（早期把"磁盘上存在"当成"可访问"的教训）。
配额 `quotaBytes` = 1 GB；一次 26 MB 的重放约 2.6%。

**单写者**：`.writer-pid` 每存储目录一把；发现并发写者时**大声报告并计 `multiWriter`**，而不是拒绝启动（拒绝会打断一个正常会话）。
**不支持**多进程共享一个 root——这是被记录在案的边界。

**读缓存**：两级边界——条数 256（`verifiedMax`）+ **索引条目总量 16384**。单个超预算条目仍保留（正确性优先）。

**资源上限**：措辞边界——这些是**关键路径的显式上限**，不是"内存有界"。

## 2.7 前缀缓存友好性与配置

- 机制：工具 schema 指纹 `SCHEMA_FINGERPRINT` = SHA-256 over `{name, description, parameters, output}`——**工具定义不变，前缀就不变**。
- 配置分两层：插件配置（`index.js` 读取）与存储引擎可调项（构造函数）。关键项：`threshold`(4096)、`maxResponseChars`(48000)、`quotaBytes`(1 GB)、各类上限。

# 第 3 章 · v8 边界层（可逆上下文分层）

## 3.1 要解决的问题

宿主压缩把一段表层换成摘要：**内容真的没了**，模型不知道自己丢了什么，我们也没留地址。
CMB 只管"工具输出太大"，管不了"宿主把我丢掉的那段"。v8 就是补这一层。

## 3.2 四层模型与压缩响应流程

| 层 | 职责 |
|---|---|
| G1 | 差分观测：抓住"压缩前后表层差了什么" |
| G2 | 根：把丢失内容变成**可发现**的指针（稳定名 `art://root`） |
| G3 | 保留与释放：临时钉住 + 到期释放（免驱逐保护） |
| G5 | 观测第四层：把"我们到底看见了多少"记下来 |

**流程**：宿主压缩 → `compaction/*` 事件 → 取丢失集合 → 归档 blob → 追加到根 →（重启后）重放补档 → 模型/人按需读回。

## 3.3 丢失集合：两个来源与并集

| 来源 | 内容 | 特点 |
|---|---|---|
| **差分** | `pre-step` 前后表层节点差集 | 曾经**跨 turn 恒为空**（缺陷 8：存了引用而非快照） |
| **宿主账本** | `compaction/summary.data.shadowedSeqs` | **权威源**，119/119 可核验 |

- 二者**取并集**，并用 `lostSource ∈ {both-agree, both-disagree, host, diff}` + `lostDisagree` 记录不一致——字段表达不了的就不算记过。
- ⚠️ **禁用 `shadowedRange`**：那是包围区间，4834 个 seq 值 vs 23 个真丢失（约 **6 倍**）。
- 实测复活：跨 turn 由修前的 `lostSource=host`（盲）→ 修后的 **`both-disagree` / `lostDisagree=1`**。

## 3.4 根、身份键与幂等

- **稳定名** `art://root`，**每会话一份**（store 复合键 `(sessionId, handle)`，缺陷 9 的修复）。
- **只追加**（H2）+ **连续性检查**：新表必须以本进程上次写的表为前缀，否则记 hard 事件 `root-rewritten` 并**补回旧表**（检测 + 自愈）。
- **身份键** `key=ev<seq>`（事件身份，不是派生区间）。**根本身就是持久游标**——重启重扫日志时键已在根里 ⇒ 跳过，不需要第二个游标机制。
  实测：长会话 `alreadyPresent=20`、鹈鹕 `alreadyPresent=4`，均 `queued=0` ⇒ 零重复写入。
- **读侧排序定死**：按 `lostAt`（丢失时刻）排，不按 `ts`（归档时刻）——复活的条目 `ts` 是旧的。

## 3.5 重放（重启补档）

重启后第一次 pre-step 重扫宿主日志，把历史上静默丢失的区间补档，每步最多 4 个（`replayPerStep`）。
重放条目 `source=replay`、`lostSource` **只能是 `host`**（过去没有我们的快照，出现 `diff` 就是编造观测）。
重放条目带 `cmd`（如 `cmd-0c766a6e-1`）⇒ **每条丢失可追到是哪个手动命令造成的**，这是差分永远给不了的信息。
实测代价：长会话 19 区间 / 2803 节点 / **26.15 MB**；鹈鹕 72 节点 / 0.65 MB。

## 3.6 读根三态与硬失败

| 态 | 含义 | 处理 |
|---|---|---|
| `missing` | 没有记录（正常态） | 可以静默 |
| `unreadable` | **有记录却读不出来** | **绝不静默、绝不覆盖**，走暂存 |
| `lost` | 记录被回收 | **不单独区分**——store 把它和别的读失败塌缩成同一个错，硬分就是编造精度 |

`verifyRoot` 要求根里每个句柄都能解析；破损是**硬失败**（`archive-lost` hard）。

## 3.7 我们什么时候动手

**只在宿主压缩时**（压缩搭车归档）。这是 H1 合规的根据：搬东西的时机由宿主决定，我们从不主动折叠。
⚠️ 由此有一条边界：「随剩余预算主动外置」= 把触发时机从"宿主说了算"变成"我们说了算"，**需要与 H1 重新对账**，不是白捡的合规优化。
（核过：`T1_BUDGET` 只有声明与 boot 日志、**代码里无消费点**；插件里 `tokens` 出现 **0 次**；`contextWindow` 生产实测 `null`。）

# 第 4 章 · 宿主契约（实测，写代码前必读）

| 事实 | 含义 |
|---|---|
| 压缩会**拒绝**"不划算"的提交 | 我们不能假设"提交了就一定生效" |
| 触发链与两条入口 | 自动阈值触发 + 手动 `/compact`，后者**在 pre-step 括号之外**（缺陷 2 的来源） |
| 事件订阅顺序可控 | 决定了我们能看到什么 |
| 文件沙箱**只围栏写** | ⇒ 因果隔离不可得（我们能读到不属于我们的东西） |
| 会话记录：只追加、多帧 zstd、路径被暴露 | 所以重放可读、可核验 |
| `llm/stream` 处的消息形状是**嵌套**的 | 解析要按嵌套处理 |
| 检查点模板是**任务导向**的 | 摘要偏向任务，不是事实清单 |
| 压缩归属：**preset**，不是宿主 bundle | 配置点在哪里要找对 |

只列**真实缺陷**（能复现、有后果、已修）；「发现方式」一栏说明它当初为什么没被更早发现。完整修法见 `cmb-summary.md` §8。

| 8.7 | 无净收益检查 | 缓冲膨胀时"多花 token 换更少信息"且照样写盘 | 经济性实测（6695 > 6089） |

## 6.2 v8 边界层九条（全是同一个形状）

| # | 缺陷 | 一句话 |
|---|---|---|
| 1 | 暂存/读取控制流 | "根还不存在"与"根读不出来"混为一谈 |
| 2 | 手动 `/compact` 在 pre-step 括号外 | 差分窗口被整个绕过，一条日志都没有 |
| 3 | 跨会话状态串味 | 插件是宿主级单实例，共享 `lastScan` |
| 4 | 重启后"先压缩后首次 pre-step" | 根不在场，并集也补不动 ⇒ 必须读权威源 |
| 5 | `missing` 被记成 `root-read-failed` | 正常态报成故障，淹没真信号 |
| 6 | 首次写根永久停在暂存 | 新会话建不起根 ⇒ G2 静默失效 |
| 7 | `verifyRoot` 只验句柄可解析 | 发现不了条目缺失 |
| 8 | `lastNodes` 存引用不存快照 | 宿主就地 `splice` ⇒ 跨 turn 差分恒空 |
| 9 | `art://root` 全局单 owner 槽位 | 后写者夺走 owner ⇒ 互相清空（证据恢复：journal 里两条都在） |

## 6.3 一族形状 + 八条抽象原则

**九条全是一个形状：静默失败**——写成功了、日志也说成功了、**没人知道**。所以修复的重点不是这九条，而是让这一族不再产生。

1. **无数据 = SKIP，绝不报 PASS**；每条 PASS 必须带"检查了几条"。
2. **完备性检查本身也要被检查**（加载时断言 `EXPECTED_RULES`）。
3. **缺失 ≠ 失败 ≠ 未授权**（权威源会把"无权"报成"无"）。
4. **夹具必须复现被测对象的可变性语义**（桩比现实干净，就把真缺陷藏起来）。
5. **规则要能自动判定，否则就是散文**。
6. **只为观测过的时刻生成观测**（不为过去编造观测；H3 是不为未来编造价值）。
7. **身份用事件键，不用派生区间**（派生的会漏、会双写）。
8. **冲突不可见时，先让冲突可见**（诊断索引/计数）。

# 第 8 章 · 否决清单

## V1 工具集白名单（`ctx.tools.restrict({allow})`）

`allowTools=[inspect_artifact, read, glob, pwsh, grep, job_output]`，tools 26→6、30092→9637 B（-68%）。三条理由：

1. **所有权**：工具集属于用户与第三方；六个名字来自**单一使用分布**（读代码 + 搜索 + 跑命令），换任务形态立刻失效。
2. **静默**：被屏蔽的工具**不报错**，模型不举手说"我没有这个工具"，而是用近似工具硬凑 ⇒ 用错工具了、没报错、产出看着正常、没人知道。
3. **不可恢复**：`restrict` 装配期一次性生效；中途加回工具 ⇒ toolsHash 变 ⇒ 前缀断裂 ⇒ 缓存全断。按 §2.3，我们不会为拿回一个工具支付断裂 ⇒ **工具就一直缺着**。

**状态**：从未进入生产装配（代码与配置 0 处命中）；由 `verify-all` 的**否决清单守卫**持续检查其未复活。

## 三条实验否定结果

v3–v6 折叠策略 + 保护集（A/B 证伪）· v7 索引一等公民（每次折叠都变字节 ⇒ 缓存断裂）· 摘要链（前提拿不到）。

# 第 9 章 · 已知边界、债与未闭合项

## 9.1 CMB 明确不承诺（9 条中的关键）

| # | 不宣称 | 为什么 |
|---|---|---|
| 1 | **掉电持久化** | 证据是定点进程终止 + 失败注入，不是断电/掉盘；fsync 的价值无法用 ack 证明 |
| 2 | **任意并发部署安全** | 单写者标记是**检测不是 fencing**，租约是进程内的；支持形态是单根/单进程/单 Store |
| 3 | **任何任务都省钱** | 只有 n=1 的一次观察、没有 p 值；成本函数一侧已实测，另一侧（N、p）没有真实样本 |
| 4 | **L1 与原文语义等价** | L1 是**投影**，会丢信息——这是设计选择，不是缺陷 |
| 5 | **内存严格有界** | 上限是条目/结构上限，不是精确字节预算；单个超额条目被有意保留 |
| 6 | **热重载是承诺能力** | 宿主是否 await 异步 dispose **未验证**；支持路径是进程级重启 |
| 7 | **已在真实付费网关验证** | 全部证据离线或 mock；本会话余额约 0.03 美元，不允许花钱验证 |
| 8 | **跨进程防篡改** | 完整性校验是**每进程一次**：同进程内已验证的 blob 被原地改写（trailer 不变）不会被再发现；下一个进程以 `BLOB_CORRUPT` 拒绝 |
| 9 | **取消语义（设计契约）** | 不支持取消：在途读取不提前退出，操作未结束仍计入排空，超时不交接；**不为取消而提前减 `activeOps`** |

另外三条"已知但不阻塞"的债：多进程互斥 / LRU→逐条 FIFO / 无阻塞压实 / 检索跨页缓存 / 后台巡检（**未实现、未阻塞**）；
`threshold`=4096 与 `cushionBudget`=4500 存在配置耦合（实测无害，但与"死区"判据相邻）；工作区 dirty 标志不可用（非 git 仓库，清单如实写 `null` + 原因）。

## 9.2 工程债（非阻塞）

- 宿主 spill-policy 与 CMB spill 的**竞争关系未定**（同族：`.writer-pid` 每存储目录一把锁、journal owner lease）；
  失败方向是**拒绝写入**（fail-closed），比静默重置安全，故保留为债。

## 9.3 科学未验证（明确排除在修复循环外）

宿主真实 80% 阈值触发（**最贵的一项**；长会话已 679 KB，可能自行发生）· 工具误用率 · `p` 的真实值 · 跨模型/跨任务形态泛化。

## 9.4 待决策（新机制，不是缺陷）

**随剩余预算主动外置**。两个障碍：①与 H1 的对账（触发时机是否该由我们决定）；②**仪表缺分母**（`contextWindow` 生产实测 `null`）。
合规增量：先把 `node.tokens`（宿主已在表层节点上提供）接进 `observe` 日志，等真实阈值触发拿到"宿主在第几 token 压缩"的锚点，
再按 §2.6 读宿主账本决定——**而不是从数据学参数**。
