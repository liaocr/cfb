# Target-model trace survey: DeepSeek-V4.1-Flash — 2026-10-07

Purpose: answer one question with evidence — can the designated target model's own coding-agent traces (including its chain of thought) be obtained from public sources, or must other models' traces stand in? Findings below are read-only checks of public artifacts. No model API was called, nothing was downloaded into the corpus, and no license was accepted on the user's behalf.

## Answer in one paragraph

No public source of genuine DeepSeek-V4.1-Flash reasoning traces was found. The only confirmed public archive of real DeepSeek-V4.1-Flash coding-agent rollouts is the SWE-bench-Live/TianxiCode submission; it is unlicensed for reuse and it stores the model's reasoning as blank text plus an encrypted blob, so the reasoning channel is not recoverable from it. The nearest usable DeepSeek-family, in-domain trace corpus is generated by the **predecessor model DeepSeek-V4-Flash** (21,208 OpenHands SWE trajectories with non-empty `reasoning_content`, `enable_thinking=true`, `reasoning_effort=max`), not by the target model. Any plan that depends on the target model's own chain of thought therefore requires generating traces with the target model itself (API or served checkpoint); public data cannot supply them, and Qwen/MiniMax traces are off-distribution substitutes that need explicit justification rather than silent substitution.

## Source-by-source results

### 1. DeepSeek-V4.1-Flash rollouts — SWE-bench-Live submission archive (real target model, reasoning redacted, no license)

- Location: `SWE-bench-Live/submission`, path `submissions/lite/tianxicode/deepseek-flash/` (PR #52, "add lite/tianxicode/deepseek-v4.1-flash result", merged 2026-09-29).
- Model identity: `logs/environment.md` states Model `tianxi-agent-plan/deepseek-flash` **(DeepSeek V4.1 Flash)**; harness `tianxicode 0.1.423` headless (`--format=json --thinking --auto`), framed task-agnostic preamble, network-isolated run 2026-09-21→22.
- Contents: 300 SWE-bench-Live `lite` rollouts; `trajs/<instance_id>.md` per-instance transcripts (median ≈ 96 KB, max ≈ 382 KB, ≈ 33 MB total), `logs/rollouts/<id>/events.jsonl` raw event streams, `preds.json`, `results.json` (204 resolved / 96 unresolved).
- Reasoning channel: `events.jsonl` contains 13 `reasoning` events in a sampled instance, but every one has `"text": ""` with `metadata.openai.reasoningEncryptedContent` set to an opaque id — the provider returned encrypted reasoning and the archive does not decrypt it. Assistant commentary text, tool calls and tool outputs are present; the actual thinking text is not.
- Licensing: no `LICENSE` file at repository root and the GitHub API reports `license: null`. The README frames the archive as "kept for analysis and reproduction of the run". No reuse grant is declared, so this cannot be admitted as a licensed corpus and cannot be redistributed. Reading it for analysis is fine.
- Contamination: these are SWE-bench-Live benchmark instances. Training on them would compromise that benchmark's future evaluation validity independent of the model question.
- Disposition: **target-model behavioral reference only** (harness framing, tool/step structure, token statistics). Not training data, not a reasoning-trace source, not redistributable.

### 2. DeepSeek-V4-Flash (predecessor generation) — Open-SWE-Traces v1.1, OpenHands/SWE tasks (in-domain, full reasoning, licensed)

- Location: pinned `nvidia/Open-SWE-Traces@f8fb5b3d2c787f85f8a00f5fe04fe3f1a11088ef`, config `v1.1`, paths `data/openhands/deepseek_v4_flash/scale-swe/*.parquet`.
- Official release note (pinned README): "[08/26] Release v1.1: Added new agent trajectories generated by DeepSeek-V4-Flash and Qwen3.6-27B across OpenHands, SWE-agent, mini-swe-agent."
- Measured with DuckDB over the 9 parquet shards (≈ 2.52 GB): `metadata.teacher_model.name = DeepSeek-V4-Flash`, `enable_thinking = true`, `reasoning_effort = "max"`, **21,208 rows**, and `sum(resolved) = -21208`, i.e. every row is `resolved = -1` (no success label).
- Sampled 60 rows from shard 0: 60/60 contain at least one assistant message with non-empty `reasoning_content`; ≈ 2.54 M reasoning characters across those 60 rows (≈ 42 K characters per trajectory). Per-message reasoning lengths range from tens to ~940 characters in the inspected examples.
- Other splits measured for completeness: `v1.0/openhands` = MiniMax-M2.5 (43,603) + Qwen3.5-122B-A10B (40,463); `v1.0/sweagent` = MiniMax-M2.5 (46,819) + Qwen3.5-122B-A10B (20,334); `v1.1/sweagent` = Qwen3.6-27B (77,261); `v1.1/minisweagent` = Qwen3.6-27B (95,291); `v1.2/minisweagent` = Qwen3.8-27B (144,410; the six rows already in the seed corpus come from this config). No DeepSeek-V4.1-Flash rows exist in any config of this dataset.
- Disposition: **nearest available auxiliary source in the DeepSeek family**. Off-target by one model generation; must be labelled as such and cannot support a V4.1-Flash reasoning claim. Row-level repository SPDX licenses still need per-row checks before any use.

### 3. DeepSeek-V4-Flash (predecessor) — Terminal-Bench 2.1 trajectories (full reasoning, MIT, different domain)

- Location: `openguardrails/terminal-bench-2.1-deepseek-v4-flash-trajectories` at revision `3f5b93ff1c5ea84b2c94cf479d0c942227191b4a` (last modified 2026-09-11).
- Setup per card: model `DeepSeek-V4-Flash-0731`, 89 Terminal-Bench 2.1 tasks, two scaffolds (`dsh` sdk-minimal and Terminal-Bench `terminus2`), one attempt each; card declares MIT for the published trajectories.
- Verified: 88 `terminus2/**/trajectory.json` files; a sampled trajectory contains 18 non-empty `reasoning_content` fields (largest ≈ 46 K characters) — reasoning text **is** published for this predecessor model.
- Disposition: supplementary. Different domain (terminal operations rather than repository SWE), predecessor model, so it cannot substitute for target-model SWE traces either.

### 4. Hugging Face dataset search for V4.1-Flash traces (negative result)

Searches (`deepseek-v4.1`, `v4.1-flash`, `deepseek flash trajectory`, `deepseek agent trajectories`, `deepseek-v4-flash trajectory`, `deepseek traces`) returned only distillation/CoT-derivative datasets (`mondk/Deepseek-v4.1-CoT`, `dengxiaodi/deepseek-v4.1-flash-distill-zh-2k`, `giosky123/arena-expert-deepseek-v4.1-flash`, `lautiss/qwen3-4b-agent-distill-deepseek-v4.1`) and unrelated older DeepSeek-R1 trace sets. No dataset of DeepSeek-V4.1-Flash agent trajectories was found. `datacurve/deep-swe` publishes tasks and leaderboard results for V4.1-Flash but its Hugging Face dataset contains only `data/test-00000-of-00001.parquet` (task definitions), not rollout traces.

## Follow-up measurement: is another model's CoT a substitute?

`docs/MICRO-GENERATOR-COT-PORTABILITY-2026-10-07.md` answers this with pinned-corpus measurements (script `tools/micro-generator/measure-cot-portability.py`, output `transfer/models/micro-generator-target-model-survey/cot-portability.json`). With harness and task sources fixed, the reasoning channel is model- and version-specific: DeepSeek-V4-Flash v1.1/OpenHands carries ≈ 44.3 k reasoning characters and ≈ 12 visible characters per trajectory, Qwen3.6-27B in the same config carries zero reasoning characters and 8 k visible characters, Qwen3.8-27B in the same harness as Qwen3.6 emits ≈ 100.7 k reasoning characters, and MiniMax-M2.5 sits at 24 k reasoning plus 2.7 k visible characters. A single-version change inside one model family therefore moved reasoning volume from 0 to the corpus maximum. V4.1-Flash additionally changed model architecture (trained from scratch), training data and the effort control itself (three prompt-level modes → integer 1–100), so its CoT cannot be assumed interchangeable with V4-Flash's.

## Consequences for the CFB corpus

**Correction (2026-10-07, after the compressor's role was restated).** An earlier version of this filing treated the CFB target as a "model-agnostic progress draft". That was wrong. The micro-compiler's job is: take **one born `reasoning` block** (`raw`) plus the context visible at that moment (`ctx`) and emit the **compressed reasoning block that the same main model will read back on later turns**. Its value is defined downstream — by whether the target model then fixes the task in fewer rounds and no worse than with the raw text — i.e. the gold axes **E1 (fixedAtRound ≤ 6) / E2 (not worse than raw)**, measured on the real machine. This changes three conclusions:

1. **Genuine target-model reasoning traces are only obtainable by running the target model.** Public data does not contain them. Hard constraint, not a preference.
2. **"Model-agnostic" is not a valid specification for the draft.** The draft is written *for the target model to consume*; its quality is whatever raises that model's continuation performance. Other-model traces can only supply raw material, and every compression candidate must be judged with the target model as the reader.
3. **The predecessor corpus (DeepSeek-V4-Flash, 21,208 rows) remains the strongest auxiliary source** — in-domain (SWE + OpenHands), `reasoning_effort=max`, full `reasoning_content`, CC BY 4.0 dataset with per-row repository SPDX — but drafts built from it stay `未测` on E1/E2 (provisional at best) until the real-machine A/B is run with the target model.
4. **The 300 real V4.1-Flash rollouts must not be trained on** (no declared license, benchmark-held-out, reasoning encrypted). They are useful only as format/behaviour reference.
