# 用户提供的真机材料：交叉核验与使用边界

2026-09-22。来源是本次对话中的证据包，不是本工作区直接读取的生产日志。没有获取用户网关、商户凭据或完整宿主仓库。用户明确提示其中可能含本地统计错误。

## 如何使用

不把“信 80%”变成每条结论都有 0.8 概率，更不把统计文字自动当成机器可验证事实。采用三档：

- **源码可复现**：按当前源码定位，并用生产函数、磁盘及 HTTP 副作用回归确认。
- **样本支持**：贴出的原始行足以支持有限描述，但不外推全部负载。
- **待完整原始数据复算**：只能作为排序线索，不宣称已经独立复算。

## 本次明确调整的判断

### 1. 并发不是当前主要收益来源

包中报告仅 7/772 次起飞时有任务在飞，间隔中位数 26.302 秒。完整逐笔记录未随包给出，不能在此独立复算这个比例；但它足以要求重新验证上一轮突发实验的适用性。

因此：第三批 54.5% 的本地突发字符变化不再用于代表当前生产收益。有界通道继续默认关闭，定位为未来并发保护。本轮新增**三个完全串行请求**的生产函数／SSE 实验，不靠减少调用数得到输入变化。

### 2. 大输入、输出截断、上游等待必须分开

样本确实有：

- 25,068 和 26,254 字符输入成功，不能说超过 20k 必然失败；
- finish=length，不能当作可用半成品；
- ttfbMs 为空、eventCount=0 的超时；
- 已收到数百事件之后仍触及 8 秒的超时。

所以不是单一“网络慢”或“上下文越大必失败”的定律。输入增长是值得优先处理的负载因素，但跨天成功率变化同时跨越构建／配置／取消策略／上游条件，尚不是隔离变量的因果实验。

本轮维持 1500/8000/1200，不靠加预算解决。

### 3. 材料的 PART 1 / PART 2 正文没有实际附出

目录声称包含完整宿主字段契约、328 次分布，但所贴内容在目录后直接进入关键行样本；后文有统计摘要和插件源码片段，不能等同于完整宿主实现。

因此不能宣称已经核对 surface/token-meter/CAS 全部宿主源码。PART 9 给出的 API 形状足以实现一个严格、可失败回退的适配器，并对这个形状做本地契约测试。

### 4. CAS 镜像缺失与“所有结构化状态都不存在”不是同一个结论

producer 分布数相加等于 3295，与摘要总数自洽；cot-snapshot=0 与此前源码未接 putText 的事实一致。

但没有 CAS 镜像不能单独证明当前本地 snapshots 目录也不存在结构化状态。故实现同时支持：备份已有合法本地状态，以及恢复后来确实写入过的 CAS 结构化镜像。不从旧渲染文本反推 entries 或覆盖集合。

### 5. 倒置区间不应直接交换端点

startSeq > endSeq 可能涉及原始畸形数据、统计提取错误，或 surface 排列与数值顺序不等价。未见完整宿主契约，不能认定 Math.min/Math.max 一定保留原意。

本轮对**本插件准备发出的破坏性替换**做拒绝式门禁：倒置／非法区间不发送，不自动扩大或重排删除范围。没有修改宿主既有历史事件。

包中的“删除节点数”还需区分序号跨度与真实 surface 成员数，不能用 end-start+1 自动替代实际节点计数。

### 6. 标记命中不等于可信来源

工具输出中引用 <cot-ledger> 不能获得记忆权限，这个方向成立。但“只有 assistant/message 算真看板”的统计方法也可能漏掉合法 plugin-origin user/message。

本轮继续使用插件保存的结构化状态，不凭正文标记建立范围回执。范围复用也不根据最终 role 推断用户授权。

### 7. 不把不同统计窗口混成一个分母

材料同时有 328 次编译、772 次起飞、按天合计 770 次终结记录，以及多组不同失败计数。它们可能来自不同选择范围或有未终结任务，不能直接互除。

提供 `deploy/analyze-trace.mjs`：锚定真实日志前缀，按 BOOT 分组，缺失 reason 显式列 unknown，缺失数值不填零，不自动推断因果或总体任务成功率。

```sh
node deploy/analyze-trace.mjs /path/to/trace.log
```

这工具目前只用可控夹具测试；没有把用户未附出的完整生产日志虚构成已执行的输入。

## 对优先级的最终影响

先处理串行负载中的重复／无界证据输入和成功状态的持久保存，再考虑并发收益。信息可信度的门禁不回退；通过范围回执和明确标注的输入工作集控制体量，而不是重新给截断全文错误覆盖权限。
