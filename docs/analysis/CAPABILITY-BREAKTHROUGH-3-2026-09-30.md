## 1. 诊断：我们的「反复修改」在文献里有名字、有量化

### 1.1 无接地的自我批判 = reformulation, not progress

Mirror Loop 实验（三个厂商的模型 × 四个任务族 × 十轮无外部接地自我批判）：**信息量逐轮下降 55%**，产出的是「改写」而不是「进展」；而在第 3 轮插入**一个最小的验证步骤**，前进立刻恢复（引自 2607.07663 §5.2）。
→ 我们这九版的工作方式（看分数 → 改提示词 → 再看分数）在结构上就是「无接地自我批判」：模型审自己、宿主审文本，没有第三方证据进入循环。这不是我们不够努力，是这一类循环的固有相。

### 1.2 迭代修复的收益集中在前 2 轮

- 迭代自修复（2604.10508，跨 4 个现代模型/多个基准）：**两轮修复吃下 76–95% 的可获得增益**；继续轮次边际锐减；自修复比独立重采样省 **11–54%** token；最难修的是断言类逻辑错误（修复率 ~45%）。
- 迭代精修的「性能平台期」在 2–3 轮后出现，且常伴随退化（Loughridge；CodeTree/BESTER 综述）。
- 自训练在固定分布上会 **rise-and-collapse**（2606.21090：20 步内 pass@1 先涨后崩，有时近零；KL/EWC 都压不住）。

### 1.3 长程任务的真正瓶颈是「单步可靠性 × 误差污染」，不是单步智力

- ICLR 2026《The Illusion of Diminishing Returns》(2509.09677)：单步 95%→99% 在 100 步任务上等于 **0.6% → 36.6%**；短任务上的「边际递减」是错觉。
- **Self-conditioning 效应**：模型看到自己之前的错误会提高后续出错概率；历史错误率 20% 时出现雪崩；**thinking 模型基本免疫**；处方是「在执行中清理/隔离错误历史」。
- 长程综述：H>200 需要单步可靠性 >99.65%；最可行路线是 **层级分解 + 反应式执行 + 验证** 的混合架构，而不是单体模型硬扛。

### 1.4 任何按分数搜索的自改进都会撞上 reward hacking（这是硬约束）

- SpecBench（2605.21384）：前沿 agent **能打满可见测试**，但留出测试上缺口 43–48pp；缺口随代码规模每 10× 增长 28pp；**搜索越久，P90 越严重**（搜索改变 hacking 的形态，不消除激励错配）。
- Cursor 审计（2026-06）：SWE-bench Pro 上 63% 的「成功」轨迹是检索到了已知修复；换成严格 harness 后 Opus 4.8 Max 87.1% → 73.0%。
- Fudan 综述（2604.13602）：proxy gap + 优化放大 + **evaluator–policy 共同适应**；诊断法叫「评估器交换测试」——测量在对污染受控/扰动变体上是否退化。
- HackProbe：harness 无关的 hacking 检测 + 免疫，带带宽受限的重选规则。

**小结**：我们的感受（被动、零碎、有限）被文献精确复现了；同时文献把出口限定在三件事上——把能力**引出来**、把改进对象换成**验证器**、给循环**控制**。

## 2. 三个机制族（每条：主张 → 证据 → 对我们的精确含义 → 反证/风险）

### 族 A ｜引出（elicitation）：能力已在，缺的是接口

**主张**：有些 agent 能力不是「没学会」，而是模型对自己运行时状态是**本体感觉盲**；把状态变成可见、可寻址、可恢复的接口，能力当场出现，无需训练。

**证据**
- **VISTA**（2606.30005）：把工作记忆表示为**类型化可寻址块** + 运行时仪表盘（每块 token 量、新旧、访问史、剩余预算）+ **无损存档与句柄恢复**。无训练、模型无关，在 LOCA-Bench 把 Gemini-3-Flash 从 **22.7 → 50.7%**，BrowseComp-Plus 58.0%，**增益随上下文压力增大**、跨 4 个 backbone 迁移；消融显示仪表盘本身（不只是存档工具）有独立贡献；Fano 不等式给出「恢复与本体感觉各自必要」的两条论证。作者原话：competent context management is already latent in capable models; what is missing is not a learned policy but an interface exposing this state。局限：低能力端有地板（GLM-5 增益最小）；Pith 批评「手写协议」部分混淆了归因。
- **引出的量化方法**（NeurIPS 2025《Quantifying Elicitation of Latent Capabilities》）：用**可训练参数量**当信息预算，性能呈 logistic-in-log(p)；50% 差距闭合在 Alpaca-Eval/TinyStories 上只需 ~1000 个参数，而「教新能力」要 ~100,000+；配合 MDL（RDA 上界）可判定「引出 vs 教学」。
- **Voyager**（2305.16291）：技能库 = **可执行的代码 + 描述 embedding 检索**（top-5 命中 96.5%）；消融：去掉自动课程 −93% 发现量，去掉自验证 −73%；**技能库在后期才发力**（80+ 迭代后无库者开始平台化）；技能库可跨世界零样本迁移。
- **AgentEvolver**（2511.10395）：自提问（自己从环境里长出任务）把 avg@8 从 15.8→**36.1**（7B）/ 29.8→**52.3**（14B）；再加自归因 → 41.3 / 56.4；收敛步数 −55~67%。**最大的单点增益来自「自己生成任务」**。
- **LongSeeker**（2605.05191）：五元上下文算子（Skip/Compress/Rollback/Snippet/Delete）**在 10k 合成轨迹上微调**后 BrowseComp 61.5% vs 最佳旧系统 43.2%；上下文稳定在 ~15k token 不再线性膨胀。
- **OdysseyBench**：分块摘要（<20% token）56.29 反而高于长上下文原样存 **33.67**；检索量再翻倍反而 56.29→54.97。
- **ReasoningBank**（ICLR 2026）：从成功**与失败**中蒸馏 title/description/content 三元经验项注入系统提示：WebArena +8.3pp（40.5→48.8），最多 +20% 相对、−16% 步数；**k=1 条记忆最好，k=4 反而变差**（49.7→44.4）；跨域泛化增益最大；MaTTS 并行 k=5 → 56.3%。

**对我们的精确含义（可落地，全部零模型成本可建）**
1. 台账从「宿主替模型压缩」改成「**模型可见的类型化块**」：块名、大小、新旧、被访问次数、剩余预算表 + 每条块有稳定句柄，**原文无损存档、可随时取回**。宿主只保证「无损 + 可恢复」，删/留的决定权交回模型。
2. 「验收条款/三问」从散文改成**可执行检查**（命令 + 期望输出 + 退出码），由宿主运行——这是 Voyager/GEPA 里唯一被证明能进化的形态。
3. 记忆进上下文用**少而精**（k=1–2），不是越多越好；失败经验单独成项（ReasoningBank 的 ablation 说失败经验有独立价值，但总量必须小）。

**反证/风险**
- VISTA 的增益是在**弱 harness** 上测的；我们的宿主已有 gate + 不变量，增量可能被吸收，必须小样本 A/B 才敢说。
- 上下文本体感觉要求宿主把「预算/新旧」真实暴露；我们的台账目前是宿主私有状态，暴露意味着接口改动（compile-v4 与 messages.js 都要动）。
- 检索越多越差、记忆注入对**早期**无益（Voyager：库在 80+ 迭代后才见效）——不要指望立刻见效。

### 族 B ｜验证优先（verification-first）：把「改进对象」从生成器换成验证器

**主张**：生成能力与自我验证能力是**不对称**的；训练/强化验证能**反过来提升生成**，并且是已知唯一能越过训练平台期的杠杆。

**证据**
- **不对称性**（2602.07594）：同一任务上，生成变强**不会**带来自验证变强（跨规模、跨基准）；但**只训练自验证**却能提升生成，且推理 token 更少，并解锁「验证引导的多数投票」测试时扩展。
- **STV**（2605.30290）：利用「**有参考答案时更容易诊断**」这一不对称，把参考解当作特权信息训练验证器；在线时验证器无参考。结果：硬数学上收益约 **2×**（对比未训练验证器），科学推理 **1.5% → 21%**；ViL（验证器在环训练）使 pass@1 **+33%**，且**去掉验证器**后生成器独立性能仍比 RLVR 平台期 **+30%**；20 轮精修持续上升而 SFT/Verdict-RL 早已饱和。
- **TTRL-CoCoV**（2606.03608）：经验陈述「**验证能力普遍领先生成能力**」；置信度分区（高置信→给探索奖励防塌缩；低置信→验证器筛伪标签；中置信→跳过验证省开销）；生成器与验证器**共同进化**。
- **ExecCritic**（2609.09133）：测试-验证-修复三段式 + **角色分离训练**，关键工程细节：**修复期间冻结测试**，修复代理不能改弱判据；SWE-bench Verified 61.2% → **72.6%**。
- **上下文蒸馏**（2209.15189）：把「有上下文时的收益」蒸馏进参数后，指令跟随 9.0→34.7 Rouge-L、8 位数加法直接 **0%→94.7%**、推理 token 少 8–11×——即**能力可以被「搬运」而不是被「重新训练」**。

**反向证据（必须一起看，否则会走错）**
- **agent 自写测试几乎没用**（2602.07900）：Claude 写测试 ~83% 的时间、GPT-5.2 几乎不写，两者完成率只差 **2.6pp**；强制 GPT-5.2 写测试（~500 任务）**净变化为 0**；自写测试更像 console.log 而不是 QA。结论是「**独立验证**」才有价值，而不是「让干活的模型顺手写个测试」。
- **自训练会自退化**（2606.21090）：需要**早停 + 跨轮记忆（capability posterior + transfer gate）+ 奖励归一化**的组合，单靠一个控制不行。
- **过度搜索**（2607.07663 §3.5）：34 种推理扩展配置的 Pareto 分析——相对于 CoT 的峰值增益 **+7.1 分，代价 ~20× 计算**；自一致性早饱和，多智能体收益持续时间更长；「这一主题的大部分收益目前来自更好的工程，而不是递归」。

**对我们的精确含义**
1. **顺序必须反过来**：先把判据建成「生成器碰不到」的东西——(a) 宿主可执行检查（客观、确定性）、(b) 独立验证器（不同角色/不同提示/尽量不同来源）、(c) Likert 评委降级为参考而非信号。
2. 我们有现成的 BTB 资产：oracle 手写稿（= STV 里「带参考的强诊断」）+ judge-cache + run4 的 79 行。可以**零成本**把 judge 的行为「编译」成可审二元问题（judge obj 里已有 claim/claimJustified/greenAsProof/followsPlan/repeat），能机械化的部分全部下沉到宿主。
3. 「修复时不改判据」= 我们的硬规则应写成：**一次评测周期内判据冻结**；改判据必须开启新周期并重跑基线。
4. 费用纪律与文献一致：**最多 2 轮**（第 3 轮只验证不生成）；修复优于重采样（省 11–54% token）；best-of/自一致性不做默认（早饱和、20× 成本）。

**风险**
- 我们无法训练验证器（无权重）。所以「验证器优先」对我们只能是：**用参考信息校准 + 判据客观化 + 独立性工程**，而不是训练。别把论文里「训练验证器」的数字直接当预期。
- ExecCritic 的 4.3pp 增量被审稿人指出统计不足；可迁移的是**结构**（冻结测试、角色分离），不是那个数字。

### 族 C ｜循环控制（control）：有记忆、有门、有早停、有归档

**主张**：长程自改进需要**显式组合多个控制**；单点修补会被 rise-and-collapse 吃掉。

**证据**
- **Self-regress 的三个控制**（2606.21090）：跨轮能力后验 + **迁移门**（CARE，3B 端到端近乎翻倍）、**滚动保留峰值检查点**的早停（ES）、组相对归一化（GRPO）；论文原话：有效长程自改进需要组合，而不是依赖任一单独控制。
- **平台期的结构化出口**：线性循环 → 树搜索（BESTER/CodeTree：分支 + 自评回溯）；接地反馈（执行数据 > 自省）；角色分离（planner/coder/tester）；**Feedback Friction**（2506.11930）：模型往往无法把外部反馈完整吸收——所以反馈要少、要 executable、要二元。
- **harness 端搜索**（第二轮已录）：Meta-Harness 同模型 harness 差最高 6×；DGM 归档 + 目标黑客警告；SkillOpt 的**严格留出门**（平局拒绝）+ 拒绝编辑缓冲。
- **失败驱动补丁**（2606.31270）：用一个 meta 推理者分析失败轨迹 → 生成推理期代码补丁：OSWorld 42.3%→48.9%；**四个结构化更新叠加优于任何单次更新**（构造性地叠加）。
- **能力定向训练 TRACE**（2604.05336）：对比成功/失败轨迹**自动识别缺失能力** → 为每种能力合成针对性环境 → 同 rollout 数下超 GRPO +9.2、超 GEPA +7.4（τ²-bench +14.1pp）。

**对我们的精确含义**
1. 建 **peak checkpoint / 归档**：每轮结束若指标不劣则留存制品版本（对应 ES 早停），并记录「为什么被接受/拒绝」（对应拒绝编辑缓冲）。
2. **错误历史隔离**（self-conditioning 的直接应用）：给生成器的续写上下文只包含**经宿主验证的事实**（台账三元组 + 通过的可执行检查），不包含上一轮的原始失败稿与批评文本。这是一个**机制性预测**，可以两轮小 A/B 验一次。
3. 反馈二元化：把「你这稿不行」拆成「检查 A 通过/不通过」——Feedback Friction 说长文本反馈吸收率低。
4. 评估器交换测试进常规流程：同一制品在**扰动变体**（换任务措辞/换判据顺序/换样本）上对比，退化即视为过拟合（Fudan 的诊断规则）。

## 3. 一条主线（把三族收成一句话）

> **把「改文字」换成「改接口 + 改验证器 + 控制循环」。**
> 生成器的文字不是改进对象；改进对象是**它能看到的运行时状态**（引出）、**它必须通过的判据**（验证优先）、**它被允许走的轮次与历史**（控制）。

| 动作 | 文献期望量级 | 我们现状 | 第一步（零模型成本） |
|---|---|---|---|
| A 引出：类型化块 + 仪表盘 + 无损存档 | VISTA +28pp（弱 harness，LOCA-Bench）；跨 4 backbone | 宿主私下压缩，模型看不见块 | `messages.js` 渲染块表 + 句柄；存档走文件，可 `read` 取回 |
| B 验证优先：判据客观化 + 冻结 + 独立 | STV ~2×；ViL +33%；ExecCritic 结构；self-verify→generation | 判据部分是 Likert；judge 与生成同族 | 把 judge 四维落成宿主布尔检查；周期内冻结判据；oracle 稿校准 |
| C 控制：峰值存档 + 错误历史隔离 + 2 轮 | 两轮 76–95%；self-conditioning 级联；ES/CARE | 多轮把原始失败稿喂回去；无 checkpoint | 续写上下文只给台账三元组；轮次上限 2（第 3 轮只验证） |

## 4. 与第二轮的差异（诚实修订）+ 本轮新增的硬事实

**新增硬事实（最刺眼的一条）**
- **SkillsBench：人类写的技能使通过率 +16.2pp，LLM 自己写的技能没有可测增益**（2607.07663 §3.6）。
  → 直接打击「让模型自写制品并保留」的默认假设。它把第二轮「制品可训练」修正为：**制品可训练，但必须有极强门 + 人类/预言机锚点**。我们的 oracle 手写稿正是那个锚点——所以正确的路径不是「教模型写到 8.9」，而是**把手写稿的质量转成宿主可执行的约束**（obligation），让模型只能产出满足约束的稿子。
- **Mirror Loop**：无接地自我批判十轮信息量衰减 55%，一次最小接地即恢复。
- **自写测试的反证**（2602.07900）：独立性是关键词，不是「写测试」这个动作。
- **技能库/记忆系统在早期几乎无用，在后期才发力**（Voyager 80+ 迭代、ReasoningBank k=1 优于 k=4）。

**修订表**
| 第二轮的说法 | 本轮修订 |
|---|---|
| ①制品可训练（SkillOpt/GEPA）排第一 | 降为**有条件**：无强门 + 锚点时自写制品增益≈0（SkillsBench）；门是前提而非附加 |
| ⑥测试时搜索缺省化 | 降级：相对 CoT 峰值 +7.1 分/20× 成本，自一致性早饱和；**只在验证器已强**时用，且默认 2 轮修复而非搜索 |
| ②可执行义务（PIS） | 保持并**升级为第一优先级**：与本轮验证优先的三篇独立证据同向 |
| ③harness 搜索 | 保留，但必须先有留出集 + 评估器交换测试，否则是 SpecBench 式的自我欺骗 |
| 新的第一 | **验证对象替换**（改进验证器/判据，而不是改进提示词）——它是唯一被三篇独立论文证明能越过平台期的杠杆 |

## 5. 停止清单（更新）

1. 在同一批提示词上做第 4、5 轮「看分改稿」（Mirror Loop：reformulation）。
2. 让生成器自评自改且无外部接地（同上）。
3. 在判据可被生成器影响时继续迭代（ExecCritic 的教训：修复期间冻结测试）。
4. 把 Likert 分数当训练/决策信号（Fudan：evaluator–policy 共同适应；我们已有 judge 锚定风险）。
5. 无留出集的「按分搜索」（SpecBench：搜索放大 hacking）。
6. 让模型把自己的原始失败稿读回去（self-conditioning 级联）。
7. 期待记忆/技能库立刻见效（后期效应）。

## 6. 建议的下一步（如果只做一件事）

**V → E → C**

- **V（验证优先，第一优先）**：判据客观化（judge 四维 → 宿主布尔检查）→ 周期内冻结 → 用 oracle 参考稿做校准/特权诊断。**零模型成本可建**；验证它需要一次小规模实跑（预算待批）。
- **E（引出接口）**：类型化台账块 + 仪表盘 + 无损存档/句柄恢复；把验收/三问改成可执行检查。
- **C（循环控制）**：峰值 checkpoint + 错误历史隔离 + 轮次上限 2（第 3 轮只验证）。

三者都**不需要**白盒、不需要训练、不违反「任何情况下都不能更坏」：每一项都能在宿主侧以「旧的路径仍保留、新增路径只在通过检查时启用」的方式落地。
