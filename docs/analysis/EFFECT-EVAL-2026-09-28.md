# 效果评测（2026-09-28）：压缩后的思考让主模型下一步更好还是更差

> 工具：`tools/effect-eval.mjs`（任务规格 `tools/effect-specs.json`）。模型：中转 a6api 的 `deepseek-v4.1-flash`（主模型开思考；盲评 = 同模型关思考）。
> 样本量小（每格 2–3 个样本，5 个任务），盲评噪声大（同一格可以 9 分和 2 分）。以下数字用于**定位机制**，不作为显著性结论。

## 1. 为什么这样测

DeepSeek 文档（thinking_mode）：请求带 `tools` 时，历史 assistant 的 `reasoning_content` 必须回传，并被拼进上下文；不带 tools 则被忽略。
turn 20 实测（中转）：带 tools 时 2262 字 reasoning ⇒ `prompt_tokens` +1340，模型能读出其中埋的暗号；不带 tools 看不到。
⇒ 在 Agent 会话里，**压缩稿确实就是主模型下一轮看到的思考**，效果评测必须带 tools。

构造（每个任务一次调用）：

| 消息 | 内容 |
|---|---|
| system | 编码 Agent，可用 bash / read_file / edit_file |
| user | 任务原文（`tools/v4-live.mjs` 内置任务，带工具输出） |
| assistant | `content` = 录制的真实回答（含它当时给出的下一步调用）；`reasoning_content` = **变体** |
| user | 该调用的工具结果（按录制回答设计，证实或推翻它的假设）+「下一步？」 |

变体：`raw`（录制原文 3.4k–11k 字）/ `empty`（无思考，对照）/ `v3` / `v4` 整块 / `v4inc` 增量 / `v3r`、`v4r`（v12.4 新提示词）。
评分：盲评（只看任务、工具结果、参考答案、候选回答；不知道变体）给 下一步正确 / 死路 / 事实 / 专注 / 综合（0–10）；规则正则作旁证。

## 2. 两个会让结论作废的坑（已在工具里自动防住）

1. **中转缺省不开思考**：不显式 `thinking:{type:'enabled'}` 时主模型 0 reasoning token、只回 30–40 token 的调用。第一轮（`effect-1`）因此作废。
2. **中转至少两条通道，其中一条丢弃历史 `reasoning_content`**：usage 带 `claude_*` 字段的那条，同一输入 `prompt_tokens` 恒为无思考值
   （wrong-model：该通道 813，正常通道 2712 = 1377 + 思考）。另有通道 token 计数偏低。
   ⇒ 每次主调用核验：claude 形 usage，或 `prompt_tokens` < 该任务无思考基线 + 0.3×思考字数 ⇒ 作废重发（≤5 次）。
   约 40% 的调用被作废重发；少数格子 5 次都没拿到有效通道，记为错误、不计分。

**压缩稿比完全没有思考还差。**

### 机制：分数几乎是二值的 —— 「直接改」9–10 分，「先回头再读一遍文件」2–3 分

| | 直接 edit_file 的比例 |
|---|---|
| raw | 4/10 |
| empty | 3/9 |
| 所有压缩变体合计 | **1/19** |

eacces 为例：原文思考末尾有一句**条件预案**——「如果 verify.mjs 中完全没有该变量……下一步修复：在 verify.mjs 的 env 中加 `CFB_REAL_DSH_HOME: tmp`」。
第二轮工具结果恰好证实了前提，带原文的主模型当场执行（两次都是 `edit_file verify.mjs … CFB_REAL_DSH_HOME: tmp`，9.5 分）；
v3 / v4 都把这句当「推测」删了，主模型一律 `read_file verify.mjs`（≈2 分）。
按「修复 / 改成 / 改为 …」检索：原文 eacces 12 句、flaky 8 句、sse 1 句，**v3 与 v4 保留 0 句**。

另两处发现：
- **v3 的产物几乎就是可见回答的复述**（同样的根因段落 + 同样的 grep 调用）。主模型本来就看得到 `content`，这等于零新增信息。
- v4 渲染以未决问句收尾（「还没弄清的是……？」）。推理末尾的疑问句是最近、最强的锚（Thought Anchors：不确定性管理句影响最大），把下一步推向继续取证。

## 4. 结论（对理论的修正）

1. 「思维链约 90% 冗余」在**字数**上成立（产物 5–9%），但被当作冗余删掉的部分里有决定下一步的内容：
   **原文已想好的改法与它的前提**（条件预案）。它看起来像「左右互搏 / 推测」，实际是给下一轮准备好的动作。
2. 压缩稿的价值不在于更短，而在于**下一轮能不能直接接着干**：保留「若 X 就 Y」、以动作收尾，而不是以问题收尾。
3. v3 这类「写摘要」的形态会收敛到复述可见回答 —— 这是 v4「只标注、由代码渲染」路线比 v3 更有前途的直接证据。

## 5. 下一步

- 提高 READY 召回：副模型单独一遍只抽改法（便宜：只看最后 30% 原文）；或规则回捞（原文「修复 / 改成 / 改为 / 下一步修复」句作为候选，锚点校验后收为 READY）。
- 扩大样本（每格 ≥5、更多任务）后再判显著性；换一个不丢 reasoning 的通道（官方 API）可去掉约 40% 的重发成本。
- 评测的「正确下一步」偏向直接动手；读文件再改在真实环境里也合理。已在参考答案中写明「节选已给出」，但仍需第二套评分口径（例如两步内是否改对）作为复核。

| 变体 | n | 上下文思考字数 | 综合 | 直接改 | prompt tokens |
|---|---|---|---|---|---|
| raw | 20 | 7857 | **5.4** | **40%** | 4440 |
| empty | 20 | 0 | 3.5 | 20% | 1400 |
| v3r / v3h（v12.4 / +改法线索、不复述回答） | 20 / 20 | ≈720 | 3.5 / 4.2 | 25% / 25% | ≈1720 |
| v4r / v4h | 20 / 20 | ≈550 | 4.4 / 4.0 | 25% / 25% | ≈1660 |
| v3long（目标 1500–2500；副模型只在 2 条上真的写长） | 20 | 935 | 4.8 | 30% | 1804 |
| **tail（原文最后 ≈2500 字逐字）** | 17 | 2434 | **5.1** | **41%** | 2374 |

- 5–9% 的压缩稿（无论 v3 / v4、有无改法线索）≈ 无思考；**改法线索对 v4 无可测收益**（上一轮的「2.5 → 7.3」是小样本噪声）。
- 保留原文最近 ≈25–30%（逐字）：综合与直接改率与原文持平（配对差 +0.5），prompt tokens 少 47%。
  逐任务分化大：eacces 8.8 / perf 10.0（高于原文），wrong-model 4.9 / flaky 2.8（低于原文）—— 这两条的关键推理在前半段。
- 稍长的压缩稿（v3long）比短稿好（4.8 vs 4.2），与倒 U 形一致。
⇒ 方向：**「前段压缩 + 最近一段逐字」混合**（v4 增量的 condensed-partial 本来就是这个形态），而不是把整块压到 5–9%。

## 7. 归因：理论为什么没生效（零调用分析，基于已有样本与产物）

先排除两种解释：
- **不是「短上下文本来就不行」**：原文最后 ≈2500 字（占 25–30%）的效果与全文持平（5.1 vs 5.4，直接改 41% vs 40%）。
- **不是单纯「压得太狠」**：v3long（≈935 字）比 ≈550 字的稿好（4.8 vs 4.2），但还远不到原文。字数只是次要因素，关键在于**删掉的是什么**。

| # | 原因 | 证据 | 属于 |
|---|---|---|---|
| 1 | **理论只建模了「状态」，没有建模「判读」**。原文针对即将回来的观察写了答案表（「若 finishReason=length ⇒ maxOutputTokens 是主因；若 stop ⇒ compressTargetMax」「若 grep 显示 verify.mjs 没设 ⇒ 根因明确」）。v4 只保留了问题（OPEN：「需查 finishReason 是 length 还是 stop」），把答案表删了 | 原文每块有 1–7 句条件判读；v4 产物 10 份里有 9 份条件句为 0。tail 刚好保住了这些句子（perf 10.0、eacces 8.8） | 理论缺陷 |
| 2 | **价值函数的对象错了**：v(i) 衡量一句话对「理解当前状态」的价值；但下一轮需要的是「观察回来之后该做什么」。改法与判读的价值最高，却被当成推测删掉（规则 3「存疑的不得升级」、规则 2「不给建议」被副模型理解成删掉候选改法） | 原文 21 句「修复 / 改为」，v3 / v4 保留 0 句 | 理论缺陷 |
| 3 | **渲染语域**：reasoning_content 是主模型自己的思考，但 v4 把它写成第三方笔记（「目前判断 / 当时计划 / 来源 / 未决」、零第一人称），并且以问句收尾。「当时计划」这类过去时，本意是防止被读成指令，实际却让主模型把它当成过期记录 | v4 产物第一人称 0 次、标签 3–8 个；末尾问句 → 继续取证 | 理论规则副作用 |
| 4 | **副模型不守规格**：长度目标被无视（1500–2500 只写 557）；v3 仍复述可见回答；判读句已逐字列进提示词，仍有 2/5 块不标；模板语言判错（perf 套英文模板） | 见 §3、§6 与 ops7 首次产物 | 执行缺陷 |
| 5 | 评测噪声：每格 2–3 个样本时，单格可以从 7.3 变到 3.0 | §6 | 测量 |

## 8. 修改（v12.5，全部零调用完成；自测 582 / 0）

- **IF 判读条目**（理论补「判读层」）：`cond ⇒ then`，原文给几个分支就标几条；针对即将执行的调用的判读最高优先；最后 4 条必留；
  有判读时，尾段不再停在问题上，而是以「若 A，就 B」收束。
- **代码保底**：副模型对 IF / READY 一条都没标时，由程序从原文**逐字**补上判读句 / 改法句（逐字 ⇒ 不可能编造；否定 / 犹豫句与超长句不补；已覆盖的不补）。
- **第一人称内心独白语域**：「我目前判断 / 我现在采用 / 接下来要 / 还要确认 / 我准备的改法 / 判读：若…就…」。
- **预算下限 800**（450 装不下判读 + 改法 + 死路）。
- 模板语言跟随条目内容（阈值 0.1）；「不复述最终回答」规则（v3 / v4）；答案 kind2 降权。
- `captureSideOutput` + `tools/compile-direct.mjs --recompile`：以后改编译 / 渲染规则时**零调用重编译**，不再重新压。
