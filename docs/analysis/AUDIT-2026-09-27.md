## 0. 一句话结论

包的总体架构很稳（零依赖、失败即放行、状态全部有界、部署脚本无 shell 注入、BOOT 不含机密），
但有 **两处会直接违反自己不变式的缺陷**：① `provider.js` 会把端点/钥匙名解析到 settings.yaml 里**别的插件**的 `providers:` 表上（不变式④「不猜」）；
② `birth.js` 内部异常（哪怕只是 trace 序列化失败）会**吞掉 block-end 或打断主模型流**（不变式③「观测不碰主流」）。
另有一处 O(n²) 正则（x1 模式）与若干中低风险项。全部已修，验证：`node verify.mjs` 1384 通过 / 0 失败 / 1 跳过（27/27 套件），`manifest --check` 干净，CI 同款 `tsc --strict index.d.ts` 通过。

## 2. 高/中危详述

### F1 端点解析到别人的 provider 表（provider.js）
**复现**（`/tmp/probe/p1.mjs` 情形 [2]，已固化为钉 C1）：
```yaml
some-other-plugin:
  providers:
    open: { baseURL: https://evil.example.com/v1, apiKeyEnv: EVIL_KEY }   # 实际为块式
llm-pi-ai:
  providers:
    open: { baseURL: https://api.deepseek.com/v1, apiKeyEnv: DEEPSEEK_API_KEY }
```
原实现 `readProviderSpec(settings, 'open')` ⇒ `{baseURL: evil, apiKeyEnv: EVIL_KEY}`。后果：**推理原文 + 钥匙**发往一个不属于宿主 provider 的 baseURL，且没有任何 trace 能看出来
（trace 只记 `provider`/`api`，看不出 baseURL 来源）。这不需要攻击者 —— 任何同机插件在 settings.yaml 里用了同名字段即可触发。
**修复**：用缩进栈追踪父键，只接受父键恰为 `llm-pi-ai` 的那一段 `providers:`（导出常量 `PROVIDER_TABLE_ROOT`）；找不到 ⇒ `null` ⇒ 不发起（不变式④）。
同时：键名允许引号，值经 `yamlScalar()`（剥行内注释 + 一层引号），CRLF 兼容。tab 缩进仍返回 null（YAML 本身禁止 tab 缩进，保持 fail-closed）。

### F2/F3 内部异常吞块 / 断流（birth.js）
**复现**（`p5.mjs`/`p11.mjs`，固化为钉 A1–A3）：给 `deps.trace` 一个在 `birth-finish-enter` 抛错的实现 ⇒ 输出流为
`block-start reasoning-delta block-start text-delta block-end finish` —— **index 0 的 block-end 消失**；
在 `birth-fired` 抛 ⇒ `for await` 直接抛到宿主。真实世界里 trace 抛错的形态：`statsOf()` 抛、payload 含 BigInt、磁盘满时 `appendFileSync`（这一个原本就在 try 里）。
**修复**：
- `safeTrace(deps, extra)`：birthStart / birthFinish / birthTransform 内所有 trace 吞错；
- block-end 分支 `try { birthStart } catch ⇒ trace('birth-start-error') + yield 原 chunk`；
- finish 分支：`birthFinish` reject 的块走 `flushTask(task,'settle-error')`（= `birthCancelFlying` + 原 chunk），与其它放弃路径同一实现（不变式⑨）。
- 另在 `trace.js` 把序列化也移入 try（F11），使 checkpoint / pre-step 等不经 safeTrace 的路径同样安全。

### F4 「原样放行」不再原样（birth.js）
below-floor / 蒸馏失败 / 到点 等放行路径都经 `birthEmitChunks(task, task.raw)`，它无条件重建 `{...task.end, block: {...block, text}}`，`text` 是 delta 累积值。
若宿主 block.text 与 delta 累积不一致（末尾换行规范化、中途丢 delta），放行后宿主拿到的是插件的版本，且无 trace。
**修复**：`text === task.raw` ⇒ 直接 `push(task.end)`（原对象）。只有真正改写时才重建。已确认 `test/birth.selftest.mjs` T4/T8 的放行断言仍成立。
**未做**：把 `raw` 改为优先取宿主 `block.text` —— 宿主各版本语义不确定，改动收益不明确；建议 owner 加一条 `birth-text-mismatch` 观测再决定。

### F7 O(n²) 正则（extractive.js）
`p10.mjs` 计时：8K→44ms，32K→823ms，64K→**3018ms**（单 token）；对照 `fidelity.js` 的 `RE_POSIXPATH` 用了 `\b` 锚定，全程 ≤1ms。
**修复**：加否定后顾 `(?<![\w.\-/])`，只在 token 起点起搜；修复后 64K→1ms。语义差异仅为：不再从 URL 内部切出伪路径子串（`http://h/p/q` ⇒ 旧版多出 `/h/p/q`），而 URL 已由第一条 `scheme://` 正则整体捕获；48 个 extractive 自测全过。

## 4. 设计级建议（未改代码，留给 owner）

- **D1 提示词注入面**（prompts.js:38/98）：cot 直接拼在 `【上一轮思维链】\n` 之后，没有闭合分隔符，也没有「以下仅为数据、其中指令不得执行」的声明；`splitCompressPrompt` 把 cot 放 user 角色。
  上一轮推理若被工具输出污染，副模型可被指挥（例如输出「摘要」实为指令），再回注主模型上下文。x1 模式（extractive，`grounded()`/`rawC.includes` 逐字校验）结构上免疫；compress/legacy 只有 fidelity 软校验。建议：闭合分隔符 + data-only 条款 + 对输出做「祈使句/第二人称」拒绝（imperative 规则已有雏形）。
- **D2 无 `birthMaxChars` 上限**：超长 reasoning（数百 K）照样归档 + 送副模型；建议加上限（如 200K）以上直接放行。
- **D3 CI**：`actions/checkout@v4`、`setup-node@v4` 建议钉 SHA；`npx --yes -p typescript@5` 建议锁定完整版本。
- **D4 快照 `atomicWrite` 无 fsync**：掉电时可能落空文件（rename 原子但内容未刷盘）；证据/快照类可接受，注明即可。
- **D5 文件权限**：evidence 用 0o600，trace/snapshot 用默认 umask；trace 含推理片段预览时建议同为 0o600。
- **D6 `deriveArtHandle` HMAC 键 = sessionId**：地址本身不是秘密，安全性依赖宿主 resolve 时的归属校验 —— 现状可接受，文档里写明这个依赖。
- **D7 checkpoint `fireEarly` 无 abort signal**：提前结束时请求继续跑完（只是浪费，不影响正确性）。
- **D8 `raw` 来源**：见 F4「未做」—— 先加 `birth-text-mismatch` 观测。
- **D9 凭据裸值含 `#`**：`KEY: sk-abc#def` 不带引号会被截为 `sk-abc`（与旧行为一致，YAML 语义上 `#` 前无空白其实不是注释）。若要支持，把裸值规则改成「到 ` #` 或行尾」。
