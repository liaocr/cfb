## 0. 结论先行

**唯一主干**：`birth` 模式 · `compress` 编译 · `compressPrompt: x1`（抽取式 r2）· 固定一个更快更便宜的副模型 · 只压大块起步 · 失败一律原文放行。

**冻结**：v1 / v2 / memory 模式 / checkpoint 模式 / 迟到认领 / 对冲 / 跨轮批量 / 主模型自写摘要 / 纯规则抽取。冻结 ≠ 删除，但**不再投入一分钟**，解冻条件见 §3。

**v3 的身份**：不是主线、不是兜底（兜底永远是原文放行）——它只作为离线评测的**对照腿**活着；若测出 x1 明显不如 v3，预定动作是「v3 + 大块门槛」，不再开会。

**顺序不可调换**：先零风险观测（§5 阶段 0）→ 离线评测（阶段 1）→ 单会话金丝雀（阶段 2）→ 扩面（阶段 3）。三轮文档都卡在阶段 0 没做，这一次阶段 0 是**第一件事**，不是"以后"。

## 1. 为什么会乱：两种"不确定"被混在一起了

| 说法 | 实际含义 | 性质 |
|---|---|---|
| 「旧的（v1/v2/v3 改写式）不行」 | 结构上允许副模型**写出原文没有的句子**、把假设升级为定论、删掉转折（研究 [4][8][9][12] 指出这恰是最危险的失败形态）；且旧真机数字不好看（收网命中率 23.1%、`finish=length`、归档失败 ≥28%） | **最坏情况无界**：错了是静默地写错内容 |
| 「新的（x1 抽取式）没有证据稳定」 | 零真机数据、只有 48 个单元测试 + 一个合成 fixture | **最坏情况有界**：错了只能是"漏句子"，可度量、有硬闸门、原文可按句柄取回、闸门不过就原文放行 |

两者都缺"任务质量"证据，这一点是对称的。**不对称的是失败的形态。** 在「每错一步都是巨大损失」的约束下，正确的选择不是"等谁先有证据"，而是**选最坏情况有界的那个去取证据**。这就是锁 x1 的全部理由——它不是"更好"，它是"错了也不致命"。

第二个混淆：**「省钱」和「提升表现」是两个目标，之前的文档在两个目标之间来回切换。** `ECONOMICS-V11.11` 证明了：同价副模型下，平均块（≈1,075 token）压缩净亏，回本线 r ≥ 3,635 token；「覆盖 2/3 的块」与「每块盈利」**数学上不可兼得**，唯一杠杆是副模型解耦计价。而 `RESEARCH-*` 两篇的价值全在表现侧（Tau² 87 vs 64 的量级）。两边都对，只是回答的不是同一个问题。§2 把优先级钉死。

## 2. 决策公理（三条，之后不再重议）

1. **优先级：不伤主模型 > 不增加可感知延迟 > 省 token。** 依据：成本侧的下行是有界的（`ECONOMICS` 算出 cfb 最差 +4.3% 总成本），表现侧的杠杆是两位数百分点且双向（保留 vs 丢弃历史思维链 87 vs 64；死分支诱发级联错误）。一次任务失败/死循环的代价是几十步重读上下文，远超压缩省下的那点 token。这也与用户早先的硬约束「正确性 > 速度」一致。
2. **损失不对称原则：两个方案都缺证据时，选最坏情况有界的。** 见 §1。
3. **争议只能被测量关闭。** 阈值、模型选择、要不要扩面，全部由 §5 的决策表按数字裁决。没有数据的路线提案不进入讨论。

## 3. 唯一路线：主干与冻结清单

### 3.1 主干（锁定）

| 层 | 锁定值 | 一句话理由 |
|---|---|---|
| 介入机制 | `mode: birth`（出生时改写，H2 合规，前缀永不回写） | 唯一与宿主不变式和前缀缓存都相容的写入点；checkpoint/late-claim 各自带一类 birth 没有的正确性问题 |
| 编译器 | `stateCompress: true` + `compressPrompt: x1`（r2 四开关缺省 true） | 最坏情况有界；副模型只输出编号（输出 token 是成本大头，4× 单价）；保留主模型自己的 token（离策略代价最小） |
| 副模型 | `followHostModel: false` + 显式 `model`（同 provider，端点/钥匙仍跟随宿主） | 解耦计价是覆盖率与盈利兼得的**唯一**杠杆；更快的 TTFB 同时抬高收网命中率。配置已支持，零代码 |
| 触发门槛 | `birth.minTokens`（与语言无关），起步只压大块，数值由阶段 1 反解 | 大块是经济上唯一明确为正的区间（10k 块净 +3,183），也是噪声最多、表现收益最大的区间 |
| 收网 | `finishWaitMs` 按实测 `needWaitMs` p50 设；`hedgeAfterMs: 0` | 不用 2× 成本对冲上游抖动，用更快的副模型和免费窗口解决 |
| 失败 | 原文放行（唯一兜底） | 不再增设"确定性抽取兜底"这一条新路线 |
| 前置 | 合入 `audit/fixes-2026-09-27`（`AUDIT-2026-09-27.md`） | 金丝雀之前必须先保证"插件内部异常 ⇒ 原文放行"真的成立（此前 F2/F3 会吞块/断流） |

## 5. 三阶段门禁与决策表

### 阶段 0 —— 零风险观测（现在开始；3–7 天或 ≥300 个 reasoning 块，先到为准）

分两小步（原因：`dryRun: true` 时 `plugin.js` 直接返回**未包装**的流，`birth-window-probe` 与逐块长度都不会产生）：
- **0a** `dryRun: true`：零介入，只有 `llm-stream` 可见 ⇒ N1 / N5 / N6，N2 为近似值。2–3 天或 ≥100 次请求。
- **0b** `dryRun: false` + `birth.minChars: 100000000`（不可达门槛）：包装态 —— 每块走 below-floor 直接放行，不归档、不调副模型、不改写；产出 `birth-below-floor`（N2 精确）与 `birth-window-probe`（N3/N4），同时证明「插件在路径里」对宿主无害。3–5 天或 ≥300 块。
- 报告一条命令：`node tools/phase0-report.mjs trace.log`（判定已按本表写在数字旁）。逐步操作见 [`RUNBOOK-PHASE0.md`](RUNBOOK-PHASE0.md)。

| # | 要拿到的数字 | 从哪读 | 数字 → 动作 |
|---|---|---|---|
| N1 | 历史 reasoning 是否跨 user 轮保留 | `llm-stream.reasoningChars`：**非最后一条** assistant 是否 >0 | 是 ⇒ 全路线；否（只在同一 user 轮的工具循环内保留）⇒ 收益只剩循环内，门槛再抬一档，并把「是否值得上线」列为阶段 1 的显式问题 |
| N2 | `rawChars` 分布（p50/p90、≥门槛占比） | 0b：`birth-below-floor.rawChars`（精确）；0a：`llm-stream.reasoningChars` 去重（近似） | ≥门槛占比 <5% ⇒ 大块路线覆盖太小，能否扩面完全取决于副模型单价（N7） |
| N3 | 免费窗口 `otherStartToLastEndMs` p50 | `birth-window-probe` | >1000ms ⇒ 阶段 2 后实现"第一个非 reasoning 块 block-start 起火"（带 `h.text === raw` 硬校验）；≤300ms ⇒ 不做 |
| N4 | `lastEndToFinishMs` | 同上 | 决定 `finishWaitMs` 的免费部分 |
| N5 | 宿主模型版本 | `host-model` | V4 系：带工具时全量保留历史 reasoning；V3.2：新 user 轮丢弃 ⇒ 回到 N1 的"否"分支 |
| N6 | 基线任务指标 | 每任务工具调用数、完全相同的重复调用数、同一错误签名重复次数 | 阶段 2 的对照基线；没有基线就没有 A/B |

### 阶段 1 —— 离线评测（花少量 API 费，线上零变化）

1. 从真实会话日志构造 **30–50 个** `cf-eval` fixture（格式见 `tools/cf-eval.mjs` 头注释；配对连续指标 30 个即可给区间）。
2. 跑 `--variants raw,v3,x1,x1:nofold,x1:nodedupe`，副模型两档：`--compressor-model` = 宿主模型 / 候选小模型。
3. 顺带得到：副模型 `usage` ⇒ **chars/token 实测值**（结束 1.67 vs 2.57 之争）；`keptRatio`；副模型 TTFB/总时长。

| 闸门 | 判据 | 通过 | 不通过（预定动作，不再讨论） |
|---|---|---|---|
| G1 | x1 `successRate ≥ 0.95 × raw` 且 `loop`/`avoid` 的配对区间不高于 raw | 进 G2 | 先看消融：某个 r2 特性拖累 ⇒ 关掉它重测一次；仍不过 ⇒ x1 出局，进 G2′ |
| G2 | x1 vs v3 配对 `deltaVsRaw` | x1 ≥ v3 或区间跨 0 ⇒ **x1**（结构安全是平局裁决） | v3 显著更好 ⇒ **v3 + 大块门槛**成为主线（G2′：若 v3 也不过 G1 ⇒ 压缩本身伤表现 ⇒ **不上线**，保持 dryRun；这是合格的结局，不是失败） |
| G3 | 小模型作副模型 `successRate ≥ 0.97 ×` 宿主模型作副模型 | 用小模型 | 用宿主模型，覆盖率目标相应下调（同价下不可能覆盖 2/3） |
| G4 | 门槛反解：用实测 chars/token、`keptRatio`、副模型单价代入 `ECONOMICS` §三公式 | 得到 `birth.minTokens` | — |

阶段 1 之前的临时值：`birth.minTokens: 4000`（≈同价改写式的回本线 3,635 上浮；x1 的输出更便宜但提示词更长，两者相抵前先取保守）。

### 阶段 2 —— 单会话金丝雀（1 周或 200 个被压块，先到为准）

```yaml
- id: cot-form-b
  config:
    mode: birth
    dryRun: false
    stateCompress: true
    compressPrompt: x1
    followHostModel: false
    model: <阶段 1 选定的副模型>      # 端点与钥匙仍跟随宿主 provider
    birth:
      minTokens: <G4 反解值>          # 阶段 1 前用 4000
      finishWaitMs: <needWaitMs p50>  # 阶段 1 的副模型工期 − N4 免费窗口
    distill: { hedgeAfterMs: 0 }
```

**预先承诺的熔断（任一触发 ⇒ 当天改回 `dryRun: true`，一行回滚）**：

| 熔断 | 阈值 |
|---|---|
| 宿主不变式报错 / `birth-start-error` / `birth-settle-error` | **1 次** |
| 非 below-floor 的放行率（= 白花钱的副模型调用） | > 50% |
| `extractive-rejected`（unparseable / empty / too-long） | > 20% |
| `identifierRecall < 0.95` 的块占比 | > 5% |
| finish 处新增等待 p95 | > 配置的 `finishWaitMs`（说明宽限在兜底） |
| N6 指标恶化（重复调用、同签名错误重复） | 相对基线 +20% |

### 阶段 3 —— 扩面（只按数据）

- 门槛每步 ×0.7 下调，条件：上一步 `birth-econ` 每块净收益 ≥ 0 且熔断表全绿一周。
- 宿主侧有按 `art://` 读回的工具 ⇒ 打开 P5 取回率闭环（取回率高的桶提高 keep）。
- N3 成立 ⇒ 实现免费窗口起火（单独 PR，单独金丝雀）。
- 覆盖 2/3 只有在 G3 通过（小模型）后才可能是目标；同价副模型下**不设**这个目标。
