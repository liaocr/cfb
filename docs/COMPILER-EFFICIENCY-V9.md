# v9：减少无效编译，改善判断交接，拆清实际耗时

日期：2026-09-22。基于最终 v8。未部署、未推送、未修改宿主 profile。

## 结论先行

本轮把上一轮讨论的方向一起落实到默认生产路径：判断组织、精确在途复用、明确不可消费任务的取消、提示词一次构造、阶段耗时、稳定前缀布局，以及按真实请求身份整理缓存用量。

**代码及本地验证已完成；真实产品效果尚未验收。** 不把主模型看见摘要等同于使用判断，不把共享请求次数等同于节省账单，也不把更长的相同前缀等同于供应商缓存命中。

| 方向 | 实际修改 | 本地能确认的范围 |
|---|---|---|
| 判断真正帮助后续决策 | 两栏强调结论／适用条件／依据／修正原因；恢复提供既有模型记忆作为待核对材料 | 输入契约与材料保留，不能证明模型理解或重复探索下降 |
| 无效编译 | 完全相同的在途请求共享传输；原文归档终局失败时撤销该消费者 | 默认 hook + HTTP 可复现；各任务门禁仍独立 |
| 请求前重复工作 | 统计与发送使用同一份已构造提示词 | 不再构造两次完整判断提示词；HTTP实际正文一致 |
| 8000ms 内完成机会 | 补齐失败路径的首内容、内容跨度、尾部耗时与总耗时；保留完整结束门禁 | 能定位瓶颈，不声称解决上游排队／波动 |
| 缓存友好度 | 稳定规则与证据在前，易变编译位置等记账信息后置；新增请求级 usage 整理 | 保留字段，观察缓存自报用量；不能认证费用 |

## 1. 判断交接：保留“为什么、在什么条件下”

仍然只输出【关键判断与依据】和【未决差距】，没有新增模型步骤或固定输出长度。

新增要求：

- 同一对象的现有判断、适用条件、可见依据、明确修正与否决原因尽量相邻。
- 材料不足就保留分歧，不为了排版补出因果关系或解决冲突。
- 一次失败只约束已经观察到的参数与环境，不推广成永久不可行。
- 用户禁止与技术失败分开；依赖变化和旧判断的失效范围必须保留。
- 未决差距只写已有的不确定性、缺失核验、已有计划的未执行状态，不生成新计划。

审计还发现：已有 `priorMemory` 已进入证据信封，但 v8 的判断提示词并未展示这个字段。v9 将其放入“既有模型记忆：待核对，不提升来源权限”，使旧判断与本轮观察有机会交叉核对。它仍是旧推断，不是用户授权，更不是执行证明。

保留原有目标、约束、验收条件、路径、命令、数字、否定条件、备选解释和已有计划的要求。工具正文选择和 v8 区间并集机制不变。

**代价**：新增规则及旧判断材料可能增加输入，不承诺输入压缩率不降。合成布局样本中，提示词从7602字符增至7895字符；工具核对正文与原始 reasoning 均完整保留。这是输入保真与交接改进，不包装成字符压缩收益。

## 2. 精确在途复用：只共享模型传输，不共享应用权限

新增 `exact-flights.js`，每个插件实例持有自己的在途表，默认 birth 状态编译接入，无新增配置开关。

只有下列条件全部相同才共享：

- 来自生产采集路径的非空 session、branch 和有效固定 cut；
- **完整提示词逐字相同**，不是相同前缀、相似目标或仅 hash 相同；
- 实际端点、API、provider、凭据、模型；
- 输出上限、超时、重试、thinking、stream、连接配置。

身份用小型配置序列化串加完整提示词构造，不再为了匹配对完整提示词额外做 JSON 转义。凭据只参与私有、临时内存中的严格匹配，不写入 trace，也不导出凭据指纹。

### 不做的复用

- 不跨插件实例或未知作用域共享。
- 不缓存已完成的结果；以后再来相同请求仍正常调用。
- 不忽略新增事件增量、截断标记、来源或宿主编译位置差异。
- 不把一份模型响应的条目身份、归档成功或认领权限给另一任务。

每个逻辑任务独立解析、分配记忆条目身份、检查 CAS、净省和认领条件。共享响应不代表多个任务已经合并成一个任务。

在途索引上限32项、身份串合计4MiB UTF-8字节、每个在途请求最多128次附件注册（取消后也不重置累计数，避免回调堆积）。这些不是全插件内存上限。超出时走原本的独立请求，不排队、不驱逐正在工作的请求，也不丢任务。

### 本地生产路径结果

在真实插件 hook + 本地 HTTP 的合成场景中，3次相同截面的触发产生2次 HTTP：第一份账本视图有新事件增量，不能与后两份相同视图合并；后两份共享一个请求。原文在结果未就绪时仍逐字放行，3个任务仍独立结算。

这证明默认接线有效，**不证明真实工作负载有相同的重复率或费用收益**。

## 3. 只取消已经确定不可消费的工作

原文归档终局失败（包括既有归档超时门禁）后，该任务不可能满足“模型完整成功 AND 原文 CAS 成功”条件。v9 在这时撤销该消费者：

- 还有其他消费者：请求继续，健康任务不受影响。
- 最后一个消费者撤销：中止底层在途请求并释放共享索引。
- 请求已完成：不会倒推它没有发生，也不会声称追回费用。

归档稍后才完成，也不推翻既有超时后的失败门禁。原文继续原样保留。取消不算成功，不从原有失败统计中剔除。

**没有新增**按“日志结束”“来了新任务”“出现较新状态”推测旧任务失效的取消策略。缺少可信的宿主终止／替代信号时，保留迟到消费机会比激进取消更重要。

## 4. 提示词只构造一次，阶段诊断覆盖失败

v8 默认路径为体量统计构造一次判断提示词，发送时又构造一次。v9 在固定截面上创建单次准备产物，统计长度与发送使用相同文本。它不是跨请求缓存；不同信封不会使用另一信封的产物。生产和编译重放都传递同一准备产物。

新增或完善记录：

- `compiler-preparation-cost`：采集、适配、证据准备、提示词统计阶段；
- `promptBuildMs` / `promptBuildCount`：判断提示词构造；
- `compiler-flight-started/shared`：逻辑在途工作与附件关系；
- `compiler-transport-started/settled`：每次实际传输尝试；
- `toFirstContentMs`、`contentSpanMs`、`afterContentMs`、`totalMs`：包含部分输出之后仍超时的路径；
- `parseRenderMs`：模型结果解析与记忆渲染。

每次重试分配不同 `requestId`；一组共享工作用 `flightId` 关联。不能把多个逻辑任务的同一 usage 重复累计，也不能把重试当成一次已计费请求。

继续等待既有完整流结束及正常完成信号，不因收到完整-looking 两栏或 `finish_reason` 就提前把连接中的半成品当成功。本地“已收到内容与 stop、连接继续停滞”的反例仍然超时失败，并保留首内容与尾部耗时。

没有调大1500ms、8000ms或1200输出上限；没有修改 ready-only 适用条件、增加串行模型链或启用预热。

## 5. 前缀稳定与费用证据分开

静态指令统一在最前面；工具核对材料、用户原话、运行记录和已有模型记忆在易变记账字段前面。宿主位置、采集边界、索引等字段仍保留；原始 reasoning 仍位于末尾。未改主模型工具消息或 runtime context。

合成样本只改变宿主 blockIndex 时，最长相同前缀从4530字符增至5038字符。该数字不是 token，也不是缓存命中。真实输入在工具证据变化时仍可能很早分叉。

新增离线分析：

```bash
node analyze-efficiency.mjs trace.log efficiency.json
```

输出按 BOOT 分组，不合并不同启动；网络时延继续按可见模型／provider-API标签／预算／输出上限／thinking／stream／提示词版本分组，并区分成功和失败。缺乏 BOOT 的前缀明确标为未锚定。provider-API标签不是完整 URL 或凭据版本；同一启动内热更新这些配置时仍需外部记录分段，不能据此宣称运行条件相同。

支持读取常见供应商 `cached_tokens` 和 `prompt_cache_hit_tokens`，按请求身份保留原始 usage。它们仍是供应商自报数据，不是账单凭据。不计算金额，不臆测定价。

`decisionReview` 只提供已观察到呈现或认领任务的人工审核入口，后续轮次、同目标重复探索、实际采用判断、错误走向及审核人默认为 null，不能自动填成成功。仍使用现有完整会话配对重放和独立审核进行产品验收。

## 6. 验证、反证和交付

新增13项检查，包含真实 HTTP、默认生产 hook、归档失败与共享消费者隔离、凭据／端点／作用域差异、截断输出、失败不缓存和失败耗时。

最终全量：**1137通过／0失败／1宿主跳过，17套件通过**。这不是完整宿主验收，也未宣称完成 tsc 验收。

8项源码反证全部检出并恢复：

1. 重新构造已准备提示词；
2. 仅用提示词前缀判相同；
3. 匹配身份忽略凭据；
4. 取消一个消费者时误杀其他消费者；
5. 归档终局失败仍继续编译；
6. 超时路径丢失首内容观测；
7. 隐去既有推断材料；
8. 默认生产路径绕过在途复用。

证据目录：`docs/optimization-evidence-v9/`，包含生产 hook 夹具原始 trace、HTTP 请求正文与分析结果，可直接核对分析报告的 sourceSha256。其中 HTTP、usage、时延、重复请求数量均来自**本地合成夹具**，不是线上实测。反证脚本可在无活动进程的源码副本上运行：

```bash
python3 docs/optimization-evidence-v9/run-mutations.py
node verify.mjs
node manifest.mjs --check
```

反证会临时改源码并在 finally 中恢复，勿对运行中的插件执行。重生成测试证据会改变文件清单，应在交付副本之外运行。

完整交付：`cfb-v9-delivery.zip`，包含完整插件、最终v8→v9增量补丁及原始 `5a4def6`→v9累计补丁。完整目录或对应补丁二选一，不能重复应用。

仍缺完整真实会话、真实主模型配对重放、同目标探索标注、独立错误归因及任务结局审核。因此 timeout8000+empty下降、重复探索下降、错误状态走错路零例、总失败不升、任务结局不退步，**均未在本轮被宣称达标**。
