## 0. 一页纸

**要解决的问题**：宿主压缩会丢内容，而且**不可逆**——丢了就没了，模型也不知道自己丢了什么。

**立场（v8）**：不阻止压缩、不减少信息，**只降低指针精度**。丢失的内容搬到可检索的档案，
在上下文里留下一个稳定地址；需要时读回。原文件永远在磁盘上。

**三条不变式**：H1 零主动折叠 · H2 只追加不改写 · H3 只用年龄/最后触碰，不预测价值。

**数据流（文字版）**：

```
用户/模型 ──▶ 宿主表层 surface.nodes（每个节点带 tokens）
                  │
                  │  宿主压缩（它自己的阈值，不是我们决定的）
                  ▼
   compaction/* 事件  ──┬─▶ ① 我们的差分：pre-step 前后表层差集
                       └─▶ ② 宿主账本：compaction/summary.shadowedSeqs（权威源）
                                  │
                        并集 = 丢失集合（lostSource 记录两边是否一致）
                                  ▼
                      归档：内容寻址 blob（可跨重启读）
                                  ▼
                      根：稳定名 art://root（每会话一份、只追加、身份键去重）
                                  ▼
                  读回：inspect_artifact / read  ──▶ 模型或人
```

**今天的形状**：`dsh-boundary-plugin`（宿主 pre-step 钩子）+ `dsh-context-memory-bundle`（store + 工具）；
T2 上下文索引**默认关**（G2 之后根已提供发现性）；重启**重放**补档；日志审计 R1–R10；`verify-all.mjs` 一条命令验收。

## 1. 理论

### 1.1 核心命题

上下文的价值不在于"我们现在认为它重要"，而在于**它是否还能被找回来**。
所以本系统从不判断重要性，只做两件事：**如实归档** + **保持地址稳定**。

### 1.2 五条硬约束（H 系列）

| 约束 | 内容 | 违反的后果 |
|---|---|---|
| **H1** | 零主动折叠 | 我们自己决定"该丢什么" = 猜测重要性，且会打断前缀 |
| **H2** | 两次压缩之间只追加、不改写 | 改写 ⇒ 前缀断裂 ⇒ 缓存全断（§2.3） |
| **H3** | 只用年龄/最后触碰 | 给内容打分 = 价值预测 = 换个方式拟合 |
| **H4** | 索引必须有字节预算 | 索引是无界历史，会重新长成第二个上下文 |
| **H5** | 删索引前必须先有归档检索 | 没有检索的删除 = 销毁 |

### 1.3 七条设计哲学（§2.1–2.7，全部是被教训逼出来的）

| 条 | 一句话 | 逼出它的教训 |
|---|---|---|
| 2.1 禁止价值预测 | 价值只能从单一分布拟合，在大众分布上必然失效 | 保护集/打分方案全部被证伪 |
| 2.2 只追加，不改写 | 历史一旦改写就无法解释 | 前缀断裂与缓存 |
| 2.3 断裂是成本，不是工具 | 缓存断裂是真金白银，不是可随手支付的代价 | v7 索引在头部 ⇒ 每次折叠都变字节 |
| 2.4 不拟合、不造假、不自我安慰 | 没有数据就说没有数据 | 空数据报 PASS、把手动触发说成阈值触发 |
| 2.5 保真度 ≠ 可取回性 | 内容在磁盘上 ≠ 找得回来 | 有归档但无地址 ⇒ 等于丢了 |
| 2.6 读权威源 | 宿主自己记的账本 > 我们推导出来的信号 | `shadowedRange` 误差 6 倍；差分对跨 turn 恒盲 |
| 2.7 不拥有别人的工具集 | 别去决定不属于你的东西（否决项 V1） | 硬编码工具白名单 |

### 1.4 观测 vs 拟合（本轮的定论）

| | 性质 | 允许？ |
|---|---|---|
| **拟合** | 从**样本**估计**总体**，外推到别的会话/未来 | ❌ 禁止进决策回路（§2.1） |
| **实时测量** | 读**当前会话此刻**的仪表（剩余预算、缓存命中、这块内容有多大） | ✅ 允许 |

关键在**有没有外推**：拟合计的是"别人/以后会怎样"，实时测量读的是"现在读数是多少"。
本项目的**净收益守卫**就是实时测量（外置后逐块现算大小），从来不是拟合。

### 1.5 认知等级（本项目的写作契约）

- **已实测**：有数字、有出处，可以当事实用。
- **结构性推理**：由机制与代码推出，**不是实验**，必须自己标出来（V1 属此类）。
- **未验证**：明确写"未验证"，**绝不与已证事实混排**（§2.4）。

## 2. 机制

### 2.1 丢失集合的两个来源

- **差分**：`pre-step` 前后表层节点差集。**跨 turn 时曾经恒为空**（缺陷 8：`lastNodes` 存了引用，宿主 `surface.js:284` 就地 `splice`）。
- **宿主账本**：`compaction/summary.data.shadowedSeqs`——**权威源**（167 个会话日志 119/119 可核验）。
- **并集 + 记账**：`lostSource ∈ {both-agree, both-disagree, host, diff}` + `lostDisagree` 计数。
  字段表达不了的不一致 = 没记（§2.6）。
- ⚠️ **绝不用 `shadowedRange`**：它是包围区间，4834 个 seq 值 vs 23 个真丢失（约 6 倍）。

### 2.2 身份键与幂等

- 根条目带 `key=ev<seq>`（**事件身份**，不是派生区间）。
- **根本身就是持久游标**：重启重扫日志会重建队列，但键已在根里 ⇒ 跳过。不需要第二个游标机制。
- 实测：长会话重启后 `alreadyPresent=20 / queued=0`；鹈鹕 `alreadyPresent=4 / queued=0` ⇒ **零重复写入**。

### 2.3 根（G2：解决可取回性）

- **稳定名** `art://root`，**每会话一份**（store 复合键 `(sessionId, handle)`——缺陷 9 的修复）。
- **只追加**（H2）：每次写入前做**连续性检查**——新表必须以本进程上次写的表为前缀，否则记 hard 事件
  `root-rewritten` 并**把旧表补回**（检测 + 自愈）。这条不需要任何预测就能抓住"表被重写"。
- **读侧排序定死**：按 `lostAt`（丢失时刻）排，不按 `ts`（归档时刻）；复活的条目 `ts` 是旧的。

### 2.4 重放（重启补档）

- 重启后第一次 pre-step 重扫宿主日志，把历史上静默丢失的区间补档；每步最多 4 个区间（`replayPerStep`）。
- 重放条目 `source=replay`、`lostSource` **只能是 `host`**（过去的事件没有我们的快照；出现 `diff` = 编造观测）。
- 重放条目带 `cmd`（如 `cmd-0c766a6e-1`）⇒ **每条丢失可追到是哪个手动命令造成的**（差分永远给不了这个）。

### 2.5 读回路径

- 读根三态：`missing`（无记录，正常态，可静默）/ `unreadable`（有记录却读不出：**绝不静默、绝不覆盖**，走暂存）/
  `lost`（已回收）——**不单独区分**，因为 store 把它和别的读失败塌缩成同一个错，硬分就是编造精度。
- `verifyRoot`：根里每个句柄都要能解析，破损是**硬失败**。

### 2.6 我们什么时候动手

**只在宿主压缩时**（压缩搭车归档）。这是 H1 合规的根据：搬东西的时机由宿主决定，我们从不主动折叠。
⚠️ 由此推出一条边界：「随剩余预算主动外置」= 把触发时机从"宿主说了算"变成"我们说了算"，**需要与 H1 重新对账**，不是白捡的合规优化。

### 2.7 关键常量与开关（生产实测值）

| 名 | 值 | 说明 |
|---|---|---|
| `T1_BUDGET` | 4096 | **仅声明与 boot 日志，代码里无消费点**（核过） |
| `T2_RATIO` / `T2_ABS` | 0 / 2048 | T2 索引默认关（G2 后不需要） |
| `replayPerStep` | 4 | 重放限速 |
| `PIN_LIMIT` | 3 | 固定钉住上限 |
| `quotaBytes` | 1 GB | store 配额；一次 26 MB 重放 ≈ 2.6% |
| trace 上限 | 64 MB | `DSH_TRACE_MAX_BYTES` 覆盖；到顶**停止并计数**，永不半行 |

## 4. 缺陷史（9 条）与抽象原则

**九条缺陷全是一个形状：静默失败**——写成功了、日志也说成功了、没人知道。

| # | 缺陷 | 一句话 |
|---|---|---|
| 1 | 暂存/读取控制流 | `!prev.ok` 把"根还不存在"和"根读不出来"混为一谈 |
| 2 | 手动 `/compact` 在 pre-step 括号之外 | 差分窗口被整个绕过 ⇒ 一条日志都没有 |
| 3 | 跨会话状态串味 | 插件是宿主级单实例，共享 `lastScan` ⇒ 一个会话的日志长度决定另一个的窗口 |
| 4 | 重启后"先压缩后首次 pre-step" | 根本不在场（`lastNodes=null`），并集也补不动 ⇒ 必须读权威源 |
| 5 | `missing` 被记成 `root-read-failed` | 把正常态报成故障，淹没真信号 |
| 6 | 首次写根永久停在暂存 | 任何新会话都建不起根 ⇒ G2 静默失效 |
| 7 | `verifyRoot` 只验句柄可解析 | **发现不了条目缺失**（表被截断也能过） |
| 8 | `lastNodes` 存引用不存快照 | 宿主就地 `splice` ⇒ 跨 turn 差分恒为空（**夹具用"换数组"把它藏了**） |
| 9 | `art://root` 是全局单 owner 槽位 | 后写者夺走 owner，先写者读到自己"不存在" ⇒ 互相清空（**证据恢复：journal 里两条都在**） |

**抽象原则（可直接复用）**：

1. **无数据 = SKIP，绝不报 PASS**；每条 PASS 必须带"检查了几条"。
2. **完备性检查本身也要被检查**（`EXPECTED_RULES` 加载时断言）。
3. **缺失 ≠ 失败 ≠ 未授权**：三者在控制流上要分开（权威源会把"无权"报成"无"）。
4. **夹具必须复现被测对象的可变性语义**（桩比现实干净，就把真缺陷藏起来）。
5. **规则要能自动判定，否则就是散文**（否决项、审计规则都要可执行）。
6. **只为观测过的时刻生成观测**（R10：不为过去编造观测；H3 是不为未来编造价值）。
7. **身份用事件键，不用派生区间**（派生的会漏、会双写）。
8. **冲突不可见时，先让冲突可见**（`lostSource`/`lostDisagree`/`byNameAll` 诊断索引）。

## 5. 验证与审计（可执行的那部分）

**一条命令**：`node verify-all.mjs`（`--fast` 跳过编译器套件）

- 7 个边界套件 + 10 个编译器/存储套件 + 窗口内审计 + 7 条生产不变量 + 否决清单守卫。
- 现况：**26 项，23 通过 / 0 失败 / 3 跳过**（跳过 = 窗口内还没有压缩事件；按设计**报 SKIP 不报 PASS**）。

**日志审计** `audit-log.mjs`（可对任意 `boundary.jsonl` 重跑）：R1–R10 + 自检。

- **窗口制**：R2/R2b/R9 只判"自最近一次重载起"（它们守的是已修缺陷，全日志口径会被历史永久钉红 ⇒ 无法充当验收信号）；

- **正确的绿**：R9 的绿必须是"同一个 `replayKey` 不再出现两次"，不是"计数从 0 重来所以看着不重复"。

## 6. 否决清单

### V1 工具集白名单（§2.7）

`ctx.tools.restrict({allow})`，`allowTools=[inspect_artifact, read, glob, pwsh, grep, job_output]`。三条理由：
**所有权**（工具集属于用户与第三方，我们无权用硬编码白名单覆盖；六个名字来自单一使用分布）、
**静默**（被屏蔽的工具不报错，模型用近似工具硬凑，用户以为自己的工具坏了）、
**不可恢复**（装配期一次性生效，中途加回 ⇒ toolsHash 变 ⇒ 缓存全断 ⇒ 工具就一直缺着）。
**状态**：从未进入生产装配（代码与配置 0 处）；由 `verify-all` 的**否决清单守卫**持续检查其未复活。

### 三条实验否定结果（§6）

v3–v6 折叠策略 + 保护集（A/B 证伪）· v7 索引一等公民（每次折叠都变字节 ⇒ 缓存断裂）· 摘要链（前提拿不到）。

## 7. 未闭合与待决策

**工程债（非阻塞）**：宿主 spill-policy 与 CMB spill 的**竞争关系未定**（同族：`writer-pid` 每存储目录一把锁、
journal owner lease——失败方向是拒绝写入，fail-closed，比静默安全）。

**科学未验证（4 项，明确排除在修复循环外）**：宿主真实 80% 阈值触发（唯一昂贵的一项；长会话已 679 KB，可能自己送上门）·
工具误用率 · `p` 的真实值 · 跨模型/跨任务形态泛化 · "当时不相关、后来才相关"的靶点。

**待决策（新机制，不是缺陷）**：随剩余预算主动外置。障碍有二：①与 H1 的对账（触发时机是否该由我们决定）；
②**仪表缺分母**——`contextWindow` 生产里实测为 `null`，插件里 `tokens` 出现 0 次（今天只看 bytes）。
可行的合规增量：先把 `node.tokens`（宿主已提供）纳入 `observe` 日志，等真实阈值触发拿到"宿主在第几 token 压缩"的锚点，
再按 §2.6 读宿主账本决定，而不是从数据学参数。
